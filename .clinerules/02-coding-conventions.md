# Coding Conventions

Follow the project's existing conventions at all times:

- Use tabs for indentation (matches `@antfu/eslint-config`).
- Follow the project ESLint config (`@antfu/eslint-config`) and TypeScript strictness.
- Prefer Nuxt auto-imports (composables, components, utilities) over manual imports.
- Use `<script setup>` in Vue SFCs.
- Respect the existing folder structure and naming patterns (e.g. `app/composables/`, `app/components/<Group>/`).
- Run `pnpm typecheck` and `pnpm lint` after changes and fix any errors.
- After changing `runtimeConfig` keys in `nuxt.config.ts`, run `pnpm exec nuxt prepare` before `pnpm typecheck` — `.nuxt/types/runtime-config.d.ts` is generated, so a stale copy fails with `TS2353 ... does not exist in type`.
- Do not introduce new dependencies unless they are already used in the project.

## CI self-check conventions

- Before editing a UI / integration self-check step in `.github/workflows/ci.yml`, confirm the instance under test gets its required environment: `check:ui` and `check:bff` boot their own fake upstream plus build output, so hand-starting a server (or pointing `CHECK_UI_BASE_URL` at an external one) requires providing `NUXT_BFF_UPSTREAM_BASE` yourself — otherwise the "upstream ready" and login cases fail as false positives (measured 2026-10-31).
- When a self-check gains cases, update the counts quoted in its own summary output and in the related architecture doc — never leave a stale "N/N" in prose.

## Tauri Conventions

- Tauri APIs are auto-imported with the `useTauri<Module><Function>` prefix (generated by `modules/tauri.ts`); use them instead of manual imports.
- When adding a new Tauri plugin, register it in three places: `src-tauri/src/lib.rs`, `src-tauri/capabilities/*.json`, and `modules/tauri.ts`.
- Guard Tauri API calls that run at page load with `isTauri()` (from `@tauri-apps/api/core`) so the app still works in a plain browser.
