# ADR-0018：后端代际切换 —— 上游由旧代 go-zero 网关整体切到 8888 端口 NMS 统一网关

> **层级**：Tier 5 记录层 —— 正文发布后只追加；细则补充用 `##` 追加节。
> **与基准文档的关系**：本 ADR 是**代际切换的裁决与证据记录**；规范本体仍是 `NMCPS-ARCH-003`（`arch.iam`）与 `NMCPS-DESIGN-005`（`domain.system`），二者冲突时以基准文档为准（基准文档须随本次切换同步升版，见 §七）。
> **作业单**：落地步骤、逐文件 diff 草案与验收命令见 `documents/3.operations/backend-generation-migration.md`（Tier 4 作业层，非依据）。

## 一、裁决

| 编号 | 裁决 | 依据 |
| :--- | :--- | :--- |
| **D1** | BFF 唯一上游固定为 `http://192.168.1.55:8888/api/v1`（NMS 统一网关）。旧代 go-zero 网关实例**已退役**，仓库、脚本、文档、联调环境**不得再出现旧端口** | §二 实测 + 需求方指令（2026-11-04） |
| **D2** | 出站白名单按新代十二个服务命名空间重建：`iam` / `asset` / `metric` / `topology` / `alarm` / `audit` / `system` / `task` / `transmission` / `dashboard` / `frequency` / `protocol`（＋`health`）。旧的 `account` / `role` / `permission` / `abac` / `access` / `tenant` / `user` 资源名一律退役 | OpenAPI 131 条路径 / 13 个 tag |
| **D3** | 登录改 `POST /api/v1/iam/login`，入参 `{ username, password }`；响应 `data.{ access_token, refresh_token, expires_in, user_info }`。**没有 `whoami`**，身份一律来自登录响应的 `user_info`（BFF 侧持久化，会话单一事实源不变） | §二 行 2 / 行 6 |
| **D4** | **撤销** `NMCPS-ADR-0011` 的「刷新即轮换」前提：新代 `/iam/refresh` 只回 `{ access_token, expires_in }`，同一 `refresh_token` 可重复使用（实测两次同值刷新均成功）。保留：401 后单飞刷新、双 cookie 模型、桌面端回传 body、CSRF 校验 | §二 行 5 |
| **D5** | 业务错误走 **HTTP 200 + `code ≠ 0`**（如口令错误 `code: 10003`）。消费面一律以 `isSuccessResponse()` 判定，禁止只看 `status`/HTTP 码 | §二 行 3 |
| **D6** | 分页信息在 `data` 内：`data.{ list, page, page_size, total }`；**空列表可能是 `list: null`**（不是 `[]`）。BFF 出口统一归一为 `[]` 或消费面判空 | §二 行 4 / 行 5 |
| **D7** | `GET /api/v1/asset/device` 返回 `snmp_auth_pass` / `snmp_priv_pass` **明文**，BFF 必须在出口掩码（`***`），前端只读掩码值 | §二 行 5 |
| **D8** | 命名风格整体由上游 camelCase 改为 **snake_case**（`display_name` / `tenant_id` / `mfa_enabled` / `created_at`），BFF 不做驼峰转换，前端类型按 snake_case 重写 | §二 行 4 |

## 二、证据（2026-11-04 复测，seed 账号 `admin` / `Admin@123456`）

| # | 请求 | 观测 | 结论 |
| :---: | :--- | :--- | :--- |
| 1 | `GET /api/v1/health` | `200 { code: 0, data: { status: "ok", version: "v1.0", services: { …12 个 up… } } }` | 就绪探针（`NUXT_BFF_READINESS_PATH=/health`）**无需改动** |
| 2 | `POST /api/v1/iam/login` | `200 { data: { access_token, expires_in: 86400, refresh_token, user_info: { id: "u_platform_admin", username: "admin", display_name: "平台管理员", email, phone, tenant_id: null } }, code: 0 }` | 有 `user_info`，无 `accountCode` / `accountLevel` / `sessionId` / `mfaRequired` / `mustResetPassword` |
| 3 | `POST /api/v1/iam/login`（错误口令） | `200 { code: 10003, message: "用户名或密码错误" }` | **业务错误仍是 HTTP 200** |
| 4 | `GET /api/v1/iam/users?page=1&page_size=2` | `200 { code: 0, data: { list: [{ id, tenant_id, department_id, username, email, display_name, status, mfa_enabled, created_at, updated_at }], page, page_size, total: 23 } }` | 账号模型 = IAM user；无 `accountLevel` |
| 5 | `GET /api/v1/audit/operation-logs?page=1&page_size=1` | `200 { code: 0, data: { list: null, total: 0, page: 1, page_size: 1 } }` | **空列表返回 `null`** |
| 6 | `GET /api/v1/asset/device?page=1&page_size=1` | `200 data.list[0]` 含 `snmp_auth_pass: "rYeg…"`、`snmp_priv_pass: "DrpC…"` | 明文凭据出厂 → 必须脱敏（D7） |
| 7 | `GET /api/v1/iam/whoami` | `404 page not found` | `whoami` 不存在（D3） |
| 8 | `POST /api/v1/iam/refresh`（同一 `refresh_token` 连发两次） | 两次均 `200 { data: { access_token, expires_in: 86400 } }`，响应**不含** `refresh_token` | 刷新不轮换、可重放（D4） |
| 9 | `GET /api/v1/iam/users`（不带令牌） | `401 { code: 40101, message: "缺少认证凭证" }` | 未认证走 HTTP 401 + 数字码（与业务错误 200 形态不同） |
| 10 | `POST /api/v1/iam/logout` | 需 `Authorization: Bearer` + body `{ user_id }`；成功 `200 { code: 0 }` | 登出**不再是空 body 的 form-urlencoded** |

JWT claims（`exp / iat / sub: "admin" / tid: null / uid: "u_platform_admin"`）中**没有** `display_name` / `email` / 角色，故 D3 的「身份取 `user_info`」是唯一可行路径。

## 三、契约形状

```
成功：{ code: 0, message: "success", data: T }
业务失败：HTTP 200 + { code: 10003, message: "用户名或密码错误" }   // 无 data
认证失败：HTTP 401 + { code: 40101, message: "缺少认证凭证" }
分页：data = { list: T[] | null, page, page_size, total }
```

- 键序不稳定（`data` 可能在前）、字段成 snake_case —— BFF 透传即可，前端不得依赖键序。
- BFF 现有信封 `ApiResponse<T>`（`{ code, status, message, data, total… }`）与新代**不冲突**：`code` 语义需补一条「上游业务码原样透传、`status` 由 `code === 0` 推出」。

## 四、字段映射表（旧代 → 新代）

### 4.1 认证（`shared/types/auth.ts` 全体重写）

| 旧代（`/api/v1/auth/*`） | 新代（`/api/v1/iam/*`） | 备注 |
| :--- | :--- | :--- |
| `POST /auth/login` | `POST /iam/login` | 路径 |
| 入参 `accountName` | 入参 `username` | 改名 |
| 入参 `tenantCode` | **无** | 新代按账号归属解析租户，登录不接受租户编码 |
| 入参 `mfaCode` | **无** | 无 MFA 端点（见 §六） |
| `data.accessToken` | `data.access_token` | 命名风格 |
| `data.refreshToken` | `data.refresh_token` | 命名风格 |
| `data.expiresIn`（可变） | `data.expires_in`（固定 86400 = 24h） | TTL 从 30 分钟变成 24 小时 |
| `data.sessionId` | **无** | 会话标识改由 BFF 自签或省略 |
| `data.accountCode` | `data.user_info.id` | `u_platform_admin` |
| `data.accountName` | `data.user_info.username` | |
| `data.displayName`（旧代登录不返回） | `data.user_info.display_name` | **新代直接给显示名**，「未知即 null」的兜底可收窄 |
| `data.tenantId: number`（超管 0） | `data.user_info.tenant_id: string \| null`（平台管理员 `null`） | 类型与语义同时变 |
| `data.accountLevel: 0/1/2/3/4` | **无** | 等级概念消失，改看角色（§六 缺口 G1） |
| `data.mfaRequired` / `mustResetPassword` | **无** | 强制改密流程失去上游信号（缺口 G2） |
| `GET /auth/whoami` | **无** | 身份取登录态 `user_info`（D3） |
| `POST /auth/token/refresh { refreshToken }` | `POST /iam/refresh { refresh_token }` | 响应只回 `access_token` / `expires_in`；**不轮换**（同一 RT 连用两次均 200，2026-11-04 实测） |
| `POST /auth/logout`（空 body + form） | `POST /iam/logout`（Bearer + `{ user_id }`） | 参数来源变成 `user_info.id`；上游**幂等**（重复调用仍 `200 { code: 0 }`） |
| `POST /auth/password { newPassword, oldPassword?, firstReset? }` | `PUT /iam/password { old_password, new_password }` | 入参实测：camelCase → `400 field "old_password" is not set`；旧口令错 → **`200 + code 10003`** |
| `POST /auth/mfa/bind`、`/auth/mfa/confirm` | **无** | MFA 页面必须下线或标未实现 |

实测补充（2026-11-04）：`POST /iam/refresh` 用坏令牌返回 **`HTTP 200 + code 10007`**（「无效的认证令牌」），
不是 401 —— BFF 必须把它当会话失效（`SESSION_INVALID_CODES` 含 `10007`），否则「200 即成功」的旧判据会把刷新失败读成成功。

### 4.2 账号 / 租户（`/system/user`）

| 旧代 | 新代 | 备注 |
| :--- | :--- | :--- |
| `GET /account?page&pageSize&accountName&accountLevel` | `GET /iam/users?page&page_size&keyword&status&department_id` | `pageSize` → `page_size`；无等级过滤 |
| `POST /account { accountName, password, accountLevel, tenantId }` | `POST /iam/users { username, password, email?, display_name?, tenant_id?, department_id? }` | 必填集待实测；`department_id` 为新增维度 |
| `PUT /account/{accountCode}/status { status }` | `PUT /iam/users/{id} { status }` | 主键从 code 变 uuid |
| （无删号端点，缺陷 `UP-ACC-04`） | `DELETE /iam/users/{id}`（软删 `deleted_at`） | 上游缺口**已闭环** |
| `GET /account` 列表缺租户归属（`UP-ACC-05`） | 列表自带 `tenant_id` / `department_id` | 闭环 |
| `GET /tenant` | `GET /iam/tenants` | |
| `POST /account/role` 只写不读（`UP-POL-07`） | `POST /iam/subject-roles/AssignRole` / `RevokeRole` + `GET /iam/subject-roles` | 读写对称，闭环 |

| 旧代 | 新代 | 备注 |
| :--- | :--- | :--- |
| `GET /role`、`POST /role`、`DELETE /role/{roleCode}` | `GET\|POST /iam/roles`、`DELETE /iam/roles/{id}` | `roleCode` → `id` |

## 八、风险

| 编号 | 风险 | 影响 | 缓解 |
| :---: | :--- | :--- | :--- |
| R1 | `proxy.normalizeUpstreamEnvelope` 丢了「`status` 由 `code === 0` 推出」这条推导（上游 2xx 信封不带 `status`） | HTTP 200 + `code: 10003` 会被当成 `success`，口令错误读成登录成功 | 动网关 / 迁移上游路径时保住该推导，并在 `check:bff` 断言「200 + `code: 10003` → 不得为 success」 |
| R2 | `SESSION_INVALID_CODES` 仍是 `{401, 10201, 20205}` | 新代 401 业务码是 `40101`，会话失效识别不到、旧会话不清 | 改常量并加断言（登出后 refresh 必须判失效） |
| R3 | `list: null` 未归一 | 列表页 `.map` 崩 | BFF 出口归一（`?? []`），并加自检断言 |
| R4 | 字段 snake_case 半改 | 类型对但运行时空值 | 类型与页面同批提交，禁止跨提交混跑 |
| R5 | 无 `accountLevel` 后权限语义漂移 | 越权可见性 | §六 G1 的规则须先出新 ADR 再动 `/system/user` |
| R6 | SNMP 明文凭据经 BFF 直达前端 | 凭据泄露 | D7 掩码与 `asset` 端点同批上线 |
| R7 | 新代无导出/校验/试算 | 页面功能倒退 | 明确标注「上游未提供」，不静默置灰 |
