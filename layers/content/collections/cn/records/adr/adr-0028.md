# ADR-0028：SNMP 采集面的最小形态（M2 首增量）

> **层级**：Tier 5 记录层 —— 正文发布后只追加；后续修正用 `##` 追加节，不回改已发布结论。
> **与既有基准的关系**：`NMCPS-DESIGN-008`（`layers/content/collections/cn/architecture/2.domain/simulation.md`）把 M2 的验收写成「外部 `snmpwalk` 取到一致 OID」，`NMCPS-ARCH-007`（`layers/content/collections/cn/architecture/1.architecture/lab-deployment-architecture.md`）把「SNMP `:161` 与宿主 `snmpd` 冲突」留在待裁决，`NMCPS-ADR-0027` D5 / R6 规定 SNMP 写面必须新开 `lab:snmp`、`snmp/onboard` 不得以转发形态复刻。三条都没有写**首增量具体长什么样**，本 ADR 补这一段。

## 1. 背景（为什么不能照抄参考侧）

- **参考侧的实现形态依赖第三方系统组件**：`_reference/netsim` 的 `engines/mininet_wifi/snmp_agent.py` 在**每个节点命名空间**里生成 `snmpd.conf`、拉起 `net-snmp` 的 `snmpd`，再用 AgentX / `pass` 协议接企业 OID；无线侧另有 21 份 MIB 文本要随包分发。这条路的两个前提在本仓都不成立：再分发许可未确认（`NMCPS-ADR-0027` D7），而宿主是否装 `net-snmp` 不该决定仿真面能不能被采集。
- **采集是外部行为，不是页面行为**：NMS 拿自己的 `snmpwalk` / exporter 轮询仿真节点，采集面必须对标准 OID 成立，而不是「我们自己的客户端能读」。所以验收口径仍是 `snmpwalk -v2c -c public <node> 1.3.6.1.2.1.1`，只是实现不必是 `snmpd`。
- **端口冲突是宿主面的问题，不是节点面的问题**：节点是独立 netns，在**节点自己的 netns 里**绑 `:161` 不会碰到宿主 `snmpd`；只有「在宿主根 netns 起一个代理所有节点」才会抢端口 —— 那种形态也不成立，因为节点 IP 不在根 netns 的路由里。

## 2. 裁决（D1–D7）

| 编号 | 裁决 | 说明 |
| :--- | :--- | :--- |
| **D1** | **自写 stdlib agent，每个节点一份** | `services/mininet-api/mininet_gui_backend/snmp/` 下实现 BER 编解码、MIB 投影与 UDP 服务，只依赖 Python 标准库；不 import `net-snmp`、不生成 `snmpd.conf`、不随包分发任何 MIB 文本。OID 只写**数字弧**（RFC 1213 / 2863 的既有编号），名字由 NMS 自己的 MIB 解析。 |
| **D2** | **agent 跑在节点自己的 netns 里** | 起网成功后，用 `nsenter -t <node.pid> -n --` 把 agent 进程放进目标节点的网络命名空间，绑 `0.0.0.0:<port>`；节点 IP 因此天然可达，宿主 `snmpd` 与宿主端口表都不受影响。非 root / 缺 `nsenter` 时该节点记为 `unavailable`，**不**回落到根 netns 代理。 |
| **D3** | **只读 v2c，社区串来自环境变量** | 只实现 GET / GETNEXT 与 `SNMPv2c`（version 编码 1）；SET / v3 USM / trap 全部不做。社区串取 `LAB_SNMP_COMMUNITY`（缺省 `public`）、端口取 `LAB_SNMP_PORT`（缺省 161，在节点 netns 内），两者都属部署配置而不是页面输入。写面（开通 / 轮换 / 吊销）按 `NMCPS-ADR-0027` D5 走独立 `lab:snmp`，**本增量不暴露任何 SNMP 写端点**。 |
| **D4** | **生命周期挂网络起停，默认关闭** | `LAB_SNMP_ENABLED=1` 时才在 `POST /api/mininet/start` 成功后拉起；`stop` / `reset` / `full_reset` 与进程退出时全部回收。采集面失败**不得**让起网失败：单节点起不来只体现在状态读数里。默认关闭的理由是 M2 仍属实验能力，且 161 在节点内虽是独立命名空间、仍应由部署方显式打开。 |
| **D5** | **MIB 子集只有三组 + 企业类型 OID** | `SNMPv2-MIB` 的 system 组（`1.3.6.1.2.1.1`，含 `sysName` / `sysDescr` / `sysObjectID` / `sysUpTime` / `sysServices`）、`IF-MIB` 的 `ifTable` 基础列（含 `ifName` / `ifAlias`）、`IP-MIB` 的 `ipAddrTable`（含 `ipAdEntNetMask`）。`sysObjectID` 用参考侧同形的企业编号 `1.3.6.1.4.1.99999.<type>`（1 switch / 2 ap / 3 router / 5 station / 7 host …），让按 `sysObjectID` 分类的 NMS 仍能识别节点类型。计数列（`ifInOctets` / `ifOutOctets`）首版恒 0，见 §4。 |
| **D6** | **邻接不从 LLDP 读，从台账投影拿** | LLDP 面已按 `NMCPS-ADR-0027` R8 撤销，agent 不提供 `lldpRemTable`。NMS 要做拓扑，用 `GET /api/mininet/snmp/topology`（BFF 同名，`lab:read`）：它把台账节点 / 链路投影成「可采集目标清单」（节点 IP、端口、community、sysObjectID、接口），供 NMS 的 seed 列表使用。这与参考侧 `POST /snmp/topology`（扫子网 + 读 LLDP 反推）**语义不同**：那是在发现宿主网，我们是在发布仿真网。 |
| **D7** | **首增量不含凭据编排与 exporter 联动** | `snmp/onboard`（v2c/v3 开通、rotate/revoke/export）、`nms/*`（vmagent、snmp-exporter-reset）、`GET /snmp/tools` 都不在本增量；它们要么要 `lab:snmp` 与 IAM 角色 `lab_snmp` 先落地，要么属外部监控栈运维。BFF 白名单只新增两条只读端点。 |
## 3. 落地物与验收

| 项 | 位置 | 验收 |
| :--- | :--- | :--- |
| BER / PDU | `mininet_gui_backend/snmp/ber.py`：TLV 编解码、OID 弧、Integer / OctetString / TimeTicks / Counter32 / IpAddress、GET / GETNEXT 请求解析与响应编码 | `pnpm check:snmp`（纯 stdlib，无 root）：编码往返 + 手工构造请求的响应断言 |
| MIB 投影 | `mininet_gui_backend/snmp/mib.py`：从「节点档案」生成有序 OID 表，`get()` / `getnext()` 语义（缺对象 `noSuchObject`、越过末项 `endOfMibView`） | 同上：system / ifTable / ipAddrTable 关键 OID 存在且 `getnext` 单调 |
| 节点档案 | `mininet_gui_backend/snmp/inventory.py`：从 `app.net` 取节点与接口事实（IP / MAC / 前缀 / MTU），生成 agent 档案；不读页面状态 | 同上：桩节点对象 → 档案字段完整；无 IP / 无 pid 的节点被跳过 |
| agent | `mininet_gui_backend/snmp/agent.py`：`respond()`（纯函数）+ `serve()`（UDP）；只处理 v2c GET / GETNEXT；社区串不符直接丢包 | 同上：本机 `127.0.0.1:0` 起服务，回环客户端读回 system 组；错社区无响应；另起**真子进程** `python -m … snmp.agent --profile … --port … --community …`，断言档案 / 端口 / 社区三个参数都生效、SIGTERM 退出码 0、退出后端口可重新绑定 |
| 运行时 | `mininet_gui_backend/snmp/runtime.py`：`LAB_SNMP_ENABLED` / `LAB_SNMP_PORT` / `LAB_SNMP_COMMUNITY`、档案落 `.data/snmp/`（0600）、进程表、起停与状态 | 同上：未启用时 `start` 为 no-op；状态读数三态（running / stopped / unavailable） |
| 上游端点 | `GET /api/mininet/snmp/state`（运行态 + 每节点状态）、`GET /api/mininet/snmp/topology`（台账投影） | `pnpm lab:check` 路由清单 + `pnpm check:lab-bff` 计数 / 转发 |
| 起停挂点 | `start_network()` 成功后拉起、`stop_network()` / `full_reset_network()` 与 lifespan 退出时回收；异常只记日志 | `pnpm lab:check` 源码守卫（第 4 组「SNMP 采集面挂点」）：四处挂点与 `_start_snmp_collection()` 的 try/except 都在 |
| 真实验收 | 90 上 root 后端 + `LAB_SNMP_ENABLED=1`，`snmpwalk -v2c -c public <h1-ip> 1.3.6.1.2.1.1` / `…1.3.6.1.2.1.2.2.1` | 2026-11-26 已闭环（宿主装了 net-snmp）：见 §5 的实测输出、跨节点可达与起停回收 |

## 4. 首增量明确不做（不是遗漏）

- **计数器真实化**：`ifInOctets` / `ifOutOctets` / 错误计数首版恒 0；要真实流量得让 agent 周期读接口统计或与后端 IPC，属 P1。
- **64 位计数与 `ifXTable`**：`ifHCInOctets` 等需要 Counter64 与同一份统计来源，随计数器真实化一起做。
- **动态拓扑**：运行中增删节点 / 链路后，agent 视图要等下一次 `start` 才刷新（`/snmp/topology` 读的是实时台账，两者会短暂不一致）。这条在页面上没有入口，先按「重启网络刷新」记账。
- **凭据编排**：`LAB_SNMP_COMMUNITY` 是单值部署配置；按节点 / 按租户的社区串、v3 用户、rotate / revoke 都等 `lab:snmp` 与 IAM `lab_snmp` 角色。
- **MIB 文件**：不随包分发；NMS 侧自备标准 MIB 即可。若未来确需随包，先解决再分发许可（`NMCPS-ADR-0027` D7）。

## 5. 验收口径与已知限制

- 机器侧：`pnpm check:snmp`（stdlib、无 root、无 mininet；当前 28 项）覆盖编解码 / MIB / 档案 / 回环 UDP / **真子进程入口**（`python -m … snmp.agent --profile/--port/--community` 的参数生效、SIGTERM 退出码 0、退出后端口释放 —— `runtime.py` 那条命令行的自检，不是 netns 验收）；`pnpm lab:check` 覆盖上游路由与起停挂点；`pnpm check:lab-bff` 覆盖 BFF 白名单计数与转发。CI 里它是独立步骤 `SNMP agent self-check`（结论键 `snmp`，正则 `结果：N 通过 / 0 失败`，样本 `scripts/fixtures/ci-logs/snmp.log`），不再挂在 `lab-api` 步骤的日志后面 —— 混在源码守卫里时「红在哪一层」只能翻全量日志。
- 真机侧（2026-11-26 在 90 上闭环）：先 `GET /api/mininet/export_json` 备份台账，`mn -c` 后以 root 重启后端并带 `LAB_SNMP_ENABLED=1`，逐条重建同形拓扑（3 交换机 / 4 主机 / 6 链路）再 `POST /start`，`GET /api/mininet/snmp/state` 四台主机全部 `running`。宿主装上 net-snmp 工具后（`apt-get install snmp` → `/usr/bin/snmpwalk`）实测：
  - `nsenter -t <h1 pid> -n snmpwalk -v2c -c public 127.0.0.1 1.3.6.1.2.1.1` → `sysName=h1`、`sysObjectID=1.3.6.1.4.1.99999.7`、`sysServices=72`；
  - `…1.3.6.1.2.1.2.2.1` → `ifDescr=h1-eth0`、`ifType=6`、`ifMtu=1500`、`ifPhysAddress=00 00 00 00 00 01`（与台账 MAC 一致）、admin/oper up；
  - `…1.3.6.1.2.1.4.20.1` → `ipAdEntAddr=10.0.0.1`、`ipAdEntNetMask=255.0.0.0`，与 `addressing_plan` 的 `10.0.0.1/8` 同值（agent 报的是节点 netns 的真实前缀，不是台账里的假设前缀）；
  - 从 **h2 的 netns** 打 `10.0.0.1` 同样拿到 system 组 —— 说明 agent 绑的是节点真实 IP，跨仿真网可达，不只是回环；
  - `-c private` 无响应（超时）、未登记 OID 回 `No Such Object`；
  - `POST /stop` 后 agent 进程数 0、`running=false`；`POST /start` 后重新 4 条 `running`（起停挂点两向都验过）。
  `sysName` 等于台账节点 id、`ifDescr` / `ipAdEntAddr` 与 `GET /api/mininet/interfaces` / `addressing_plan` 一致这三条断言全部满足。收尾按 `09-local-sudo.md` 把 `.data` 与 `services/mininet-api/.data` 都 chown 回当前用户（agent 档案是 root 下的 0600 文件）。
- 端口：在节点 netns 内绑 161，不需要宿主端口映射；宿主 `snmpd` 可以继续占着根 netns 的 161。`NMCPS-ARCH-007` §七的「端口冲突」自此按本条收口（节点面不冲突；只有「根 netns 代理」那种形态才冲突，而它已被 D2 否决）。
