# ADR-0020：Mininet 实验后端的只读 BFF 通道

> **层级**：Tier 5 记录层 —— 正文发布后只追加。
> **与 ADR-0019 的关系**：ADR-0019 裁决的是仿真平台（8001）作为第二上游；本 ADR 接入的是 Mininet-GUI 的 FastAPI 后端（默认 8000），两者**不是同一个数据源**，也不共享白名单、配置或客户端。
> **状态**：阶段 A 已实施（只读通道）。写操作、终端、抓包与多用户隔离仍未开放，须另立裁决。

---

## 一、裁决（速览）

| 编号 | 裁决 | 说明 |
| :--- | :--- | :--- |
| **D1** | Mininet 后端作为 BFF 的**第三出站通道** | 独立 `runtimeConfig.mininet`、独立 `layers/scenario/server/utils/bff/mininet*.ts`、独立路由前缀 `layers/scenario/server/api/lab/**`；不复用主网关或仿真通道。 |
| **D2** | 当前**只开放 GET 查询** | `MININET_ROUTES` 的 `method` 类型只有 `GET`；写端点不在表中，因而没有入口，不依赖运行时布尔开关。 |
| **D3** | 显式逐端点白名单 | 17 条查询端点；模板匹配，非前缀放行；未登记路径 404、动词不符 405、路径穿越 400。 |
| **D4** | 出站**不携带任何凭据** | 不读 `nmcps_at`、不转 `Bearer`、不转发 cookie；只转发 `accept` / `user-agent` / `x-request-id`。 |
| **D5** | 导出、WebSocket 与全部写操作**不在本阶段** | 文本 / pcap 下载需要独立内容类型契约；终端 / 日志 / 抓包 / 监控需要 ticket 鉴权。 |
| **D6** | 鉴权与多用户隔离**仍未裁决** | 本通道上线前提是 Mininet 仅监听 loopback 或受控内网；BFF 本身不提供新的权限模型。 |

---

## 二、通道形状

| 项 | 值 |
| :--- | :--- |
| 浏览器入口 | `/api/lab/**` |
| 上游 | `${NUXT_MININET_BASE_URL}`，默认空（未启用） |
| 配置 | `runtimeConfig.mininet.baseUrl` / `timeoutMs` |
| 白名单 | `layers/scenario/shared/constants/mininetRoutes.ts` |
| 出站 | `layers/scenario/server/utils/bff/mininet.ts` |
| 探针 | `GET /api/lab/channel`（200 + 能力位，不回 `baseUrl`） |
| 未配置 | `/api/lab/**` → 503 `mininet_not_configured` |

**为什么不复用 `proxyToUpstream()`**：主代理会把访问令牌 cookie 转成 `Bearer` 并参与 401 单飞刷新。Mininet 后端没有鉴权能力，把令牌发给它既无收益，也扩大泄露面；上游的 401/403 也不能触发会话刷新。

---

## 三、只读白名单

| 分组 | BFF 路径 | 上游路径 |
| :--- | :--- | :--- |
| 探针 | `/health`、`/version`、`/ryu/apps` | `/api/health`、`/api/version`、`/api/ryu/apps` |
| 台账 | `/hosts`、`/interfaces`、`/switches`、`/controllers`、`/nats`、`/routers`、`/links`、`/start` | `/api/mininet/*` |
| 运行态 | `/addressing_plan`、`/stats/{node_id}`、`/flows/{switch_id}`、`/links/stats/{src_id}/{dst_id}` | `/api/mininet/*` |
| 抓包读数 | `/sniffer/state`、`/sniffer/history` | `/api/mininet/sniffer/*` |

**明确排除**：

- `export_json` / `export_script` / `sniffer/export`：文本或 pcap 二进制，下载语义与 JSON 信封不同；
- 所有 POST / PUT / PATCH / DELETE：`start`、`stop`、`reset`、`full_reset`、增删节点 / 链路、流表、iperf、sniffer 启停；
- 四个 WebSocket：`terminal/{node_id}`、`logs`、`sniffer`、`monitor`。

排除项不是“以后补一个正则”即可放开：写操作与终端需要权限位、审计与多用户隔离先落地（见 §五）。

---

## 四、拒绝语义与守卫

与主网关、仿真通道共用一套 `ApiResponse` 拒绝词汇：

| 情形 | 状态 / message |
| :--- | :--- |
| `/api/lab` 或 `/api/lab/` | 400 `bff_path_missing` |
| `..` / `%2e%2e%2f` / 含 `/` 的段 | 400 `bff_path_invalid` |
| 未登记路径（含所有写端点） | 404 `bff_resource_not_allowed` |
| 已登记路径的非 GET 动词 | 405 `bff_method_not_allowed` |
| 未配置 `baseUrl` | 503 `mininet_not_configured` |
| 上游不可达 / 超时 | 502 `mininet_unreachable` / 504 `mininet_timeout` |

`pnpm check:lab-bff` 共 26 项断言，覆盖白名单 ⊆ OpenAPI 快照、只读动词、未配置、白名单、查询参数、参数化路径、路径穿越、写请求零触达、出站头无凭据、上游错误保真与 channel 能力位。该脚本消费构建产物，前置为 `pnpm build:server`。

---

## 五、尚未裁决

1. **单用户还是多用户**：`app.net` 是进程内全局拓扑，同一时间只有一张网络。BFF 不能假装它是按会话隔离的。
2. **BFF 鉴权**：当前通道只限制“浏览器不直连”，没有新增登录校验；部署必须保证 8000 只监听 loopback / 受控内网。
3. **权限位**：`lab:read`、`lab:operate`、`lab:terminal`、`lab:sniffer`。
4. **WebSocket 鉴权**：BFF 签发短时 ticket，反向代理校验后转发。
5. **审计**：所有写操作、终端会话、抓包启停必须留痕。

在上述问题有结论前，任何写端点、终端、抓包启停与 `reset` 都**不得**加入白名单。
