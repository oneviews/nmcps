# ADR-0016：移除根路径下载落地页，下载入口迁入系统管理的「下载中心」

> **层级**：Tier 5 记录层 —— 正文不可修改（append-only）；变更须新开 ADR 并登记 `supersededBy`。

- **背景**：
  - **落地页与产品形态不符**：本仓库交付的是「登录后使用控制台」的业务系统，`/` 却是模板时代的下载页 —— 打开站点先看到 `Powered by` / `下载 NMCPS` / `Star on GitHub`，想进系统还要再点一次「登录」。下载入口真正的使用者是已安装的运维人员，不是未登录访客。
  - **它把一堆孤儿资源维持成活代码**：只要 `/` 还在，`app/layouts/home.vue`、`useOS()`、`app.config.downloads`（4 个平台共 13 个安装包名）与 `pages.index.*`（cn/en 各 10 键）就必须存在并可构造，`check:ui` 也要为落地页维持断言。
  - **`blank` 布局与 `SiteNavbar` 早已无页面使用**：`NMCPS-ADR-0006` 已记录 `/` 走 `default` 布局、`home` / `blank` 布局无页面使用；`Site/LanguageSwitch.vue` 只被 `SiteNavbar` 引用。语言切换、配色切换与「检查更新」在 `AppHeader` 里都有正式入口。
  - **需求**：清掉 `/` 的落地页让站点打开即进登录页，同时**不丢掉下载入口** —— 把它收进系统配置，成为系统管理下的一级子页面。
- **决策**：
  1. **`/` 不再是页面**：`nuxt.config.ts` 增加 `routeRules: { "/": { redirect: "/auth/login" } }`，冷启动在 Nitro 层直接 `302`（实测 `307`）到登录页，首屏不经过 SPA、不闪白。
  2. **站内跳回 `/` 也要分流**：SPA 下 `vue-router` 会把 `/` 交给 `[...all].vue`（404 页），所以 `auth.global.ts` 增加根路径分支 —— 已登录 → `/dashboard/overview`，未登录 → `/auth/login`（`replace: true`）。HTTP 层管冷启动，守卫管站内跳转与桌面端。
  3. **守卫白名单只留 `/auth/**`**：`PUBLIC_PATHS` 常量删除，`isPublicPath()` 只剩前缀判断；下载中心因此与其余业务页一样要求登录。
  4. **下载页迁到 `layers/system/app/pages/system/download.vue`**（`/system/download`，`sort: 5`、`icon: carbon:download`，侧栏「系统管理 → 下载中心」）：保留原下载卡片的平台检测 / 主推格式 / 其他格式下拉 / 其他平台链接，改用控制台外壳（`LayoutTile` + `UCard`），去掉落地页专属的 hero（Logo 动画、`Powered by`、Nuxt / Nuxt UI / Tauri 外链、「Made by」页脚）。导航项与面包屑由 `useNavigation` 按路由表自动生成，不手写菜单。
  5. **只保留下载真正需要的资源**：`app.config.ts` 的 `downloads` 回归（4 平台 13 个安装包）并新增 `releaseUrl`（「全部安装包」指向 Release 页）；`useOS()` 迁到 `layers/system/app/composables/useOS.ts` —— 它唯一的消费方就是这一页。`app.author` / `nuxtSite` / `nuxtUiSite` / `tauriSite` 不回归（`app.repo` 保留，`/webview` 探针与页脚按钮在用）。
  6. **删除仍是孤儿的部分**：`app/pages/index.vue`、`app/layouts/home.vue`、`app/layouts/blank.vue`、`app/components/Site/Navbar.vue`、`app/components/Site/LanguageSwitch.vue`；`Site/ColorModeButton.vue` 保留 —— `AppHeader` 仍在使用。i18n `pages.index.*` 改为 `pages.system-download.*`（cn/en 各 11 键）。
  7. **自查跟着改**：`check:ui` 原有 4 条落地页断言换成 2 条根路径断言（`/` 返回 3xx 且 `location: /auth/login`；浏览器打开 `/` 落在登录页并渲染表单），另加 1 条守卫断言（未登录直进 `/system/download` 回登录页并带回跳）与 3 条下载中心断言（侧栏有入口 / 检测到 Linux 时主按钮指向 `.deb` / 其他平台 3 个），计数由自建 68 / 外部 51 变为 70 / 53。
- **影响**：
  - 代码：删除 5 个文件；新增 `layers/system/app/pages/system/download.vue` 与 `layers/system/app/composables/useOS.ts`；`nuxt.config.ts`（`routeRules`）、`app/middleware/auth.global.ts`（根路径分支 + 白名单收窄）、`app/app.config.ts`（`downloads`）、`i18n/locales/{cn,en}.json`、`scripts/check-ui.mjs`。
  - 文档：`NMCPS-ARCH-003` §7.4 / §7.6 / §7.7 与变更记录；`NMCPS-DESIGN-005` §二 功能范围登记 `download` 子页面；`NMCPS-GOV-003` 登记本 ADR。本 ADR 取代 `NMCPS-ADR-0008`（下载落地页恢复），后者按记录层规则置 `superseded`。
  - 行为变化：`/` 不再展示下载按钮；下载入口在「系统管理 → 下载中心」，登录后可达，链接仍直指 GitHub Release（控制台只做索引，不代理二进制）。
- **备选方案（未采用）**：
  - **保留 `/` 落地页、只把按钮改成「进入系统」**：仍然要为它维护 `home` 布局与 `pages.index.*`，等于继续背着模板残骸。
  - **在 `index.vue` 里 `navigateTo('/auth/login')`**：客户端跳转，首屏要先下载并执行 JS，弱网下会看到空白帧；`routeRules` 是真正的 HTTP 跳转。
  - **下载页放顶层 `/download`**：不登录即可下载，但要多开一条公开路由、再给它单独的布局与导航位；这与「下载入口属于系统配置」的归属不符，也会让守卫白名单重新长出一个例外。
  - **只在守卫里删掉 `/` 白名单、不加 `routeRules`**：能跑，但入口会先加载一次 SPA 再由 `[...all]` 与守卫各自判断，404 页与登录页都有机会闪一下；HTTP 层 302 更确定。
