# ADR-0025：Webshell 的渲染边界（暂不引入终端模拟器）

> **层级**：Tier 5 记录层 —— 正文发布后只追加；后续修正用 `##` 追加节，不回改已发布结论。
> **与 ADR-0022 的关系**：`NMCPS-ADR-0022`（`layers/content/collections/cn/records/adr/adr-0022.md`）W8 只回答了「Webshell 要能逐键交互」，没有回答「渲染到什么程度算够」。上线后这个缺口会以缺陷单的形式反复出现（「`top` 显示乱码」「看不到颜色」），所以先把边界写成裁决。

## 1. 背景（现状与实测）

W8 之后 Webshell 的两侧能力并不对称：

- **输入侧已经是真终端**。面板把 `keydown` 翻成 PTY 字节（回车 `\r`、退格 `0x7f`、Tab `\t`、方向键 / Home / End / Delete 走 CSI、`Ctrl+字母` 发 `0x01–0x1A`），连续字符攒 8ms 一帧，IME 走隐藏 textarea 的 `input`；回显交给 PTY，面板不做本地回显。
- **渲染侧仍是「清洗后的文本观测窗」**：`labTerminalTextOf()` 剥掉 ANSI / OSC 序列、按 `\r` 取最后一段、按退格删字符，然后整段塞进 `<pre>`。这样做的目的是让「真 PTY 一定带颜色码」这件事不变成 `^[[1;32m` 满屏。

2026-11-17 用真实 `bash --norc -i` + PTY 复测输入侧（把组件实际发送的字节序列原样喂给 shell），6/6 成立：退格按字符删、`\r` 真的执行、`0x03` 打断 `sleep`、`\t` 触发 `ech → echo ` 补全、`\x1b[D` 移动光标后字符插在中间、`0x0c` 清屏后提示符仍在。**所以缺口只在渲染，不在按键。** 现状下能用的：行式命令、`ls` / `cat` / `tail -f`、补全、`Ctrl-C` / `Ctrl-D` / `Ctrl-L`、上下键召回历史（末尾几行可用）。现状下不能用的：`vi` / `top` / `htop` 这类全屏 TUI（光标定位与清行不还原，界面与转写互相覆盖）、颜色与粗体、宽字符（中文）列对齐、窗口尺寸变化（没有 `SIGWINCH`，`COLUMNS` 恒为默认值）。

## 2. 裁决

| 编号 | 裁决 | 说明 |
| :--- | :--- | :--- |
| **D1** | **暂不引入终端模拟器依赖**（xterm.js / hterm / 同类） | 项目规则是不引入未被使用的依赖；它还会给共享的 `layers/scenario` 带上渲染层、字体度量与 worker / WebGL 路径，并影响 CSP 与首屏预算。收益（全屏 TUI）尚未被需求方确认，代价立刻发生。 |
| **D2** | 渲染只有一条路径：`labTerminalTextOf()` + `<pre>` | 保持纯函数，`check:lab-ws` / `check:ui` 可直接断言「ESC 一个不剩」。不允许在页面里再写第二套「半解析」分支。 |
| **D3** | 边界写进文档，不靠用户撞墙才知道 | 上表的两列（能用 / 不能用）就是产品承诺；面板的提示文案只说「点一下终端就能输入」，不承诺全屏程序。 |
| **D4** | 不在 textarea 之上自己实现 CSI 光标定位 | 那等于重写一个终端模拟器，风险与工作量都高于引入成熟实现；半成品会比现状更难解释。要么文本观测窗，要么真模拟器，不做中间态。 |
| **D5** | 重估触发条件（任一满足则新开 ADR，不追加节改本裁决） | ① 需求方明确要求 `vi` / `top` 类交互；② 与「颜色 / 光标 / 宽字符」相关的缺陷单累计 ≥ 3；③ 上游出现必须以真终端语义完成的操作（交互式配置向导、`dialog` / `whiptail`）。届时评估范围：`xterm.js` + `@xterm/addon-fit`（尺寸上报）、CSP 放行、bundle 预算、`check:ui` 的断言路径，以及 `labTerminalTextOf()` 的保留范围（做离线回放仍需要它）。 |
| **D6** | 服务端不改语义 | PTY 字节经 `labWsRelay` 原样转发，渲染是前端的事；不在服务端做 HTML / Markdown 渲染（会破坏「原样」也扩大注入面），不裁剪字节流（裁剪后无法还原）。 |

## 3. 后果

- 短期：Webshell 对「配置型操作」够用（改配置、看日志、起停服务、抓 `tail -f`），对「交互式全屏程序」不够用，且这一点是公开事实而不是缺陷。
- 假上游（`scripts/lib/bff-harness.mjs`）已经按真 PTY 的形状回帧（逐字节回显、换行才回 `echo:<line>`、`0x03` 回 `^C`），断言的是链路行为而不是渲染效果；真机输入侧由 `pnpm check:lab-terminal`（真 `bash` + PTY，需 POSIX）守住。
- 不引入依赖意味着没有版本 / 许可证 / 打包面新增，也没有 `pnpm check:platform`、capabilities 之类的连带改动。

## 4. 验收

- `pnpm check:lab-terminal` 6/6：真 `bash --norc -i` + PTY，复跑组件实际发送的字节序列（退格 / 回车 / `0x03` / `\t` / CSI 光标 / `0x0c`）。非 POSIX 平台跳过并说明原因，不伪装成通过。
- `pnpm check:ui` 11.8 的 12 条不变（它断言的是「面板发出的字节」与「上游回来的文本」，与渲染实现无关）。
- `pnpm check:lab-bff` ⑬ 不变（BFF 只转发字节）。
- 真机（需 root + Mininet）人工确认：`POST /start` → 开 h1 会话 → `ls` / `tail -f` 可用、`vi` 明确不可用（这是裁决内的事实，不是待修缺陷）。
