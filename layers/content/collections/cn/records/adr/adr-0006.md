# ADR-0006：桌面端自动更新入口与启动静默检查

> **层级**：Tier 5 记录层 —— 正文不可修改（append-only）；变更须新开 ADR 并登记 `supersededBy`。

- **背景**：
  1. `useUpdater()`（`app/composables/useUpdater.ts`）此前只被 `SiteNavbar.vue` 消费，而它所属的 `home` / `blank` 布局在 2.0.0 已无任何页面使用（`/` 直接重定向到 `/dashboard/overview`，走 `default` 布局），桌面端因此**没有任何可见的「检查更新」入口**。
  2. 自动更新的实际链路（`latest.json` 平台映射 → GitHub release asset → 签名校验）已验证通过：v1.7.1 安装包只要构建于 `main@5b921b0`（含 `plugins.updater`）即可升级到 2.0.0。缺少入口意味着已装 2.0.0 的用户无法再自行触发升级。
- **决策**：
  1. 在 `AppHeader.vue` 右侧控制区新增检查更新按钮（`carbon:renew`），以 `isTauri()` 显隐 —— 浏览器预览不显示无效入口；点击走既有 `useUpdater().checkForUpdates()`（发现新版本即下载安装）。
  2. 在 `app/layouts/default.vue` 增加启动静默检查：`onMounted` 调用 `useUpdater().silentCheckForUpdates()`，仅当存在新版本时弹一条常驻提示（`duration: 0`），由用户点击「立即更新」触发 `downloadAndInstall()`；无新版本或检查失败均静默。
  3. `useUpdater` 的三个入口文案统一走 i18n（`updater.*`，cn / en 同步），消除此前硬编码中文在英文界面下的漂移。
- **影响**：
  - 下一版桌面安装包（≥ 2.0.1）同时具备「手动检查更新」与「启动提示新版本」两条路径，2.0.0 → 2.0.1 的更新链路恢复可触发。
  - i18n 新增 `updater.desktopOnly` / `found` / `downloading` / `upToDate` / `failed` / `available.*`。
  - 已发布的 2.0.0 安装包仍无入口，需用户手动下载 2.0.1 安装包一次；此 ADR 不改变已发布产物。
- **遗留**：
  - `nmcps-v1.7.1` tag 指向 `2c71100`（不含 `plugins.updater`），而实际发布资产由 `main@5b921b0` 构建；从 tag 重建会得到不可更新的应用，需后续单独核对 tag 与构建提交。
  - 2.0.0 的 macOS 产物未签名，升级后需 `xattr -c /Applications/nmcps.app` 解除隔离。
