# ADR-0027：引擎面定位与不复刻清单

> **层级**：Tier 5 记录层 —— 正文发布后只追加；后续修正用 `##` 追加节，不回改已发布结论。
> **与既有基准的关系**：`NMCPS-DESIGN-008`（`layers/content/collections/cn/architecture/2.domain/simulation.md`）管会话 / 引擎 / 统一投影 / 阶段边界，`NMCPS-ARCH-007`（`layers/content/collections/cn/architecture/1.architecture/lab-deployment-architecture.md`）管监听面 / 特权 / 凭据 / 重启语义；两者都假定「引擎面就是本仓这一套」，但没有裁决**哪些能力进引擎面、哪些永远不进、旧通道怎么退役**。本 ADR 补这一段，把 `docs/ai/simulation-parity.md`（工程计划，非受治理文档）里的定档固化成可引用的裁决。

## 1. 背景（为什么必须写下来）

- **参考侧的部署形态是既成事实**：`_reference/netsim` 的后端（`app/` 36,961 行、131 个端点）在 90 上以 **root `uvicorn :8001`** 运行（`_reference/netsim/BASELINE.md`）。它与本仓 `services/mininet-api`（3,138 行）是两套代码、两套资源模型（会话制 vs 全局单例、统一 node vs 五张分表，见 parity §一末表）。
- **「废弃 `:8001`」目前只写在计划里，代码里没有**：`server/api/sim/[...slug].ts` 经 `shared/constants/simulatorRoutes.ts` 的 `SIMULATOR_ROUTES`（**23 条，其中 18 条写**）直通 8001，`GET /api/sim/channel` 回 `writeEnabled`，写面由 `NUXT_SIMULATOR_ALLOW_WRITE`（默认 `false`）单独放行；生产拓扑监控页（`layers/topology/app/pages/topology/monitor.vue` + `useTopologyMonitor.ts`）仍从它读 `runtime-inventory` / `stats` / `lldp/neighbors`，并下发节点 / 链路动作。
- **不加裁决的后果是可预期的**：只要通道还在、白名单还能加条目，「参考侧有、所以本仓也该有」就会在每个阶段重新开一次讨论；而一个被租户页面触发的 `allowWrite: true` 就等于把 8001 的 18 条写端点借给浏览器面。

## 2. 裁决（D1–D7）

| 编号 | 裁决 | 说明 |
| :--- | :--- | :--- |
| **D1** | **唯一引擎面是本仓 `services/mininet-api`；参考侧退役为只读参考** | `:8001` 不再新部署、不再作为事实源与契约来源；`_reference/netsim` 只用于取行为与踩坑记录（且受 D7 约束）。对外面只有一个：BFF 前缀 `/api/mininet/**`、WS `/mininet-ws/*`（`NMCPS-ADR-0022` D11），不保留 `/api/sim/**` 作为长期第二通道（退役路径见 §4）。 |
| **D2** | **统一节点模型：引擎面只有一种节点 `NodeSpec{type, ...}`** | `type` 取值 `host` / `router` / `switch` / `controller` / `nat` / `ap` / `station`（`engines/base.py` 的 `NODE_TYPES`，该文件已按本条引用）。五张分表（`/hosts` `/routers` `/switches` `/controllers` `/nats`）属于**兼容只读视图**，不进引擎；统一投影只在 `engines/wired.py` 的 `unified_nodes()` 一处，`GET /api/mininet/nodes` 与会话侧 `/sessions/{id}/nodes` 同形。分表与统一投影不是两份真源：分表由同一张网投影出来，不允许出现「分表有、统一视图没有」的节点。 |
| **D3** | **会话是资源根；不引入隐式会话双路径** | `/api/simulation/sessions/**`（BFF 侧 `/api/mininet/sessions/**`）是 2.0 的资源根；1.x `/api/mininet/**` 等价「默认会话」（`NMCPS-DESIGN-008` M1.1）。parity §4.1 的 S-B（保留单例 + 只有一个 id 的隐式会话、两套路径并存）**被否决**：两套路径并存会让 `contracts:gen` 出的 OpenAPI 分裂，也让权限与台账归属出现两个入口。 |
| **D4** | **引擎注册表不回落；`dryrun` 保留** | `get_engine()` 名字没登记就抛 `EngineNotFound`（路由层 404），绝不回落到「随便挑一个能用的」—— 回落会把「请求了无线却拿到有线」变成静默的错误拓扑。`dryrun` 是无 root CI 上唯一能验证 API 语义的引擎（`check:engines` / `check:simulation` 都靠它），不得以「生产不用」为由删除；`ap` / `station` 在 M3 之前由 `wired` 建节点回 501，不用有线顶上。 |
| **D5** | **能力位不随参考侧扩张** | 参考侧「内网服务、无鉴权」的形态**不继承**。唯一权限面是 6 个 `lab:*`（`read` / `create` / `operate` / `delete` / `terminal` / `sniffer`，`layers/scenario/shared/constants/mininetRoutes.ts`）；`terminal` / `sniffer` 不由读写推导（`NMCPS-ADR-0021` D3）。SNMP 面若要开放写（开通 / 轮换 / 吊销），新增**独立** `lab:snmp`，不得由 `lab:operate` 推导 —— 「参考侧有 131 个端点」不是扩能力位的理由。 |
| **D6** | **一宿主一实例；租户→实例注册表 fail closed** | `app.net` 与 `mac80211_hwsim` radio 都是全局资源，一宿主只跑一个仿真实例；多租户靠「一租户一实例」映射，唯一真源是 `NUXT_MININET_INSTANCES`，没配就回 `503 tenant_runtime_unavailable`，**不提供**「没配就用默认实例」的回落（`NMCPS-ARCH-007` §5）。 |
| **D7** | **移植门禁：不复制代码与 MIB 文本** | 参考侧代码与 21 个 MIB 的再分发许可未确认前，不复制任何代码或 MIB 文本；本仓按**行为**自写（因此 M1 不被许可阻塞，只有「照抄 MIB 定义」要等许可）。`.bak-*` 热修残留（`engine.py` 5 个、`runtime_config.py` 2 个、`snmp_agent.py` 2 个…）只作 bug 线索，**不作为需求**。 |

## 3. 不复刻清单（R1–R8）

R1–R7 与 `shared/constants/simulatorRoutes.ts` 的 `SIMULATOR_EXCLUDED_PREFIXES`（1.0 通道的现状守卫，7 条）按顺序一一对应；R8 是通道级退役，不是端点。判据列同时写「为什么」与「2.0 落到哪儿」。

| 编号 | 参考侧 | 处置 | 判据 / 2.0 落点 |
| :--- | :--- | :--- | :--- |
| **R1** | `/api/network/nodes/{id}/execute`（POST） | **永久排除** | 2.0 只有**交互式 PTY**（`/mininet-ws/terminal` + `lab:terminal`，逐键上行、不做本地回显），没有「一次调用执行一条命令」的 REST 面。给节点装一条任意命令端点，等于把宿主 root 以 HTTP 形式借给任何拿到能力位的人；终端面的审计与审批口径也不覆盖「脚本式批跑」。 |
| **R2** | `/api/browser/*` | **永久排除** | 无头浏览器抓取是运维脚本能力，不是产品能力；一旦进 BFF，就是一条**可被租户触发**的出站抓取（目标地址由请求决定），与 `NMCPS-ARCH-007` 的出站面约束直接冲突。 |
| **R3** | `/api/integrity/*`（含 `watch/*`） | **永久排除** | 拓扑 / 配置完整性巡检属运维能力，2.0 首个版本不需要（parity §2.5 定档 P2）。要巡检就走外部只读客户端，不在引擎进程里长第二套状态。 |
| **R4** | `/api/devices/*`（含 `devices/clear`） | **不入引擎** | 设备库是管理面数据（资产域），引擎只认 `NodeSpec`。把设备库塞进引擎会让「建网」与「资产维护」互相绑死：删一台设备就得考虑正在跑的网。 |
| **R5** | `/api/test/*`（`mtr` / `traceroute` / `netcat` / `lldp` 探测） | **不复刻独立通道** | `ping` / `iperf` 已由 `/api/mininet/pingall`、`/api/mininet/iperf` 承载（后者是自带超时的子进程，见 `NMCPS-ADR-0026` §5）；其余探测工具无消费方，且 `netcat` 类工具与 R1 是同一类风险。 |
| **R6** | `/api/snmp/onboard`（v2c / v3 开通、`rotate` / `revoke`、`export`） | **换形态重建（M2）** | 8001 的「开凭证」形态**不复刻为转发通道**；2.0 在进程内 agent（与台账同源）上重建，并要求**独立能力位 `lab:snmp`**（D5）。在那之前该前缀继续被 `SIMULATOR_EXCLUDED_PREFIXES` 挡住。 |
| **R7** | `/api/nms/vmagent`（目标管理、`snmp-exporter-reset`） | **永久排除** | 外部监控栈（VictoriaMetrics agent / exporter）有自己的部署与凭据，不是本产品能力；BFF 代为下发目标等于让租户间接改宿主监控栈。 |
| **R8** | `/api/sim/**` 直通 8001 的网关 + 任何 `:8001` 兼容别名 | **退役并删除** | 与 `NMCPS-ADR-0022` D11 对 `/api/lab/**` 的处置同口径：**不留别名、不双写**。删除条件是 §4 的迁移动作全部落地；在迁移完成前它只是「正在退役」，不是「允许新增」的通道。 |

> P2 里剩下的 `network/scan-subnets`、`DELETE /metrics/{sim_id}`、`protocol/compare`、`gateway/*` 按 parity §二 的定档处理，不占 R 编号 —— 它们没进 `SIMULATOR_EXCLUDED_PREFIXES`，是因为 1.0 页面从未调用（白名单只登页面真正调用的条目），不是因为安全上放行。

## 4. R8 的影响面与迁移顺序

链路现状（全部在仓库内，不是推测）：

| 文件 | 作用 | 迁移后 |
| :--- | :--- | :--- |
| `server/api/sim/[...slug].ts` | 逐端点白名单转发（未命中 404 / 动词不符 405 / 未配 503 / 写被关 405） | 删除 |
| `server/api/sim/channel.get.ts` | 回 `configured` / `writeEnabled` / `timeoutMs`，不触达上游 | 由 `GET /api/mininet/channel` 取代（`capabilities` + `endpointCount`） |
| `server/api/sim/index.ts` | 无路径段回 400 `bff_path_missing` | 删除 |
| `server/utils/bff/simConfig.ts`、`server/utils/bff/simulator.ts` | `runtimeConfig.simulator` 读取与出站 | 删除（`NUXT_SIMULATOR_*` 一并退役） |
| `shared/constants/simulatorRoutes.ts`、`shared/types/simulator.ts` | 白名单本体与上游形状 | 删除 |
| `layers/topology/app/composables/useTopologyMonitor.ts`、`layers/topology/app/pages/topology/monitor.vue` | 页面消费点（读 + 节点 / 链路动作） | 改走 `/api/mininet/**` |
| `app/utils/graph/simulatorOverlay.ts`、`app/utils/graph/topologyNeighbors.ts` | 运行态对齐算法（把 8001 节点按「管理 IP → 名称」贴到 8888 拓扑上） | 随页面改写；其中的 8001 形状注释是对齐依据的事实记录，不是通道依赖 |
| `scripts/fixtures/simulator-openapi.json`、`check-bff` ⑨-6 | 「`SIMULATOR_ROUTES` ⊆ openapi paths」守卫 | 随白名单一并退役 |

顺序（必须按序，不许「先删后迁」）：

1. **读**：`runtime-inventory` 换成 `GET /api/mininet/nodes` + `/links`（M1.1 已就绪）；`stats` 换成按节点的 `/stats/{id}` 聚合；`lldp/neighbors` **不补等价端点**，改用 `/links` 推导邻接（见 §7 追补，2026-11-25 裁决）。
2. **写**：节点 / 链路动作换成 `/api/mininet/**` 对应端点（能力位 `lab:operate`），不保留「8001 更顺手」的旁路。链路 `up` / `down` / `toggle` 已由 `PATCH /api/mininet/links/{src_id}/{dst_id}/state` 提供（M1.2，2026-11-25）；节点级动作页面已无入口，切读路径时不补。
3. **能力位**：页面的 `writeEnabled` 判据从 `/api/sim/channel` 换成 `GET /api/mininet/channel` 的 `capabilities`（`NMCPS-ADR-0022` D3）。
4. **删**：上表「删除」行的文件与配置一次删净，同批更新 `docs/ai/repo-map.md` 的数据流图与自检计数。**先文档后落码**：`/api/sim/**` 是 `NMCPS-ARCH-002` §6（Tier 1，normative）登记的第二出站通道，`SIMULATOR_ROUTES` 的每条又都追到 `NMCPS-DESIGN-001` / `007` 的数据源表 —— 删除前必须先修订这两处（本 ADR 是 Tier 5 记录层，只裁「要退役」与顺序，不覆盖 normative 基准），否则代码删了而基准仍写着「通道存在」。

迁移完成前的纪律：**不新增** `SIMULATOR_ROUTES` 条目、不打开 `NUXT_SIMULATOR_ALLOW_WRITE`（默认 `false` 就是这条纪律的机器形态）、页面新代码不得 import `/api/sim` 或 `shared/types/simulator.ts`。

## 5. 后果与不做什么

- **不做**：① 不保留 `:8001` 兼容入口（含反代与 `/api/sim` 别名）；② 不以「照抄参考侧端点」的方式迁移（结构差异见 parity §一末表：会话 / 统一 node / 引擎抽象 / 能力位 / 单实例）；③ 不因参考侧端点数量扩张能力位或补等价动作（D5）；④ 不在引擎层复制五张分表（D2）。
- **代价**：拓扑监控页在迁移完成前仍依赖 8001，`check-bff` ⑨-6 仍钉「白名单 ⊆ 模拟上游 openapi」；这两条一起消失，R8 才算完成。在那之前，`/api/sim/**` 的写面只能靠 `allowWrite` 关闭来兜，不能靠「没人会用」。
- **分工**：DESIGN-008 管「会话 / 引擎 / 投影 / 阶段」；ARCH-007 管「监听面 / 特权 / 凭据 / 重启」；本 ADR 管「哪些能力进引擎面、哪些永远不进、旧通道怎么退役」。三份都不重复对方的细节。

## 7. 追补（2026-11-25，v0.1.2）：LLDP 面不建，邻接由 `/links` 推导

§4 第 1 条原写作「LLDP 面在 M1 补齐 `/lldp/*` 之后切换」，等于把「补一个 LLDP 端点族」当成 R8 的最后一个前置。本节改变这条：**不建 `/api/lldp/*`，也不引入 `lldpd`**；页面邻接改由 `GET /api/mininet/links` 推导。改动只涉及前置与落点，D1–D7 与 R1–R7 不动；R5 的「不复刻独立通道」据此**扩展**到 `/api/lldp/**`。

### 7.1 三条检查（都在本仓可复核）

1. **参考侧本来就不是 LLDP 实测**：`_reference/netsim/backend/app/engines/mininet_wifi/lldp_agent.py` 的 `native` 模式注释是「基于真实拓扑构建 LLDP-MIB 数据（**无需额外守护进程**）」，实现是把台账里的链路逐条拼成 `lldpRem*` 字段（`_build_neighbor_entry()`）。也就是说 `:8001` 的 `neighbors[]` 一直是「拓扑邻接 + 一层 LLDP 字段外壳」，没有收到过 LLDP 帧。`shared/types/simulator.ts` 里记的「实测原样」记的是**这个合成结果**的形状，不是协议事实。
2. **那套合成有已知缺陷**：`_reference/netsim/docs/已知问题-AP侧LLDP假边.md` 记的是「AP 侧 LLDP 假边」（合成邻接与真实无线关联不一致）；`docs/backlog/2026-09-21-lldp-ghost-404.md` 记的是「未知节点回 200 + 空数组」（本该 404）。两者都是合成路径的必然产物，不是实现疏漏。
3. **真 LLDP 在本仓要付的代价大于收益**：宿主未安装 `lldpd`（`which lldpd` 空），要真采就得给每个节点命名空间各起一个守护进程；而 Mininet 的交换机是 OVS、跑在根 netns，只做二层转发，LLDP 的保留组播（`01:80:C2:00:00:0E`）默认既不上送也不转发 —— 主机之间的 LLDP 到不了对端，交换机身份又无处可取（一个 OVS 进程服务所有端口，没有「某台交换机的 chassis id」）。它交付不出比台账更多的事实，只会多一个会撒谎的通道。

### 7.2 裁决

| 项 | 结论 |
| :--- | :--- |
| `/api/lldp/summary`、`/api/lldp/neighbors/{node_id}` | **不实现**。BFF 白名单（`mininetRoutes.ts`）不登记任何 `/lldp/*`；`check:lab-bff` ⓪ 的「22 查询 + 37 写 = 59」因此不变。 |
| `lldpd` / `lldpcli` | **不作为依赖引入**（系统依赖与每节点守护进程都不加）。 |
| 页面邻接（`topology/monitor.vue` 的「LLDP 邻居」卡） | 切读路径时改为 `GET /api/mininet/links` + 纯函数 **`topologyNeighborsOf()`**（`app/utils/graph/topologyNodeFacts.ts`，现役，已从画布链路推导邻居并带链路状态）；不新增端点、不新增后端状态。 |
| 字段落差 | `ttl` / `discovered_at` / `sys_name` / `chassis_id` / `mib_oids` **没有替代品**（只在真实 LLDP TLV 里存在），卡片不得编造，也不得把 `discovered_at` 换成本机时间；可展示的只有 `neighbor_id` / 名称 / 两端接口 / 链路状态（`up` / `down` / `unknown`，M1.2 已有的语义）。卡片标题与文案随之改名（「拓扑邻接」），不要继续叫 LLDP。 |

### 7.3 为什么不选另外两条路

- **自建合成 agent**：等于把 §7.1 第 2 条的缺陷原样移植，并与 M1.2 已经定下的口径冲突 —— 一条**没有测过**的读数只能回 `unknown`，合成邻接却会理直气壮地回 `up` + `ttl: 120`。既有「不替上游做归一、不编数据」的取向（`NMCPS-ADR-0026` D4、`shared/types/simulator.ts` 的注释）都不允许。
- **`apt lldpd` + 每节点守护**：见 §7.1 第 3 条，交付不出更多事实；且新增系统依赖与 per-node 进程生命周期（起停 / 删节点 / 重建）会拖进 M3 的无线面，收益仍是「台账已经知道的那几条边」。

### 8.2 失败语义

- 通道探测不触达上游；`configured: false` 与读失败分开：前者是 `disabled`，后者才是 `unreachable` 并挂降级条。
- 404 `lab_resource_not_found` 是「该租户还没有实验网络」（台账没有归属记录），归成 `empty`：与实验台页面的「暂无仿真网络」同口径，页面不挂降级条、不给写入口，只说明先去建网。`check:ui` 的实验台 / 监控两块都按实验台页面的形状种一条台账记录，否则这条 404 会让整份快照判成读失败。
- `nodes` / `links` / `start` 并行读、一份快照落地：部分失败按整体失败处理，不展示「节点在、链路没了」的残缺快照。
- 邻接卡只有 `idle` / `ok` 两态：没有可读对象（不在实验里 / 通道不可用 / 还没有实验网络）为 `idle`，读到台账才谈「0 条」。
