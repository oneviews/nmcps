# ADR-0012：新增 platform 层收纳 Tauri 平台能力演示页

> **层级**：Tier 5 记录层 —— 正文不可修改（append-only）；变更须新开 ADR 并登记 `supersededBy`。

- **背景**：根 `app/pages` 同时承载两类页面 —— 站点壳（`index.vue` 下载落地页、`[...all].vue` 404、`auth/login.vue` 登录页）与 6 个 Tauri 能力演示页（`commands` / `file` / `notifications` / `os` / `store` / `webview`）。后者的前提是桌面运行时（Shell、FS、Store、通知、WebviewWindow），浏览器下只显示 `common.unavailableInBrowser`；二者混放导致「根层只放壳」的边界消失，新增页面时归属难以判断。
- **决策**：
  - 新建图层 `layers/platform`（`package.json` + `nuxt.config.ts` + `app/pages/`），并在根 `nuxt.config.ts` 的 `extends` 末尾登记 `./layers/platform`（无路由冲突，顺序不影响行为）。
  - 6 个演示页 `git mv` 至 `layers/platform/app/pages/`，**文件名不变 → 路由 path 不变**（`/commands`、`/file`、`/notifications`、`/os`、`/store`、`/webview`）。
  - 由路由派生的一切保持零改动：`app/composables/pages.ts` 按 `meta.category`（`system` / `storage` / `interface`）聚合导航；i18n `pages.*` key；`webview.vue` 内部链接 `/os`。
  - 根 `app/pages` 只保留站点壳（`index.vue`、`[...all].vue`、`auth/login.vue`）；演示页照旧受全局登录守卫覆盖（`NMCPS-ARCH-003` §7.6）。
- **影响**：构建产物路由表不变；`eslint` / `vue-tsc` 自动覆盖新目录（`.nuxt` 配置由 `extends` 生成）；后续平台能力演示页一律落在本层。
- **备选方案（未采用）**：
  - **迁入 `layers/user`**：user 层语义是账号与偏好，平台能力演示不属于用户域，混入会让层职责再次发散。
  - **改为 `/platform/*` 子路径**：需要额外父级页面与嵌套出口，并会改动现有 URL、内部链接与导航高亮，收益仅是 URL 前缀分组，代价不成比例。
  - **继续留在根 `app/pages`**：根层持续混装壳与演示页，与本次要解决的问题相同。
