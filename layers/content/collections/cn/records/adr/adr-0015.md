# ADR-0015：platform 演示页降级为能力探针并移除 shell 执行权限

> **层级**：Tier 5 记录层 —— 正文不可修改（append-only）；变更须新开 ADR 并登记 `supersededBy`。

- **背景**：
  - **这批页面是模板残骸，不是产品功能**：6 个页面来自 ViTauri 模板（`package.json` 的 description / author / identifier `com.nicolaspadari.nmcps` 仍留着模板值），`NMCPS-ADR-0012` 把它们整体搬进 `layers/platform` 时只承诺「路由 path 不变」，没有定义去留。
  - **它们没有任何入口**：`useNavigation()` 只收 `meta.sort` 为数字且 `meta.hide` 非真的路由；这 6 页从未设过 `sort`（git 历史确认不是分层时丢的），因此侧栏、顶栏、`usePages()` 都看不到它们，只能手输 URL。`meta.category` 只喂 `Site/Navbar.vue`，而这些页走 `default` 布局，连那条路也不通。
  - **`commands.vue` 是安全负资产**：它靠 `desktop.json` 的 `shell:allow-execute` 把任意字符串交给系统 shell。Tauri 的 `ShellCommand` 校验器就是 `\S.*`，等于「WebView 里能跑任意命令」；仓库内没有任何业务代码需要它（真实 Tauri 调用只有 `getTauriVersion`、`useAuthTokens` 的 store、以及 updater）。
  - **其余 5 页没有降级路径**：`os` / `file` / `store` / `notifications` / `webview` 直接 `await useTauri*`，在浏览器里进页面就是一片静默失败或未捕获异常；同时它们演示的 `store` 用法（`autoSave: false` + 手写 `save()`）与生产实现 `useAuthTokens`（`autoSave: true`）不一致，照着抄会把令牌落盘写坏。
  - **跨平台落码没有基准**：仓库没有 `arch.platform` 文档，移动端语义（`BaseDirectory.Document` 在 Android/iOS 是应用私有目录、多窗口需 Activity Embedding / UIScene、通知需运行时授权链）只散落在 Tauri 官方文档里，下次动手仍要重查。
- **决策**：
  1. **保留 5 页，定位为「能力探针」**：`/os`、`/file`、`/store`、`/notifications`、`/webview` 保留，职责只有一条 —— 在真机上验证对应插件是否真的可用。不接业务数据，不做产品化。
  2. **删除 `commands.vue` 与 `shell:allow-execute`**：页面删除，`src-tauri/capabilities/desktop.json` 中的 `shell:allow-execute` 移除。`tauri-plugin-shell` 的注册与依赖暂时保留（无 `allow-execute` 即无法执行命令），待确认无其他用途后再单独清理，避免一次性改动 Cargo / lockfile 扩大回归面。
  3. **抽出 6 个组合式函数**：`usePlatformInfo()` / `usePlatformStore()` / `usePlatformFile()` / `usePlatformNotify()` / `usePlatformWindow()` / `useExternalLink()`，统一返回 `{ ok, reason }` 结构并在内部做 `isTauri()` 守卫。探针 store 用独立文件 `platform-probe.bin`，不复用 `auth.bin`。
  4. **导航用虚拟分组，URL 不变**：新增 `meta.group = "platform"` + `meta.tauriOnly = true`，`useNavigation()` 把带 `group` 的路由从顶层摘出，聚合成一个无 `to` 的父项（标题 `pages.platform.title`）。`/os` 等 path 保持原样 —— 这是对 `NMCPS-ADR-0012` 第 3 条「导航聚合逻辑不变」的**明确修订**，同时保留它「path 不变」的承诺，避免书签与文档失效。
  5. **Tauri 环境才显示入口**：`meta.tauriOnly` 的路由在 `isTauri()` 为假时不进导航；浏览器直访仍可打开，但页面只显示降级提示。这样 `check:ui` 能断言「浏览器不暴露入口」，桌面用户又能找到探针。
  6. **文档先行**：新增 `NMCPS-ARCH-005`（`arch.platform`，Tier 1，能力矩阵 / 权限分层 / 组合式约定 / 探针口径），并新增 `pnpm check:platform` 静态自查，把「不许再出现 `shell:allow-execute`」变成门禁。
- **影响**：
  - 代码：`layers/platform/app/pages/commands.vue`（删除）、`os.vue` / `file.vue` / `store.vue` / `notifications.vue` / `webview.vue`（改用组合式 + 降级提示）、新增 `layers/platform/app/composables/usePlatform*.ts`、`app/composables/useNavigation.ts`（虚拟分组 + `tauriOnly` 过滤 + 扩展 `RouteMeta` 的 `group` / `tauriOnly`）、`src-tauri/capabilities/desktop.json`（移除 `shell:allow-execute`）。
  - 文案：`i18n/locales/{cn,en}.json` 新增 `pages.platform.title` 与降级提示键；`pages.commands.*` 删除（cn/en 同步）。
  - 自查：新增 `scripts/check-platform.mjs`（`pnpm check:platform`）；`check:ui` 的守卫用例 `/commands` 改判 `/os`，并新增两条浏览器断言（侧栏无「平台能力」分组、`/os` 显示不可检测），另加两条 Tauri 宿主模拟断言（注入 `globalThis.isTauri` + 最小 IPC 桩后侧栏出现分组、分组含 5 个入口），计数由自建 64 / 外部 49 变为自建 68 / 外部 51（`NMCPS-ARCH-003` §7.7 与变更记录同步）。
  - 移动端仍未实测：矩阵中 Android / iOS 两列来自 Tauri v2 官方文档，需真机跑一遍探针后回填 `NMCPS-ARCH-005` §7。
- **备选方案（未采用）**：
  - **整体删除 6 页**：最省事，但仓库里就再没有可执行的「这个插件在目标机上到底行不行」的验证入口；下次接移动端要凭记忆重建。
  - **保留 `commands.vue` 只加提示**：`shell:allow-execute` 一旦在包里，任何 XSS 都能升级为本地命令执行；演示价值不抵这个风险。
  - **把页面移到 `platform/` 子目录做真实父子路由**：能自然成组，但 `/os` → `/platform/os` 会打断 `NMCPS-ADR-0012` 的 path 承诺，且 6 页的 i18n 键要整体改名；虚拟分组以 `useNavigation()` 十几行逻辑换同样的效果。
