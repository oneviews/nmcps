# ADR-0029：会话通道的更新类语义（M1.2 冻结）

> **层级**：Tier 5 记录层 —— 正文发布后只追加；后续修正用 `##` 追加节，不回改已发布结论。
> **与既有基准的关系**：`NMCPS-DESIGN-008`（`layers/content/collections/cn/architecture/2.domain/simulation.md`）§四把「统一模型的更新语义未冻结」写成事实，因此 `Engine` 协议**刻意没有** `update_node`；§八把「写与更新类仍走 1.x」列为现状。本 ADR 补的正是那一段：更新类怎样进会话通道、生效语义怎么分档、哪些东西刻意不做。

## 1. 背景（为什么先冻结，而不是边写边定）

- **会话通道缺的只剩更新一类**。白名单里 12 条会话端点覆盖读 / 建 / 删 / 起停（`mininetRoutes.ts` 末尾那一段），更新类仍是 1.x 的九组分表端点：`POST /node_position`、`PATCH /hosts/{id}`、`PATCH /routers/{id}`、`PUT /controllers/{id}`、`PUT /switches/{id}/openflow`、`PUT /links`、`PATCH /links/{src}/{dst}/state`、`POST /flows`（+ 两条 `DELETE /flows`）、`POST /associate_switch`（+ `DELETE /remove_association/{src}/{dst}`）。
- **同一件事在「网络没起」时表现四种**，这是本 ADR 要修掉的真实缺陷（口径都读自 `api.py`）：
  - `PATCH /hosts/{id}`：`app.net.nameToNode` 在停网时是空的，先撞 `404 Node … not found` —— 台账里明明还有这个主机；
  - `PATCH /routers/{id}`：200 成功，`_apply_router_configuration()` 见 `is_started` 为假直接 return，改动**延迟**到下次起网；
  - `PUT /links`：200 成功，`link.intf1.config()` 的异常被 `debug()` 吞掉，台账已改而接口没动；
  - `POST /flows`、`PATCH /links/{}/state`：`400 network must be started …`。

  页面拿不到可判读的「这次改到底生效没有」，自检也无法用统一断言覆盖这一类。
- **按分表进会话通道等于在 2.0 里复制五张表**。分表模型（`Host` / `Router` / `Switch` / `Controller` / `Nat`）是 1.x 的遗留视图，统一节点投影（`engines/wired.py` 的 `unified_nodes()`，`NMCPS-DESIGN-008` §四）才是会话侧的唯一形状；更新若按分表字段名开口，切完通道马上就多出「统一读、分表写」的第二套字段词汇。
- **切换顺序决定冻结时机**。页面一次只切一处，切换的那一刻写路径必须已经在会话通道里且语义稳定；先实现再补文档，等于让页面在未定语义上先落一版行为。

## 2. 裁决（D1–D7）

| 编号 | 裁决 | 说明 |
| :--- | :--- | :--- |
| **D1** | **更新只经统一节点 / 链路路径** | M1.2 新增两条会话端点：`PATCH /api/simulation/sessions/{session_id}/nodes/{node_id}` 与 `PATCH /api/simulation/sessions/{session_id}/links/{link_id}`。请求体是**统一模型的部分更新**：节点 `{ x?, y?, attributes? }`，链路 `{ options? }`；分表字段名（`of_version` / `interface_ips` / `switch_type` …）只允许出现在 `attributes` 内，且按类型白名单校验。1.x 的 `POST /node_position` 语义并入节点 PATCH（位置就是 `x` / `y`），不再单列端点。 |
| **D2** | **生效语义只有三档：`layout` / `deferred` / `live`** | `layout`（`x` / `y`）：只写台账，任何状态可写，永不重启任何东西。`deferred`（主机 `ip` / 默认路由、路由器 `interface_ips` / `routes` / `proxy_arp` / `ip_forward`、链路 `options` 的 `bw` / `delay` / `jitter` / `loss`、控制器属性）：**先写台账**，会话 `running` 时立即应用到运行中的节点 / 接口，`created` / `stopped` 时留给下一次 `start`。`live`（交换机 OpenFlow 版本）：要求 `running`，否则回 `409 engine_conflict`（`session is not running`）—— 它改的是 OVS 桥参数，停网时兑现不了。响应必须带 `applied` 布尔，让页面能区分「已生效」与「已排队」。 |
| **D3** | **不可变字段显式拒绝** | `id` / `type` / `mac` / `name` 在 M1.2 不可改（改名、换类型、改 MAC 都要重建节点，属另一种动作）；出现即 `400 engine_invalid_request`，不做静默忽略 —— 静默忽略会让页面以为改成功。`attributes` 里未登记的键同样回 400，而不是原样塞进台账。 |
| **D4** | **响应是投影，不是分表模型** | 更新成功回 `{ "node": <统一节点投影>, "applied": <bool> }` / `{ "link": <统一链路投影>, "applied": <bool> }`，投影复用 `NodeSpec.as_dict()` / `LinkSpec.as_dict()` 与 `unified_nodes()` 的同一形状；不回 `{"status": "ok"}`、不回分表 `model_dump()`、不回请求体回声。错误归一沿用引擎词汇：`engine_invalid_request`（400）/ `engine_resource_not_found`（404）/ `engine_conflict`（409）/ `engine_unsupported`（501）。 |
| **D5** | **`Engine` 协议新增 `update_node` / `update_link`** | 两个同步方法，签名 `update_node(session_id, node_id, patch) -> (projection, applied)` 与 `update_link(session_id, link_id, patch) -> (projection, applied)`；`wired` 的实现**只做映射与错误归一**，实际应用仍调 `api.py` 既有的 `setIP` / `setDefaultRoute` / `_apply_router_configuration()` / `intf.config()`，不重写建网函数（与 `NMCPS-DESIGN-008` §三同口径）。`wireless` 在 M3 之前一律 `501 engine_unsupported`，不回落。 |
| **D6** | **权限位不变，不新增能力位** | 两条 PATCH 都只要 `lab:operate`（与 1.x 的更新类条目一致）；更新不是破坏性动作，不给它加 `lab:delete`，也不因为「能改 IP」就要求 `lab:create`。能力位表（`LAB_PERMISSIONS`）因此不变。 |
| **D7** | **流表、统计与链路通断留在 1.x（M1.3 再议）** | `POST /flows` / `DELETE /flows*` 是 `ovs-ofctl` 命令、`GET /stats/{node_id}` 与 `GET /links/stats/{src}/{dst}` 是运行态读数、`PATCH /links/{}/state` 改的是「此刻通不通」而不是模型属性 —— 它们都不以统一模型为对象，硬塞进 `PATCH nodes` / `PATCH links` 会让「属性」与「命令」混在一条路径上。M1.2 只搬页面真正会改的两类（节点、链路属性），流表与统计继续走 1.x；把它们也搬走要另开追加节，且以「页面确实需要」为前提。 |

## 3. 逐字段语义表

节点（`attributes` 按类型白名单，未登记键回 400）：

| 类型 | 字段 | 档 | 说明 |
| :--- | :--- | :--- | :--- |
| 全部 | `x` / `y` | `layout` | 顶层字段；与 1.x `POST /node_position` 等价，只动台账与画布坐标 |
| `host` | `ip` | `deferred` | 带前缀长度（`10.0.0.5/24`）；running 时调 `node.setIP()` 立即生效 |
| `host` | `defaultRoute` | `deferred` | 与 1.x `default_route` 同义；`via <ip>` 或设备名，空串表示删除默认路由 |
| `router` | `ip` | `deferred` | 主接口地址 |
| `router` | `interfaceIps` | `deferred` | `{ <intf>: <cidr> }`；接口必须挂在节点上，否则 400 |
| `router` | `routes` | `deferred` | 静态路由串列表，按 `ip route` 语法 |
| `router` | `proxyArp` / `ipForward` | `deferred` | 布尔；`ipForward` 同时决定 `/proc/sys/net/ipv4/ip_forward` |
| `controller` | `ip` / `port` / `ryuApp` | `deferred` | 只改台账，控制器进程不重启（与 1.x `PUT /controllers/{id}` 同口径），见 §5 |
| `switch` | `ofVersion` | `live` | `OpenFlow10`…`OpenFlow15` 或 `null`（清空）；只支持 OVS 系交换机，其余 400 |
| `nat` | — | — | 只读：NAT 连 1.x 更新端点都没有，M1.2 不给它开口 |

链路（`options`）：

| 字段 | 档 | 说明 |
| :--- | :--- | :--- |
| `bw` | `deferred` | Mbit 上限，落 `TCLink`；running 时立即 `intf.config()` |
| `delay` / `jitter` | `deferred` | 毫秒数或 `10ms` 串，落 tc netem |
| `loss` | `deferred` | 丢包百分比 |
| 缺省 | — | 不传 `options` = 不改；显式 `{}` = 清空台账属性，**不回收**已下发的 tc（与 1.x 同口径，见 §5） |

## 4. 落地物与验收

| 项 | 位置 | 验收 |
| :--- | :--- | :--- |
| 上游端点 | `api.py` 两条会话更新路由（节点 PATCH、链路 PATCH；位置并入节点 PATCH）；`sessions.py` 转发 | `pnpm lab:check` 路由清单 + `pnpm contracts:gen` 快照 |
| 引擎 | `engines/base.py` 的 `Engine.update_node` / `update_link`（抽象）；`engines/wired.py` 映射到 1.x 的 apply 函数 | `pnpm check:engines`：dryrun 走通「建节点 → 改位置 → 改属性 → 读回投影」；`applied` 随 `is_started` 变化 |
| BFF | `mininetRoutes.ts` 两条（`lab:operate`）；白名单计数同步 | `pnpm check:lab-bff` ⓪ / ① 的计数与 ⑰ 同组的读写隔离用例 |
| 页面 | 拖动落库、双击节点 / 链路详情的保存，全部改打会话 PATCH；1.x 更新端点不再被页面调用 | `pnpm check:ui` 11.14 与拖动用例改成断言会话路径的上游命中 |
| 真机 | 90 上 root 后端 | 改主机 IP → `GET /nodes` 读回新值且 `applied: true`；停网改 IP → `applied: false`，`start` 后读回新值；改链路 `bw` → `tc class show` 的 `rate` 与请求一致（root 才断言，非 root 打 `⏭`） |

## 5. 已知限制（不是缺陷）

- **没有版本号 / ETag**：并发更新以最后一次为准；防「两个写同时进行」仍靠 BFF 的在途写 409（`NMCPS-DESIGN-008` §五）与台账对账，不在模型上加乐观锁 —— 单实例宿主上多用户并发不在本阶段范围。
- **`deferred` 不等于「停网也立刻看到」**：停网改 IP 只在下次 `start` 后成立；`applied: false` 就是这件事的机器可读表达，页面不得把它渲染成「已生效」。
- **显式 `options: {}` 不回收 tc**：1.x `PUT /links` 对空 `options` 也只清台账、不 `tc qdisc del`，M1.2 沿用同口径；要回收得先删链路再建（`DELETE /sessions/{id}/links/{link_id}` + `POST`）。
- **控制器属性改了不重启**：控制器是进程，改台账不会让它带着新端口 / 新 app 重启；这是 1.x 的既有语义，M1.2 只把它写进文档，不新增「重启控制器」端点。
- **无线不可用**：`ap` / `station` 的更新在 M3 之前一律 501，不做「先写台账等 M3」的假成功。

## 6. 迁移顺序与「不做双写」

1. **先上游**：`Engine` 两个方法 + `wired` 映射 + 两条会话路由 + `sessions.py` 转发，`dryrun` 全程可跑（无 root 也能验收语义）。
2. **再 BFF**：白名单两条（`lab:operate`）+ 计数同步 + 自检用例；此时会话 PATCH 已可被调用，但页面还没切。
3. **最后页面**：一处一处切（拖动 → 节点详情 → 链路详情），每切一处就把对应的 1.x 调用删掉；**同一动作只保留一个入口**，不写双份请求。
4. **1.x 更新端点保留**：它们仍是「默认会话」的等价物，供未切换的页面与真机自检使用；删除要另开裁决，且必须在页面全部切完之后。
5. 页面切换完成的判据：`check:ui` 里拖动与详情保存的上游命中表只剩 `/api/simulation/sessions/**`，1.x 的 `node_position` / `PATCH hosts` / `PATCH routers` / `PUT links` 命中数为 0。

## 7. 本节明确不做

- **批量更新**：一次一条，不做 `PATCH /nodes`（数组）。
- **改名 / 换类型 / 改 MAC**：见 D3，要重建节点。
- **流表、统计、链路通断**：见 D7，留在 1.x，M1.3 再议。
- **自动重启**：更新不触发 `stop` + `start`；要重建网络由页面显式调用（重启是设备栏既有动作，一个动作一个入口）。
- **分表字段直通**：`attributes` 按类型白名单校验，不做「把不认识的键原样塞进台账」。
