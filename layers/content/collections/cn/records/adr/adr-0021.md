# ADR-0021：仿真网络的租户隔离与访问裁决

> **层级**：Tier 5 记录层 —— 正文发布后只追加；后续修正用 `##` 追加节，不回改已发布结论。
> **与 ADR-0020 的关系**：ADR-0020 只解决了「浏览器不直连 Mininet」的只读通道问题，明确把多用户隔离留作未决项。本 ADR 回答该未决项，并把它扩展到仿真平台 `/api/sim/**`。
> **与 ADR-0009 / ADR-0018 的关系**：ADR-0009 的 `x-tenant-id` 客户端透传与 ADR-0018 的「身份 cookie 只服务 `/api/auth`」在本域被收紧：仿真资源的租户归属**只能**来自 BFF 会话，不接受请求体、查询参数或 `x-tenant-id`。
> **状态**：需求方于 2026-11-15 选择「每租户独立运行实例」（方案 A）。平台管理员跨租户运行态访问按**默认拒绝**处理；若未来需要支持排障，必须另立「限时支持会话」裁决，不得在本 ADR 上直接开口子。

## 一、裁决（速览）

| 编号 | 裁决 | 说明 |
| :--- | :--- | :--- |
| **D1** | 采用**每租户独立运行实例**（方案 A） | 每个租户拥有独立的 Mininet 实例 / 容器 / 网络命名空间；禁止多个租户共享同一个 `app.net` 进程。仿真平台同样按租户隔离实例或命名空间。 |
| **D2** | 所有仿真资源带 `tenant_id`，且只从 BFF 会话派生 | 请求体、查询参数、`x-tenant-id` 一律不参与归属判定；出站前必须剥掉客户端伪造的租户头。 |
| **D3** | 权限位与角色基线固定 | `lab:read` / `lab:create` / `lab:operate` / `lab:delete` / `lab:terminal` / `lab:sniffer`；租户普通用户默认只有 `lab:read`，租户管理员额外拥有创建 / 操作 / 删除；终端与抓包必须单独授权。 |
| **D4** | 跨租户访问一律 **404**，不是 403 | 不泄露「另一租户存在该资源」这一事实；未知资源与越权资源共用同一拒绝语义。 |
| **D5** | 平台管理员默认**没有**租户运行态访问权 | 只可读平台元数据 / 配额 / 审计。运行态访问只能通过独立、限时、全程审计的支持会话，且必须由被支持租户的管理员显式授权。 |
| **D6** | 单租户同一时间最多一张运行中的网络 | 第二次创建 / 启动回 `409 lab_network_already_running`；不得用「先排队再覆盖」隐式抢占。 |
| **D7** | BFF 维护资源台账，上游 ID 不是权限边界 | 每条记录至少含 `id`、`tenant_id`、`engine`、`upstream_id`、`state`、`created_by`、`created_at`；所有 `{sim_id}` / `{network_id}` / `{node_id}` / `{link_id}` 先查台账再触达上游。 |
| **D8** | 鉴权必须先于写操作落地，且失败关闭 | 需要 BFF 签名会话 + IAM 角色解析；缺签名密钥、缺会话、角色查询失败分别回 401 / 403 / 503，绝不回退到「全局可见」。 |
| **D9** | 高风险操作全部审计 | 创建、启动、停止、重置、删除、终端开关、抓包开关都必须记录租户、主体、网络、动作、结果、`request_id` 与客户端 IP。 |
| **D10** | 写操作、终端、抓包、WebSocket 在 P1~P3 完成前保持关闭 | 不是「先渲染再等 405」；`/api/mininet/channel` 的 `writeEnabled` 在权限与隔离落地前恒为 `false`。 |

## 二、为什么必须是数据面隔离

Mininet 的 `app.net` 是**进程内全局对象**，同一进程同一时间只有一张网络。只做 UI 过滤、BFF 台账或 `sim_id` 校验，都不能阻止租户 B 的进程看到租户 A 的节点、流表、抓包与终端。

因此「隔离」在本 ADR 中的定义是：

1. **控制面隔离**：BFF 只把请求路由到本租户实例，路由表由 BFF 持有，客户端不能指定地址。
2. **数据面隔离**：每个租户实例有独立进程、独立网络命名空间 / 容器、独立 bridge 与 veth 命名空间；租户之间的包不得经过同一 bridge。
3. **存储隔离**：抓包文件、导出脚本、终端日志按 `tenant_id` 分目录或分卷；对象存储路径不得可被跨租户枚举。
4. **资源隔离**：每租户实例设置 CPU / 内存 / 进程数 / 网络配额；单租户打满不得拖垮其它租户。

如果部署条件暂时只能提供单实例，则必须把它明确命名为「全局租约（global lease）」，并在 UI 与 API 中标注「非隔离、仅演示」，**不得**宣称支持多租户。方案 C（单实例全局锁）已作为不满足本 ADR D1 的选项被否决。

## 三、资源模型与 BFF 台账

### 3.1 资源记录

最小台账形状（字段名为建议契约，落地时进 `shared/types`）：

```ts
type LabEngine = "simulator" | "mininet";

interface LabNetworkRecord {
  id: string;                 // BFF 自有 ID，外部只暴露这个
  tenant_id: string;          // 只来自签名会话
  engine: LabEngine;
  upstream_id: string;        // 上游实例内 ID，不单独作为权限凭据
  state: "creating" | "stopped" | "running" | "error";
  created_by: string;         // 主体 ID
  created_at: string;
  updated_at: string;
}
```

### 3.2 查找顺序

所有带资源 ID 的请求按以下顺序处理：

1. 从签名会话取 `tenant_id` 与 `subject_id`；
2. 在台账中按 `(tenant_id, engine, id)` 查找；
3. 未命中 → `404 lab_resource_not_found`（不区分「不存在」与「别人的」）；
4. 命中后检查权限位；
5. 最后才把 `upstream_id` 拼到本租户实例的基址上。

**禁止**把上游返回的 `sim_id`、节点 ID、链路 ID 直接当成授权凭据；它们只在台账命中后作为路由参数使用。

### 3.3 列表过滤

上游列表若返回全局资源，BFF 必须在出口按台账中的 `tenant_id` 过滤；无法判断归属的记录一律丢弃并记一条告警。前端不得承担过滤职责，也不得收到跨租户记录的「灰显占位」。

### 3.4 资源清单随写操作收敛

台账一旦登记了 `resources`，这份清单就是租户边界：列表出口按它丢记录、路径参数按它先判 404。**它必须跟着写操作收敛**，否则只在读路径上正确、一写就过期：

- 建节点（`POST /hosts|switches|routers|nats|controllers`）成功后，把请求体里的节点 id（`id`，缺省取 `name`）加入 `resources.nodes`；
- 建链路（`POST /links`，请求体 `{ src, dst }`）成功后加入 `resources.links`（键按字典序归一的 `src--dst`）；
- 删节点（`DELETE /delete_node/{node_id}`）/ 删链路（`DELETE /delete_link/{src_id}/{dst_id}`）成功后移出清单，删节点同时移除挂在它上面的链路键；
- 整表替换（`POST /import_json` / `full_reset`）不按增量猜，属于 NMCPS-ADR-0022 W4 导入导出的一部分；
- 上游失败时**不**改清单 —— 清单描述的是「已经发生的事实」；清单写盘失败不回滚上游，但必须 `console.warn` 留痕（否则新节点会在列表里静默消失）。

新增节点的 ID 由租户自己写，因此入清单不构成越权；把别人的资源塞进请求的前提本来就是能写这张网。

**写响应不套资源清单**：上游 `POST /switches` 回的是交换机本体（单对象），若照读路径判可见性，一次成功的建节点会被回成 `404 lab_resource_not_found`（实测症状：弹窗“创建失败”，节点其实已建好）。写响应对应的就是刚被这次请求改动的对象，只核对 `tenant_id` / `network_id` / `sim_id` 是否与本网络一致，不按清单判。

## 四、身份与租户绑定

### 4.1 会话来源

仿真通道不接受 `nmcps_ui` 这种未签名 JSON cookie 作为租户边界。P1 必须新增 BFF 签名的会话 cookie（建议名 `nmcps_sess`，`HttpOnly`、`SameSite=Lax`、`Path=/`）：

- 载荷至少含 `sub`（用户 ID）、`tid`（租户 ID，平台用户为 `null`）、`iat`、`exp`；
- 用 `runtimeConfig.bff.sessionSecret`（环境变量 `NUXT_BFF_SESSION_SECRET`，至少 32 字节）做 HMAC-SHA256 签名；
- 校验失败、过期、缺 `tid` 一律视为未认证；
- 未配置密钥时 `/api/mininet/**` 与 `/api/sim/**` 回 `503 bff_auth_not_configured`，**不得**回退到未签名 cookie。

访问令牌仍由 `nmcps_at` / `Authorization` 提供，用于调用 IAM 与上游；会话 cookie 只解决「这个浏览器登录的是谁、属于哪个租户」，不替代访问令牌。

### 4.2 角色解析

角色不从客户端读取，也不只看角色编码。P1 通过 IAM 解析：

1. `GET /iam/subject-roles?subject_id=<会话 sub>` 取该主体的角色关系；
2. 对每个 `role_id` 调 `GET /iam/roles/{id}` 取 `code` 与 `tenant_id`；
3. **租户角色必须满足 `role.tenant_id === 会话 tid`**，否则丢弃；这正是 `UP-RBAC-09`（租户管理员可把用户绑到 `platform_admin`）的 BFF 侧兜底；
4. 平台角色（`platform_admin`，`tenant_id` 为 `null`）只在 `会话 tid === null` 时识别；平台用户不获得任何运行态权限；
5. 角色查询失败或超时 → `503 bff_role_resolution_failed`，不降级为「无角色但可读」。

角色结果可按 `subject_id + 访问令牌哈希` 缓存 ≤ 60 秒；登出、改密、角色变更事件必须使缓存失效。缓存只允许放在 BFF 单实例内，不得写入共享可变台账。

### 4.3 权限基线

| 角色编码 | 适用主体 | 默认权限 |
| :--- | :--- | :--- |
| `tenant_user`（默认语义，不强制绑定） | 租户用户 | `lab:read` |
| `tenant_admin` | 租户管理员（`role.tenant_id` 匹配） | `lab:read` + `lab:create` + `lab:operate` + `lab:delete` |
| `lab_terminal` | 显式授权 | `lab:terminal`（不隐含 `lab:read` 之外的任何权限） |
| `lab_sniffer` | 显式授权 | `lab:sniffer`（不隐含 `lab:operate`） |
| `platform_admin` | 平台管理员（`tenant_id` 为 `null`） | 无运行态权限；仅平台元数据 / 配额 / 审计 |

权限位语义：

- `lab:read`：查看本租户网络、拓扑、节点、链路、运行态与统计；
- `lab:create`：创建本租户网络（受 D6 单网络限制）；
- `lab:operate`：启动、停止、重置、pingall、修改本租户网络；
- `lab:delete`：删除本租户网络与关联产物；
- `lab:terminal`：打开本租户节点终端；
- `lab:sniffer`：启停本租户抓包、读取/导出抓包。

`lab:terminal` 与 `lab:sniffer` **不得**由 `lab:read` 或 `lab:operate` 隐含；它们需要独立角色或独立权限声明。

## 五、隔离实例与路由

### 5.1 实例注册表

BFF 持有一张**只读**的租户 → 实例注册表（来自部署配置 / 服务发现），至少含：

```ts
interface LabInstance {
  tenant_id: string;
  engine: LabEngine;
  base_url: string;        // 仅服务端可见，永不下发浏览器
  capacity: number;        // 该租户允许的并发网络数，当前固定 1
  healthy: boolean;
}
```

客户端请求只能带 BFF 资源 ID；`base_url` 不得出现在响应、日志（除脱敏审计）或前端配置中。

### 5.2 路由规则

- 读请求：按会话 `tenant_id` 选实例；实例不存在或不健康 → `503 tenant_runtime_unavailable`；
- 写请求：在选实例前先检查 `lab:create` / `lab:operate` / `lab:delete`；
- 上游返回 404：BFF 仍回 404，不把上游错误映射成 403；
- 上游返回 401/403：视为 BFF 与实例之间的配置错误，回 `502 upstream_auth_misconfigured` 并告警，绝不能触发用户会话刷新；
- 任何情况下不得把一个租户的请求转发到另一个租户的实例。

### 5.3 单租户单网络

同一租户同一 `engine` 同时只允许一张 `running` 网络：

- 创建第二张 → `409 lab_network_already_running`；
- 启动第二张 → 同上；
- 停止后可创建新网络，旧网络保留为 `stopped` 直到删除或配额回收；
- 并发创建用台账的租户级互斥（数据库唯一约束或事务锁）保证，不能只靠前端按钮禁用。

## 六、失败语义

| 情形 | 状态 / message |
| :--- | :--- |
| 无签名会话 / 会话过期 | `401 bff_auth_required` |
| 会话有效但无对应权限位 | `403 lab_permission_denied` |
| 资源不属于本租户 / 不存在 | `404 lab_resource_not_found` |
| 同租户已有运行中网络 | `409 lab_network_already_running` |
| 租户实例未配置 / 不健康 | `503 tenant_runtime_unavailable` |
| 缺少 `sessionSecret` | `503 bff_auth_not_configured` |
| IAM 角色查询失败 | `503 bff_role_resolution_failed` |
| 写能力未开放 | `405 bff_method_not_allowed`（与 ADR-0020 一致） |
| 上游鉴权配置错误 | `502 upstream_auth_misconfigured` |

**禁止**：跨租户返回 403；无会话时返回空列表冒充成功；角色查询失败时按 `tenant_user` 放行；把 `x-tenant-id` 当作租户来源。

## 七、审计

高风险操作在**动作执行前**写入审计 outbox，执行后补结果；审计写入失败时高风险动作回 `503 audit_unavailable`，不得「先做后补」。

最小字段：

| 字段 | 说明 |
| :--- | :--- |
| `tenant_id` | 会话租户，不得为空 |
| `actor_id` / `actor_username` | 会话主体 |
| `engine` | `simulator` / `mininet` |
| `network_id` | BFF 台账 ID |
| `action` | `create` / `start` / `stop` / `reset` / `delete` / `terminal_open` / `terminal_close` / `sniffer_start` / `sniffer_stop` |
| `result` | `allowed` / `denied` / `succeeded` / `failed` |
| `reason` | 拒绝或失败原因（不写敏感载荷） |
| `request_id` | 上游 / BFF 关联 ID |
| `client_ip` | 审计需要，日志展示时按部署策略脱敏 |
| `created_at` | 服务端时间 |

终端与抓包必须记录会话开始/结束、目标节点、持续时长；不得记录终端输入内容或抓包载荷。

## 八、实施顺序与门禁

| 阶段 | 内容 | 完成条件 |
| :--- | :--- | :--- |
| **P0** | 本 ADR + `shared/constants/labPermissions.ts` 权限矩阵 + `check:lab-tenancy` | 纯函数断言全绿；文档索引同步 |
| **P1** | 签名会话 cookie + IAM 角色解析 + `/api/mininet/**` 读守卫 + `x-tenant-id` 剥离 | 未登录 401、缺密钥 503、跨租户 404；`check:lab-bff` 增加鉴权组 |
| **P2** | 资源台账 + 列表出口过滤 + 读页面接租户上下文 | 两个租户的只读数据互不可见；台账不命中不触达上游 |
| **P3** | 每租户实例部署 + 创建 / 启动 / 停止 / 删除 + 单网络 409 | 双租户并发跑网络互不影响；数据面隔离演练通过 |
| **P4** | 终端 / 抓包 / WebSocket ticket + 审计 + 支持会话（若立项） | ticket 短时、一次性、绑定租户与节点；审计可回放 |

**门禁**：P1 与 P2 未完成前，P3 的写端点不得加入 `MININET_ROUTES` 或仿真白名单；P4 未完成前，终端、抓包与四个 WebSocket 不得开放。任何阶段都不得以「部署在内网」替代权限检查。

> 实施状态（2026-11-16）：P0–P2 已落地——签名会话、IAM 角色解析、`/api/mininet/**` 读守卫、租户实例注册表、`x-tenant-id` 剥离、BFF 台账与列表出口过滤均完成，资源清单随写操作收敛（§3.4）；`check:lab-bff` 73/73 全绿。跨租户资源访问（节点 / 链路）在台账未命中或清单外时统一回 `404 lab_resource_not_found`，且不触达上游；无实例租户仍回 `503 tenant_runtime_unavailable`。仿真网只读页已迁入场景层 `/scenario/simulator`。

## 九、被否决的选项

| 选项 | 否决理由 |
| :--- | :--- |
| **C：单实例全局锁** | 只保证「一次一个人用」，不保证租户隔离；一个租户的拓扑、抓包与终端对另一个租户仍可见。若临时采用，必须命名为 global lease 并在 UI 标注非隔离。 |
| 用 `x-tenant-id` 作为租户来源 | 客户端可伪造；ADR-0009 已指出租户与令牌绑定未决。本 ADR 要求从签名会话派生并剥离该头。 |
| 用未签名的 `nmcps_ui` cookie 做边界 | 可被注入 / 篡改；路径又只在 `/api/auth` 下可见。 |
| 只校验角色编码 `tenant_admin` | `UP-RBAC-09` 证明角色可被跨租户绑定；必须同时校验 `role.tenant_id`。 |
| 把上游 `sim_id` / 节点 ID 当权限凭据 | 上游 ID 可猜测或跨租户返回；权限边界必须是 BFF 台账 + 会话租户。 |
| 跨租户回 403 | 泄露资源存在性；统一 404。 |
| 平台管理员默认跨租户读写 | 违反最小权限；排障必须走限时支持会话。 |

## 十、遗留风险与后续裁决

1. **实例编排不在本仓库**：每租户容器 / 命名空间的实际创建、配额与销毁属于部署面；BFF 只消费注册表。注册表由谁写入、如何健康检查需在部署文档中补。
2. **IAM 角色查询成本**：逐角色详情查询可能较慢；P1 先做 60 秒缓存，若上游提供批量角色端点再替换。
3. **签名密钥轮换**：`NUXT_BFF_SESSION_SECRET` 需支持双密钥验证窗口，避免轮换时全员掉线；具体窗口在 P1 实现。
4. **支持会话**：若需求方要求平台管理员排障，需另立 ADR 定义授权人、时限、可操作范围与审计留存，不在本 ADR 内放开。
5. **仿真平台能力差异**：若 8001 无法提供每租户独立实例，则 `/api/sim/**` 写操作保持关闭，只开放台账内的只读数据；不得用单实例假装隔离。
