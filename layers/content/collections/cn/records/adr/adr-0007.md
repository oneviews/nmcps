# ADR-0007：启用 Nitro BFF 网关与 server/shared 目录

> **层级**：Tier 5 记录层 —— 正文不可修改（append-only）；变更须新开 ADR 并登记 `supersededBy`。

- **背景**：
  1. v1（`_reference/nmcps-v1`）是 **SSR + Nitro Node server** 的 BFF 形态：`server/api/**` 共 95 个路由，`server/api/[...slug].ts` 是统一网关；`server/utils/proxy.ts` 是唯一出站点（上游超时、Header 白名单、401 单例刷新、响应信封归一化、错误洗涤）；`server/routes/health.get.ts` 供 k8s 探针；`shared/types/api.ts` 与 `shared/utils/apiGuard.ts` 提供前后端共享信封与守卫；`Dockerfile` 以 `pnpm build → node .output/server/index.mjs` 部署。
  2. v2 当前是纯 SPA（`nuxt.config.ts` 的 `ssr: false`），`app/` 单层，`shared/` 仅有 `constants/docIds.ts`，**没有 `server/` 目录、没有 API 客户端、没有鉴权**；桌面包由 `nuxt generate` 产出静态 `dist` 后打包进 Tauri，因此 Nitro 路由**不可能**运行在桌面进程内。
  3. v1 的鉴权实现有一个不可照搬的缺陷：BFF 用 **httpOnly** cookie 存 `auth_token`，而客户端 `useAuth` 用 `useCookie('auth_token')` 读取 —— httpOnly 对 JS 不可见，页面刷新即丢失登录态（`isSignedIn` 只存在于内存）。v2 必须显式定义会话模型，不能复制该组合。
- **决策**：
  1. **启用 `server/` 与 `shared/`**：Nuxt 4 已默认识别这两个目录（`tsconfig.json` 已引用 `.nuxt/tsconfig.server.json` / `tsconfig.shared.json`），无需改 `srcDir`；`shared/` 只放前后端同构的纯类型与纯函数，`server/` 放 BFF。
  2. **部署形态**：BFF 为独立 Node 服务（`pnpm build:server` → `.output/`），web SPA 与 Tauri 静态包都通过 `runtimeConfig.public.bffBase` 指向它；桌面构建仍用 `pnpm generate`，产物形态不变。
  3. **上游地址只存在于服务端**：`runtimeConfig.bff.upstreamBase`（server-only，`NUXT_BFF_UPSTREAM_BASE` 覆盖）；前端只认识 `public.bffBase`，浏览器产物不再出现真实后端地址（v1 把 `apiBase` 放在 `public`，属信息泄露）。
  4. **统一网关**：`server/api/[...slug].ts` 按 `shared/types/api.ts` 的 `GATEWAY_RESOURCES` 与动词白名单解析目标路径，非白名单资源/动词直接 404/405；`server/utils/bff/proxy.ts` 是唯一出站点（超时、Header 白名单、Body 原样透传、响应统一为 `ApiResponse<T>` 信封）。
  5. **CORS 显式化**：`server/middleware/cors.ts` 按 `bff.allowedOrigins` 白名单回显 Origin 并允许 credentials（含 `tauri://localhost` / `http://tauri.localhost`）。**不使用** `routeRules: { '/api/**': { cors: true } }` —— 它下发 `Access-Control-Allow-Origin: *`，与 credentials 互斥（v1 的写法）。
  6. **健康检查**：`GET /health` 只反映进程存活，不依赖上游（k8s liveness）；上游就绪探针待部署规范确定后另加。
  7. **鉴权只做透传**：本 ADR 的 proxy 仅转发 `Authorization`（并预留从 `bff.tokenCookieName` cookie 读取），登录 / 刷新 / 会话存储另立 ADR（需裁决 web 用 httpOnly cookie、桌面用 Bearer 的双模，或统一 Bearer）。
- **影响**：
  - 新增 `server/`（`api/[...slug].ts`、`middleware/cors.ts`、`routes/health.get.ts`、`utils/bff/*`）、`shared/types/api.ts`、`shared/utils/apiGuard.ts`、`app/composables/useApi.ts`、`.env.example`。
  - `pnpm build:server` 产出的 `.output/` 成为 BFF 发布物；`pnpm generate` 仍只服务 Tauri；两者在 CI 中分别构建。
  - 桌面端构建必须提供 `NUXT_PUBLIC_BFF_BASE`，否则 `useApi` 抛出 `bff_not_configured`（显式失败，不静默回落到相对路径）。
  - 后端地址与内网拓扑不再进入前端产物；BFF 需能访问上游，并按 SSE/长连接评估副本数。
  - 渲染模式保持 SPA（`ssr: false`），避免引入 hydration 风险；后续若切 SSR 需新 ADR。
- **备选方案（未采用）**：
  - 桌面内嵌 Nitro：Tauri 不携带 Node 运行时，需 sidecar 二进制，体积、权限、端口与升级都不可控。
  - 桌面直连后端：每台客户端直连内网后端且需放开 CORS，违背 BFF 收敛目标。
  - `routeRules` 通配 CORS：与 credentials 冲突，且无法按 origin 白名单收敛。
  - 继续手写 `$fetch('http://…')`：地址硬编码、错误形态不统一。
- **遗留**：
  - 会话/令牌模型（httpOnly cookie vs Bearer、刷新与登出）未定，需 ADR-0008。
  - `shared/` 目前只有 `api.ts` / `apiGuard.ts`，v1 的 `route-engine`、`metrics` 等同构算法尚未迁移。
  - 网关当前按 JSON 处理响应；v1 的 SSE/流式端点（`text/event-stream`）需专用 handler（`sendStream`）另行接入，不能走统一 JSON 代理。
