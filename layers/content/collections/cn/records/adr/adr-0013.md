# ADR-0013：登录页命名统一为 login 与演示种子账号预填

> **层级**：Tier 5 记录层 —— 正文不可修改（append-only）；变更须新开 ADR 并登记 `supersededBy`。

- **背景**：
  - **命名单词分裂**：认证页为 `app/pages/auth/sign-in.vue`（route `/auth/sign-in`），但同一动作在代码里一律叫 `login` —— BFF 端点 `/api/auth/login`、服务端路由 `server/api/auth/login.post.ts`、组合式函数 `useAuth().login()`、架构文档正文（`NMCPS-ARCH-003` 第七节）都是 `login`。两套词并存意味着按 `login` 检索会漏掉页面本身，按 `sign-in` 检索也只在 UI 侧命中。
  - **文件命名规则不一致**：其余页面文件一律是**名词性 kebab-case**（`overview` / `security` / `plan-generation` / `auto-transmit`），`sign-in` 是动词短语，与「页面 = 资源」的既有语义不符。
  - **演示程序需开箱可登**：本仓库是演示程序，登录表单当前全空，演示与录屏每次都要手打账号口令；并且要同时演示**超级管理员**与**租户管理员**两个身份（`accountLevel` `0` / `1`）。
- **决策**：
  1. **页面与路由统一为 `login`**：`app/pages/auth/login.vue` → `/auth/login`；不保留 `sign-in` 别名重定向 —— 白名单本就是 `/auth/**`，旧路径无外部引用，留别名等于继续维护两套词。
  2. **源码术语统一**：i18n 键 `auth.signIn` 改为 `auth.login`；注释、脚本、文档一律写 `/auth/login`。已入库的历史 ADR（`NMCPS-ADR-0011`）正文按记录层规则保持原样；`NMCPS-ADR-0012` 与本条同批未入库，其路径引用随本次一并更正。
  3. **种子账号单一事实源**：新增 `shared/constants/demoAccounts.ts` 导出 `DEMO_ACCOUNTS`（超级管理员 / 租户管理员），页面只消费，不硬编码账号口令。
  4. **默认预填 + 一键切换**：登录页初始状态 = 第一个种子账号（超级管理员）；「演示身份」按钮把 `accountName` / `password` / `tenantCode` 整体回填，字段仍可手动编辑（需要真实 MFA 账号时不被锁死）。
  5. **演示专用边界**：预填仅为演示 / 录屏服务；真实部署前须核对 `DEMO_ACCOUNTS` 与上游 IAM 种子脚本一致，或移除预填。
- **影响**：
  - 路由 `/auth/sign-in` 不复存在；同步修改 `app/middleware/auth.global.ts`、`app/components/App/AppHeader.vue`、`scripts/check-ui.mjs` 的断言与 `NMCPS-ARCH-003` §7.4 / §7.6。
  - `NMCPS-ARCH-003` 新增 §7.7 固化「演示种子账号与登录页预填」口径；登录流程本身不变（仍走 `POST /api/auth/login`，守卫判据仍是 `/api/auth/session`）。
  - 登录页由「空表单」变为「预填 + 可切换」，`check:ui` 的空提交校验需要先清空字段再断言。
- **种子值核实（需求方给定 + 2026-10-31 实测，关闭上一版遗留项）**：登录 API 为 `POST http://192.168.1.55:10000/api/v1/auth/login`；种子账号 `admin / Admin@123456`（超级管理员）与 `tenantadmin / Tenant@123456`（租户管理员），两者实测均返回 `code: 0`。种子不含租户编码 —— 上游按账号解析租户，`tenantCode` 留空即可登录（`GET /api/v1/tenant` 显示内置默认租户 code 为 `default`，仅在显式多租户场景才填）。先前常量写的 `tenant / Admin@123456 / demo` 三值皆错（实测 `20201 账号或口令错误`），已按实测更正；口令仍只留在 `shared/constants/demoAccounts.ts` 一处。
- **登录前提（同一轮实测暴露）**：本仓库不带 `.env`（仅 `.env.example`），`NUXT_BFF_UPSTREAM_BASE` 为空时 BFF 对认证路由直接 503，任何种子账号都登不上 —— 「种子数据无法登录」的第一现场是上游未配置，而不是账号口令。`.env` 已按 `.env.example` 本地补齐（`.gitignore` 忽略，不入库）。
- **备选方案（未采用）**：
  - **保留 `/auth/sign-in` 并新增 `/auth/login` 别名**：两套词继续并存，grep 依旧会漏，还要额外维护重定向。
  - **用 `auth/index.vue`（`/auth`）代替 `login.vue`**：URL 失去动作语义，且 `/auth` 会被 `/auth/**` 白名单前缀「顺带」放行而不自解释。
  - **种子账号写进 `.env` / runtimeConfig**：演示包要多一份部署配置，口令还会随环境变量进入构建元数据；常量文件一处可改、可评审。
  - **只在文档登记种子账号、表单不预填**：演示与录屏仍需手输，达不到「默认填写」的诉求。
