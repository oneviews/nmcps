# ADR-0013：登录页命名统一为 login 与演示种子账号预填

> **层级**：Tier 5 记录层 —— 正文不可修改（append-only）；变更须新开 ADR 并登记 `supersededBy`。

- **背景**：
  - **命名单词分裂**：认证页为 `app/pages/auth/sign-in.vue`（route `/auth/sign-in`），但同一动作在代码里一律叫 `login` —— BFF 端点 `/api/auth/login`、服务端路由 `server/api/auth/login.post.ts`、组合式函数 `useAuth().login()`、架构文档正文（`NMCPS-ARCH-003` 第七节）都是 `login`。两套词并存意味着按 `login` 检索会漏掉页面本身，按 `sign-in` 检索也只在 UI 侧命中。
  - **文件命名规则不一致**：其余页面文件一律是**名词性 kebab-case**（`overview` / `security` / `plan-generation` / `auto-transmit`），`sign-in` 是动词短语，与「页面 = 资源」的既有语义不符。
  - **演示程序需开箱可登**：本仓库是演示程序，登录表单当前全空，演示与录屏每次都要手打账号口令；并且要同时演示**超级管理员**与**租户管理员**两个身份（`accountLevel` `0` / `1`）。
- **决策**：
  1. **页面与路由统一为 `login`**：`app/pages/auth/login.vue` → `/auth/login`；不保留 `sign-in` 别名重定向 —— 白名单本就是 `/auth/**`，旧路径无外部引用，留别名等于继续维护两套词。
  2. **源码术语统一**：i18n 键 `auth.signIn` 改为 `auth.login`；注释、脚本、文档一律写 `/auth/login`。已入库的历史 ADR（`NMCPS-ADR-0011`）正文按记录层规则保持原样；`NMCPS-ADR-0012` 与本条同批未入库，其路径引用随本次一并更正。
  3. **种子账号单一事实源**：新增 `shared/constants/demoAccounts.ts` 导出 `DEMO_ACCOUNTS`（超级管理员 / 租户管理员），页面只消费，不硬编码账号口令。
  4. **默认预填 + 一键切换**：登录页初始状态 = 第一个种子账号（超级管理员）；「演示身份」按钮把 `accountName` / `password` / `tenantCode` 整体回填，字段仍可手动编辑（需要真实 MFA 账号时不被锁死）。
  5. **演示专用边界**：预填仅为演示 / 录屏服务；真实部署前须核对 `DEMO_ACCOUNTS` 与上游 IAM 种子脚本一致，或移除预填。
- **影响**：
  - 路由 `/auth/sign-in` 不复存在；同步修改 `app/middleware/auth.global.ts`、`app/components/App/AppHeader.vue`、`scripts/check-ui.mjs` 的断言与 `NMCPS-ARCH-003` §7.4 / §7.6。
  - `NMCPS-ARCH-003` 新增 §7.7 固化「演示种子账号与登录页预填」口径；登录流程本身不变（仍走 `POST /api/auth/login`，守卫判据仍是 `/api/auth/session`）。
  - 登录页由「空表单」变为「预填 + 可切换」，`check:ui` 的空提交校验需要先清空字段再断言。
- **种子值核实（需求方给定 + 2026-10-31 实测，关闭上一版遗留项）**：登录 API 为 `POST http://192.168.1.55:8888/api/v1/auth/login`；种子账号 `admin / Admin@123456`（超级管理员）与 `tenantadmin / Tenant@123456`（租户管理员），两者实测均返回 `code: 0`。种子不含租户编码 —— 上游按账号解析租户，`tenantCode` 留空即可登录（`GET /api/v1/tenant` 显示内置默认租户 code 为 `default`，仅在显式多租户场景才填）。先前常量写的 `tenant / Admin@123456 / demo` 三值皆错（实测 `20201 账号或口令错误`），已按实测更正；口令仍只留在 `shared/constants/demoAccounts.ts` 一处。
- **代际切换（2026-11-04）**：上文的登录路径 `POST /api/v1/auth/login` 与 `tenantCode` 预填属旧代上游；新代为 `POST /api/v1/iam/login`（入参 `username`，无租户编码入参），预填三项收敛为账号 + 口令两项。种子账号与口令未变，裁决见 `NMCPS-ADR-0018`（`layers/content/collections/cn/records/adr/adr-0018.md`）。
- **默认口令更新（2026-11-16）**：按需求方要求，租户管理员 `tenantadmin` 的默认口令由 `Tenant@123456` 改为 `admin_2026`；超级管理员 `admin` / `Admin@123456` 不变。补齐上一行的「口令未变」表述：口令的单一事实源仍是 `shared/constants/demoAccounts.ts`，同批更新 `check:ui` 的预填断言与 `NMCPS-ARCH-003` §7.7（0.8.1）。若上游 IAM 账号口令未同步修改，页面预填的只是演示默认值，真实登录仍以上游账号为准。

- **实验台操作员随演示开关出现（2026-11-18）**：本地演示需要一个能直达 `/scenario/simulator` 的账号（假上游的 `alice` / `p@ssw0rd`，同时带 `lab:create` / `lab:operate` / `lab:read` / `lab:sniffer` / `lab:terminal`），但它不是上游生产种子数据 —— 真实 IAM 没有它的实验室角色（`docs/ai/lab-boundary.md` 的 AssignRole 缺陷一节）。因此新增演示开关 `NUXT_PUBLIC_DEMO_LAB_OPERATOR`（`runtimeConfig.public.demoLabOperator`，缺省 `false`）：`true` 时登录页多出「实验台操作员」按钮并预填 `alice`，`false` 时按钮不渲染、预填回到超级管理员 `admin`。选择器在常量文件里（`demoAccountsFor()` / `defaultDemoAccountFor()`），页面只读开关、不硬编码账号 —— 让用户点一个真实环境登不进去的账号，只会把「本地演示账号」当成「生产账号坏了」。
  **2026-11-18 补充：`alice` 已在真实 IAM 落库。** 用 `POST /api/iam/users` 在 `192.168.1.55:8888` 建号（`department_id = dept_default_ops` → 租户 `tnt_default`，口令 `p@ssw0rd`，id `a6541d3f-7880-4bb9-8917-5338d78e6925`），实测 `POST /api/v1/iam/login` 与 BFF `/api/auth/login` 都是 200，`tenantId = tnt_default`。所以本机 `.env` 的 `NUXT_PUBLIC_DEMO_LAB_OPERATOR=true` 指向一个**真能登录**的账号。角色一度仍缺（`lab_terminal` 已建、`lab_sniffer` 没有，且 `AssignRole` 落库的关系 `tenant_id` 恒为 `NULL`、租户上下文读不到，取证见 `docs/handoff/iam-assignrole-report-2026-11-18.md`），`GET /api/mininet/channel` 当时只回 `read: true`。**2026-11-18 上游修复后已闭环**：重新分配出的 `lab_terminal` 关系行带 `tenant_id = tnt_default` 且读得回来（全量关系 20 行、`tenant_id` 为空的行 0 条），alice 的 `/api/mininet/channel` 变成 `terminal: true`（`create` / `operate` / `delete` 仍 `false`），页面右栏从 日志 / 监控 / 网络 变成 日志 / 监控 / 网络 / Webshell，真连 `h1` 拿到 `root@h1:…$` 并跑通 `id` → `uid=0(root)`。同一轮随后把 `lab_sniffer`（`bcadd871-d4f2-40f5-9ac6-1c4ad28e096f`）也建出来并绑给 alice：`sniffer: true` 后右栏再涨一格「连通」，里面只有抓包读数（菜单「开始 / 停止抓包」实测把上游 `sniffer/state` 推到 `active: true`、实时流变「实时」，停止后回到 `false`），探测按钮依旧不出现（`lab:operate` 未授予）—— 这是能力位互不推导的双向证据。换上游实例前先确认该实例有没有 `alice`，没有就把开关关掉。

- **登录前提（同一轮实测暴露）**：本仓库不带 `.env`（仅 `.env.example`），`NUXT_BFF_UPSTREAM_BASE` 为空时 BFF 对认证路由直接 503，任何种子账号都登不上 —— 「种子数据无法登录」的第一现场是上游未配置，而不是账号口令。`.env` 已按 `.env.example` 本地补齐（`.gitignore` 忽略，不入库）。
- **备选方案（未采用）**：
  - **保留 `/auth/sign-in` 并新增 `/auth/login` 别名**：两套词继续并存，grep 依旧会漏，还要额外维护重定向。
  - **用 `auth/index.vue`（`/auth`）代替 `login.vue`**：URL 失去动作语义，且 `/auth` 会被 `/auth/**` 白名单前缀「顺带」放行而不自解释。
  - **种子账号写进 `.env` / runtimeConfig**：演示包要多一份部署配置，口令还会随环境变量进入构建元数据；常量文件一处可改、可评审。
  - **只在文档登记种子账号、表单不预填**：演示与录屏仍需手输，达不到「默认填写」的诉求。

- **演示账号 ↔ 实验台能力档位（2026-11-19，`NMCPS-ADR-0022` 复刻验收配套）**：三个演示账号刻意覆盖三种**互不蕴含**的能力组合，用来手验「能力位只按会话给、跨档不推导」（`NMCPS-ADR-0021` D3）。表格里 `alice` 一行是实测（下段给出取证），`admin` / `tenantadmin` 两行是角色**设计意图**，验收时按同一张表逐格核对。

  | 账号 | 口令 | 角色 | `read` | `create` | `operate` | `delete` | `terminal` | `sniffer` | 说明 |
  | :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
  | `admin` | `Admin@123456` | 超级管理员 | ✅ | ✅ | ✅ | ✅ | ❌ | ❌ | 全局管理账号；实验室能力仍取该租户的角色，不由「超级管理员」身份推导 |
  | `tenantadmin` | `admin_2026` | 租户管理员 | ✅ | ✅ | ✅ | ✅ | ❌ | ❌ | 演示「能改拓扑、但进不了终端」：右栏没有 Webshell，也没有抓包读数 |
  | `alice` | `p@ssw0rd` | 实验台操作员 | ✅ | ❌ | ❌ | ❌ | ✅ | ✅ | 演示「能看能连，但改不了拓扑」：Webshell 与抓包可用，探测 / 测速与拖动 / 增删全部不渲染 |

  `alice` 的档位是**实测**：`GET /api/mininet/channel` 回 `{ read: true, terminal: true, sniffer: true, create: false, operate: false, delete: false }`，右栏因此是 5 个标签（Webshell / 日志 / 监控 / 网络 / 连通），而「连通」里只有抓包读数与实时包列表 —— 探测按钮不出现，因为它是 `lab:operate`。这条组合同时证明两件事：`lab:terminal` 与 `lab:sniffer` 都不由 `lab:read` 推导；`lab:sniffer` 也不由 `lab:operate` 推导（`tenantadmin` 有 `operate` 却没有抓包读数）。换上游实例前先核对这三个账号是否都存在，缺哪个就把对应演示项关掉。
