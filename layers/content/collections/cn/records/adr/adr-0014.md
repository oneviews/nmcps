# ADR-0014：强制改密页命名为 change-password 而非 reset-password

> **层级**：Tier 5 记录层 —— 正文不可修改（append-only）；变更须新开 ADR 并登记 `supersededBy`。

- **背景**：
  - **行业把两类流程严格二分**：`reset password` 指**匿名**的「忘记口令」流程，凭邮件/短信令牌自助重设（Auth0 `password-reset`、Firebase `sendPasswordResetEmail`、Django `reset/<uid>/<token>/`、Keycloak `reset-credentials`、Azure AD SSPR）；`change password` / `update password` 指**已认证**、需要旧口令的改密（Django `PasswordChangeView`（`/password_change/`）、Azure AD `ChangePassword`、AWS IAM `ChangePassword`、OWASP Cheat Sheet「Change Password」）。初登强制改密属后者的一种：Keycloak required action `UPDATE_PASSWORD`、AD `ChangePasswordAtLogon`、Linux `chage -d 0`。
  - **上游设计同样二分**：`_reference/DESIGN.md` 的接口表里 `ResetPassword` 是「管理员重置口令」（`POST /auth/user/{id}/action/reset-password`），`ChangePassword` 是「用户自助改密」（`POST /auth/user/action/change-password`）。我们这页属自助改密，却借了 `reset` 的词。
  - **仓库内已有一致的一套词**：`useAuth().changePassword(newPassword, oldPassword)`、BFF `POST /api/auth/password`、`/user/security` 页的「改密」区块；只有这个页面叫 `reset-password`，另有 21 个 `auth.reset*` i18n 键跟着分裂。`NMCPS-ADR-0013` 刚因「同一动作两套词 ⇒ 按词检索必漏」把 `sign-in` 统一成 `login`，此处是同类问题的反向复现。
  - **与命名规则也不符**：ADR-0013 定「页面文件名 = 名词性 kebab-case」（`overview` / `security` / `plan-generation`），并把 `sign-in` 作为**动宾短语**否掉；`reset-password` 是同一形态。
- **决策**：
  1. **页面与路由统一为 `change-password`**：`app/pages/auth/change-password.vue` → `/auth/change-password`。不保留 `reset-password` 别名重定向：该页在 `/auth/**` 白名单内，没有任何外部引用，留别名等于继续维护两套词（与 ADR-0013 对 `sign-in` 的判断一致）。
  2. **i18n 键改名不改文案**：`auth.reset*` 共 21 个键 → `auth.changePassword*`（`changePasswordTitle` / `changePasswordCurrentLabel` / `changePasswordNewTooShort` / `changePasswordSameAsCurrent` / `changePasswordCurrentInvalid` …），zh/en 两边同步。文案原样保留，`check:ui` 的文案断言因此不受影响。
  3. **`reset` 一词留给忘记口令流程**：未来若要接「忘记口令」，按行业命名走 `/auth/forgot-password`（发起）+ `/auth/reset-password?token=…`（凭令牌重设），两者都是匿名流程，与本次改密页不冲突。
  4. **记录层历史不改**：`NMCPS-ADR-0011` 正文里的旧路径按 append-only 规则保持原样，以本 ADR 为准。
- **影响**：
  - 代码：`app/pages/auth/change-password.vue`（更名）、`app/pages/auth/login.vue`（`mustResetPassword` 分支的落点与注释）、`i18n/locales/{cn,en}.json`（21 键 ×2）。
  - 自查：`scripts/check-ui.mjs` 的 4 条路径断言 + 1 条未登录守卫用例改判新路径；用例条数不变（自建 61 / 外部 49）。
  - 文档：`NMCPS-ARCH-003` §7.4 / §7.5 / §7.6 / §7.8 与 `NMCPS-REC-001` REPO-04 全部改新路径，并补一句「为何不叫 reset」。
  - 运行时不涉及数据迁移：路由只在客户端白名单内使用，书签失效后回登录页重新登录即可（`mustResetPassword` 会把人再送回来）。
- **备选方案（未采用）**：
  - **保留 `/auth/reset-password`，只在文档注明「本仓库 reset = 强制改密」**：术语仍与上游设计（`ResetPassword` = 管理员重置）和行业惯例冲突，排障时会被当成忘记口令流程去查邮件端点。
  - **`/auth/password`（纯资源式，最贴名词化规则）**：与 BFF `POST /api/auth/password` 同名不同入口，日志与排障时最容易混；页面语义是「改」而不是「口令资源本身」。
  - **`/auth/password/change`**：更 RESTful，但 `app/pages/auth/password/change.vue` 多一层目录，换来的是目录层级而非检索收益。
