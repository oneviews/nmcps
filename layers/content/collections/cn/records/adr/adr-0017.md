# ADR-0017：数据表单交互基准 —— 两栏布局（左栏 / 右栏）、两级工具栏、视图态与记录级面包屑

> **层级**：Tier 5 记录层 —— 正文在发布后只追加；本次为 0.1.0 首次成文，基准细则直接写入正文（同 `NMCPS-ADR-0015` 的「后续记录」做法，细则补充用 `##` 追加节）。
> **与基准文档的关系**：本 ADR 是**裁决与依据**，规范本体是 `NMCPS-ARCH-006`（`arch.ui`，Tier 1）；两者冲突时以 `NMCPS-ARCH-006` 为准。

---

## 一、背景

### 1.1 参考实现（1.0）到底做了什么

`_reference/nmcps-v1/layers/connector/app/pages/connector/device.vue`（524 行）已是完整三段式，`_reference/nmcps-v1/layers/system/app/pages/system/user.vue`（357 行）是单栏列表页。二者的结构事实：

| 维度 | 1.0 `connector/device.vue` | 1.0 `system/user.vue` |
| :--- | :--- | :--- |
| 布局 | M 区 `UDashboardPanel resizable`（`min 25 / default 30 / max 40`，百分比）+ 右半区 `grid-cols-12`：D 区 `col-span-8`、R 区 `col-span-4` | 无分栏：`UDashboardPanel` 单栏，`UTable sticky` + 底部分页 |
| 工具栏 | **两层**：M 区 header 工具栏（搜索 + 状态 `UTabs` + 新建分组）、D 区 header 工具栏（标题 + 新建 + 删除 + 取消 + 保存） | **一层**：header 工具栏左（搜索）右（批量删除 + 状态筛选 + 页大小 + 列显示 + 刷新 + 新建） |
| 选中模型 | `activeContext = { type, id, data }` 单源 + `isCreating` 标志 | 无选中模型（行内动作 + 弹窗表单） |
| 编辑入口 | D 区内联表单，`<component :is>` 按实体类型切换，`<keep-alive>` 按 `${type}-${id||'new'}` 重建 | `UserFormModal` 弹窗（新建/编辑共用） |
| 未保存保护 | `dirtyState{isDirty,id}` + `requestSwitch(next)` 闭包 + `pendingTarget`，脏则弹「Stay / Discard and switch」 | 无（弹窗关闭即丢弃） |
| 删除 | D 区工具栏按钮 → 确认弹窗 → 执行，成功后 `activeContext=null` 并重载两列表 | 行内图标按钮 / 批量按钮 → 删除确认弹窗 |
| 默认选中 | `defaultSelectionSettled` 保证只执行一次，`firstVisibleDevice()` 复刻列表排序取首条 | 无（无详情区） |
| 保存动作 | 工具栏按钮经 `ref` 调子组件暴露的 `{ save, cancel }` | 弹窗内提交 |
| 空态 | D/R 区整块空态（`UIcon size-32 text-dimmed` + 文案，`hidden lg:flex` 居中） | `UTable :empty` |

### 1.2 必须继承的四点

1. **面板级工具栏**：每栏自带 header 工具栏，动作贴着它作用的区域。这比「一个全局工具栏装全页动作」信息架构更轻 —— 用户看 M 区的搜索框就知道过滤的是左栏，看 D 区的「保存」就知道保存的是右侧这条。1.0 的 `device.vue` 已经这么做了，`system/user.vue` 也把筛选与批量放在列表工具栏。**两侧一致，说明这是本仓的自然形态**。
2. **单一选中源 + 切换守卫**：`activeContext` 一个 ref 描述「当前在编辑什么」，切换统一走 `requestSwitch()`，脏则弹确认。
3. **删除先确认、后执行**，且确认文案带实体可读名（`entityName()`）。
4. **默认选中必须与列表首行一致**：`firstVisibleDevice()` 完全复刻 `Device/List.vue` 的排序（含中文展示名映射），否则「打开页面默认选中的不是列表第一行」。

### 1.3 必须在 2.0 收紧的三点

1. **行内动作与工具栏动作重复**：`system/user.vue` 的行内 `edit` + `trash` 图标组与工具栏「新建/批量删除」职责重叠，同一删除有两处入口；`device.vue` 则把删除放在 D 区工具栏（正确）。收紧为：**行内至多 1 个动作，写操作与危险动作一律上移**。
2. **默认选中排序键不同源**：1.0 曾因「列表按展示顺序、默认选中按中文名排序」导致选中项不是第一行（代码注释里明确记为事故点）。收紧为：**默认选中必须复用列表的同一个 `sortKey` 函数**，禁止各写一份。
3. **详情始终可编辑**：`device.vue` 的 D 区没有 view 态，一进页面就是可编辑表单，脏状态常驻 —— 任何切行都要弹「放弃修改」。收紧为：**默认 view（只读）→ 显式「编辑」进入 edit**，脏状态只在 edit/create 时存在。

### 1.4 现状与本决策的关系

当前仓库的 `/system/user` 是单栏列表页 + 两个弹窗（新建 / 启停），`/system/log`、`/system/permission`、`/system/policy` 仍是占位页。1.0 的 `device.vue` 证明分栏在本仓可行，但它的 M/D/R 尺寸、工具栏分层、视图态都靠页面自己约定；`usePageToolbar()` 只有 `AppToolbar` 自己读（模块级 `shallowRef` 单例，多实例互相覆盖；项目 `ssr: false`，不存在跨请求共享）；记录级面包屑只有内容中心用 `route.meta.breadcrumb` 打过一次 15 行补丁。**在第二块真实表单页落码之前，把这些约定固化成基准。**

## 二、决策

### D1 两栏骨架、最小页面宽度与容器预算

任何「集合 + 单条」页面的目标形态只有一种：**左栏（数据列表栏）+ 右栏（数据详情栏）**，由 `Layout/Split.vue` 单点提供，页面只填 `#list` / `#detail`。技术标识一律用**角色名** `list` / `detail`（选择器 `[data-pane="list"]`）；「左 / 右」是两栏形态下的视觉位置，覆盖式形态下同一组件呈现为「列表页 / 详情页」，角色不变。**不设第三栏**：关联数据在右栏内分区实现（见 D4）。

**最小页面宽度（可断言常量）**：

| 量 | 值 | 含义 |
| :--- | :--- | :--- |
| `--page-min-w` | **20rem（320px）** | 单栏 / 覆盖式形态的最低可用宽；低于此属壳层缺陷，不在本基准内 |
| `--split-min-w` | **56rem（896px）** | **两栏门槛**：页面可用宽度 < 56rem 时只允许覆盖式 |
| 右栏最小宽 | **32rem（512px）** | 两栏时右栏不得低于此值 |
| 左栏宽 | **20–24rem（默认 22rem）** | 可拖拽区间 18–28rem |
| 视口下限 | 320px | 任何模式、任何形态下都不得出现横向滚动 |

56rem 的来历可复算：左栏上限 24rem + 右栏下限 32rem = **56rem**。所以「两栏门槛」不是拍的数，而是两栏各自下限之和。

**形态判定**（顺序即优先级，判据是宽度与设备，不是作者偏好）：

1. `isMobile`（`mobile` 模式或视口 ≤ 1023px）→ **覆盖式**；
2. 页面可用宽 < 56rem → **覆盖式**（窄桌面回退，不是"三栏降级"）；
3. 其余 → **两栏**。

| 形态 | 触发 | 左栏 | 右栏 | 分隔 |
| :--- | :--- | :--- | :--- | :--- |
| **两栏** | `!isMobile` 且 W ≥ 56rem | 20–24rem（默认 22rem），可拖拽 | 弹性，最小 32rem | 栏间 1px `border-default`，无 gap |
| **覆盖式** | `isMobile` 或 W < 56rem | 100% | 100%（覆盖左栏），工具栏左端有唯一「返回」 | 无 |

- **两栏门槛只认容器宽**，不用 `md:` / `lg:` 视口断点：侧栏收起/展开差 12rem、`topbar` 叠 1440px 限宽、分屏窄窗三种情况都会误判。
- **不实现「折叠左栏」**：列表是主界面，把左栏收成图标栏会让「数据在哪一栏」失去稳定预期；窄了就走覆盖式，而不是把左栏压扁。
- **拖拽三条**：① 面板用**稳定 `id`**（按页面 + 栏名，例如 `user-list`）记忆宽度；② 双击分隔条复位默认 22rem；③ 区间锁 18–28rem，不允许拖到 0。
- **实现不采用 `UDashboardPanel resizable`**：其主题含 `min-h-svh`（→ `bigscreen` 双滚动条）、`lg:w-(--width)`（视口断点）、分隔条 `hidden lg:block`，且尺寸用 cookie 存储、拖拽每移动一像素写一次 `document.cookie`。改为 `@container` + `grid` + 自建 `usePaneResize`（pointer events + rAF 合帧 + 松手后 300ms 防抖写 `localStorage` + 键盘可达）。

### D2 左栏（数据列表栏）规范

**结构（自上而下）**：面板级工具栏 → 列表滚动区 → 可选 footer（计数 + 分页）。

| 元素 | 规范 |
| :--- | :--- |
| 工具栏左 | 搜索框（`size="sm"`，宽 11–16rem，`watchDebounced` 300ms，变化即 `page=1`） |
| 工具栏右 | 集合域动作：状态分段（`UTabs size="xs" :content="false"`）、筛选、批量、刷新（`loading` 跟随）、列显示 |
| 行高 | 40–48px；单行主标识 + 状态徽标 + 1 条次级信息（时间 / IP / 租户），超出截断并 `title` 提示 |
| 行内动作 | **至多 1 个**（多数页面就是「选中」，由整行点击承担）；写操作与危险动作不得下行到行内 |
| 选中态 | `bg-elevated` + 左缘 2px primary 竖条 + `aria-selected`（不靠颜色单通道） |
| 分组 | 仅两级（分组 → 条目），折叠状态按分组 id 记忆；不做三级嵌套 |
| 空态 | 栏内空态文案 + 主 CTA（「新建」），不是把空态塞进表格 |
| 加载 | 骨架行 ×5，不整块 spinner；刷新时保留旧数据 + 顶部细进度条 |
| 错误 | 栏内内联错误 + 重试按钮，右栏保持可用 |
| 默认选中 | 两栏形态默认启用（右栏默认 `view` 只读，选中即得上下文）；**必须复用列表的同一个 `sortKey`**，只执行一次（`settled` 标志）；覆盖式形态不默认选中 |
| 窄栏内容 | 左栏 20–24rem 内**最多两行信息**（主标识 + 次级信息），第三字段降级到 `title` 或右栏 |

### D3 右栏（数据详情栏）规范

**三态视图**：`view`（默认，只读）→ `edit`（显式进入）→ `create`（「新建」进入空表单）。1.0 缺 view 态，为此付出的代价是「随时脏、切行必弹确认」。

**结构（自上而下）**：面板级工具栏 → 表单滚动区 → 可选底部危险区。

面板级工具栏的**固定顺序**（左 → 右，不得重排）：

1. **标题区**：记录展示名（`text-sm font-semibold`）+ 副标题（编号 / 状态），`create` 时为「新建 XX」。
2. **记录级动作**：`UFieldGroup`（新建、编辑/取消编辑、危险动作如删除 `color="error"`）。`view` 态显示「编辑 + 删除」；`edit`/`create` 态隐藏编辑入口。
3. **提交级动作**：`UFieldGroup` 靠右（取消 `neutral`、保存 `primary`），仅在 `edit`/`create` 出现，文案为「保存」/「创建」。

| 维度 | 规范 |
| :--- | :--- |
| 表单宽度 | 单列 ≤ 640px 且左对齐；右栏可用宽 ≥ 44rem 时允许两列栅格（label 上置，禁止左右对齐的表格式 label）。**宽屏不得把单列拉宽**（1920 屏右栏可达 1200px，靠 `max-w` 收住，不是拉伸输入框） |
| 分区 | 用分区标题 + 分隔线分组，标题吸顶 `top-(--content-sticky-top)`；分区 ≤ 7 个，超出改抽屉/标签页 |
| 校验 | 字段级内联错误 + 顶部汇总（「N 项待修正」可点击跳到首错）；上游业务码（如 `10302`）映射到具体字段，不弹裸 toast |
| 脏检查 | `isDirty` 只在 `edit`/`create` 为真；切行、切页、关窗、路由离开统一走 `requestSwitch(next)`，脏则弹「留在本页 / 放弃并切换」（Stay 为默认焦点） |
| 保存成功 | 保持当前选中；列表**就地 patch** 或静默刷新（不重置滚动、不重选）；`create` 成功后 `?id` 由 `new` 变为真实 id（`replace`） |
| 保存失败 | 留在 edit 态、保留输入、错误就近展示；不得清空表单或退出编辑 |
| 空态 | 无选中：「从左侧选择一条记录查看详情」+ 主 CTA（新建） |
| 键盘 | Tab 顺序 = 视觉顺序；`⌘/Ctrl+Enter` 提交；`Esc` = 取消编辑（脏则确认） |

### D4 右栏内的关联数据（替代原「第三栏」）

- **位置**：右栏内、主表单之后的固定分区；**不新开栏、不新开二级主从**。分区顺序固定：**概览字段 → 关联表 → 活动 / 审计**。
- **上限**：≤ 2 张关联表，每张默认 ≤ 5 行 + 「查看全部」；「查看全部」跳转到该实体自己的页面，**不允许在右栏里再嵌「列表 → 详情」**。
- **只读**：关联表不承载主记录 CTA、不发起跨实体写操作；写操作只发生在主记录自己的表单里。
- **三态独立**：每张关联表各自 `pending` / `empty` / `error`，一张失败不影响主表单与其他表；无数据渲染「暂无关联数据」，不留白。
- **依赖顺序**：必须等 `?id` 就绪再请求；`create` 态用说明占位（「保存后可查看关联数据」）。
- **窄屏**：覆盖式形态下关联分区随主表单一起滚动，**不折叠成标签页**（同一信息只有一种查找路径）。
- **迁移关系**：1.0 `device.vue` 的 R 区（设备接口列表）迁到此分区。

### D5 单层工具栏与动作归属

| 区域 | 归属 | 内容 | 与两栏的关系 |
| :--- | :--- | :--- | :--- |
| **左区** | 布局层 `AppToolbar`（`app/layouts/default.vue`）的 `#app-toolbar-left`，页面经 `Teleport` 注入 | 面包屑（`topbar` 模式）、集合域动作（搜索 / 筛选 / 排序 / 批量 / 刷新） | 与列表栏同侧，作用于整份列表 |
| **右区** | 同一工具栏的 `#app-toolbar-right` | 记录域动作（含危险动作）、提交域动作、主 CTA（新建 / 保存） | 与详情栏同侧，作用于选中记录 |

**动作归属判定（三问，按顺序命中即停，只决定落在哪个区）**：

1. 这个动作改变的是**集合**（多条 / 全部）→ 左区。
2. 改变的是**单条**（含危险动作）→ 右区「记录域」组。
3. 只改变**当前未保存的编辑内容**（取消 / 保存）→ 右区「提交域」组。
4. 以上都不是（跨页、只读导航、全局）→ 不另开一条：右区最右，或留在页面内容里。

**硬约束**：

- **同一动作全页只有一个入口**；行内动作与工具栏动作不得重复（1.0 `system/user.vue` 的教训）。
- **一页至多一个 primary**：`create` 态的「创建」或 `edit` 态的「保存」；`view` 态无 primary，主 CTA 退为 `variant="outline"`。
- **危险动作**在右区（不是行内），`color="error" variant="outline"`，位于提交组左侧；批量危险动作在左区，仅在 `selectedCount > 0` 时出现，并带 `UKbd` 计数。
- **工具栏高度单一来源 `--app-toolbar-h`**（默认 49px 等值 rem），不得换行；放不下时右端折叠为 `⋯` 菜单，保留 primary 与危险动作，**不得整体隐藏**。
- **全页只有一层工具栏**：栏内不得再起 header（覆盖式与两栏共用这一层，内容按当前面板切换：列表态给集合域动作，详情态给左区「返回」+ 右区记录域 / 提交域动作）。
- **无动作时整条收起**：`Teleport` 内容不是父组件的响应式子节点，判空必须观测挂载点（`MutationObserver`），既无面包屑也无注入时收成 0 高。
- 图标按钮必须 `aria-label` + Tooltip（`UKbd` 显示快捷键）；`size="sm"` 统一。

### D6 选中、URL 与默认选中

- 唯一事实源：`?id=<记录标识>`；`create` 用 `?id=new`（或页面自定义的可识别占位），提交后 `replace` 为真实 id。
- **历史行为按形态决定，不按设备**：两栏 → `router.replace`（左右栏同屏，切换不产生历史）；覆盖式 → `router.push`（返回 = 回列表，浏览器/系统返回键即「返回」）。
- 深链进入：列表加载后自动选中；**只有命中当前 `rows` 的记录才能渲染详情**（无详情端点时这是唯一可靠来源）。未命中时右栏显示「该记录不在当前筛选 / 分页结果内」+「清除选择」，**不发详情请求、不静默翻页去捞**。
- `?id` 指向不存在的记录 → 右栏空态 + 一次提示，**不清空 URL**（不把上游抖动当成「已删除」）。
- 改筛选/翻页：保留 `?id`；若当前记录不在新结果集中，走上面的「未命中」分支，**不静默重选**。
- 默认选中：两栏形态默认启用（排序键与列表同源，只执行一次）；覆盖式不默认选中（否则首屏直接进详情，用户看不到列表）。
- 面包屑：路由段（`useNavigation` 自动）+ 记录段（末尾、无 `to`、点击清除选择），标签随数据到达自动更新。

### D7 反馈、空态与错误

- 四类反馈分工：**内联**（字段错误、栏内空态/错误）、**Toast**（写操作成功/失败，成功 1 条、失败保留可复制信息）、**Banner/Alert**（页面级口径说明，如身份可见范围）、**Modal**（破坏性确认、未保存确认）。
- 乐观更新只用于**幂等且可回滚**的动作（启停、置顶）；失败回滚到旧值并 toast，不整页重载。
- 上游业务码必须映射成人话（`accountError.ts` 已建立该模式），禁止直接把上游 `message` 抛给用户。
- 任何写操作都要有 `pending` 态（按钮 `loading` + 禁用），防止重复提交。

### D8 无障碍、键盘与密度

- 选中态双通道（背景 + 竖条 + `aria-selected`）；表格用 `UTable` 语义，列表用 `role="listbox"`/`option` 或表格均可，但必须与选中模型一致。**列表行必须可聚焦**（`tabindex="0"` + `Enter`/`Space` 选中 + `aria-selected`）；`UTable` 默认行不可聚焦，需要在行插槽补键盘绑定或在左栏改用自建 listbox。
- 命中区 ≥ 44×44px（移动端）/ 32×32px（桌面工具栏图标）；焦点环不可移除。
- 键盘：`⌘/Ctrl+K` 命令面板（`UDashboardSearch` 已有）、`⌘/Ctrl+Enter` 提交、`Esc` 取消编辑、`j/k` 或 `↑/↓` 在列表中移动选中（可选增强）、`⌘/Ctrl+S` 保存。
- 密度：`comfortable`（默认，行高 48）/ `compact`（行高 40，保留 2 行以上文本截断），按用户偏好存 `useUserPreferences`，不按断点自动切换。

### D9 前瞻性预留（不在本次实现）

- **离线草稿**：Tauri/移动端的 `edit` 草稿落本地（`useStorage`），重进提示「恢复上次未提交的修改」。
- **协作提示**：`?id` 级别的「他人正在编辑」占位（先留 slot，不实现实时通道）。
- **AI 辅助槽位**：D 区工具栏最右端预留一个 `ghost` 图标按钮位，用于「按自然语言填充表单」，不占主干布局。
- **命令面板纳入页面动作**：M/D 的工具栏动作同时注册进 `UDashboardSearch`，键盘用户不必找按钮。
- **面板布局记忆**：左栏宽度按「页面 id + 栏名」持久化到 `localStorage`（防抖写、双击复位），跨会话保持；不记忆折叠态（本基准没有折叠动作）。

## 四、被否方案

| 方案 | 否决理由 |
| :--- | :--- |
| 单一全局工具栏装全页动作（本 ADR 初稿的 L0 单层方案） | 1.0 的 `device.vue` 已是面板级工具栏，「搜索过滤左栏 / 保存保存右栏」的对应关系被单层方案破坏；且左区一旦容纳筛选，右区必然堆成 6–8 个按钮（`system/user.vue` 就是这么长的） |
| **固定第三列（关联栏常驻 / 可折叠）** | 三份证据都不支持：① 本仓 61 个页面里只有 1 个有表格、`/system/user` 仅 3 个端点且无关联接口 → 第三列长期是空壳；② 三栏需要 ≥ 80rem 容器，1366 默认窗（侧栏展开 1110px）放不下，实际会退成"两栏 + 空白"；③ 第三列的收益（少一次点击）远小于成本（多一个断点、多一套折叠规则、`UDashboardPanel` 无折叠能力）。**否决后关联数据改在右栏内分区实现（D4），形态数从 3 降到 2** |
| 三栏用百分比 + 可拖拽、两栏用固定宽（初稿的混合方案） | 同一组件两套尺寸语义，折叠顺序（R 先消失）还必须单向，等于把"当前几栏"编码进三张表；两栏化后只剩一个可拖拽维度，规则从 3 条降到 1 条 |
| 照抄 1.0：D 区默认即可编辑 | 脏状态常驻，任何切行都弹确认；且「查看」被迫承担写入口，误改面最大 |
| 照抄 1.0：行内 `edit`/`delete` 图标组 | 与工具栏重复入口；移动端命中区不足；「改哪一条」出现两个来源 |
| 详情用 `UModal` 而非分栏 | 无 URL 语义（不可分享、刷新即失）、与列表滚动互斥、无法承载关联分区；弹窗只保留给「无记录可依附」的一次性表单 |
| 用视口断点（`md:`/`lg:`）决定形态 | 侧栏折叠差 12rem、`topbar` 模式叠 1440px 限宽、分屏窄窗三种情况全部误判；两栏门槛必须读容器宽（`@container`） |
| 由设备（`isMobile`）决定 `push` / `replace` | 同一设备上宽度可变（拖动窗口、展开侧栏），形态会在一次会话里切换；历史行为必须跟**当前形态**走，否则桌面窄窗里按返回会跳回列表而不是上一条记录 |
| 覆盖式形态另做一套页面 / 另开路由 | 两份实现、两个回归面，`?id` 契约要维护两遍；同一组件的两种排列即可覆盖 |
| 继续用 `route.meta.breadcrumb` 承载记录段 | 路由记录级共享对象，多写入者互相覆盖，离开页面串标签 |
| 保留 `usePageToolbar()` 的模块级 `shallowRef` 并启用 | 模块级单例：同页多个组件实例互相覆盖写入（项目 `ssr: false`，不存在跨请求共享这一说）；且强制为动作另写 SFC |
| 四套独立布局（每模式一套页面） | 四份回归，模式切换时组件重建、选择与滚动全丢 |

## 五、迁移步骤

1. **机制层（零 UI 变更）**：高度合同（`default.vue` 内容容器 `flex min-h-0 flex-1 flex-col` + 页面根 `flex-1 min-h-0`）+ 工具栏挂载点 + `--app-toolbar-h` 单源化 + 删除 `usePageToolbar.ts`；`check:ui` 保持 70/70。
2. **选择与记录上下文**：`?id` 契约 + 命中判定 + 记录段派生 + 「记录不在当前结果集」空态用例。
3. **分栏原语**：`Layout/Split.vue` + `@container` 两档 + `usePaneResize`，用占位内容在 320 / 768 / 1024 / 1366 / 1440 / 1920 六档验证形态与滚动。
4. **首例落地**：`/system/user` 两栏（桌面）/ 覆盖式（窄），收紧行内动作、默认选中与 `sortKey` 同源；`edit` 态与脏守卫**挂起**（上游无 `PUT`）。
5. **回填**：`check:ui` 增加 3 条 `/system/user` 用例（含最小宽度与形态切换），同步脚本 summary 与 `NMCPS-ARCH-006` §7。

## 六、验收

- 六档容器宽（320 / 768 / 1024 / 1366 / 1440 / 1920）：`!isMobile` 且 ≥ 56rem → 两栏，否则覆盖式；**任何一档都无横向滚动、无嵌套滚动条**。
- 320px 下满足 `--page-min-w`：列表主操作可见、工具栏折叠为 `⋯` 而不换行。
- 两栏：右栏 ≥ 32rem；左栏可拖拽 18–28rem；双击复位 22rem；刷新后宽度保持。
- 覆盖式：点行 `push`，系统/浏览器返回键与工具栏「返回」都回列表；两栏不渲染「返回」，切行不产生历史记录。
- 行内动作 ≤ 1 且不与工具栏重复；一页 ≤ 1 个 primary；覆盖式只渲染一层工具栏。
- `edit` 态切行弹未保存确认（Stay 为默认焦点）；`view` 态切行无弹窗。
- 默认选中 = 列表第一行（同一 `sortKey`）；覆盖式不默认选中。
- `?id` 不在当前结果集 → 右栏空态 +「清除选择」，**零详情请求**。
- 选中记录后面包屑末位出现记录段，点击清除；`?id` 深链自动选中且列表滚动位置不变。
- 右栏无二级主从：关联表只有「查看全部」外链，没有内嵌列表 → 详情。
- `rg 'usePageToolbar'` 在代码中为 0 命中（仅历史文档）。

## 七、后续记录

### 7.1 2026-11-01：三段式收敛为两栏（左栏 / 右栏）

- **改动**：D1 由「M/D/R 三段式 + 折叠顺序」改为「两栏 + 覆盖式回退」；D4 由「R 区（第三栏）」改为「右栏内关联分区」；新增**最小页面宽度**常量（`--page-min-w` 20rem、`--split-min-w` 56rem、右栏 ≥ 32rem）；D6 的历史行为改按**形态**（两栏 `replace` / 覆盖式 `push`）而非按设备；D5 增加「覆盖式只渲染一层工具栏」与 `--app-toolbar-h` 单源。
- **依据**：① `/system/user` 仅 3 个端点（list / create / status）、无关联接口，第三列无数据可填；② 初稿三栏门槛 80rem 与 1366 默认窗（侧栏展开后可用 1110px）冲突，实机上第三列从未出现；③ `UDashboardPanel` 无 `collapsible`，其三栏尺寸走百分比 + cookie、主题内含 `min-h-svh` 与 `lg:` 视口断点，与本 ADR「不许视口断点」自相矛盾。
- **代价**：关联信息从「常驻第三栏」降为「右栏内滚动可见」，宽记录页多一次滚动；宽屏右栏需 `max-w` 收住表单，否则被拉稀。
- **不回退条件**：若将来出现「关联数据本身需要独立列表 + 详情」的域，优先把它做成独立页面并由关联表的「查看全部」跳转，**不恢复第三栏**。

### 7.2 2026-11-01：D5 由「两级分层」改为「单层 + 左右分区」

- **改动**：撤销 0.2.0 的 L0 / L1 分层 —— 内容页预留的 `AppToolbar` 是唯一一层，集合域动作进 `#app-toolbar-left`、记录域 / 提交域 / 主 CTA 进 `#app-toolbar-right`；栏内不再起 header；覆盖式与两栏共用这一层，内容随当前面板切换；记录标题（展示名 + 编号）下沉到右栏内容区顶部；「返回」由页面注入左区。
- **依据**：① 两层在窄窗必然叠成两条 49px（600px 视口吃掉 98px），而实机上 `/system/user` 的顶部预留工具栏长期是**空白**一条 —— 动作在栏内、L0 空转，用户直接问「操作按钮为什么不在 toolbar 里」；② `Teleport` 内容不是 `AppToolbar` 的响应式子节点，`computed` 判不出空，必须 `MutationObserver` 观测挂载点才能让「无动作整条收起」成立；③ 左右分区已足够表达作用域，栏内 header 未带来额外信息（只是把同一批按钮复制一行）。
- **代价**：记录标题不再有专属 49px 条（改为内容区标题），「搜索框紧贴它过滤的那一栏」的位置暗示变弱 —— 用左右分区（左区对应列表）补偿。
- **不回退条件**：若将来某页真的需要「栏内独立控件条」（例如多列筛选面板），先评估能否放进右区折叠菜单；**不恢复第二条 49px 工具条**。

### 7.3 2026-11-01：工具栏改为单一渲染点（修「侧栏模式下动作全丢」）

- **改动**：`app/layouts/default.vue` 原先把 `AppToolbar` 按模式渲染成两处（`v-if="isBigscreenMode"` 在滚动容器内、`v-if="!isBigscreenMode"` 在外）。改为**全模式只渲染一次、且位于滚动容器之外**；大屏模式的 `sticky top-0` 因此成为无副作用的空操作，`--content-sticky-top` 恒为 `0px`。
- **依据**：`<Teleport>` 在挂载时绑定目标节点。切换布局模式时旧挂载点被销毁重建，页面注入的内容留在**已脱离文档的子树**里 —— 实测侧栏模式 `bars=1, h=0, leftKids=0, rightKids=0`：工具栏还在，搜索框与全部按钮为空。这与 0.2.0 的 D5 无关，是渲染点数量的问题，因此只改布局，不动工具栏契约。
- **代价**：无 UI 代价；布局层失去「按模式微调工具栏位置」的能力（本来也没有用到）。
- **不回退条件**：**不得**再为任何模式新增第二个 `AppToolbar` 渲染点。需要模式差异时改 `AppToolbar` 内部的样式，不要改渲染点数量。`check:ui` 的「偏好设置 → 侧栏后动作仍在」用例守这条线。

| 空态 | 各页自写（`hidden lg:flex` 居中块） | 统一栏内空态 + 主 CTA |

## 附录 C：行业对标与前瞻取舍

| 参考 | 采纳 | 不采纳 |
| :--- | :--- | :--- |
| SAP Fiori **List Report + Object Page** floorplan | 列表工具栏（筛选 + 批量 + 计数）与对象页 header（标题 + 动作 + 保存/取消）分离；draft 状态切行拦截 | 复杂的 filter bar 弹出面板（本仓筛选字段少，内联即可） |
| Material 3 **canonical list-detail** | supporting pane → two-pane 的两档收敛（对应 56rem 门槛），覆盖式作为窄容器回退 | 折叠为 label/tab 的层级导航（与面包屑冲突） |
| Apple HIG **split view** | 侧栏固定宽 320–375pt 的口径（对应 20–24rem 左栏） | 三栏 + 覆盖式 sidebar 的移动端叠加 |
| Azure Portal / AWS Console | 可拖拽分隔 + 记住宽度（本 ADR 只保留一个拖拽维度） | 顶部「服务抽屉」式的多级导航 |
| Ant Design Pro `ProTable` + 抽屉详情 | 批量动作带计数、列设置下拉 | 抽屉承载详情（无 URL 语义） |
| Carbon **data table + side panel** | 侧面板 16–24rem、只读关联信息作为**参考** | 侧面板作为**第三栏常驻**、且承担主表单 —— 本仓无数据源，第三列长期空壳（见"被否方案"） |
| 前瞻：命令面板 / 乐观更新 / 离线草稿 / AI 槽位 | 见 D9 预留 | 实时协作通道（本轮只留 slot） |

> 取舍原则：**能在同一层解决的，不加层**。行业里「抽屉详情 + 弹窗编辑 + 分栏详情」三种范式并存的方案一律不采纳 —— 本仓页面数量有限，一致性收益远大于灵活度收益。
