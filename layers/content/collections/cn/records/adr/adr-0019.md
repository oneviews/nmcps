# ADR-0019：六层迁移的三项前置裁决

> **层级**：Tier 5 记录层 —— 正文发布后只追加；细则补充用 `##` 追加节。
> **与基准文档的关系**：本 ADR 只回答「能不能做、按什么边界做」，**不承载字段级契约**。字段与页面形态的权威仍是 `NMCPS-DESIGN-001`（`domain.topology`）、`NMCPS-DESIGN-002`（`domain.spectrum`）、`NMCPS-DESIGN-003`（`domain.transmission`）、`NMCPS-DESIGN-004`（`domain.device`）、`NMCPS-DESIGN-006`（`domain.scenario`）、`NMCPS-DESIGN-007`（`domain.dashboard`），数据源权威是 `NMCPS-ARCH-002`（`arch.datasource`），类型权威是 `NMCPS-CONTRACT-001`（`contract.shared-types`）。冲突时以基准文档为准；基准文档须按 §七 随本次裁决同步升版。
> **与 `NMCPS-ADR-0018` 的关系**：ADR-0018 裁定的是 8888 统一网关的**唯一主上游**事实与本代契约形态；本 ADR 在其之上追加**第二个出站通道**（仿真平台 8001），因此对 ADR-0018 D1 是**补充而非作废**——`bff.upstreamBase` 仍是业务数据的唯一上游，仿真平台只承载「仿真控制面」。
> **状态说明**：三项裁决已由需求方于 2026-11-05 确认执行（门 A / 门 C 授权我按技术判断定稿；门 B 由需求方实测 `http://192.168.1.55:8001/docs` 与 `/openapi.json` 均可达后确认通道存在）。

## 一、裁决（速览）

| 编号 | 裁决 | 门 | 依据 |
| :--- | :--- | :---: | :--- |
| **D1** | **不引入** `@antv/g6` / `@unovis` / ECharts 等图形库 | A | §三 3.1 |
| **D2** | 图形能力收敛为 2.0 自有的四个渲染组件（`TopologyCanvas` / `TrendChart` / `SpectrumWaterfall` / `SparkStat`），一律自绘（SVG 为主，Canvas 2D 仅用于高密度瀑布与频谱扫描） | A | §三 3.2 |
| **D3** | 1.0 的**纯 TS 计算层**按文件粒度搬运；**含库 import 的 13,135 行不搬**（占六层 65,946 行的 20%） | A | §二 2.3 |
| **D4** | 新增「仿真平台」`http://192.168.1.55:8001` 为 BFF **第二出站通道**：独立配置 `runtimeConfig.simulator`、独立 client `server/utils/bff/simulator.ts`、独立路由前缀 `server/api/sim/**`；**不复用** `server/api/[...slug].ts` 与 `proxyToUpstream` | B | §四 4.1 |
| **D5** | 仿真平台出站走**显式白名单**（动词 + 路径模板，模板匹配而非前缀放行），白名单以其实测 `/openapi.json`（113 条路径 / 16 个 tag）为机械来源；`check:bff` 新增「白名单 ⊆ openapi」断言 | B | §四 4.2 / 4.5 |
| **D6** | **永久不进白名单**：`POST /api/network/nodes/{node_id}/execute`（节点内命令执行）、`/api/browser/**`（无头浏览器与代理）、`/api/integrity/watch/**`（后台守护）。与 `.clinerules` 永不开 `shell:allow-execute` 同源 | B | §四 4.3 |
| **D7** | 仿真平台是**写型控制面**：`runtimeConfig.simulator.allowWrite` 默认 `false`；写端点须显式开启 + 二次确认 + 审计日志 | B | §四 4.4 |
| **D8** | BFF **不得**成为通用业务状态宿主：只允许无状态纯函数式派生/计算，**禁止进程内可变台账**（1.0 的 `globalThis` 单例与 Nitro 内存 store 一律不搬） | C | §五 5.1 / 5.3 |
| **D9** | 逐域裁决：**RRM/频点池 = 算法搬、状态不搬**；**mesh 边台账 = 只读**；**route 策略 = 只算不存**；**场景筹划的 netforge/topoWizard = 留在客户端** | C | §五 5.2 |
| **D10** | 六层落码的**唯一门禁**：§七 五项文档义务（DESIGN 逐层升版 / ARCH-002 增数据源 / CONTRACT 增类型 / `check:bff` 新增断言 / i18n 词条）全部完成后方可动业务代码 | A+B+C | §七 |
| **D11** | 工作量基线 **57~82 人日**（±20~30%，未含逐页 `check:ui` 与全量文案），按 P1~P4 四批推进；**传输管控（iframe 复用，1~2 人日）与频谱 view/waterfall 为零裁决快赢** | — | §六 |

### 2.1 两侧上游

| 上游 | 地址 | 可达性 | 契约来源 | 实测要点 |

### 2.2 2.0 现状

- 29 个目标页齐备，均为 **7 行占位**，与 1.0 页面 1:1 对齐，i18n 标题/描述已就位；`grep` 数据层调用（`/api/v1/`）= **0 命中**（即无历史包袱，也无既有契约可破坏）。
- BFF 是**单上游架构**：`server/api/[...slug].ts` → `resolveGatewayTarget()`（`shared/types/api.ts` 的 `GATEWAY_RESOURCES` 白名单 + 动词集合）→ `proxyToUpstream()`。通道只有一条，`GET /ready` 也只看这一条。
- 依赖面：无 `@antv/g6`、无 `@unovis`、无任何图表库；图形与图表能力为**零**。

**结论**：13,135 行（20.0%）与图形库强绑定，**不可直接搬运**；剩下 52,811 行里，布局算法（`topologyLayout` / `topologyLayering` / `topologyRadialLayout` / `topologyTierTreeLayout` / `topologyEdgeStyle`）、频谱 DSP（`spectrumDsp` / `spectrumSynthetic`）、状态映射与格式化函数都是**纯 TS**，与渲染器无耦合。这条边界正好落在 `import` 上，是 D1/D3 成立的关键证据——**换渲染器不等于重写领域逻辑**。

## 三、裁决 A：图形与图表自绘（D1 / D2 / D3）

### 3.1 为什么不自带图形库

| 判据 | 说明 |
| :--- | :--- |
| **需求形状固定** | 六层只需要四类图形：分层/径向**拓扑图**、时间序列**趋势线**、频谱**瀑布/扫描条**、**单值卡与仪表**。这是「特定形状」，不是通用 BI（无联动钻取、无自定义指标编排、无多轴组合）。 |
| **包体与运行环境** | 2.0 是 Tauri 桌面 + `ssr: false` 的浏览器应用，`@antv/g6` 及其扩展属重量级依赖；引入即与「不新增依赖」的项目约束冲突，且离线包与 CSP 面都要重估。 |
| **代码可控性** | 自绘代码在仓内，`check:ui` 能断言、`typecheck` 能覆盖；库的黑盒布局一旦出偏差，只能靠猜。 |
| **复用边界清晰** | §2.3 已证明计算层与渲染层可分离：52,811 行纯 TS 可搬，只有 13,135 行因 `import` 而失效。 |

### 3.2 四个渲染组件（唯一渲染入口）

| 组件 | 位置 | 载体 | 覆盖页面 | 说明 |
| :--- | :--- | :--- | :--- | :--- |
| `TopologyCanvas` | `app/components/Graph/TopologyCanvas.vue` | SVG（节点 ≤ 400）+ 等距投影模拟 2.5D | 拓扑监控、设备组网、场景筹划、系统全景迷你拓扑 | 布局由纯函数注入（分层 / 径向 / 树；力导向降级为固定网格），**不做真 3D**：1.0 的 `topology3dLayouts` 只取投影公式 |
| `TrendChart` | `app/components/Graph/TrendChart.vue` | SVG polyline + 面积填充 | 设备/链路指标、告警趋势、频谱占用趋势 | 阈值带、区间选择、游标读数；点数 > 2,000 时按像素列聚合（保留极值） |
| `SpectrumWaterfall` | `app/components/Graph/SpectrumWaterfall.vue` | Canvas 2D（`ImageData`） | 频谱瀑布、实时扫描 | 逐像素高密度写入，SVG 不适用；DPR 自适应，帧率上限 30fps |
| `SparkStat` | `app/components/Graph/SparkStat.vue` | SVG | 系统全景卡片徽标 | 单值 + 迷你趋势 + 状态色，替代 1.0 里散落的 unovis 小图 |

页面**不得**各自创建 canvas、各自写 `requestAnimationFrame`；需要新图形形态时，先扩这四个组件或另立 ADR。

### 3.3 硬约束

1. **单一渲染入口**：图形只通过上述四组件出现，页面传数据与布局名，不传绘图指令。
2. **降采样与上限**：`TopologyCanvas` 节点上限 400、边上限 1,200，超出按权重裁剪并显示「已裁剪 N 个」；`TrendChart` 按像素列聚合；`SpectrumWaterfall` 单帧写入上限 5 MB。
3. **尺寸与 DPR**：一律 `ResizeObserver` 驱动重算，配 `useDevicePixelRatio`；不得读 `window.innerWidth` 做布局决策（违反 `NMCPS-ARCH-006` 的容器查询收敛原则）。
4. **动效克制**：遵循 `prefers-reduced-motion`，关闭路径动画与呼吸高亮；不做无必要的持续 `rAF` 循环（瀑布仅在流式数据到达时重绘）。
5. **三态完整**：空（无节点/无数据）、加载（`USkeleton`）、错误（`UAlert` + 重试）必须实现，不允许「白屏即无数据」。
6. **可达性兜底**：拓扑与趋势图必须提供「列表视图」等价信息（可键盘遍历）；图形本身 `role="img"` + `aria-label`。

### 3.4 否决条件（何时可以重启「引入库」）

若后续出现**通用 BI 需求**——多指标联动、下钻、用户自定义看板编排、或需要真三维透视——则**不在本裁决下扩张**，另立 ADR 评估引入图表库，并把已自绘组件作为兼容层保留。

### 3.5 风险与缓解

| 风险 | 缓解 |
| :--- | :--- |
| 自绘交互（拖拽、缩放、命中测试）工期估低 | P1 先在拓扑监控一个页面打通交互内核再复用；交互代码集中在 `app/composables/useGraphInteraction.ts` |
| 大图性能不达标 | 上限 + 裁剪 + 像素聚合三重保护；实测数据（36 节点 / 48 边）远低于上限 |
| 与 Nuxt UI 视觉不一致 | 颜色/间距一律读 `app.config.ts` 与 CSS 变量，不硬编码色值 |

## 四、裁决 B：仿真平台作为第二上游（D4 ~ D7）

### 4.1 通道形态（代码级落点）

| 段位 | 落点 | 要求 |
| :--- | :--- | :--- |
| 配置 | `nuxt.config.ts` → `runtimeConfig.simulator = { baseUrl: "", allowWrite: false, timeoutMs: 15000, readinessPath: "/api/health" }` | 全部可被 `NUXT_SIMULATOR_*` 覆盖；`baseUrl` 为空 = **通道未启用**，页面降级为只读/未接入态，不得抛错 |
| 读配置 | `server/utils/bff/simConfig.ts` | 形状对齐 `getBffConfig()`：缺省值集中一处，`baseUrl` 去尾斜杠，`allowWrite` 严格布尔 |
| 出站 | `server/utils/bff/simulator.ts` | **不注入 `Authorization`**、不读 `nmcps_at` cookie、不透传前端自定义头（仅 `accept` / `content-type`）；超时与 `AbortSignal`；响应归一为 `ApiResponse` |
| 路由 | `server/api/sim/[...slug].ts` → `resolveSimulatorTarget()` | **模板匹配**（`{param}` 占位），非前缀放行；未命中 → 404 `bff_resource_not_allowed`；动词不符 → 405；段内 `.` / `..` / `/` / `\` / NUL 拒绝（与 `resolveGatewayTarget` 同口径） |
| 白名单表 | `shared/constants/simulatorRoutes.ts` | 逐条登记 `{ method, template, write }`；`write: true` 的条目在 `allowWrite === false` 时直接 405 |

**为什么不复用 `server/api/[...slug].ts`**：`proxyToUpstream()` 会读 token cookie 转 `Bearer` 并参与 401 单飞刷新。把 Bearer 发往一个**无鉴权的仿真平台**等于凭据外泄（与 1.0 `proxySimulator.ts` 单独出站的取舍一致）。同时 401 语义不同：仿真平台的 401 不应触发会话刷新或登出。

### 4.2 白名单草案（按页面实际用量，非全量开放）

| 层 | 读（GET） | 写（`write: true`） |
| :--- | :--- | :--- |
| 拓扑监控 | `GET /api/network/runtime-inventory`（一次返回 `nodes[]` + `links[]`，实测 36/48）、`GET /api/network/stats`、`GET /api/lldp/summary`、`GET /api/lldp/neighbors/{node_id}`、`GET /api/network/runtime/preview` | `POST /api/network/links/{link_id}/{down,up,toggle,disable,power,reconfigure}`、`PATCH /api/network/links/{link_id}/{tc,radio}`、`POST /api/network/nodes/{node_id}/{start,stop,restart,power}`、`PATCH /api/network/nodes/{node_id}/{radio,ip}`、`POST /api/network/runtime/{nodes,links}`、`DELETE /api/network/runtime/{nodes,links}/{id}` |
| 设备组网 | `/api/devices`、`/api/devices/importable`、`/api/devices/{dev_id}`、`/api/configs`、`/api/configs/{name}`、`/api/configs/{name}/topology-preview`、`/api/network/snmp-accounts`、`/api/network/wireless-nodes` | `/api/devices/import`、`/api/configs/{name}`（建/改，`POST`）、`/api/configs/{name}`（删，`DELETE`）、`/api/configs/{name}/snmp-v3` |
| 场景筹划 | `/api/simulation/engines`、`/api/simulation/sessions`、`/api/simulation/sessions/{sim_id}/{status,topology,connectivity,diagnostics,build-plan,boot-progress}`、`/api/network/overrides/{scenario}`、`/api/metrics/summary/{sim_id}` | `/api/simulation/sessions`（建）、`/api/simulation/sessions/{sim_id}/{start,stop,pause,resume,trigger,bgtraffic}`、`/api/simulation/sessions/{sim_id}`（`DELETE`，销毁） |
| 传输管控 | `/api/protocol/catalog`、`/api/protocol/catalog/{protocol_id}`、`/api/protocol/comparison-config/{scenario}`、`/api/protocol/transport/{scenario}`、`/api/protocol/sessions/{sim_id}` | `POST /api/protocol/compare`、`/api/protocol/sessions/{sim_id}/set` |
| 频谱管控 | `/api/network/wireless-nodes`、`/api/weaknet/presets`、`/api/weaknet/profiles`、`/api/weaknet/current` | `/api/weaknet/sessions/{sim_id}/{apply,clear}`、`PATCH /api/network/nodes/{node_id}/radio` |
| 系统全景 | `/api/simulation/sessions`（只读徽标）、`/api/metrics/summary/{sim_id}` | — |

> 规则：每层**只登记该层页面真正调用的条目**。这与 ADR-0018 D2 的「命名空间先整组登记」不同——那是同一上游内的路径分组，这里是**跨上游的能力授权**，授权粒度必须到端点。

> **2026-11-05 按实测 `openapi.json` 复核修正**（本节初稿凭 1.0 记忆登记，动词有四处错）：
> ① `/api/network/runtime/nodes`、`/api/network/runtime/links` 实为 **POST**（运行时新建），其 `{id}` 子路径实为 **DELETE**；只读全量走 `GET /api/network/runtime-inventory`——按旧表取列表会拿到 405。
> ② `tc` / `radio` / `ip` 是 **PATCH**（参数化改属性），不是 POST；`power` 在节点与链路上都是 POST。
> ③ `POST /api/configs` 不存在（`/api/configs` 只有 GET），新建与修改都走 `POST /api/configs/{name}`。
> ④ `POST /api/protocol/compare` 是写语义端点（会落一次对比计算），不是 GET；`GET /api/simulation/sessions/{sim_id}` 不存在，状态走 `.../status`，该路径的 GET 是 404 而 DELETE 是销毁会话。
> ⑤ 同日复核网关侧：`openapi.json` 现为 **127 条路径**（§2.1 记录的 131 条已随上游小幅变更漂移），`/metric/{datapoint,definition,device,link,name}` 六条端点未变，`metric_ListDatapointResp` / `metric_Datapoint` 两个 schema 与 `NMCPS-CONTRACT-002` §六 一致。

### 4.3 永久排除（不在白名单，需要时另立 ADR）

| 端点 | 排除理由 |
| :--- | :--- |
| `POST /api/network/nodes/{node_id}/execute` | **节点内任意命令执行**，与 `.clinerules` 永久禁止 `shell:allow-execute` 同类；开放即等于把宿主 shell 暴露给前端 |
| `/api/browser/{sim_id}/{capture,proxies,start,stop}` | 无头浏览器与代理进程控制：既是任意 URL 抓取（SSRF 面），又是旁路出网 |
| `/api/integrity/watch/{start,stop}` | 在仿真平台侧起后台守护任务；BFF 不该成为长驻任务发起者（见 D8） |
| `/api/devices/clear` | 清空设备台账的破坏性操作，无页面需求 |
| `/api/test/{ping,traceroute,mtr,iperf,lldp,netcat}` | 主动网络探测，可能被当作内网扫描工具；需要时按「单独能力 + 单独确认框」另立 ADR |
| `/api/snmp/onboard/**`（`rotate` / `revoke` / `export` / `live`） | 凭据轮换与凭据导出，敏感度高于只读台账 |
| `/api/nms/vmagent/reload`、`/api/nms/vmagent/targets/{scenario}` | 修改采集侧配置，属部署面而非展示面 |

### 4.4 未鉴权上游的风险与护栏

仿真平台实测**无鉴权头要求**，因此护栏只能落在 BFF 侧：

1. **默认关闭**：`baseUrl` 为空时通道不存在，任何 `/api/sim/**` 请求返回 503 `simulator_not_configured`（与 `/ready` 的未配上游口径一致）。
2. **写开关**：`allowWrite` 默认 `false`，全部写端点返回 405，页面以只读态呈现并标注「仿真控制未启用」。
3. **不携带凭据**：出站头白名单只有 `accept` / `content-type`；`check:bff` 的假上游断言「未出现 `authorization` 头」。
4. **来源受控**：浏览器侧 CORS 仍由 BFF 的 `allowedOrigins` 决定；Tauri 侧不直连 8001（桌面 WebView 只认 `bffBase`）。
5. **审计**：所有 `write: true` 调用在 BFF 侧记一条结构化日志（`sim write <method> <template> <status> <duration>`），不含请求体。
6. **就绪分离**：仿真平台不可达**不得**让 `/ready` 变红——它只影响依赖它的页面，页面显示局部降级，避免把一个可选上游的抖动升级为全站不可用。

### 4.5 守卫（`check:bff` 新增第 ⑨ 组）

| 断言 | 说明 |
| :--- | :--- |
| ⑨-1 | 未配 `simulator.baseUrl` → `/api/sim/**` 返回 503 且信封为 `ApiResponse` |
| ⑨-2 | 白名单内路径到达假上游；白名单外 404；动词不符 405 |
| ⑨-3 | 路径穿越（`..`、`%2e%2e`、含 `/` 的段）→ 400 |
| ⑨-4 | `allowWrite: false` 时写端点 405；`true` 时到达假上游 |
| ⑨-5 | 出站请求头**不含** `authorization`，且不读 `nmcps_at` |
| ⑨-6 | **白名单 ⊆ `/openapi.json` 的 `paths`**：脚本读 `shared/constants/simulatorRoutes.ts`，把每条模板的 `{param}` 归一后与快照 `scripts/fixtures/simulator-openapi.json` 比对；快照过期（`info.version` 与实测不符）只告警不红，避免上游升级把 CI 拖红 |

⑨-6 是把需求方实测到的 `/openapi.json` 转成治理收益的关键：1.0 时代的仿真代理只能靠人工逐条记端点，现在白名单**可机械校验**——新增条目漏登记、上游改名、模板写错都能被发现，而生成本就是一条 `curl`。

## 五、裁决 C：BFF 本地引擎边界（D8 / D9）

### 5.1 四条准入（缺一不许落码）

| 编号 | 条件 | 反面（不许） |
| :--- | :--- | :--- |
| C-1 | **纯函数、无进程内可变状态**：输入 → 输出，同一输入同一输出 | `globalThis` 单例、模块级 `Map`/`Set` 台账、`setInterval` 后台刷新 |
| C-2 | **要么只读派生，要么写回真实上游**：BFF 不持有「第二本账」 | 在 BFF 里维护一份只有自己认的设备/链路/策略状态 |
| C-3 | **命名与路由专属**：实现放 `server/utils/engine/<domain>/*`，接口放 `server/api/<domain>/…`，**不经过** `[...slug]` 网关 | 把引擎端点塞进资源白名单，混进业务数据通道 |
| C-4 | **登记三元组**：`页面 → 端点 → 引擎文件` 逐条写进本 ADR（§5.2 表），表里没有的组合不许实现 | 「顺手加个接口」 |

### 5.2 逐域裁决

| 页面 / 能力 | 1.0 来源 | 2.0 落点 | 状态归属 | 结论 |
| :--- | :--- | :--- | :--- | :--- |
| 频谱频点池（pool） | `server/utils/rrm/*`（约 2,337 行确定性算法：频点池、信道规划、冲突检测） | `server/utils/engine/rrm/*`（纯函数）+ `server/api/spectrum/pool.get.ts` | **不持久化**：AP 输入读 8888 `/frequency/wifi/aps`，候选与冲突在请求内算完即弃；「锁定/保护」改为客户端会话态 | ✅ 引擎搬、状态不搬 |
| 频谱推荐 / RRM | 同上（`recommend` / `plan`） | 同上（同引擎不同出口） | 同上 | ✅ 引擎搬 |
| 频谱视图 / 瀑布 / 分辨率 | `layers/spectrum` 手写 Canvas/WebGL2 + `spectrumDsp`（零外部依赖） | 客户端 `SpectrumWaterfall` + 纯 DSP 函数 | 客户端 | ✅ 直接搬运（零裁决） |
| mesh 边台账 | `server/utils/mesh/edge-store.ts` + `server/api/mesh/edge/index.get.ts` | **无**（不建等价物） | 只读：`/topology/graph` + `/metric/link` | ⚠️ 降级为只读；1.0 的写 CRUD 不迁移（它是 mock，落码即造第二本台账） |
| route 策略 / 演练 | `shared/route-engine`（纯 TS，可搬）+ `memory-policy-store`（Nitro 内存） | `server/utils/engine/route/*` + `server/api/route/plan.post.ts` | **只算不存**：策略由前端持有并随请求提交；部署/演练按钮标「未实现」 | ✅ 引擎搬、store 不搬 |
| 场景筹划 netforge / topoWizard | `layers/scenario` 客户端引擎 | 留在客户端 composable | 客户端 | ✅ 不占 BFF |
| 拓扑布局计算 | `topologyLayout` / `topologyLayering` / `topologyRadialLayout` / `topologyTierTreeLayout` / `topologyEdgeStyle` | `app/utils/graph/*`（客户端纯函数） | 客户端 | ✅ 直接搬运 |

> 上游缺口的处置：8888 没有 `spectrum` / `rrm` / `mesh` / `route` / `simulation` 命名空间（ADR-0018 §4.3 的 G9 / G10 同源结论）。本 ADR 不申请新增上游能力，只在 §5.2 的边界内用「已有数据 + 纯计算」拼出页面；**任何需要上游持久化的诉求都回到上游立项**，不在 BFF 里兜。

### 5.3 反模式清单（明确不搬）

- `globalThis` 单例（1.0 mesh / rrm 的状态宿主）。
- Nitro 内存 store 充当业务数据库。
- BFF 侧定时拉取 + 缓存（应由前端按需拉，或用上游 SSE）。
- 在 BFF 里实现「策略下发」——没有上游端点支撑时，`deploy` 一律返回 501 并在页面标注。

### 5.4 守卫与测试

| 项 | 要求 |
| :--- | :--- |
| 单测 | `server/utils/engine/**` 每文件至少一组输入输出用例，跑在 Node 内置 `node --test`（零新依赖；项目当前无 vitest，本 ADR 不引入测试框架） |
| 静态约束 | `check:bff` 断言「`/api/*` 的业务数据出站仍只有 `proxyToUpstream` 一处」；引擎端点不得出现在 `GATEWAY_RESOURCES` |
| 文档同步 | §5.2 三元组新增/删除必须同批改本 ADR（追加节） |

## 八、被否决的选项

| 选项 | 否决理由 | 何时可重启 |
| :--- | :--- | :--- |
| 引入 `@antv/g6` 复用 1.0 渲染层 | 重量级依赖 + 与「不新增依赖」冲突；且 1.0 渲染层与 2.0 的 Nuxt UI / 容器查询模型不一致，搬运后仍需大改 | 出现通用 BI 需求（§3.4） |
| 让 `proxyToUpstream` 兼顾仿真平台 | Bearer 会发往无鉴权上游；401 语义混用会误触发刷新/登出 | 永不（分通道才安全） |
| 仿真平台「整命名空间放行」 | 该上游含命令执行、无头浏览器、凭据轮换等端点，前缀放行等于全开 | 永不 |
| 在 BFF 承载 mesh / rrm 的可变台账 | 造第二本账，与 8888 单一事实源冲突；重启即丢，多实例即分叉 | 上游出现对应持久化服务后改为读写上游 |
| 迁移 1.0 `memory-policy-store` 做 route 策略持久化 | 同上；且 1.0 里它就是 mock | 上游 `/route` 命名空间落地 |
| 六层一次性全量迁移 | 无中间验证点，风险集中在最后；且 A/B/C 三项未验证前任何一层都可能返工 | 不适用 |
