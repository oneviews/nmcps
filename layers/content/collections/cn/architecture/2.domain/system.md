# 系统管理领域基准（NMCPS-DESIGN-005）

> **本文职责**：`domain.system` 域的唯一权威，定义系统管理——系统日志、策略管理、用户与权限管理。身份与访问控制的架构基准见 `NMCPS-ARCH-003`。
> **目标读者**：实施工程师 / AI 助手。
> **代际提示（2026-11-04）**：后端已整体切换至 `http://192.168.1.55:8888/api/v1` 的 NMS 统一网关，第六 / 七 / 八 / 九节的端点与字段（`/api/v1/account`、`/api/v1/role`、`/api/v1/audit`、`accountLevel`、`/abac/rule`、`/access/dryrun`、`/audit/export`、`/audit/verify`）对应**旧代**，须按新代契约（`iam` / `audit` 命名空间）重写；重写完成前以联调实测为准，切换的记录见记录层索引（`NMCPS-GOV-003`）。

---

## 一、定位

系统管理是网络管理系统的「治理面」：管理系统的运行日志、全局策略、用户账号与权限分配，是 IAM 架构（见 `NMCPS-ARCH-003`）的落地界面。

---

## 二、功能范围

| 子页面 | 功能 |
| :--- | :--- |
| log | 审计日志：列表查询、详情、链式校验与导出（`/system/log`） |
| policy | 全局策略管理 |
| user | 用户账号管理 |
| permission | 权限分配（角色/策略绑定） |
| download | 客户端安装包下载中心（按 UA 检测平台，链接直指 GitHub Release，不代理二进制） |

## 三、关键数据实体

| 实体 | 说明 |
| :--- | :--- |
| 日志（Audit Log） | 只增不改的操作审计轨迹 |
| 策略（Policy） | ABAC 策略文档 |
| 用户（User） | 账号与角色绑定 |
| 权限（Permission） | 角色 → 权限映射 |

## 四、领域边界与依赖

- **上游依赖**：IAM 架构（RBAC + ABAC、多租户、审计，见 `NMCPS-ARCH-003`）。
- **消费方**：全系统（统一鉴权）。
- **不承载**：底层认证协议实现（属 IAM `NMCPS-ARCH-003`）。

## 六、`/system/user` 用户管理（落码基准）

> 口径来源：2026-11-01 与 **2026-11-03 复测**对 `http://192.168.1.55:8888/api/v1` 的实调（超级管理员 / 租户管理员双身份穷举）+ swagger 比对。与契约不符处登记在 `NMCPS-REC-002`（`layers/content/collections/cn/records/defects/account-upstream-defects.md`），本节只写「页面能依赖什么」。

### 6.1 数据源与端点

| 能力 | BFF 路径 | 上游 | 说明 |
| :--- | :--- | :--- | :--- |
| 列表 | `GET /api/account` | `GET /api/v1/account` | `page` / `pageSize` / `keyword` / `accountLevel` / `status` |
| 建号 | `POST /api/account` | `POST /api/v1/account` | `accountName` / `displayName` / `password` / `accountLevel` 必填；**超级管理员另需 `tenantId`**（正值，`0` 视同缺省）；`mfaEnabled` / `mustResetPassword` 可选 |
| 改状态 | `PUT /api/account/{accountCode}/status` | 同 | body `{ status }`，返回 `{ ok: true }` |
| 详情 | `GET /api/account/{accountCode}` | 同 | 页面不单独调用：列表已含全部展示字段 |
| 租户列表 | `GET /api/tenant` | 同 | 超级管理员建号时选 `tenantId` 的唯一来源；返回 `list` / `total` / `page` / `pageSize`，条目含 `tenantId` / `tenantCode` / `tenantName` |

- 路径段 `{id}` 实为 `accountCode`（`ACC…`），不是 `accountId`。
- **没有改资料端点**（无 `PUT /api/v1/account/{id}`），也没有删号端点：`displayName` 建号后不可改，「删除」语义由 `status=2`（禁用）承接。
- BFF 白名单需含 `account`（`shared/types/api.ts` 的 `GATEWAY_RESOURCES`），否则一律 `404 bff_resource_not_allowed`。

### 6.2 字段口径

- `accountLevel`：`0` 平台超级管理员（`tenantId: 0`）/ `1` 租户管理员 / `2`–`3` 租户层下级账号 / `4` 服务账号（上游原文「服务账号由系统自动开通」，手工建号回 `20102`）。**建号可选等级 = 严格低于自己**（数字更大）且 `≤ 3`：超级管理员 `1`–`3`，租户管理员 `2`–`3`；同级或更高回 `20103`「只能向下管控」。列表里 `1`–`3` 之外的等级仍按「未定义等级」只读展示。
- `status`：`1` 启用 / `2` 禁用 / `3` 锁定 / `4` 待激活（swagger 口径）。写入 `0` 或 `5` → `10101`；`4` 由建号时的 `mustResetPassword` 决定，页面不主动写 `4`。
- `createdAt`：`GET` 返回本地时、`POST` 返回 UTC（同一字段两种时区）→ 页面原样展示，不做时区换算（UP-ACC-05）。
- 列表**不含** `tenantId` / `tenantCode` / `email` / `phone`：页面不展示租户归属，也不做「邮箱 / 手机」列（v1 那套字段上游没有）。
- `accountName` 唯一：重复 → `10302`；`accountLevel=0` 作为**过滤条件**会被上游当「未提供」（零值）→ 返回全量，页面不提供「只看超级管理员」筛选项（UP-ACC-02）。

### 6.3 权限矩阵（实测）

| 动作 | 超级管理员（`accountLevel: 0`，`tenantId: 0`） | 租户管理员（`accountLevel: 1`，`tenantId ≥ 1`） |
| :--- | :--- | :--- |
| 列表范围 | 全平台 | 仅本租户 |
| 建号 | 可建 `1`–`3`，**必须显式带 `tenantId`**（`0` 或缺失 → `10101 缺少必填参数 tenantId`） | 可建 `2` / `3`（`tenantId` 由令牌推断，无需传）；`0` / `1` → `20103 只能向下管控` |
| 建号等级上限 | `4` → `20102 账号等级与归属层不匹配…服务账号由系统自动开通`；`> 4` → `10101` | 同 |
| 改状态 | 任意账号 | 仅本租户账号，跨租户 → `10301` |
| 角色分配 `POST /api/account/role` | 恒 `10201`（域拒绝） | 本租户账号可分配 / 解除 |
| 租户成员 `POST /api/tenant/{id}/member` | 可调 | 本租户可调 |

> 2026-11-03 复测更正：0.5.6 之前矩阵里「租户管理员实测可建 `0` / `2` / `4`（应拒绝）」已经过期 —— 上游现在按「只能向下管控」拦同级与更高等级（`20103`），并把 `4` 归为「服务账号由系统自动开通」（`20102`）。同一轮复测还发现建号新增了 `tenantId` 必填，超级管理员不带该字段时**建号必然失败**（`10101`），这条缺口登记为 `UP-ACC-07`。

客户端收敛（**不是安全边界**，只为不引导用户做出上游会拒或会越权的操作）：

1. 等级下拉按身份收敛为「严格低于自己且 `≤ 3`」：超级管理员 `L1`–`L3`，租户管理员 `L2`–`L3`，默认取最低一档（数字最大）之外的第一项。0.5.6 之前只给 `1`（租户管理员）与 `0` / `1`（超级管理员），等于让两种身份都只能提交上游必拒的值（`20103`）。
2. 超级管理员建号必须选租户：`GET /api/tenant` 拉列表（本环境只有 `default` 一个），`tenantId` 随建号一起提交；租户管理员不出现该字段（上游从令牌推断，多传反而越界）。
3. 行内「变更状态」对本人账号（`accountCode` 等于会话账号）禁用，避免自锁 / 自禁。
4. 不提供角色绑定与租户成员入口：前者超级管理员被上游 `10201` 拒绝，后者列表缺 `tenantId` 无法定位目标；两块归 `/system/permission` 与租户域。
5. 上游仍是唯一鉴权点：BFF 只做白名单透传，客户端收敛不改变后端判定结果。

### 6.4 错误码 → 页面处置

| 码 | 上游含义 | 页面处置 |
| :--- | :--- | :--- |
| `10302` | 账号名已存在 | `accountName` 字段内联错误 |
| `20101` | 口令不满足复杂度 / 有效期策略 | `password` 字段内联错误 |
| `20102` | 账号等级与归属层不匹配（`4` 服务账号由系统开通） | 「本级不能建该等级」提示，指向等级字段 |
| `20103` | 只能向下管控：不可操作同级或更高权限的账号 | 「等级必须低于自己」提示，指向等级字段 |
| `10101` | 参数不合法（等级越界 / **缺 `tenantId`**） | 参数不合法提示；缺 `tenantId` 时文案点名该字段 |
| `10301` | 目标不存在或不在当前租户域 | 「账号不存在或无权限」 |
| `10201` | 未认证 / 域拒绝 | 「会话失效或当前身份无此权限」 |
| `10509` | 上游内部错误（缺必填、等级越界） | 通用失败提示 + 检查必填项 |

上游未配置 / 掉线 / 超时沿用 `upstreamHintKey()` 的运维指引（与登录页、`/user/security` 同一套文案）。

### 6.5 已知缺口

`UP-ACC-01`～`UP-ACC-08` 见 `NMCPS-REC-002`：租户管理员越级建号（**已于 2026-11-03 复测确认闭环**：`20103` 生效）、`accountLevel=0` 过滤失效、缺字段 / 越界等级报 `500`、无改资料与删号端点、列表缺租户归属与时区不一致、超级管理员无法分配角色、建号新增 `tenantId` 必填（`UP-ACC-07`）、`4` 改由「服务账号自动开通」承接（`UP-ACC-08`）。页面只依赖已确认可用的四个端点，不把上述缺口当契约。

## 七、`/system/policy` 策略管理（落码基准）

> 口径来源：2026-11-01 对 `http://192.168.1.55:8888/api/v1` 的实调（超级管理员 / 租户管理员双身份穷举）+ swagger 比对。与契约不符处登记在 `NMCPS-REC-003`（`layers/content/collections/cn/records/defects/policy-upstream-defects.md`），本节只写「页面能依赖什么」。页面定位与工具栏口径见 `NMCPS-ADR-0017`。

### 7.1 数据源与端点

| 能力 | BFF 路径 | 上游 | 说明 |
| :--- | :--- | :--- | :--- |
| 规则列表 | `GET /api/abac/rule` | `GET /api/v1/abac/rule` | **只认 `page` / `pageSize`**；没有 `keyword`，也没有 `status` / `roleCode` 过滤 |
| 授权试算 | `POST /api/access/dryrun` | `POST /api/v1/access/dryrun` | 纯计算、不落库；必填只有 `accountId` / `path` / `method` |
| 试算账号候选 | `GET /api/account` | `GET /api/v1/account` | 复用账号列表（`pageSize` 夹到 100），取前若干条做下拉 |

- **规则没有任何写端点可依赖**：`POST /api/abac/rule` 存在，但 `PUT` / `PATCH` / `DELETE /abac/rule/{id}` 全部 `404`（UP-POL-01）。建一条不能改也不能删的规则，比不建更糟 → 页面**不提供创建入口**。
- `status`（启停）没有独立端点，只能由上游改库 → 页面只读展示，不做开关。
- `path` 要带 `/api/v1` 前缀才算命中 RBAC 判定：页面在 `path` 输入框的 hint 里写死这个口径，不自动补前缀（补了会掩盖用户的真实输入）。
- BFF 白名单需含 `abac` / `access` / `account`（`shared/types/api.ts` 的 `GATEWAY_RESOURCES`），否则一律 `404 bff_resource_not_allowed`。

### 7.2 字段口径

- `ruleId`：数值主键，页面用作列表 key 与 `useRecordSelection` 的记录标识；同 `priority` 时按它升序稳定排序（`byAbacPriority()`）。
- `ruleCode`：唯一，重复创建回 `409 10302`（UP-POL-02）；页面只读展示。
- `roleCode`：**空串表示全局规则**，不是 `null`（上游约定）。页面把空串渲染成「全局」标签，不写成「—」。
- `conditionDsl`：govaluate 表达式，上游**不做语法校验**（写错也 `200`，UP-POL-02）→ 页面原样展示 + 提供复制，不提供编辑，也不做「格式化」或「纠错」暗示。
- `priority`：越小越先匹配。列表按升序展示，同优先级按 `ruleId`。
- `status`：实测只见到 `1`（生效）/ `2`（停用）两个取值（`POLICY_STATUS`）。页面只映射这两值，其余取值走 `pages.system-policy.status.unknown` 并把原值带进文案（`policyStatusKey()` + `{status}`），**不猜 `0` 的语义**。
- `createdAt`：原样展示，不做时区换算。

### 7.3 权限矩阵（实测）

| 动作 | 超级管理员（`accountLevel: 0`） | 租户管理员（`accountLevel: 1`） |
| :--- | :--- | :--- |
| 规则列表 / 试算 | **恒 `401 10201`**：策略域对超管不开放（UP-POL-08） | 可用（本租户域） |
| 新建 / 修改 / 删除 / 启停规则 | 端点不存在（UP-POL-01） | 同左 |
| 关键字搜索 | 不提供 | 客户端过滤（上游无 `keyword`，UP-POL-04 邻接现象） |

客户端收敛（**不是安全边界**，只为不引导用户踩上游缺口）：

1. 超管进入该页**不发起任何请求**，只渲染身份说明 Alert（详情栏顶部，未选中时也在；否则每次进页都刷一条 `401` 噪声）。
2. 不提供任何写入口：规则建了既不能改也不能删，且 DSL 不做语法校验——写错只能改库。
3. 搜索在客户端做：先把规则分页拉全（上限 `MAX_RULE_PAGES` 兜底），再按 `ruleCode` / `ruleName` / `roleCode` / `conditionDsl` 过滤；过滤掉当前记录时落「不在当前结果内」空态，**不静默改搜索条件去捞**。分页同样在客户端：每页条数选择器与分页器都在列表栏尾部（默认 15，`NMCPS-ARCH-006` §3.8），切片只作用于渲染层 —— 命中判定与 `?id` 深链仍对全量已加载规则生效，翻页不会让合法深链变成「记录不存在」。
4. 试算表单只给 `accountId` / `path` / `method`：其余四个字段上游接受但不参与判定（UP-POL-06），摆出来等于骗人。

### 7.4 错误码 → 页面处置

| 码 | 上游含义 | 页面处置 |
| :--- | :--- | :--- |
| `10201` | 未认证 / 域拒绝（超管必现） | 身份说明 Alert，不进「加载失败」分支 |
| `10302` | `ruleCode` 已存在 | 列表/试算不涉及；文案提示「规则编码已存在」 |
| `10101` | 参数不合法 | 「参数不合法」提示，保留用户输入 |
| `10509` | 上游内部错误 | 通用失败提示 + 重试入口 |

上游未配置 / 掉线 / 超时沿用 `upstreamHintKey()` 的运维指引（与登录页、`/system/user` 同一套文案）。

### 7.5 已知缺口

`UP-POL-01` / `02` / `04` / `06` / `08` 见 `NMCPS-REC-003`：无规则生命周期端点、DSL 不校验语法、列表无 `keyword`、试算忽略上下文、超管被域拒绝。页面只依赖「列表 + 试算 + 账号候选」三个已确认可用的能力，不把上述缺口当契约。

## 八、`/system/permission` 权限管理（落码基准）

> 口径来源同上。与契约不符处登记在 `NMCPS-REC-003`，本节只写「页面能依赖什么」。页面定位与工具栏口径见 `NMCPS-ADR-0017`。

### 8.1 数据源与端点

| 能力 | BFF 路径 | 上游 | 说明 |
| :--- | :--- | :--- | :--- |
| 角色列表 | `GET /api/role` | `GET /api/v1/role` | `page` / `pageSize` / `keyword`；无状态过滤 |
| 建角色 | `POST /api/role` | 同 | `roleCode` / `roleName` / `roleLevel` 必填，`description` 可选 |
| 删角色 | `DELETE /api/role/{roleCode}` | 同 | 路径段是 **`roleCode`**，不是 `roleId`；内置角色 `40303` |
| 权限点目录 | `GET /api/permission` | 同 | `page` / `pageSize` / `keyword` / `resourceType`；实测仅 24 条，可全量拉取 |
| 角色已授权 | `GET /api/role/{roleCode}/permission` | 同 | **不回 `effect`**（UP-POL-03） |
| 授权 | `POST /api/role/{roleCode}/permission` | 同 | body `{ permCode, effect }`，页面只用 `effect=1`（allow） |
| 撤销授权 | `DELETE /api/role/{roleCode}/permission` | 同 | body `{ permCode }`，`effect` 对删除无意义 |

- **没有角色状态端点**（无 `PUT /api/v1/role/{code}/status`），`status` 只能改库 → 页面不提供启停（UP-POL-01）。
- **`POST /api/permission` 有、删除没有**：页面只读权限点目录，不做权限点增删（UP-POL-01）。
- `GET /account/role?accountId=` **不存在**（`404`）→ 不提供「账号↔角色」绑定视图（UP-POL-07）。

### 8.2 字段口径

- `roleCode`：唯一；重复 `409 10302`。页面用它做 `useRecordSelection` 的 `id`，不做数值化。
- `roleLevel`：`0` 平台超管 / `1` 租户管理员 / `2`–`4` 自定义。租户管理员可建 `2`–`4`；建同级或更高 → `20103`；`>4` → `40308`（两者文案不区分，UP-POL-05）。
- `isBuiltin`：内置角色**只读**——授权 `40307`、撤销 `40305`、删除 `40303`（三种码同一语义，UP-POL-09）。页面禁用开关与删除入口并给出原因。
- `status`：同上，实测只见到 `1`（生效）/ `2`（停用）（`POLICY_STATUS`），只读展示；其余取值走 `pages.system-permission.status.unknown` 并带出原值，不猜语义。
- `createdAt`：`GET` 返回 UTC、`POST` 返回本地时（UP-POL-10）→ 原样展示，不做时区换算。
- 权限点：`permCode`（形如 `asset:device:read`）、`permName`、`resourceType`（`0` 会被上游当「未提供」，页面不透传 `0`；`4` = 接口类，矩阵里单独占右列）、`description`。
- 角色已授权列表**只有权限点本体**：出现在列表里即「已授权」，无法区分允许 / 拒绝（UP-POL-03）→ 页面只有 `ALLOW` 语义，不摆「拒绝」开关。

### 8.3 权限矩阵（实测）

| 动作 | 超级管理员（`accountLevel: 0`） | 租户管理员（`accountLevel: 1`） |
| :--- | :--- | :--- |
| 角色 / 权限点列表 | **恒 `401 10201`**（UP-POL-08） | 可用（本租户域） |
| 建角色 | 同左 | 可建 `2`–`4`；`0` / `1` → `20103` |
| 删角色 | 同左 | 仅自建角色；内置 `40303` |
| 授权 / 撤销 | 同左 | 可；内置角色 `40307` / `40305` |
| 角色启停 | 端点不存在（UP-POL-01） | 同左 |

客户端收敛（**不是安全边界**）：

1. 超管进入该页**不发起任何请求**，只渲染身份说明 Alert（详情栏顶部，未选中时也在）。
2. 等级下拉按身份收敛：租户管理员只给 `2`–`4`（`0` / `1` 必被 `20103` 拒）。
3. 内置角色的授权开关与删除按钮禁用（`aria-disabled` + tooltip 说明），不做「点了再报错」。
4. 授权开关用**乐观更新**：先翻 UI，失败回滚并提示；并发请求按 `roleCode + permCode` 去重。
5. 不提供权限点增删与角色启停：端点不存在，做了也只能报错。
6. 详情栏 view 态**等分两列**：左「角色信息」（标题 + 字段 + 内置角色说明），右「授权矩阵」，各占 50%、铺满容器（不设 `max-w`）。矩阵内部恢复两列：左列资源类（`resourceType` ≠ `4`）、右列接口类（`4`），列序固定，每列内按 `resourceType` 分组、条目按 `permCode` 稳定排序。判据是**容器查询**（`@min-[48rem]`，不是视口断点，见 `NMCPS-ARCH-006` §3）：窄于阈值先回归单栏（字段在上、矩阵在下），此时矩阵内部也回到单列分组。接口点占目录大头（2026-11-02 实测 24 条里 15 条是 `4`），两列可避免把「单设备 / 指标 / MIB / 告警」压到列表底部。

## 九、`/system/log` 审计日志（落码基准）

> 口径来源：2026-11-02 对 `http://192.168.1.55:8888/api/v1` 的实调（超级管理员 / 租户管理员双身份穷举）+ swagger 比对。与契约不符处登记在 `NMCPS-REC-004`（`layers/content/collections/cn/records/defects/audit-upstream-defects.md`），本节只写「页面能依赖什么」。

### 9.1 数据源与端点

| 能力 | BFF 路径 | 上游 | 说明 |
| :--- | :--- | :--- | :--- |
| 列表 | `GET /api/audit` | `GET /api/v1/audit` | `page` / `pageSize`，可选 `accountId` / `deviceCode` / `sessionId` / `category` / `traceId` / `startTime` / `endTime` |
| 详情 | `GET /api/audit/{logCode}` | 同 | 路径段是 `logCode`（`AUD…`），不是数值 id；未知代码 `404 10301` |
| 链式校验 | `POST /api/audit/verify` | 同 | body `{ startTime?, endTime? }`，返回 `{ intact, checkedCount, brokenAtLogId }`；**是写操作**（每次调用新增一条审计日志，UP-AUD-05） |
| 导出任务列表 | `GET /api/audit/export` | 同 | 只认 `page` / `pageSize`，**没有按状态或名称过滤的参数** |
| 创建导出 | `POST /api/audit/export` | 同 | `exportName` / `startTime` / `endTime` 必填，可选 `accountId` / `category` / `deviceCode` |

- **导出任务没有详情端点、也没有删除端点**（`GET|DELETE /api/audit/export/{code}` 实测 `404`）：进度只能靠列表回读，任务一旦创建不可回收（UP-AUD-07）。
- BFF 白名单需含 `audit`（`shared/types/api.ts` 的 `GATEWAY_RESOURCES`），否则一律 `404 bff_resource_not_allowed`。
- 契约类型在 `shared/types/audit.ts`（`app/` 与 `server/` 同构引用），页面不重复声明字段。

### 9.2 字段口径

- **列表项 = 详情的前 12 个字段**：`logCode` / `category` / `accountId` / `deviceCode` / `sessionId` / `traceId` / `action` / `resource` / `result` / `clientIp` / `eventTime` / `logHash`；详情额外返回 `sourceService` / `beforeSnapshot` / `afterSnapshot` / `detailJson` / `prevHash`。
- `category`：实测只有 `session`（会话：登录 / 登出 / 会话回收）与 `api`（接口调用）两个取值；**大小写敏感**，其余取值被上游静默忽略并返回全量（UP-AUD-02）→ 页面只提供这两项，其他取值按「未知类别」展示并带出原值。
- `result`：`1` 成功 / `2` 失败；其余取值无样本 → 走 `result.unknown`，不猜语义。
- `eventTime`：RFC3339 带偏移（`2026-11-02T03:15:09+08:00`）→ 只裁剪成 `YYYY-MM-DD HH:MM:SS` 展示，**不做时区换算**。
- `action` / `resource`：会话类是 `auth.login.success` / `auth`，接口类是 `METHOD path` / 请求路径；两列都原样展示。
- `accountId`：`0` 的语义未验证（不据此推断「系统动作」）；作为**过滤条件**时 `0` 与空串都被当「未提供」（UP-AUD-03）。
- `pageSize`：上游没有稳定上限（`200` 真给 200 条、`500` 只给 20 条却回显 500，UP-AUD-03）→ 页面级常量 `AUDIT_MAX_PAGE_SIZE = 100`，选项 15 / 30 / 50 / 100（默认 15，选择器在列表栏尾部，`NMCPS-ARCH-006` §3.8）。
- 时间参数：`YYYY-MM-DD HH:MM:SS` 与 RFC3339 **两种格式上游都收**（同区间结果一致），非法格式被静默忽略（回全量，UP-AUD-04）→ 页面固定发空格格式（不带偏移，浏览器本地时原样发出），反向区间本地拦下。
- 快照类字段（`sourceService` / `beforeSnapshot` / `afterSnapshot` / `detailJson`）实测恒为空串（UP-AUD-09）→ 只在非空时渲染。
- 导出任务：`status` 是**未文档化的裸数字**（实测只见到 `1`），`downloadUrl` / `objectKey` 产出前为空串，`totalRecords` 未跑完为 `0`；列表回读的 `createdAt` 比创建响应晚 8 小时（UP-AUD-08）→ `status` 原样展示数字，`createdAt` 不做换算。
- 校验结果：`checkedCount` 是**真正校验的条数**，零条窗口上游仍回 `intact: true`（单端时间同样如此，UP-AUD-04）→ 结果文案始终带「共校验 N 条」，`checkedCount = 0` 时按中性提示渲染并明说「空窗口的完整不代表链没问题」。

### 9.3 权限矩阵与页面行为

| 动作 | 超级管理员（`accountLevel: 0`） | 租户管理员（`accountLevel: 1`） |
| :--- | :--- | :--- |
| 列表 / 详情 | 全平台 | 可用，**范围由上游按租户过滤**（同刻 `total` 1893 vs 1709，行内 `accountId` 只落本租户；UP-AUD-01） |
| 链式校验 | 可用（会写一条审计） | 同左 |
| 导出任务列表 / 创建 | 可用 | 同左 |

客户端收敛（**不是安全边界**）：

1. 两种身份都照常取数：范围由上游过滤，页面只在详情栏顶部用身份说明讲清「你看的是全平台 / 本租户」（未选中空态也在，位置口径见 `NMCPS-ARCH-006` §4.1）。
2. 筛选按「是否决定数据口径」分两处：**时间范围**（按钮文案即当前窗口摘要 + `UPopover` 里给「全部时间 / 近 15 分钟 / 近 1 小时 / 近 24 小时 / 近 7 天」快捷项列、双月 `UCalendar range` 日历，以及日历下方两个到秒的 `datetime-local` 补手）和**类别**（`USelect`：全部 / 会话 / 接口）常驻工具栏左区；`accountId` / `deviceCode` / `sessionId` / `traceId` 留在筛选浮层；每页条数不在两处之列 —— 它是列表呈现而非筛选，固定在列表栏尾部（`NMCPS-ARCH-006` §3.8，默认 15）。**不提供 `result` / `keyword` 控件**（上游忽略它们）。常驻的判据是「不常驻会让人把过滤后的 `total` 当全量读」，占位预算与控件形态见 `NMCPS-ARCH-006` §4.1。
3. 列表用 `LayoutSplit` 两栏 + `useRecordSelection` 读写 `?id`；`↑` / `↓` 可在列表内移动选中，详情栏回读 `GET /api/audit/{logCode}`。
4. 校验是**显式按钮**：必须两端时间齐全才可点，成功与否都重新拉列表（因为它本身写了一条日志），断点只写「第 N 条」（`brokenAtLogId` 是整链序号，不映射到列表行）；`checkedCount = 0` 走中性提示而不是成功绿。
5. 导出弹窗只做「创建 + 列表回读 + 手动刷新」：三个必填本地先拦、反向区间本地先拦、**不做进度条也不自动轮询**（没有进度字段可读）、只提供下载（`downloadUrl` 非空时），不提供删除。
6. 工具栏由 `check:ui` 守住四条：两个常驻控件在位、且切类别 / 选快捷区间后请求里真的带上 `category` / `startTime` / `endTime`；筛选浮层不再重复时间与类别（只留四个标识）；左区总宽不超内容盒 45%；320px 下时间范围退成图标且无横向溢出。列表栏尾部同由 `check:ui` 守住：高度 49px、默认每页 15 条、选中行底色在深浅两模式都可辨（`NMCPS-ARCH-006` §3.8）。

### 9.4 错误码 → 页面处置

| 码 | 上游含义 | 页面处置 |
| :--- | :--- | :--- |
| `10201` | 未认证 / 登录态失效（与「无权限」同码，UP-AUD-01） | 「登录态已失效或没有权限」提示并引导重登，不进「加载失败」分支 |

| 非信封失败（`code = 0`） | 网络层 | 「网络异常，请重试」 |

上游未配置 / 掉线 / 超时沿用 `upstreamHintKey()` 的运维指引。

### 9.5 已知缺口

`UP-AUD-01` / `02` / `03` / `04` / `05` / `06` / `07` / `08` / `09` 见 `NMCPS-REC-004`：租户数据范围未文档化且失效令牌同码、`category` 大小写敏感且未知值静默忽略、未知查询参数被忽略且 `pageSize` 无稳定上限、时间参数双格式且非法值不报错、`verify` 是写操作且断点为整链序号、导出缺必填回 `500`、导出无详情与删除端点、导出列表时区偏移 8 小时、详情快照恒为空。页面只依赖上文已确认可用的五个端点，不把上述缺口当契约。
