# 通信面架构（NMCPS-ARCH-001）

> **本文职责**：`arch.transport` 域的唯一权威，定义系统「通信面」——数据在云端中心与边缘网关之间如何流动、通过什么协议、如何保证断网可用与最终一致。治理规则见 `NMCPS-GOV-001`，权威清单见 `NMCPS-GOV-003`。
> **目标读者**：架构与实施工程师 / AI 助手。

---

## 一、定位

通信面是网络管理系统（NMS）的「血管」：把边缘采集的数据搬到云端分析、把云端的配置下发到边缘执行。其核心约束是**断网自治**——边缘在失去云端连接时仍可持续运行，网络恢复后自动收敛。

---

## 二、边云两级网络

系统采用「云端中心 + 边缘网关」两级逻辑网络：

| 层级 | 组成 | 职责 |
| :--- | :--- | :--- |
| 云端中心 | Nuxt 4 总控台 + go-zero API/RPC 网关 + VictoriaMetrics 时序库 | 全局控制面、聚合分析、配置下发 |
| 边缘网关 | Nuxt 4 本地自治 UI + 轻量 Go Daemon + SNMP/Agent 采集 | 本地采集、本地存储、断网自治 |

两级之间通过「边云通道」连接：KubeEdge Tunnel / gRPC Tunnel / TLS MQTT。

---

## 三、控制流与数据流分离

| 维度 | 控制流 | 数据流 |
| :--- | :--- | :--- |
| 承载内容 | 资产、配置、指令、身份 | 高频监控指标 |
| 存储 | 关系型数据库（RDBMS） | 时序数据库（TSDB） |
| 特征 | 低吞吐、强一致 | 高吞吐、允许最终一致 |

读写分离是性能与扩展性的基础：指标高频写入不冲击控制数据的强一致事务。

---

## 四、三类数据流

### 1. 指标流（Metrics Stream）

策略：**边缘不存、直通云端**。边缘 Exporter 采集的指标不落边缘库，直接经轻量 Agent 定时 Push（或云端跨隧道 Pull）汇聚至云端时序库，保障边缘磁盘寿命。

### 2. 告警事件流（Alarm Event Stream）

策略：**本地判定、实时上报、高并发防冲**。边缘基于预设规则本地触发告警后，事件序列化为 JSON 经 MQTT 总线推送云端；云端逻辑层自适应限流过滤风暴告警，写入库后经 Realtime 推送总控台。

### 3. 资产与配置同步（Asset & Config Sync）

策略：**增量变更集 + 分布式事务 + 最终一致（LWW）**。

- 云下发至边：配置变更经 go-zero RPC 调度分布式事务引擎，对跨网关配置执行 SAGA 模式下发，失败自动补偿回滚；数据库监听 WAL 生成带版本号的 ChangeSet 压入队列，边缘订阅增量更新本地库。
- 断网与重连：断网期间边缘本地运维操作记入离线队列 `sync_queue`；恢复后 Daemon 批量提交，云端按「最后写入者胜（LWW）」或策略冲突判定，保证最终一致。

## 五、通信协议栈

| 协议 | 用途 | 说明 |
| :--- | :--- | :--- |
| SNMP / SNMPv3 | 设备采集 | 采集路由器/交换机/防火墙运行状态（RFC 1157 / 3411-3418） |
| MQTT（TLS） | 告警总线 / 边缘消息 | 轻量发布订阅，承载告警事件流 |
| gRPC | 边云 RPC / 配置下发 | go-zero 生态，契约驱动（.api / .proto） |
| 边云隧道 | 通道 | KubeEdge Tunnel / gRPC Tunnel，打通云边网络 |

---

## 六、断网自治与重连

1. 断网期间：边缘本地采集、本地存储、本地 UI 渲染、离线队列记录运维操作。
2. 重连之后：离线队列批量提交 → 云端按 LWW 或策略冲突判定收敛。
3. 一致性保证：跨网关批量配置走 SAGA 事务，失败自动补偿回滚，避免状态残留。
