# UI 交互架构（NMCPS-ARCH-006）

> **本文职责**：`arch.ui` 域的唯一权威 —— 所有**数据表单页**（列表 / 详情 / 增删改查）在顶栏、侧栏、大屏、手机四种布局下的结构、分栏、工具栏与面包屑口径。
> **不承载**：具体域有哪些字段、能调哪些上游接口（属各 `NMCPS-DESIGN-00x` 领域基准）；能力授权与降级（属 `NMCPS-ARCH-005`，layers/content/collections/cn/architecture/1.architecture/platform-architecture.md）。裁决过程与被否方案见 `NMCPS-ADR-0017`（layers/content/collections/cn/records/adr/adr-0017.md）。
> **目标读者**：前端工程师 / 设计评审 / AI 助手。

---

## 一、定位

本仓的四种布局模式（`topbar` / `sidebar` / `bigscreen` / `mobile`）由 `useLayoutMode()` 暴露，但**页面内部结构只写一套**：模式差异全部由外层容器吸收，页面只读三个环境量 —— **可用宽度、滚动容器归属、是否触摸**。

因此本基准约束三件事：

1. **一套页面结构**在四种模式下都成立，不出现「大屏版页面」「手机版页面」两套实现。
2. 分栏、工具栏、面包屑三类**跨域横切组件**只有一个来源，任何域都不得自建变体。
3. 列数收敛、吸顶偏移、动作归属全部有可断言的判定依据，便于 `check:ui` 覆盖。

判据来自代码而非偏好：`app/composables/useLayoutMode.ts`（模式谓词）、`app/layouts/default.vue`（滚动容器与两个 CSS 变量）、`app/components/App/AppToolbar.vue`（工具栏挂载点）。

## 二、四布局模式矩阵

| 模式 | 内容宽度 | 滚动容器 | 工具栏位置 | 分栏形态 |
| :--- | :--- | :--- | :--- | :--- |
| `topbar` | 受 `topbarMaxWidthClass` 限宽（`narrow` / `wide` 1440px / `full`） | `main` | 内容顶部，随 `main` 滚动、`sticky top-0` | 容器 ≥ 56rem 两栏，否则覆盖式 |
| `sidebar` | 视口 − 侧栏（收起 4rem / 展开 16rem） | `main` | 内容顶部，`sticky top-0` | 同上 |
| `bigscreen` | 视口 − 侧栏 − 右侧 16px 内缩 | **内容页内部滚动容器**（`absolute inset-y-4` 边框盒） | 在滚动容器**内部** `sticky top-0` | 同上 |
| `mobile` | 全宽 | `main` | 内容顶部 | **禁止并排**，覆盖式（列表 ↔ 详情） |

三条硬约束：

1. **宽度判据必须是容器查询，不是视口断点**。同一台 1920 屏，侧栏收起/展开差 12rem，`topbar` 模式还叠了 1440px 限宽；`md:` / `lg:` 会在这两种情况下误判。样式层已是 Tailwind v4（`max-w-(--ui-container)` / `text-(--ui-text-muted)` 语法），直接使用 `@container` 与 `@min-[…]` 变体。
2. **吸顶偏移只能读变量**。`default.vue` 注入 `--content-sticky-top`（`bigscreen` 为 `0px`，其余为 `49px`）与 `--content-max-h`；`bigscreen` 的工具栏与内容分别位于「滚动容器外 / 内」两层（`AppToolbar` 在 `default.vue` 中两处互斥渲染）。任何列头、分区标题、侧栏段落吸顶时硬编码 `0` 或 `49px` 都会在另一模式下错位。
3. **移动端判定用 `isMobile`，不要用 `!isMobileMode`**。`isMobile = isMobileMode || (max-width: 1023px)`，桌面窄窗（例如并排分屏 960px）也必须走移动端分支。

## 三、数据表单页两栏结构

所有数据表单页使用同一骨架：**左栏（数据列表栏）+ 右栏（数据详情栏）**。两栏由单一原语 `Layout/Split.vue` 提供，页面只填 `#list` / `#detail` 两个具名插槽（技术标识用角色名 `list` / `detail`，`[data-pane="list"]`），不自建栅格。

**不设第三栏**：与当前记录关联的次级数据在右栏内以固定分区实现（见 §3.7）。形态只有两种 —— **两栏**（桌面足够宽）与**覆盖式**（手机、或非手机但容器过窄）；覆盖式与两栏共用同一组件与同一 `?id` 契约，区别只在排列与「返回」按钮。

### 3.1 形态收敛与最小页面宽度（容器宽，非视口宽）

**最小页面宽度（可断言常量）**：

| 量 | 值 | 含义 |
| :--- | :--- | :--- |
| `--page-min-w` | **20rem（320px）** | 单栏 / 覆盖式的最低可用宽；低于此属壳层缺陷，不在本节范围内 |
| `--split-min-w` | **56rem（896px）** | **两栏门槛**：容器宽 < 56rem 只允许覆盖式 |
| 右栏最小宽 | **32rem（512px）** | 两栏时右栏不得低于此值 |
| 左栏宽 | **20–24rem（默认 22rem）** | 可拖拽区间 18–28rem |

56rem 是算术结果而非口径：左栏上限 24rem + 右栏下限 32rem = **56rem**。

| 容器宽 | 形态 | 左栏 | 右栏 | 分隔 |
| :--- | :--- | :--- | :--- | :--- |
| `isMobile` 或 < 56rem | **覆盖式** | 100%，与右栏二选一，由「当前面板」切换 | 100%（覆盖左栏），内容页工具栏左区唯一「返回」 | 无 |
| ≥ 56rem | **两栏** | 20–24rem（默认 22rem），可拖拽 | 弹性，最小 32rem | 栏间 1px `border-default`，无 gap |

- **门槛只读容器宽**：侧栏收起/展开差 12rem、`topbar` 1440px 限宽、分屏窄窗三种情况都会让视口断点误判。典型反例：1024px 窗 + 展开侧栏 = 768px 可用宽 → 覆盖式；不设回退就会得到「448px 的畸形右栏」。
- **可拖拽三条**：左栏必须有稳定 `id`（`<页面>-list`）；双击分隔条复位 22rem；拖动范围锁 18–28rem，不允许拖到 0。
- **不实现「折叠左栏」**：列表是主界面，收成图标栏会让「数据在哪一栏」失稳；窄了走覆盖式。
- **不使用 `UDashboardPanel resizable`**：其主题含 `min-h-svh`（`bigscreen` 双滚动条）、`lg:w-(--width)`（视口断点）、分隔条 `hidden lg:block`，且宽度走 cookie、拖动每移动一像素写一次 `document.cookie`。改用 `@container` + `grid` + 本地 `usePaneResize`（pointer events + rAF 合帧 + 松手后 300ms 防抖写 `localStorage` + 键盘可达）。

### 3.2 各栏职责

| 栏 | 必含 | 禁止 |
| :--- | :--- | :--- |
| 左栏（列表） | 识别字段（名称 / 编号）、状态、时间；行内最多 1 个动作（「选中」或该域唯一高频幂等动作，如启停）；宽 20–24rem 内最多两行信息。搜索 / 筛选 / 刷新等集合域动作**不放在栏内**，经内容页工具栏左区注入（§4） | 编辑类写操作、批量操作、跨实体跳转入口、第三字段（降级到 `title` 或右栏）、栏内自建 header |
| 右栏（详情） | 内容区标题（展示名 + 编号）、当前记录的表单式视图、关联分区（§3.7）、字段级校验反馈、空态（「从左栏选择记录查看详情」）与加载骨架；表单内容 `max-w` 收住（≈640px）；右栏内等分两列的形态（§3.7）铺满容器、不设 `max-w`。记录域 / 提交域动作经内容页工具栏右区注入（§4） | 用 `UModal` 再做一份「查看详情」（与分栏语义重复）；在右栏内再嵌「列表 → 详情」二级主从；栏内自建 header |

行内动作上限为 1 条的理由是可测试的：覆盖式形态下行高受限，多个行内按钮会把命中区压到 24px 以下；同时同一动作在行内与工具栏出现两次，会让「改哪一条」的判断出现两处来源。

### 3.3 高度与滚动合同

- **definite height 链已落地**（0.2.2 起）：`default.vue` 内容容器为 `flex min-h-0 flex-1 flex-col`，其下再套一层 `flex min-h-0 flex-1 flex-col overflow-y-auto` 作为滚动容器；**页面根 `flex-1 min-h-0` 是分栏页的显式选择**，不写这两个类的普通页面保持内容高度、由该滚动容器整体滚动。
- **工具栏在滚动容器之外**：`AppToolbar` 在 `default.vue` 里只渲染一次、且在滚动容器之外（§4.3 的单一渲染点），因此 `--content-sticky-top` 恒为 `0px`；栏内吸顶一律写 `top-(--content-sticky-top)`，视觉上等于贴住工具栏下沿。
- 每一栏 `min-h-0` + 自身 `overflow-y-auto`；**栏内不再嵌套 `h-svh` / `h-screen`**，否则 `bigscreen` 模式下会出现双滚动条。
- 栏内吸顶一律 `top-(--content-sticky-top)`，最大高度 `max-h-(--content-max-h)`（`DocumentPage.vue` 的三栏是既有正确实现）。
- **左栏与右栏的滚动互不联动**：选中一条记录不重置列表滚动位置。
- **任何模式、任何形态都不得出现横向滚动**（`--page-min-w` 20rem 起）；右栏表单用 `max-w` 收住，宽屏不拉伸单列输入框。

### 3.4 空态、加载、错误三态

每个可请求区域各自持有 `pending` / `error` / `empty` 三态，不允许「整页一个 loading」：列表为空时详情栏展示「暂无记录」引导，而不是把空态塞进表格；错误只在对应栏内提示，另一栏保持可用。加载用骨架（列表 5 行、详情按分区），刷新时保留旧数据 + 顶部细进度条。

### 3.5 详情栏视图态与切换守卫

详情栏固定三态，默认落在 `view`：

| 态 | 进入方式 | 工具栏「记录域」 | 工具栏「提交域」 | 脏状态 |
| :--- | :--- | :--- | :--- | :--- |
| `view` | 默认 / 保存成功 / 取消编辑 | 编辑、危险动作（删除） | 不渲染 | 不存在 |
| `edit` | 点「编辑」 | 危险动作 | 取消 + 保存 | 存在 |
| `create` | 点「新建」 | 不渲染（未落库无删除） | 取消 + 创建 | 存在 |

- **脏检查只在 `edit` / `create` 为真**：切行、切页、关窗、路由离开统一走 `requestSwitch(next)`，脏则弹「留在本页 / 放弃并切换」，「留在本页」为默认焦点。
- **保存成功**保持当前选中、就地 patch 或静默刷新（不重置滚动、不重选）；`create` 成功后 `?id` 由占位值 `replace` 为真实 id。
- **保存失败**留在 `edit`，保留输入，错误就近展示；不得清空表单或退出编辑。
- **校验**：字段级内联错误 + 顶部汇总（可跳到首错）；上游业务码（如 `10302`）映射到字段（`accountError.ts` 模式），不弹裸 toast。
- **键盘**：Tab 顺序 = 视觉顺序；`⌘/Ctrl+Enter` 提交；`Esc` 取消编辑（脏则确认）。

### 3.6 列表栏行规范与默认选中

- 行高 48px（`comfortable`）/ 40px（`compact`，偏好开关，不按断点自动切换）；单行主标识 + 状态 badge + 1 条次级信息，超长截断并 `title`。
- 选中态双通道：`bg-accented` + 左缘 2px primary 竖条 + `aria-selected`；命中区移动端 ≥ 44px。底色**不能**用 `bg-elevated`：`--ui-bg-elevated` 在浅色模式是 neutral-100、面板底色是白，`bg-elevated/60` 叠上去几乎不可见，深色模式也只是同色系一档内的过渡 —— 实测两模式都读不出「选中了哪条」。`--ui-bg-accented` 是 neutral-200 / neutral-700，与面板差一整档，深浅都可辨；悬停用低一档的 `bg-elevated`，键盘焦点 `focus-visible:bg-elevated`，三级层次（悬停 < 选中）保持不变。
- 分组仅两级（分组 → 条目），折叠态按分组 id 记忆。
- **默认选中**：两栏形态默认启用（右栏默认 `view` 只读，选中即得上下文）；排序键必须与列表展示顺序**同源**（同一 `sortKey` 函数，1.0 曾因各写一份导致「默认选中的不是第一行」）；只执行一次（`settled` 标志）；**覆盖式不默认选中**（否则首屏直接进详情，用户看不到列表）。
- **行可聚焦**：行必须 `tabindex="0"`、`Enter` / `Space` 选中、带 `aria-selected`；`UTable` 的行默认不可聚焦，需在行插槽补键盘绑定，或在左栏改用自建 listbox。

### 3.7 右栏内的关联分区与反馈分工

- **位置与顺序固定**：右栏内、主表单之后 —— **概览字段 → 关联表 → 活动 / 审计**。不新开栏、不新开二级主从。
- **等分两列的例外**：条目多、自身还要再分列的只读分区（如 `/system/permission` 的授权矩阵：左资源类 / 右接口类）可与概览字段**等分**右栏 —— 字段在左、分区在右，各占 50% 并铺满容器（不设 `max-w`）；判据是容器查询 `@min-[48rem]`，窄于阈值回落为「字段在上、分区在下」的固定顺序，两侧内部同时回到单列。
- **上限**：≤ 2 张关联表，每张默认 ≤ 5 行 + 「查看全部」；「查看全部」跳转到该实体自己的页面，**不允许在右栏内再嵌「列表 → 详情」**。
- **只读**：关联表不承载主记录主 CTA、不发起跨实体写操作。
- 依赖当前记录的请求必须等 `?id` 就绪再发；`create` / 无选中时用页面说明或统计占位，不留白。
- 每张关联表独立三态，一张失败不影响主表单与其他表；无数据渲染「暂无关联数据」。
- 覆盖式形态下关联分区随主表单一起滚动，**不折叠成标签页**（同一信息只有一种查找路径）。
- 四类反馈分工：**内联**（字段错误、栏内空态/错误）、**Toast**（写操作成功/失败）、**Alert**（口径说明：内容页一律放在**详情栏顶部**，不占页面级横幅 —— 见 §4.1）、**Modal**（破坏性确认、未保存确认）。乐观更新仅用于幂等可回滚动作（启停、置顶），失败回滚并 toast。

### 3.8 列表栏尾部：计数 / 每页条数 / 分页

- **位置与高度**：三件事合成列表栏底部一条，落在滚动区之外（`Layout/Split.vue` 的 `#list-footer` 插槽，`data-list-footer`），高度只读 `--app-list-footer-h`（`3.0625rem`，49px）—— 与工具栏同口径，不写死 px，随 `--app-font-scale` 缩放。行内容 `h-full` 垂直居中，不换行。
- **只有一处**：每页条数是**列表呈现**而不是筛选（改了它，命中的记录集不变），因此永远待在尾部，不进工具栏、也不进筛选浮层；页面不得再放第二个同类控件。
- **默认 15 条**：`shared/constants/paging.ts` 是单一来源（`DEFAULT_PAGE_SIZE = 15`、`PAGE_SIZE_OPTIONS = 15 / 30 / 50 / 100`）；四个列表页（`/system/user`、`/system/policy`、`/system/permission`、`/system/log`）一律提供选择器。上游对 `pageSize` 无稳定上限的域（`/system/log`，UP-AUD-03）在取数层夹到 100，选项上限跟着夹。
- **换条数即回第一页**：`page * pageSize` 的偏移必然错位，改条数后按筛选变更同一路径重置 `page`，不留在越界页。
- **窄栏收敛**：栏宽 < 20rem 时先收起计数文字（`truncate` + 容器查询），保留条数选择器与分页；分页只留 `sibling-count=1` 的页号，禁止横向溢出（§3.3 的 320px 口径）。
- **客户端分页的例外**：`/system/policy` 为了「搜索覆盖全部规则」先全量拉取（§7.1），分页切片只作用在渲染层；命中判定与 `?id` 深链仍对全部已加载规则生效，翻页不会让合法深链落「记录不存在」。

## 四、工具栏契约：单层 + 左右分区

内容页工具栏**只有一层**：布局层预留的 `AppToolbar`（`app/layouts/default.vue`，高度只读 `--app-toolbar-h`，`bigscreen` 与其余模式互斥渲染，任一时刻只挂一个）。页面不自建工具栏，也不在栏内另起一条 header，一律用 `<Teleport>` 注入到两个挂载点之一：

| 区域 | 挂载点 | 内容 | 与两栏的关系 |
| :--- | :--- | :--- | :--- |
| 左区 | `#app-toolbar-left` | 面包屑（`topbar` 模式，固定在最左）、集合域动作：搜索、筛选、排序、批量、刷新 | 与左栏同侧，作用对象是整份列表 |
| 右区 | `#app-toolbar-right` | 记录域动作（危险动作在提交组左侧）、提交域动作、主 CTA（新建 / 保存） | 与右栏同侧，作用对象是选中记录 |

- **为什么不再分层**（0.2.5 改）：栏内 header 与预留工具栏并存，窄窗必然叠成两条 49px —— 600px 视口被吃掉 98px。动作与作用对象的对应关系由**左右分区**表达已足够，不需要为同一批按钮再复制一条横条。
- **记录标题（展示名 + 编号）不进工具栏**：它是内容，写在右栏内容区顶部；`topbar` 模式下同时由面包屑记录段承担（§5.1）——这也是覆盖式下「我在看哪一条」的答案（§5.3）。
- 覆盖式与两栏共用同一层：左区 / 右区内容按「当前面板」切换（§4.4）。

### 4.1 左右分区

页面通过 `Teleport` 注入内容：

```vue
<Teleport to="#app-toolbar-left"> …集合域动作… </Teleport>
<Teleport to="#app-toolbar-right"> …记录域 / 提交域动作… </Teleport>
```

| 位置 | 作用对象 | 内容 |
| :--- | :--- | :--- |
| 左区 `#app-toolbar-left` | **集合** | 搜索、筛选、排序、批量操作、刷新、列设置 |
| 右区 `#app-toolbar-right` | **单条记录** | 主 CTA（新建 / 保存 / 编辑）、状态 badge、危险动作（禁用 / 删除） |

- 左区对应列表栏，右区对应详情栏：视觉位置与作用域必须一致，评审时以「这个按钮改变的是集合还是单条」为准。
- **行级动作不得进工具栏**，**集合级动作不得进右区**，**同一动作全页只有一个入口**。
- 右栏内关联分区的归属信息（例如「本租户 3 个账号」）写在分区标题旁，不进任何工具栏。
- **左区常驻筛选控件预算（0.2.14）**：只有「不常驻就会让人误读数据口径」的维度才常驻（时间区间、低基数枚举），且**不超过 2 个**、总宽 **≤ 内容盒 45%**（1440 视口下内容盒 ≈1166px ⇒ 上限 ≈520px）——`§4.4` 只允许右端折叠，左区超宽会直接挤掉右区动作。表达方式固定：时间区间用 `UButton`（文案 = 当前窗口摘要）+ `UPopover`（左侧快捷项列 | 右侧 `UCalendar range` 日历，日历下方保留两个 `datetime-local` 补手到秒），不要并排两个 `datetime-local`；低基数枚举用 `USelect`；长 ID 粘贴类（`traceId` / `sessionId` / `deviceCode`）与显示偏好留浮层。控件搬出浮层后，**浮层的「有筛选」高亮必须同步收窄**到仍留在浮层内的项，否则会出现「浮层里什么都没设却一直亮着」。

  时间区间控件的落码在 `layers/system/app/components/Audit/RangePicker.vue`（浮层形态照 Nuxt UI dashboard 模板的 `HomeDateRangePicker`：快捷项列 + 双月日历），实测两个坑：① 浮层宽度由内容决定，包日历的容器**不能**写 `w-0 flex-1`（两月视图会被压成 0 宽互相重叠，点击被邻月单元格拦截）；② 日历只给日期，选「整天」必须落成 `00:00:00` … `23:59:59`，只填 `23:59` 会漏掉当天最后 59 秒；日期对象用 Nuxt UI 自带的 `@internationalized/date`，不要自己造 `Date` 包装。
- **不自造控件**：页面与组件只用 Nuxt UI v4 原生组件（`UButton` / `UPopover` / `USelect` / `UInput` / `UFormField` / `UAlert` / `UModal` / `USkeleton` / `UDropdownMenu` …），不手写按钮、下拉、弹层、输入框的等价物；确实没有原生对应时才自建，且先写 ADR 说明缺口与替代面，再写最小的组合封装。
- 一个页面**至多一个**主 CTA（`color="primary"`）：`create` 的「创建」或 `edit` 的「保存」；`view` 态无 primary，主 CTA 降级为 `variant="outline"`。
- 危险动作位于右区提交组左侧（`color="error" variant="outline"`）；批量危险动作置于左区，仅在 `selectedCount > 0` 时出现，并带 `UKbd` 计数。
- **左右内边距与内容对齐（12px）**：工具栏左右各 `px-3`（`0.75rem`），与栏内内容的 `p-3` 同一坐标 —— 左区第一个动作压在左栏内容左缘，右区主 CTA 与右栏内容右缘齐平。**内容页不再有页面级 Alert**（0.2.11：身份 / 范围说明这类口径文案改放详情栏顶部、内边距 `px-4 pt-4`，与详情内容的 `p-4` 对齐），因此工具栏的对齐目标只剩栏内内容。`UDashboardToolbar` 根内边距必须一起清零（`ui.root` 里 `px-0 sm:px-0`，只写 `px-0` 会被默认的 `sm:px-6` 在 ≥640px 再叠 24px），也不得沿用 `UHeader` 的响应式内边距（`px-4 sm:px-6 lg:px-8`）：工具栏在内容盒内而不是整屏宽度上，`lg` 档 32px 会与内容形成 20px 横向错位，观感上"两头留白过大"（0.2.6 修正，`check:ui` 实测左右各 12px）。
- **顶栏模式：对齐的是容器，不是内边距（0.2.8）**：`topbar` 模式下工具栏内层容器与 `UHeader` 的 `container` 共用 `topbarMaxWidthClass` 并各自居中，两者左右边缘与宽度一致（1920 视口、默认 `wide` 预设下同为 `left=240` / `width=1440`）；内边距则各管各的 —— 工具栏保持 `px-3`，页头保持 `UContainer` 的 `px-4 sm:px-6 lg:px-8`，两处内容左缘因此恒差 20px。这是**有意保留**：工具栏该对齐的是页面内容（滚动容器里 `p-3` 的 12px），页头该对齐的是它自己那 32px；让工具栏改吃 `lg:px-8` 只会在内容盒里再缩进 20px（0.2.6 已实测成「两头留白过大」）。`check:ui` 把 12 / 32 / 20 三个数都断言下来，动内边距前先看这条。

### 4.2 动作归属判定（三问）

按顺序命中即停，结果只决定**落在哪个区**，不再决定层级：

1. 改变的是**集合**（多条 / 全部）→ 左区。
2. 改变的是**单条**（含危险动作）→ 右区「记录域」组。
3. 只改变**当前未保存的草稿**（取消 / 保存）→ 右区「提交域」组。
4. 以上都不是（跨页、只读导航、全局）→ 也不另开一条：放右区最右，或留在页面内容里（如帮助链接）。

右区的固定顺序（左 → 右，不得重排）：**记录域动作（危险动作在最左）→ 提交域动作 → 主 CTA**。标题不再占工具栏位。

### 4.3 注入机制

- 用 `Teleport` 而非模块级共享状态：`Teleport` 无全局状态、组件卸载自动移除、SSR 安全、`<KeepAlive>` 下不串页；页面无需为动作另写 SFC。
- 两个挂载点常驻 DOM（即使工具栏整条收起，见 §4.4），因此 target id 可静态书写；又因为全模式只有**一个**渲染点（见下一条），切换布局模式不会销毁挂载点，注入的内容稳定保留。
- 原 `usePageToolbar()` 的模块级 `shallowRef` 通道**废弃**：`ssr: false` 下不存在跨请求共享，但它是模块级单例（同页多个组件实例互相覆盖），且强制为动作另写 SFC —— 废弃理由是「多写入者 + 额外 SFC」，不是 SSR。
- **判空靠观测，不能靠 `computed`**：`Teleport` 的内容不是 `AppToolbar` 的响应式子节点，`$slots` / `computed` 都看不见它。`AppToolbar` 挂载时对两个挂载点开 `MutationObserver`（`childList`），据此决定整条是否收起（§4.4）。这是 0.2.5 之前工具栏长期空占一条 49px 的根因。
- **单一渲染点**（0.2.7 修正）：`AppToolbar` 在 `default.vue` 里**只渲染一次**，且位置在滚动容器之外（§3.3），不得按模式写成 `<AppToolbar v-if="isBigscreenMode" />` / `v-if="!isBigscreenMode" />` 两处。原因：`Teleport` 在挂载时绑定目标节点，切换布局模式若销毁并重建挂载点，页面注入的内容会跟着旧节点留在**已脱离文档的子树**里 —— 表现是「工具栏还在、搜索框与按钮全空」（侧栏模式实测）。`check:ui` 用「偏好设置 → 侧栏」切换后断言动作仍在，守这条线。

### 4.4 单层、高度与窄屏

- 工具栏高度**只读单一变量 `--app-toolbar-h`**（默认 49px 等值 rem，与 `--content-sticky-top` 同源），不得换行；放不下时右端折叠为 `UDropdownMenu`（`⋯`），保留 primary 与危险动作，不得整体隐藏。`--app-font-scale` 变化时一并缩放。
- **无动作整条收起**：既没有面包屑（非 `topbar` 模式）也没有任何注入时，`AppToolbar` 收成 0 高、去掉 `bg` / `backdrop-blur` / 底边（`min-h-0 h-0 overflow-hidden border-b-0 bg-transparent backdrop-blur-none`），避免每页白占一个工具栏高度；挂载点仍留在 DOM 里，页面加载后注入动作即恢复（先收起再展开，允许一帧位移）。`mobile` 与 `bigscreen` 同一口径（无动作即 0 高）。
- **`topbar` 模式不收起（例外）**：面包屑是设在左区最左的导航锚点，收起就没地方放它，所以顶栏模式下无动作页也留一条 49px，只渲染面包屑、左区挂载点保持 0 子节点。这是顶栏模式的固定站位成本，不是漏收起 —— 判空逻辑因此写成 `!isTopbarMode && !hasPageActions`，改这一条前先想清楚面包屑往哪放。
- 图标按钮必须 `aria-label` + Tooltip（`UKbd` 显示快捷键）；工具栏按钮统一 `size="sm"`。
- **覆盖式跟随当前面板**（同一层，不新增层）：列表态 = 左区集合域动作（含「新建」），右区空；详情态 = 左区最左「返回」，右区记录域 / 提交域动作，「新建」隐藏。两栏形态 = 左区集合域 + 右区记录域 / 主 CTA 同屏。
- 「返回」由**页面**渲染进左区（`Layout/Split.vue` 不再自带栏内返回行）；两栏形态不渲染「返回」。

## 五、记录级面包屑与选择 URL 契约

面包屑 = **路由层级（系统生成）** + **当前选择（记录级，可清除）**。二者来源不同，禁止合并为一个由页面手写的数组。

### 5.1 两段的分工

| 段 | 来源 | 变化时机 | 可点击性 |
| :--- | :--- | :--- | :--- |
| 路由段 | `useNavigation().breadcrumb`，由路由表 `meta.sort` / `meta.name` 推导 | 路由变化 | 中间段可跳转；末段（当前页）不可点 |
| 记录段 | 记录上下文（当前选中记录的展示名） | 选择变化 / 详情数据到达 | 无 `to`，渲染为按钮，点击 = 清除选择（移动端即「返回列表」） |

- 记录段**只在末位**追加一段，不构造「路由 → 记录 → 子页」三级：面包屑表达层级，不表达字段级路径。
- **父段链接的落点是默认子页，不是路由 path**：父路由（如 `/system`）只做分组、没有页面，侧栏里那一项也没有 `to`；面包屑父段因此走 `defaultChildPath()`，指向它 `sort` 最小的子路由（`/system/user`）。写 `to: m.path` 会让「系统管理」点出 404。`check:ui` 断言首段 `href="/system/user"` 而当前页段无链接。
- 记录段标签随 `pending → loaded` 自动更新（加载中显示编号，加载完成显示展示名），页面不得为此手写 `watch` 重注入。
- 内容中心文档详情的动态标题继续使用 `route.meta.breadcrumb`（既有实现，页内唯一写入者），与记录段互不覆盖；两者同时存在时记录段在前。

### 5.2 选择即 URL

当前选中记录的唯一事实源是 URL query：`?id=<记录标识>`（例如 `/system/user?id=ACC0001`）。

| 场景 | 行为 | 理由 |
| :--- | :--- | :--- |
| 两栏形态点选一行 | `router.replace` | 左右栏同屏，点选是「查看」，不应污染浏览器历史 |
| 覆盖式形态点选一行 | `router.push` | 覆盖式需要系统返回键回到列表 |
| 直接访问带 `?id` 的链接 | 列表加载后自动选中该条 | 深链可分享、刷新不丢上下文 |
| `?id` 所指记录**不在当前 `rows`** | 右栏空态「该记录不在当前筛选 / 分页结果内」+「清除选择」，不发详情请求 | 上游无详情端点时，列表结果是唯一可靠来源；静默翻页去捞会让筛选状态与 URL 不一致 |
| `?id` 指向的记录不存在 | 右栏空态 + 一次提示，URL 不清空 | 避免把「上游暂时失败」当成「记录已删除」 |

> **历史行为跟形态走，不跟设备走**：同一台设备上宽度可变（拖动窗口、展开侧栏），形态会在一次会话里切换；按设备决定会让桌面窄窗的返回键跳回列表而不是上一条记录。

**实现（0.2.3 落地）**：写入与命中判定统一走 `useRecordSelection`（`app/composables/useRecordSelection.ts`）—— `?id` 是唯一事实源，命中只在当前 `rows` 里做，`?id` 不进列表请求键；两栏 / 覆盖式分别对应 `replace` / `push`；两栏形态的默认选中由 `autoSelect` + `defaultRecord` 开启（`defaultRecord` 必须与列表展示顺序同一 `sortKey`），只执行一次，覆盖式不默认选中。记录段走 `useRecordContext`（`app/composables/useRecordContext.ts`）：页面只绑定一次标签来源（编号 → 展示名自动更新），`AppToolbar` 把它追加在面包屑末位并渲染成按钮，点击 = 清除选择。

### 5.3 覆盖式降级

- 覆盖式下（`mobile` 或容器 < 56rem）面包屑在 header 中不显示（现为 `hidden md:flex`），因此**记录名必须在右栏内容区顶部再现一次**（内容区标题：展示名 + 编号），否则用户无法确认「我在看哪一条」。
- 「返回列表」在覆盖式下**只有两个等价入口**：内容页工具栏左区最左的「返回」按钮（由页面注入，`Layout/Split.vue` 不自带），以及浏览器 / 系统返回键（因为覆盖式用 `push`）。两栏形态**不渲染**「返回」按钮。

## 六、禁止事项（反模式清单）

| 反模式 | 后果 | 正确做法 |
| :--- | :--- | :--- |
| 用视口断点（`md:` / `lg:`）决定形态 | 侧栏折叠、顶栏限宽、分屏窄窗三种情况下全部误判 | 容器查询 `@container` + 56rem 门槛 |
| 硬编码吸顶偏移（`top-0` / `top-[49px]`） | `bigscreen` 双滚动条或列头被工具栏遮住 | `top-(--content-sticky-top)`，高度读 `--app-toolbar-h` |
| 页面自建分栏栅格 | 四模式行为各自漂移，`check:ui` 无法统一断言 | `Layout/Split.vue` 原语 |
| 分栏容器沿用 `min-h-full` | 非 `bigscreen` 无 definite height，栏内滚动退化成整页滚动 | 内容容器 `flex min-h-0 flex-1 flex-col` + 页面根 `flex-1 min-h-0` |
| 按设备（`isMobile`）决定 `push` / `replace` | 同一设备宽度可变，桌面窄窗返回键行为错乱 | 按当前形态决定历史行为 |
| 在右栏内再嵌「列表 → 详情」 | 二级主从叠加，返回语义与面包屑失去唯一解 | 关联表只提供「查看全部」外链 |
| 行内动作 + 工具栏动作并存 | 同一动作两处入口，移动端命中区不足 | 行内至多 1 个，其余上工具栏 |
| 用 `UModal` 承载「查看详情」 | 分栏空态与弹窗语义重复，返回栈混乱 | 详情栏 |
| 页面写 `route.meta.breadcrumb` 拼记录段 | 多个写入者互相覆盖，离开页面串标签 | 记录上下文派生 |
| 页面级单例 loading / error | 一栏失败拖垮整页 | 分栏三态 |
| 自建工具栏或把动作塞进 `UCard` 头部 | 动作位置随页面漂移 | `Teleport` 注入内容页预留工具栏（§4） |
| 详情栏默认即可编辑（无 `view` 态） | 脏状态常驻，切行必弹确认，误改面最大 | `view → edit → create` 三态 |
| 默认选中另写一份排序 | 默认选中的不是列表第一行 | 复用列表同一个 `sortKey` |
| 用 `UModal` 承载记录的编辑表单 | 同一记录两套入口，脏检查各自为政 | 详情栏内联表单（一次性无记录表单才用弹窗） |
| 栏内自建第二条工具栏（栏内 header 再放一排动作） | 窄窗叠两层，600px 视口被吃掉 98px；动作归属随页面漂移 | 全部经 `Teleport` 进内容页预留工具栏，左右分区 |

## 七、验收与守卫

| 断言 | 位置 | 覆盖 |
| :--- | :--- | :--- |
| 六档容器宽（320 / 768 / 1024 / 1366 / 1440 / 1920）各渲染一次试点页：≥ 56rem 且非 `mobile` 为两栏，否则覆盖式；任何一档均无横向滚动、无嵌套滚动条 | `check:ui`（`/system/user` 六档实测：形态 + 双 `[data-pane]` 可见性；「无嵌套滚动条」仍是人工项） | 形态收敛 + 最小页面宽度 |
