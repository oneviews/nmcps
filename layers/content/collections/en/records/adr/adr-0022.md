# ADR-0022: Folding the full Mininet lab into the scenario layer and retiring the legacy frontend

> **Tier**: Tier 5 records layer — append-only after publication; later corrections go into added `##` sections instead of rewriting published conclusions.
> **Relation to ADR-0020 / ADR-0021**: ADR-0020 opened the read-only channel and deferred writes, terminals, sniffing and WebSockets. ADR-0021 fixed tenant isolation, permission bits, the ledger and the audit principle, and used the P4 gate to keep terminals and sniffers closed. This ADR answers those deferred items and makes "retire the legacy Vite frontend" a verifiable finish line.
> **Status**: on 2026-11-16 the requester set the goal — "replicate 5173 fully into `/scenario/simulator`, then scrap the mininet frontend and keep only the pure backend". This ADR is the technical decision for that goal; delivery follows the six stages in §9.

---

## 1. Decisions (summary)

| Id | Decision | Notes |
| :--- | :--- | :--- |
| **D1** | Write endpoints are registered **one `(method, template)` at a time**, never by prefix | 28 write endpoints join `MININET_ROUTES`; unregistered paths still return `404 bff_resource_not_allowed`, wrong verbs still `405 bff_method_not_allowed`. The whitelist itself is the capability boundary — there is no global runtime switch. |
| **D2** | Write capability is **tiered by permission bit**, one endpoint one bit | `lab:create` / `lab:operate` / `lab:delete` / `lab:sniffer` are independent; `import_json` and `full_reset` need **two** bits; no tier implies another. |
| **D3** | `channel` capabilities are computed **per session** | `GET /api/lab/channel` returns `writeEnabled` plus action-grouped `capabilities`; pages read capabilities before rendering buttons and never render-then-wait-for-405. |
| **D4** | Writes **audit first, then execute**; high-risk actions fail closed | The audit outbox appends to `.data/audit/lab-audit.jsonl` (append-only, daily shards); a failed write returns `503 audit_unavailable`. |
| **D5** | **One in-flight write per network** | Ledger-level tenant mutex plus a network lock; conflicts return `409 lab_operation_in_progress`, never a silent queue-and-overwrite. |
| **D6** | The four WebSockets go through **same-origin `/lab-ws/*` with a short-lived ticket** | `POST /api/lab/ws-ticket` signs an HMAC ticket (60 s TTL, single use, bound to `sub`/`tid`/`kind`/`target`); browsers never connect to `:8000`. |
| **D7** | Exports use a **dedicated content-type channel**, not the `ApiResponse` envelope | `GET /api/lab/export/{json,script,pcap}`: the first two are `text/plain`, pcap is a binary attachment; pcap needs `lab:sniffer`. |
| **D8** | The legacy Vite frontend **retires once replication is accepted** | `mininet_gui_frontend` leaves deployment and docs; `services/mininet-api` stays as the pure backend; no more dual-writing or read-only reference. |
| **D9** | Upstream CORS closes; browsers only reach the BFF | The backend no longer needs `Access-Control-Allow-Origin: *`; 8000 stays behind the reverse proxy. |
| **D10** | Vocabulary and ownership unchanged | Upstream node / link / flow ids are **not** credentials; tenants come only from the signed session; production and lab topologies stay separate. |

## 2. Write whitelist and permission tiers

The FastAPI routes in `services/mininet-api` are the single source of truth (result of scanning `@app.<method>`), totalling **28 write endpoints**:

| Permission | Endpoints (upstream paths) | Meaning |
| :--- | :--- | :--- |
| `lab:create` | `POST /api/mininet/start`, `POST /hosts`, `POST /switches`, `POST /routers`, `POST /nats`, `POST /controllers`, `POST /links` | Build the network, add nodes / links |
| `lab:operate` | `POST /stop`, `POST /reset`, `POST /node_position`, `POST /associate_switch`, `POST /flows`, `POST /pingall`, `POST /iperf`, `PATCH /hosts/{host_id}`, `PATCH /routers/{router_id}`, `PUT /links`, `PUT /controllers/{controller_id}`, `PUT /switches/{switch_id}/openflow`, `DELETE /delete_link/{src_id}/{dst_id}`, `DELETE /remove_association/{src_id}/{dst_id}`, `DELETE /flows`, `DELETE /flows/{switch_id}/{flow_id}` | Change the network, run tests, edit flow tables |
| `lab:delete` | `DELETE /delete_node/{node_id}` | Remove a node (and its links) |
| `lab:delete` + `lab:create` | `POST /full_reset`, `POST /import_json` | Destructive rebuild: clear then build; missing either bit is 403 |
| `lab:sniffer` | `POST /sniffer/start`, `POST /sniffer/stop` | Start / stop capture (`lab:read` is not enough to read captures) |

**Still `lab:read`**: `GET /export_json`, `GET /export_script`; `GET /sniffer/export` additionally needs `lab:sniffer`.

**Nothing stays closed**: after this ADR all 20 upstream GETs (17 query endpoints plus 3 export channels) and all 28 write endpoints are reachable (subject to permission bits and the ledger). That is the definition of "full replication".

## 3. Failure semantics (added on top of ADR-0020 / ADR-0021)

| Situation | Status / message |
| :--- | :--- |
| Valid session without the endpoint's permission bit | `403 lab_permission_denied` |
| Ledger miss / other tenant | `404 lab_resource_not_found` (never 403) |
| Another write already in flight on the same network | `409 lab_operation_in_progress` |
| Tenant already has a running network (`start` / `import_json`) | `409 lab_network_already_running` |
| Audit write failed | `503 audit_unavailable` (no do-first-patch-later) |
| Ticket expired / replayed / binding mismatch | `401 lab_ws_ticket_invalid` |
| Registered write endpoint but upstream 405 | `502 upstream_method_misconfigured` (a configuration fault, not a user error) |

**Forbidden**: treating `lab:read` as a write fallback; using frontend disabling as a permission check; merging "the network exists" and "you may operate it" into one status code.

## 4. WebSocket tickets and forwarding

```
browser ──POST /api/lab/ws-ticket {kind,target}──▶ BFF (session + permission bit + ledger)
        ◀── {ticket, expiresAt, url:"/lab-ws/terminal?ticket=…"} ──
browser ──WS /lab-ws/terminal?ticket=…──▶ Nitro (crossws upgrade)
                                            ├─verify HMAC / TTL / single use / binding
                                            ├─connect ws://<tenant instance>/api/mininet/terminal/{node}
                                            └─bidirectional piping (no payload recorded, duration only)
```

| Item | Value |
| :--- | :--- |
| Ticket body | `HMAC-SHA256(secret, "v1|kind|target|sub|tid|exp|jti")`, Base64URL |
| TTL | 60 seconds (`expiresAt` is server-provided; clients cannot renew) |
| Single use | `jti` marked used in BFF memory and the ledger; replay returns 401 |
| Binding | `kind` / `target` must match the upgrade request exactly; `sub`/`tid` come from the session, never from query parameters |
| Permission bit | `terminal` → `lab:terminal`; `sniffer` → `lab:sniffer`; `monitor` / `logs` → `lab:read` |
| Recording | start / end / target / duration / `request_id` only; terminal input and capture payloads are **never** recorded |

**Why browsers may not connect to 8000 directly**: that would require handing the upstream address to the browser, bypassing the ledger and the permission bits. A ticket only proves the BFF allowed the connection once; it does not prove it allows every frame.

## 5. Export and import

| Action | Channel | Content type | Permission |
| :--- | :--- | :--- | :--- |
| Export JSON / script | `GET /api/lab/export/json`, `/export/script` | `text/plain; charset=utf-8` | `lab:read` |
| Export capture | `GET /api/lab/export/pcap` | `application/vnd.tcpdump.pcap`, `Content-Disposition: attachment` | `lab:sniffer` |
| Import JSON | `POST /api/lab/import_json` | JSON envelope | `lab:delete` + `lab:create` |

Exports do **not** reuse the `[...slug].ts` JSON envelope: `ApiResponse` would wrap text into a JSON string, breaking `wget` / browser save-as and the pcap byte stream. The filename is generated by the BFF (`lab-<network_id>-<timestamp>.<ext>`); the upstream `Content-Disposition` is not trusted.

## 7. Retiring the legacy frontend

1. Acceptance: every row of §6 has an equivalent entry point in `/scenario/simulator`, and `check:ui` covers the critical paths.
2. Freeze: `mininet_gui_frontend` receives no new features; it only serves as a behavioural reference during replication.
3. Retire: delete the `mininet_gui_frontend` directory and its deployment unit; turn off CORS on `services/mininet-api` so it is only reachable through the reverse proxy.
4. Close out: drop the "read-only stage" and "reference only" clauses from `.clinerules/11-lab-ui` and `docs/ai/lab-boundary.md`, pointing at this ADR instead; mark ADR-0020 D2/D5 as released by ADR-0022 in an appended section.
5. Legacy: the `mininet_gui_backend` package name and `cli.py` stay unchanged (pure backend); the frontend retirement does not rename them.

## 8. Rejected options

| Option | Why rejected |
| :--- | :--- |
| Keep the legacy frontend running in parallel | Two UIs drift by construction, and writes would race on the same `app.net`; neither side can prove consistency. |
| Browsers connect to 8000 with backend-side ticket checks | Requires shipping the upstream address to browsers, bypassing the BFF ledger; the backend has no notion of a session, so it cannot bind a tenant. |
| One global `allowWrite` switch | Too coarse: `full_reset` and `node_position` carry different risk and must map to different permission bits. |
| Frontend disabling while the backend keeps returning 405 | "Full replication" becomes unreachable, and disabling a button is not a permission boundary. |
| Keep exports inside `ApiResponse` | Text and pcap get double-encoded and `Content-Disposition` is lost. |
| Copy the legacy Vue tree wholesale | The legacy app is Options API with handwritten styles; copying it would introduce a second design-token system and fight the Nuxt UI v4 / i18n / read-only canvas model in `layers/scenario`. |

## 9. Delivery order and gates

| Stage | Content | Done when |
| :--- | :--- | :--- |
| **W1** | Write whitelist + permission tiers + audit outbox + `channel` capabilities + serialisation lock | `check:lab-bff` grows past 60 assertions: for each of the 28 write endpoints "allowed / 403 without the bit / 404 unregistered / zero upstream hits", and the audit 503 path is reproducible |
| **W2** | Topology editing: add/remove nodes, links, position, openflow, flow tables | The canvas can add and delete and stays consistent with the `GET` ledger; `check:ui` covers one add and one delete |
| **W3** | Run control: `start` / `stop` / `reset` / `full_reset` / `pingall` / `iperf` | Both the single-network 409 and the in-flight 409 are reproducible |
| **W4** | Export / import (including pcap) | All three content types download directly; `import_json` dual permission asserted |
| **W5** | Four WebSockets + tickets | Expired / replayed / binding-mismatched tickets each return 401 in assertions; terminal and capture entries only render for explicitly granted roles |
| **W6** | Legacy retirement + doc close-out | `mininet_gui_frontend` deleted; `.clinerules` and `lab-boundary.md` updated; `pnpm check:doc-system` / `check:i18n` / `lint` / `typecheck` all green |

**Gates**: W2 must not start before W1 is green (otherwise the UI ships buttons over 403s); the terminal and capture entries must not render before W5 is green; "retired" may not be claimed before W6 completes.

> **Status (2026-11-16)**: W1 has landed — `MININET_ROUTES` now holds 45 entries (17 query + 28 write, each with its permission bits); `/api/lab/**` resolves in the order session → path → permission → ledger → audit → lock → egress; new `labAudit.ts` (`.data/audit/lab-audit-<date>.jsonl`, failure returns 503), `labLocks.ts` (409 for an in-flight write on the same network), and per-session `channel.capabilities`; `check:lab-bff` is **69/69** (groups ⓪ write tiers, ⑧ write channel, ⑨ audit fail-closed) and `check:lab-tenancy` **22/22** (whitelist bits ⊆ matrix, dual permission, sniffer independence). The all-of permission check now lives in the pure `hasLabPermissions()`, shared by `[...slug].ts` and `authorizeLabAll()`.
>
> **W2 has landed (topology editing, same day)**: `/scenario/simulator` reads `channel.capabilities` before rendering any action — add node (five kinds, `POST /hosts|switches|routers|nats|controllers`), delete node (`DELETE /delete_node/{id}`, with the id written into the confirm dialog), add link (`POST /links`), delete link (`DELETE /delete_link/{src}/{dst}`), drag-to-persist (`POST /node_position`, converting the canvas delta into the upstream absolute position), the switch OpenFlow version (`PUT /switches/{id}/openflow`) and flow-table read/write (`GET /flows/{switch}` shows the `ovs-ofctl` output verbatim; ## 10. Residual risks

1. **Upstream `full_reset` has no confirmation parameter**: the BFF can only require `lab:delete` plus an explicit `confirm: "<network_id>"` body check; upstream supports no idempotency key.
2. **Single-instance global `app.net`**: this ADR does not change ADR-0021 D1; the W3 409 holds only within one tenant, so cross-tenant safety still depends on per-tenant instances.
3. **Audit retention**: `.data/audit/*.jsonl` is transitional; external audit storage plus a retention policy is required long term.
4. **WebSocket piping under Nitro's resource model**: each `crossws` connection occupies an event-loop task, so deployment must cap concurrent terminals (default 4 per tenant).
5. **Deleting the legacy frontend is irreversible**: tag `legacy-mininet-gui-final` before deletion so the behavioural reference stays reachable.
