# ADR-0022: Folding the full Mininet lab into the scenario layer and retiring the legacy frontend

> **Tier**: Tier 5 records layer — append-only after publication; later corrections go into added `##` sections instead of rewriting published conclusions.
> **Relation to ADR-0020 / ADR-0021**: ADR-0020 opened the read-only channel and deferred writes, terminals, sniffing and WebSockets. ADR-0021 fixed tenant isolation, permission bits, the ledger and the audit principle, and used the P4 gate to keep terminals and sniffers closed. This ADR answers those deferred items and makes "retire the legacy Vite frontend" a verifiable finish line.
> **Status**: on 2026-11-16 the requester set the goal — "replicate 5173 fully into `/scenario/simulator`, then scrap the mininet frontend and keep only the pure backend". This ADR is the technical decision for that goal; delivery follows the six stages in §9.

---

## 1. Decisions (summary)

| Id | Decision | Notes |
| :--- | :--- | :--- |
| **D1** | Write endpoints are registered **one `(method, template)` at a time**, never by prefix | 28 write endpoints join `MININET_ROUTES`; unregistered paths still return `404 bff_resource_not_allowed`, wrong verbs still `405 bff_method_not_allowed`. The whitelist itself is the capability boundary — there is no global runtime switch. |
| **D2** | Write capability is **tiered by permission bit**, one endpoint one bit | `lab:create` / `lab:operate` / `lab:delete` / `lab:sniffer` are independent; `import_json` and `full_reset` need **two** bits; no tier implies another. |
| **D3** | `channel` capabilities are computed **per session** | `GET /api/lab/channel` returns `writeEnabled` plus action-grouped `capabilities`; pages read capabilities before rendering buttons and never render-then-wait-for-405. |
| **D4** | Writes **audit first, then execute**; high-risk actions fail closed | The audit outbox appends to `.data/audit/lab-audit.jsonl` (append-only, daily shards); a failed write returns `503 audit_unavailable`. |
| **D5** | **One in-flight write per network** | Ledger-level tenant mutex plus a network lock; conflicts return `409 lab_operation_in_progress`, never a silent queue-and-overwrite. |
| **D6** | The four WebSockets go through **same-origin `/lab-ws/*` with a short-lived ticket** | `POST /api/lab/ws-ticket` signs an HMAC ticket (60 s TTL, single use, bound to `sub`/`tid`/`kind`/`target`); browsers never connect to `:8000`. |
| **D7** | Exports use a **dedicated content-type channel**, not the `ApiResponse` envelope | `GET /api/lab/export/{json,script,pcap}`: the first two are `text/plain`, pcap is a binary attachment; pcap needs `lab:sniffer`. |
| **D8** | The legacy Vite frontend **retires once replication is accepted** | `mininet_gui_frontend` leaves deployment and docs; `services/mininet-api` stays as the pure backend; no more dual-writing or read-only reference. |
| **D9** | Upstream CORS closes; browsers only reach the BFF | The backend no longer needs `Access-Control-Allow-Origin: *`; 8000 stays behind the reverse proxy. |
| **D10** | Vocabulary and ownership unchanged | Upstream node / link / flow ids are **not** credentials; tenants come only from the signed session; production and lab topologies stay separate. |

## 2. Write whitelist and permission tiers

The FastAPI routes in `services/mininet-api` are the single source of truth (result of scanning `@app.<method>`), totalling **28 write endpoints**:

| Permission | Endpoints (upstream paths) | Meaning |
| :--- | :--- | :--- |
| `lab:create` | `POST /api/mininet/start`, `POST /hosts`, `POST /switches`, `POST /routers`, `POST /nats`, `POST /controllers`, `POST /links` | Build the network, add nodes / links |
| `lab:operate` | `POST /stop`, `POST /reset`, `POST /node_position`, `POST /associate_switch`, `POST /flows`, `POST /pingall`, `POST /iperf`, `PATCH /hosts/{host_id}`, `PATCH /routers/{router_id}`, `PUT /links`, `PUT /controllers/{controller_id}`, `PUT /switches/{switch_id}/openflow`, `DELETE /delete_link/{src_id}/{dst_id}`, `DELETE /remove_association/{src_id}/{dst_id}`, `DELETE /flows`, `DELETE /flows/{switch_id}/{flow_id}` | Change the network, run tests, edit flow tables |
| `lab:delete` | `DELETE /delete_node/{node_id}` | Remove a node (and its links) |
| `lab:delete` + `lab:create` | `POST /full_reset`, `POST /import_json` | Destructive rebuild: clear then build; missing either bit is 403 |
| `lab:sniffer` | `POST /sniffer/start`, `POST /sniffer/stop` | Start / stop capture (`lab:read` is not enough to read captures) |

**Still `lab:read`**: `GET /export_json`, `GET /export_script`; `GET /sniffer/export` additionally needs `lab:sniffer`.

**Nothing stays closed**: after this ADR all 20 upstream GETs (17 query endpoints plus 3 export channels) and all 28 write endpoints are reachable (subject to permission bits and the ledger). That is the definition of "full replication".

## 3. Failure semantics (added on top of ADR-0020 / ADR-0021)

| Situation | Status / message |
| :--- | :--- |
| Valid session without the endpoint's permission bit | `403 lab_permission_denied` |
| Ledger miss / other tenant | `404 lab_resource_not_found` (never 403) |
| Another write already in flight on the same network | `409 lab_operation_in_progress` |
| Tenant already has a running network (`start` / `import_json`) | `409 lab_network_already_running` |
| Audit write failed | `503 audit_unavailable` (no do-first-patch-later) |
| Ticket expired / replayed / binding mismatch | `401 lab_ws_ticket_invalid` |
| Registered write endpoint but upstream 405 | `502 upstream_method_misconfigured` (a configuration fault, not a user error) |

**Forbidden**: treating `lab:read` as a write fallback; using frontend disabling as a permission check; merging "the network exists" and "you may operate it" into one status code.

## 4. WebSocket tickets and forwarding

```
browser ──POST /api/lab/ws-ticket {kind,target}──▶ BFF (session + permission bit + ledger)
        ◀── {ticket, expiresAt, url:"/lab-ws/terminal?ticket=…"} ──
browser ──WS /lab-ws/terminal?ticket=…──▶ Nitro (crossws upgrade)
                                            ├─verify HMAC / TTL / single use / binding
                                            ├─connect ws://<tenant instance>/api/mininet/terminal/{node}
                                            └─bidirectional piping (no payload recorded, duration only)
```

| Item | Value |
| :--- | :--- |
| Ticket body | `HMAC-SHA256(secret, "v1|kind|target|sub|tid|exp|jti")`, Base64URL |
| TTL | 60 seconds (`expiresAt` is server-provided; clients cannot renew) |
| Single use | `jti` marked used in BFF memory and the ledger; replay returns 401 |
| Binding | `kind` / `target` must match the upgrade request exactly; `sub`/`tid` come from the session, never from query parameters |
| Permission bit | `terminal` → `lab:terminal`; `sniffer` → `lab:sniffer`; `monitor` / `logs` → `lab:read` |
| Recording | start / end / target / duration / `request_id` only; terminal input and capture payloads are **never** recorded |

**Why browsers may not connect to 8000 directly**: that would require handing the upstream address to the browser, bypassing the ledger and the permission bits. A ticket only proves the BFF allowed the connection once; it does not prove it allows every frame.

## 5. Export and import

| Action | Channel | Content type | Permission |
| :--- | :--- | :--- | :--- |
| Export JSON / script | `GET /api/lab/export/json`, `/export/script` | `text/plain; charset=utf-8` | `lab:read` |
| Export capture | `GET /api/lab/export/pcap` | `application/vnd.tcpdump.pcap`, `Content-Disposition: attachment` | `lab:sniffer` |
| Import JSON | `POST /api/lab/import_json` | JSON envelope | `lab:delete` + `lab:create` |

Exports do **not** reuse the `[...slug].ts` JSON envelope: `ApiResponse` would wrap text into a JSON string, breaking `wget` / browser save-as and the pcap byte stream. The filename is generated by the BFF (`lab-<network_id>-<timestamp>.<ext>`); the upstream `Content-Disposition` is not trusted.

## 7. Retiring the legacy frontend

1. Acceptance: every row of §6 has an equivalent entry point in `/scenario/simulator`, and `check:ui` covers the critical paths.
2. Freeze: `mininet_gui_frontend` receives no new features; it only serves as a behavioural reference during replication.
3. Retire: delete the `mininet_gui_frontend` directory and its deployment unit; turn off CORS on `services/mininet-api` so it is only reachable through the reverse proxy.
4. Close out: drop the "read-only stage" and "reference only" clauses from `.clinerules/11-lab-ui` and `docs/ai/lab-boundary.md`, pointing at this ADR instead; mark ADR-0020 D2/D5 as released by ADR-0022 in an appended section.
5. Legacy: the `mininet_gui_backend` package name and `cli.py` stay unchanged (pure backend); the frontend retirement does not rename them.

## 8. Rejected options

| Option | Why rejected |
| :--- | :--- |
| Keep the legacy frontend running in parallel | Two UIs drift by construction, and writes would race on the same `app.net`; neither side can prove consistency. |
| Browsers connect to 8000 with backend-side ticket checks | Requires shipping the upstream address to browsers, bypassing the BFF ledger; the backend has no notion of a session, so it cannot bind a tenant. |
| One global `allowWrite` switch | Too coarse: `full_reset` and `node_position` carry different risk and must map to different permission bits. |
| Frontend disabling while the backend keeps returning 405 | "Full replication" becomes unreachable, and disabling a button is not a permission boundary. |
| Keep exports inside `ApiResponse` | Text and pcap get double-encoded and `Content-Disposition` is lost. |
| Copy the legacy Vue tree wholesale | The legacy app is Options API with handwritten styles; copying it would introduce a second design-token system and fight the Nuxt UI v4 / i18n / read-only canvas model in `layers/scenario`. |

## 9. Delivery order and gates

| Stage | Content | Done when |
| :--- | :--- | :--- |
| **W1** | Write whitelist + permission tiers + audit outbox + `channel` capabilities + serialisation lock | `check:lab-bff` grows past 60 assertions: for each of the 28 write endpoints "allowed / 403 without the bit / 404 unregistered / zero upstream hits", and the audit 503 path is reproducible |
| **W2** | Topology editing: add/remove nodes, links, position, openflow, flow tables | The canvas can add and delete and stays consistent with the `GET` ledger; `check:ui` covers one add and one delete |
| **W3** | Run control: `start` / `stop` / `reset` / `full_reset` / `pingall` / `iperf` | Both the single-network 409 and the in-flight 409 are reproducible |
| **W4** | Export / import (including pcap) | All three content types download directly; `import_json` dual permission asserted |
| **W5** | Four WebSockets + tickets | Expired / replayed / binding-mismatched tickets each return 401 in assertions; terminal and capture entries only render for explicitly granted roles |
| **W6** | Legacy retirement + doc close-out | `mininet_gui_frontend` deleted; `.clinerules` and `lab-boundary.md` updated; `pnpm check:doc-system` / `check:i18n` / `lint` / `typecheck` all green |

**Gates**: W2 must not start before W1 is green (otherwise the UI ships buttons over 403s); the terminal and capture entries must not render before W5 is green; "retired" may not be claimed before W6 completes.

> **Status (2026-11-16)**: W1 has landed — `MININET_ROUTES` now holds 45 entries (17 query + 28 write, each with its permission bits); `/api/lab/**` resolves in the order session → path → permission → ledger → audit → lock → egress; new `labAudit.ts` (`.data/audit/lab-audit-<date>.jsonl`, failure returns 503), `labLocks.ts` (409 for an in-flight write on the same network), and per-session `channel.capabilities`; `check:lab-bff` is **69/69** (groups ⓪ write tiers, ⑧ write channel, ⑨ audit fail-closed) and `check:lab-tenancy` **22/22** (whitelist bits ⊆ matrix, dual permission, sniffer independence). The all-of permission check now lives in the pure `hasLabPermissions()`, shared by `[...slug].ts` and `authorizeLabAll()`.
>
> **W2 has landed (topology editing, same day)**: `/scenario/simulator` reads `channel.capabilities` before rendering any action — add node (five kinds, `POST /hosts|switches|routers|nats|controllers`), delete node (`DELETE /delete_node/{id}`, with the id written into the confirm dialog), add link (`POST /links`), delete link (`DELETE /delete_link/{src}/{dst}`), drag-to-persist (`POST /node_position`, converting the canvas delta into the upstream absolute position), the switch OpenFlow version (`PUT /switches/{id}/openflow`) and flow-table read/write (`GET /flows/{switch}` shows the `ovs-ofctl` output verbatim; `POST /flows` adds a flow, `DELETE /flows/{switch}/{flow_id}` deletes one, `DELETE /flows` bulk-deletes by `match` — a blank match runs `del-flows` on the whole table, the confirm dialog names the switch and the irreversibility, and the only local check is "no `actions=` in the match"); `lab:create` / `lab:delete` / `lab:operate` open only their own entries, and without `lab:operate` even dragging is disabled (`TopologyCanvas` gained `draggable`, defaulting to `true` — absent boolean props otherwise read as `false`). `check:ui` gained twelve 11.4 cases (capability-gated rendering, add → request body/canvas agree, drag becomes an absolute position, delete + flow read, add flow → request body and echo agree, delete one flow by dump order, the three clear-flow cases — `actions=` in the match rejected in place with zero requests / a blank match clearing the table with a body carrying only `switch` / a filled `match` removing just the matching rows — and the three local-validation branches of add-flow — actions required / `match` carrying `actions=` / priority above 65535 — each rejected in place with **zero requests**), and the fake Mininet ledger plus its flow table became **mutable** with a `mininetLog` of write requests; > **W2 addendum (drag-to-add from the toolbar, same day)**: the "Add" entry on `/scenario/simulator` moved from a dropdown menu to a toolbar node palette (`UPopover`, five kinds, each clickable **and** draggable) — clicking uses the default position, dragging onto the canvas uses the point where the pointer was released, and both paths open the **same** `NodeFormModal` (validation, request body and `POST /api/lab/<collection>` exist once). The position has two conversion layers: `TopologyCanvas` gained `dropEnabled` / `dropHint` and a `canvasDrop` event, which inverts the screen point through `getScreenCTM()` (the `viewBox` mapping) and then through the `<g>`'s `translate + scale`, emitting a graph coordinate; the page then converts that back into ledger `x` / `y` by anchoring on the **nearest existing node** (`raw = anchor.raw + (drop - anchor.display)`), because `buildGraph()` shifts and grid-snap-normalises ledger coordinates and using the graph point as a ledger point would place the node elsewhere. `dropEnabled` defaults to `false` and only becomes `true` while `lab:create` is present and a drag is in flight; the form shows "Drop position (x, y)" before anything is written. The palette is not a `UDropdownMenu`: a menu item collapses on press, which removes the element acting as the drag source, so native drag-and-drop never reaches the canvas. `check:ui` gained two 11.4 cases (palette entries are draggable and the canvas shows the drop hint mid-drag; dropping opens the form with the drop position and `POST /hosts` carries `x` / `y` matching that position and differing from the default one), and the delete case now asserts "node count before minus one" instead of a hard-coded total.

> **W2 / W3 revision (resource list converges with writes, same day)**: field testing reported "a new host succeeds but never appears on the canvas" and "creating a switch fails with `lab_resource_not_found`". Neither was a frontend bug: the ledger's resource list only ever took effect on the read path. Once `resources` is registered (NMCPS-ADR-0021 §3.3) it *is* the tenant boundary, but nothing updated it on writes, so ① a new node fell outside the list and the next `GET /hosts` dropped it at the list egress (hence an invisible node), and ② the upstream `POST /switches` answers with the **switch object itself** (a single object — `create_host` answers `{status:"ok"}`, which is why hosts did not expose this shape), so the egress filter judged it like a read and returned 404. Fix: `handleWrite()` now converges the list after a successful upstream call (the five node create endpoints add the node id, `POST /links` adds `src--dst`, deleting a node or a link removes it and a deleted node also drops its link keys), a failed ledger write only logs a `console.warn` and never rolls back the upstream action, and write responses pass `ignoreResourceScope` so they only check the tenant / network identity. The semantics and the boundary are written down in NMCPS-ADR-0021 §3.4; `check:lab-bff` ⑥ gained four cases (single-object write response is not a 404 / a new switch appears in the list / a new host appears in the list / removal makes it 404 again) and the fake upstream's hosts and switches became a mutable topology with the real response shapes (69 → 73).

> **W3 has landed (run control, same day)**: the right-hand column of `/scenario/simulator` gained a run-control card — the run state is read from `GET /api/lab/start` (the bare boolean `app.net.is_started`, three states: running / stopped / **unknown**; when it cannot be read all four actions stay disabled, because treating "unreadable" as "not started" makes the start button hit an already-running network and then report the upstream 400 as a failure); `POST /start` (`lab:create`, disabled while running), `POST /stop` (`lab:operate`, with a confirm dialog stating that every node process is terminated and the topology is rebuilt unstarted), `POST /pingall` (`operate`, the upstream text is shown line by line and the selected switch's flow table is re-read afterwards because probing rewrites it) and `POST /iperf` (`operate`, both ends can only be hosts, a blank seconds field is **omitted** so upstream applies its own default, and both outputs are shown verbatim). The four actions are mutually exclusive (single upstream instance) and upstream errors (400 / 403 / 409 / 503) are displayed verbatim. The pure functions and their assertions live in `layers/scenario/shared/types/labRun.ts` and `scripts/check-lab-run.ts` (`pnpm check:lab-run`, 13 assertions: three-state normalisation, iperf endpoints / same-host / 1–3600 decimal seconds, request-body omission rules, `pingall` and iperf result text rendering). `check:ui` gained six 11.4 cases (initially stopped with actions disabled / starting flips it to running with stop and probe enabled / `pingall` text on screen / iperf with both ends on one host rejected in place with zero requests / iperf body carrying endpoints, protocol and seconds with both outputs on screen / confirming stop returns the badge to stopped), and the fake upstream's `started` flag became mutable while still logging writes. **Not included**: the `reset` / `full_reset` UI — `full_reset` needs the BFF-side `confirm: "<network_id>"` window (risk 1 in section 10), which does not exist yet; not accidentally rebuilding comes before having the button.
>
> **W4 has landed (topology import / export, same day)**: the "File" menu at the far left of the `/scenario/simulator` toolbar now carries all three items — import topology (JSON) / export JSON / export Python script — so no dead items remain. Exports use a **dedicated static route**, `GET /api/lab/export/[kind].get.ts` (`lab:read`): it returns the raw `text/plain` body instead of the `ApiResponse` envelope, the filename `lab-<network_id>-<UTC>.<ext>` is generated by the BFF (the upstream `Content-Disposition` is not trusted), only the kinds registered in `LAB_EXPORT_UPSTREAMS` (`json` / `script`; W5 later added `pcap`) resolve, and anything else returns `400 bff_path_invalid`; the outbound call goes through the new `fetchMininetText()`. The page downloads with `useApi().download()` (`$fetch.raw` + `responseType: "blob"`, filename read from `content-disposition`) into an `<a download>`, while failures still surface through the `ApiError` JSON branch — an export never goes through `[...slug]`, and `api.get()` never names the file itself. Import goes through `POST /api/lab/import_json` (dual permission `lab:delete` + `lab:create`): the upstream signature is `file: UploadFile = File(...)`, so forwarding the JSON body verbatim would 422, which is why the BFF re-wraps the already-authorised, already-audited body as a multipart `topology.json`; before sending, the page runs the pure `parseLabImport()` shape check (three in-place failures with zero requests: empty file / invalid JSON / unrecognised shape — it accepts both the `nodes`+`edges` graph shape and the `export_json` ledger shape). Upstream import is **additive**, so the ledger converges by union (existing nodes survive) and controller ↔ switch association edges are not counted as links. Assertions: `check:lab-bff` group ⑩ gained 11 (73 → 84: JSON / script bodies, `text/plain`, the BFF filename, unregistered kind 400, multipart egress with the file body verbatim, and the node / switch / link manifest unions), and `check:ui` 11.5 gained 4 (252 → 256: all three items present / an import adds exactly one canvas node, asserted as "before + 1" / the JSON and script filenames and bodies). **Not included**: the `pcap` capture download (needs `lab:sniffer`, part of the W5 sniffer segment) and the `full_reset` UI (still needs the BFF-side `confirm: "<network_id>"` window, see risk 1 in section 10).

> **W5 sniffer segment has landed (capture start/stop, pcap download, destructive rebuild, same day)**: the toolbar now carries a "Tools" menu to the right of "Run", rendered **only when the session holds `lab:sniffer`** — capture is a standalone grant that `lab:read` / `lab:operate` cannot imply (NMCPS-ADR-0021 D3), so an unauthorised session sees no entry at all. Its three items are start capture (`POST /api/lab/sniffer/start`, which also requires a running network — upstream answers 400 otherwise), stop capture and download pcap; the readout comes from `GET /api/lab/sniffer/state` and is **three-state** (`true` / `false` / `null`) exactly like the run state, so an unreadable state disables both actions instead of pretending "not capturing". Downloads keep using the export channel: `LAB_EXPORT_UPSTREAMS` gained a third kind `pcap` (upstream `sniffer/export`, `application/vnd.tcpdump.pcap`, `lab:sniffer`), and the handler now **resolves the kind before checking permission** and dispatches to `fetchMininetText()` or the new `fetchMininetBinary()`: pcap is read as `arrayBuffer`, because `text()` turns `0xd4 0xc3` into U+FFFD and the saved file will not open. The destructive rebuild (`POST /api/lab/full_reset`) became a second group in the "Run" menu: besides the dual permission, the BFF now enforces a `confirm: "<network_id>"` gate (missing / mismatched ⇒ `400 lab_confirm_required`, upstream untouched), the modal requires typing the network ID verbatim (`ResetNetworkModal.vue`), and on success the ledger's `resources` are cleared wholesale via `reset: true` — incremental deletes would leave behind ids upstream grew on its own. > **W5 WebSocket segment has landed (one-shot tickets + live capture, same day)**: `D6`'s ticket channel is now code — `POST /api/lab/ws-ticket { kind, target? }` (`layers/scenario/server/api/lab/ws-ticket.post.ts`) decides in a fixed order (session → body / kind → permission → instance → ledger → audit → sign); the ticket is `base64url("v1|kind|target|sub|tid|exp|jti") + "." + HMAC-SHA256`, signed with the same `NUXT_BFF_SESSION_SECRET` as the session cookie but under the `lab-ws.` domain prefix (so a session cookie is never a ticket and vice versa), TTL 60 seconds, single-use `jti` (an in-process table — multi-instance deployments need it in the ledger), and `sub` / `tid` come from the session only. The channel registry is `LAB_WS_UPSTREAMS` in `layers/scenario/shared/constants/labWs.ts`: **unregistered / unimplemented kinds return `400 lab_ws_kind_invalid`** (kind is resolved before permission), and `target` only accepts a `network_id` of the caller's own network (another tenant's id and a missing one share 404). `sniffer` is implemented: `layers/scenario/server/routes/lab-ws/sniffer.ts` verifies the ticket in the crossws `upgrade` hook (failure ⇒ `401 lab_ws_ticket_invalid`, no connection), resolves the tenant instance from the ticket's `tid` on `open`, connects to upstream `/api/mininet/sniffer` with Node's built-in `WebSocket` and relays text frames verbatim, and on `close` drops the upstream socket and records `duration_ms`; session start / end each write one audit entry (`action: ws_sniffer`) and **audit records only target / duration / request_id — never terminal input or capture payloads**. To make that possible the `event` parameter of `getBffConfig()` / `getMininetConfig()` / `appendLabAudit()` became optional (the upgrade hook has a `Request`, not an H3Event, so only process-level runtime config is readable). Nitro enables `nitro.experimental.websocket` (otherwise `defineWebSocketHandler` routes answer 426). On the client, the new `useLabSnifferStream()` (`layers/scenario/app/composables/`) is the **only** `new WebSocket` entry point: the page loads `GET /api/lab/sniffer/history` first, connects only when the capture state becomes `true` (`null` / `false` never connect), keeps at most 200 rows, and disconnects on stop while keeping the rows already received; the run card gained a live packet panel (protocol / source → destination / length). Assertions: `check:lab-bff` group ⑫ gained 10 (96 → 106: 403 with zero upstream requests when signing a ticket without `lab:sniffer`, 400 for an unregistered kind, 404 for a cross-tenant `target`, the ticket's TTL / same-origin url / absence of the upstream address, three 401s for missing / tampered / replayed tickets, the TCP → ICMP frames relayed for a valid ticket, the BFF's upstream connection carrying no cookie / authorization, and one audit entry each for ticket issuance and session start with no payload), and `check:ui` 11.7 gained 3 (261 → 264: idle backfills history without opening an upstream socket, a running capture appends live frames while the upstream connection carries no cookie, and stopping disconnects while keeping the rows). **Not included**: the terminal / logs / monitor sockets — their registry entries and routes are still missing, though the signing / single-use / binding logic can be reused as-is.

> **The remaining three W5 channels have landed (Webshell / logs / monitor plus the Network Tools panel, 2026-11-17)**: `LAB_WS_UPSTREAMS` grew from one entry to four, each declaring `targetKind` (`network` / `node` / `node-intf` / `none`) and `clientToUpstream`; `ws-ticket` first validates the **shape** of `target` per channel (terminal without a node, monitor not `<node>:<intf>`, logs carrying any target ⇒ `400 bff_body_invalid`), then existence against the ledger (`network` must equal this network's id; `node` / `node-intf` are narrowed to `resources.nodes` **when that list is registered** and left to upstream's `get(node_id)` otherwise). On the client, `useLabWsChannel(kind)` (ticket / connect / disconnect / upstream send) and `SimulatorNetworkTools` (`USlideover` + `UTabs`: Webshell / logs / monitor) are new; the entry is the toolbar's "Network tools" button, hidden entirely without `lab:terminal` or `lab:read`, and the panel's tabs are then pruned by capability. > **W5 Webshell rendering closure (2026-11-17)**: a real PTY emits **ANSI colour codes and `\r` redraws**; pasting that verbatim into a `<pre>` shows the prompt as `^[[1;32mroot@h1:/#` and turns a progress bar into a wall of lines (`10%\r50%`). The new pure function `labTerminalTextOf()` (`layers/scenario/shared/types/labWs.ts`) strips CSI sequences (`ESC[` … final byte) and OSC titles (`ESC]` … `BEL` / `ESC\`), keeps only the last segment after an in-line `\r` (how a real PTY overwrites a line), deletes one character per backspace and still treats `\r\n` as a newline — a character scan rather than a regex, so it neither trips `no-control-regex` nor swallows an escape that spans lines. The panel (`SimulatorNetworkTools`) therefore gained three things: output renders from the cleaned text and **auto-scrolls to the bottom** (an appended stream that does not follow hides the echo of the line you just typed); "Interrupt" sends `0x03` (the PTY interrupt byte) instead of a literal `^C`; "Clear" wipes only the browser-side transcript plus the stale error line and **keeps the socket open** (a PTY has no standard clear-screen sequence — clearing the remote screen means typing `clear`). `useLabWsChannel()` exports `clear()` for that. The fake upstream's terminal greeting now **carries colour codes** (`MININET_TERMINAL_BANNER = ESC[1;32m…ESC[0m`) and answers `0x03` with `^C` (`MININET_TERMINAL_INTERRUPT_ECHO`), so the three new assertions have real evidence: the greeting's ESC passes through the BFF untouched and leaves none behind in the panel; interrupt is not `echo:^C`; the panel is still "connected" after clearing. The same pass fixed one piece of **fake data**: `finiteNumber()` used to fall back to `Number(value)`, so `null` became `0` and `true` became `1`, which rendered a missing monitor rate as `0 Gbit/s` (reporting "unreadable" as "no traffic") — it now accepts only real numbers and non-empty numeric strings. Assertions: `check:lab-bff` group ⑬ gained 1 (115 → 116: `0x03` travels upstream verbatim, upstream answers `^C`, the BFF swallows no control byte) and `check:ui` 11.8 gained 3 (269 → 272: ANSI stripped from the greeting, the interrupt button, clearing without dropping the stream); the new `pnpm check:lab-ws` (`scripts/check-lab-ws.ts`, 21 cases: registry and permissions, the four `target` shapes, upstream address building, ticket normalisation, monitor frame / sample normalisation, PTY cleaning) sits with `check:lab-flows` / `check:lab-run` / `check:lab-tenancy` as a local Lab self-check and stays out of `ci.yml`.

> **W8 landed (a real interactive webshell with multiple sessions, 2026-11-17)**: the 1.0 `Webshell.vue` was an xterm.js terminal with one tab per node, whereas the 2.0 webshell was a single "one line plus Send" form: keystrokes only travelled upstream after Enter, and only one node could be open. ## 10. Residual risks

1. **Upstream `full_reset` has no confirmation parameter**: the BFF can only require `lab:delete` plus an explicit `confirm: "<network_id>"` body check; upstream supports no idempotency key.
2. **Single-instance global `app.net`**: this ADR does not change ADR-0021 D1; the W3 409 holds only within one tenant, so cross-tenant safety still depends on per-tenant instances.
3. **Audit retention**: `.data/audit/*.jsonl` is transitional; external audit storage plus a retention policy is required long term.
4. **WebSocket piping under Nitro's resource model**: each `crossws` connection occupies an event-loop task, so deployment must cap concurrent terminals (default 4 per tenant).
5. **Deleting the legacy frontend is irreversible**: tag `legacy-mininet-gui-final` before deletion so the behavioural reference stays reachable.
