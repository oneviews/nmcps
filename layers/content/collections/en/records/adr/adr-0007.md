# ADR-0007: Enable the Nitro BFF Gateway and server/shared Directories

> **Tier**: Tier 5 record layer — body is immutable (append-only); changes require a new ADR with `supersededBy`.

- **Background**:
  1. v1 (`_reference/nmcps-v1`) implements a **SSR + Nitro Node server** BFF: 95 routes under `server/api/**` with `server/api/[...slug].ts` as the unified gateway; `server/utils/proxy.ts` is the only egress (upstream timeout, header allowlist, single-flight 401 refresh, envelope normalisation, error scrubbing); `server/routes/health.get.ts` serves k8s probes; `shared/types/api.ts` and `shared/utils/apiGuard.ts` hold the shared envelope and guards; `Dockerfile` deploys `pnpm build` output via `node .output/server/index.mjs`.
  2. v2 today is a pure SPA (`ssr: false` in `nuxt.config.ts`) with a single `app/` layer, `shared/` holding only `constants/docIds.ts`, and **no `server/` directory, no API client and no auth**. The desktop bundle is produced by `nuxt generate` as static `dist` and packed into Tauri, so Nitro routes can never run inside the desktop process.
  3. v1's auth has a defect that must not be copied: the BFF stores `auth_token` in an **httpOnly** cookie while the client reads it with `useCookie('auth_token')`. httpOnly cookies are invisible to JS, so a page reload loses the session (`isSignedIn` lives only in memory).
- **Decision**:
  1. **Enable `server/` and `shared/`**: Nuxt 4 already recognises both (the root `tsconfig.json` references `.nuxt/tsconfig.server.json` and `.nuxt/tsconfig.shared.json`), so no `srcDir` change is needed. `shared/` holds only isomorphic types and pure functions; `server/` holds the BFF.
  2. **Deployment shape**: the BFF is a standalone Node service (`pnpm build:server` → `.output/`). Both the web SPA and the Tauri bundle reach it through `runtimeConfig.public.bffBase`; the desktop build keeps using `pnpm generate`, so its artefact shape is unchanged.
  3. **The upstream address stays server-only**: `runtimeConfig.bff.upstreamBase` (overridable with `NUXT_BFF_UPSTREAM_BASE`). The client only knows `public.bffBase`, so the browser bundle no longer exposes the real backend address (v1 put `apiBase` in `public`, which leaks it).
  4. **Unified gateway**: `server/api/[...slug].ts` resolves the target path against `GATEWAY_RESOURCES` plus a verb allowlist from `shared/types/api.ts`; disallowed resources or verbs return 404/405. `server/utils/bff/proxy.ts` is the only egress (timeout, header allowlist, raw body pass-through, responses normalised to `ApiResponse<T>`).
  5. **Explicit CORS**: `server/middleware/cors.ts` echoes an allowlisted Origin from `bff.allowedOrigins` and permits credentials (including `tauri://localhost` and `http://tauri.localhost`). It does **not** use `routeRules: { '/api/**': { cors: true } }`, which emits `Access-Control-Allow-Origin: *` and is incompatible with credentials (v1's approach).
  6. **Health check**: `GET /health` reports process liveness only and does not depend on the upstream (k8s liveness). An upstream readiness probe is deferred until the deployment contract is fixed.
  7. **Auth is pass-through only**: the proxy forwards `Authorization` (and may read `bff.tokenCookieName`). Login, refresh and session storage need a separate ADR (web httpOnly cookie plus desktop Bearer, or a unified Bearer model).
- **Impact**:
  - Adds `server/` (`api/[...slug].ts`, `middleware/cors.ts`, `routes/health.get.ts`, `utils/bff/*`), `shared/types/api.ts`, `shared/utils/apiGuard.ts`, `app/composables/useApi.ts` and `.env.example`.
  - `pnpm build:server` output (`.output/`) becomes the BFF release artefact; `pnpm generate` still serves Tauri only, so CI must build both.
  - Desktop builds must provide `NUXT_PUBLIC_BFF_BASE`, otherwise `useApi` throws `bff_not_configured` instead of silently falling back to a relative path.
  - Backend addresses and internal topology no longer ship in frontend artefacts; the BFF must reach the upstream, and replica counts depend on SSE/long-lived connections.
  - The render mode stays SPA (`ssr: false`) to avoid hydration risk; switching to SSR requires a new ADR.
- **Alternatives rejected**:
  - Embedding Nitro in the desktop app: Tauri ships no Node runtime; a sidecar binary makes size, permissions, ports and upgrades unmanageable.
  - Direct backend access from the desktop app: each client would hit the internal backend and require open CORS, defeating the BFF goal.
  - Wildcard `routeRules` CORS: conflicts with credentials and cannot be constrained per origin.
  - Continuing with hand-written `$fetch('http://…')`: hardcoded addresses and inconsistent error shapes.
- **Open items**:
  - The session/token model (httpOnly cookie vs Bearer, refresh and logout) is undecided and needs ADR-0008.
  - `shared/` currently contains only `api.ts` / `apiGuard.ts`; v1's isomorphic `route-engine` and `metrics` helpers are not migrated yet.
  - The gateway treats responses as JSON; v1's SSE/streaming endpoints (`text/event-stream`) need dedicated handlers (`sendStream`) and cannot go through the unified JSON proxy.
