# ADR-0015: turn the platform demo pages into capability probes and drop shell execution

> **Tier**: Tier 5 records layer — the body is append-only; changes need a new ADR with `supersededBy`.

- **Context**:
  - **These pages are template leftovers, not product features.** All six came from the ViTauri template (`package.json` still carries the template description, author and identifier `com.nicolaspadari.nmcps`). `NMCPS-ADR-0012` moved them into `layers/platform` promising only that the routes would not change; it never decided whether they should exist.
  - **They have no entry point.** `useNavigation()` only keeps routes whose `meta.sort` is a number and whose `meta.hide` is falsy. These six never had `sort` (git history confirms it was not lost in the layer split), so neither the sidebar, the topbar nor `usePages()` shows them; they are reachable only by typing the URL. `meta.category` only feeds `Site/Navbar.vue`, and these pages use the `default` layout, so that path is closed too.
  - **`commands.vue` is a security liability.** It relies on `shell:allow-execute` in `desktop.json`, handing arbitrary strings to the system shell. Tauri's `ShellCommand` validator is effectively `\S.*`, i.e. arbitrary command execution from the WebView, and no business code needs it (real Tauri usage in this repo is `getTauriVersion`, the store behind `useAuthTokens`, and the updater).
  - **The other five pages have no degradation path.** `os` / `file` / `store` / `notifications` / `webview` call `await useTauri*` directly, so opening them in a browser yields silent failures or uncaught errors. Their `store` usage (`autoSave: false` plus a manual `save()`) also contradicts the production `useAuthTokens` (`autoSave: true`), and copying it would corrupt token persistence.
  - **Cross-platform work had no baseline.** There was no `arch.platform` document, so mobile semantics (on Android/iOS `BaseDirectory.Document` is the app-private directory, multi-window needs Activity Embedding / UIScene, notifications need a runtime permission chain) lived only in the Tauri docs.
- **Decision**:
  1. **Keep five pages as capability probes.** `/os`, `/file`, `/store`, `/notifications` and `/webview` stay, with one job: prove on a real device that the plugin actually works. No business data, no productisation.
  2. **Delete `commands.vue` and `shell:allow-execute`.** The page goes away and `src-tauri/capabilities/desktop.json` loses `shell:allow-execute`. The `tauri-plugin-shell` registration and dependency stay for now (without `allow-execute` no command can run); cleaning up Cargo and the lockfile is a separate change to keep the regression surface small.
  3. **Extract six composables.** `usePlatformInfo()` / `usePlatformStore()` / `usePlatformFile()` / `usePlatformNotify()` / `usePlatformWindow()` / `useExternalLink()` return `{ ok, reason }` and own the `isTauri()` guard. The probe store uses its own file `platform-probe.bin` and never reuses `auth.bin`.
  4. **Use a virtual navigation group and keep the URLs.** Add `meta.group = "platform"` and `meta.tauriOnly = true`; `useNavigation()` pulls grouped routes out of the top level and aggregates them into a parent item without `to` (title `pages.platform.title`). The `/os` paths stay unchanged — an explicit amendment to clause 3 of `NMCPS-ADR-0012` ("navigation aggregation unchanged") that preserves its URL promise and does not break bookmarks or docs.
  5. **Show the entry only under Tauri.** Routes with `meta.tauriOnly` stay out of navigation when `isTauri()` is false; direct browser visits still open the page but render only the degradation notice. `check:ui` can then assert "no entry in a browser" while desktop users still find the probes.
  6. **Docs first.** Add `NMCPS-ARCH-005` (`arch.platform`, Tier 1: capability matrix, permission layering, composable conventions, probe scope) and a static `pnpm check:platform` that turns "no more `shell:allow-execute`" into a gate.
- **Consequences**:
  - Code: delete `layers/platform/app/pages/commands.vue`; rework `os.vue` / `file.vue` / `store.vue` / `notifications.vue` / `webview.vue` on top of the composables with degradation notices; add `layers/platform/app/composables/usePlatform*.ts`; update `app/composables/useNavigation.ts` (virtual group + `tauriOnly` filter + `RouteMeta` fields `group` / `tauriOnly`) and `src-tauri/capabilities/desktop.json`.
  - Copy: add `pages.platform.title` and degradation keys to `i18n/locales/{cn,en}.json`; remove `pages.commands.*` from both.
  - Self-checks: add `scripts/check-platform.mjs` (`pnpm check:platform`); re-point the `check:ui` guard case from `/commands` to `/os` and add two browser assertions (no "Platform capabilities" group, `/os` shows "not detectable") plus two host-simulation assertions (inject `globalThis.isTauri` with a minimal IPC stub, then the group appears with five entries), moving the counts from 64 built / 49 external to 68 built / 51 external (`NMCPS-ARCH-003` §7.7 and its change log updated).
  - Mobile is still untested: the Android / iOS columns come from the Tauri v2 documentation and must be confirmed on a device, then written back into `NMCPS-ARCH-005` §7.
- **Alternatives considered**:
  - **Delete all six pages.** Simplest, but the repo would lose its only executable answer to "does this plugin work on the target device", and the next mobile effort would rebuild it from memory.
  - **Keep `commands.vue` and just add a warning.** Once `shell:allow-execute` ships, any XSS escalates to local command execution; the demo value does not justify it.
  - **Move pages into a `platform/` directory for real parent/child routes.** It groups them naturally, but `/os` → `/platform/os` breaks the `NMCPS-ADR-0012` path promise and forces renaming six i18n key groups; the virtual group achieves the same with a dozen lines in `useNavigation()`.

## Follow-up record (appended, 2026-10-31)

Decision 2 deferred the cleanup: "keep the `tauri-plugin-shell` registration and dependency for now, remove it separately once no other use is confirmed". That cleanup is done — no caller existed anywhere in the repo:

- `src-tauri/Cargo.toml` drops `tauri-plugin-shell`; `src-tauri/src/lib.rs` drops `.plugin(tauri_plugin_shell::init())`;
- `modules/tauri.ts` drops the `@tauri-apps/plugin-shell` import and the `Shell` auto-import entry; `package.json` / `pnpm-lock.yaml` drop the npm dependency.
- Verified by `cargo build --manifest-path src-tauri/Cargo.toml`; `shell` is gone from `src-tauri/Cargo.lock` and `src-tauri/gen/schemas/acl-manifests.json`; `src-tauri/gen/schemas/{desktop,linux}-schema.json` were regenerated by that build (the other targets' schemas regenerate on their first build there).
- `pnpm check:platform` gains four zero-residue assertions (`lib.rs` / `Cargo.toml` / `package.json` / `modules/tauri.ts`, 30 → 34) so the plugin cannot creep back in.

Bottom line: `shell` is no longer "registered but ungranted" in this repo — it **does not exist**. Decisions 1 and 3–6 stand; `NMCPS-ARCH-005` is updated accordingly.
