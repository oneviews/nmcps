# ADR-0010: BFF Upstream Readiness Probe and SSE Streaming Passthrough

> **Layer**: Tier 5 record layer — the body is append-only; changes require a new ADR with `supersededBy`.
>
> **Numbering**: `ADR-0009` is skipped — the follow-up section of `NMCPS-ADR-0008` already reserved 0009 for the session / token model.


- **Context**:
  1. Decision 6 of `NMCPS-ADR-0007` only shipped `GET /health`: it proves the BFF process can serve and **does not touch the upstream**; the upstream readiness probe was deferred until deployment conventions settle. The result: when the upstream is unreachable the pod still looks healthy, so new traffic keeps flowing into an instance that can only answer 502/504.
  2. The same ADR's follow-up section called it out: the gateway handles responses as JSON, so v1's SSE/streaming endpoints (`text/event-stream`) cannot use the unified JSON proxy. `server/utils/bff/proxy.ts` reads with `response.text()`, so SSE is buffered until the stream ends — heartbeats and real-time pushes stop working.
  3. Mixing `/health` and `/ready` amplifies failures: if k8s restarted pods on the same probe, a brief upstream hiccup would restart the process mid-request and cascade.
- **Decision**:
  1. **Separate `/ready` from `/health`**: `/health` stays the liveness probe (process alive), and the new `GET /ready` is the readiness probe (upstream reachable). `/ready` answers `200` when the upstream returns 2xx within `readinessTimeoutMs`, otherwise `503`.
  2. **Four reason codes**: `upstream_missing` (no base URL) → `upstream_unreachable` (connection failed) → `upstream_timeout` (probe timed out) → `upstream_unhealthy` (upstream returned non-2xx). The order is fixed so alerts can bucket by `upstream.reason`.
  3. **No upstream address, no envelope**: the body only carries `status` / `service` / `upstream.{configured,status,latencyMs,reason}` / `uptime` / `timestamp` and never the upstream URL; the shape is a flat probe object rather than `ApiResponse`, because k8s probes and load balancers only read the status code.
  4. **Probe reads status only**: the body is released with `response.body.cancel()` right after the headers, and its timeout uses a dedicated `AbortController` instead of the business timeout.
  5. **SSE is streamed**: on `2xx` + `text/event-stream`, `proxy.ts` returns a `Response` (h3 `sendWebResponse` → `sendStream`) and forwards chunk by chunk, with `cache-control: no-store` and `x-accel-buffering: no` to keep reverse proxies from batching, and `AbortController.abort()` on client disconnect.
  6. **Envelope contract unchanged**: non-2xx and non-SSE 2xx responses still return `ApiResponse<T>`; the business timeout now only covers the first byte (the timer is cleared once headers arrive), so long-lived streams are not cut mid-flight.
  7. **Configurable**: `runtimeConfig.bff.readinessPath` (default `/health`) and `bff.readinessTimeoutMs` (default 2000, minimum 200), overridable via `NUXT_BFF_READINESS_PATH` / `NUXT_BFF_READINESS_TIMEOUT_MS`.


- **Consequences**:
  - New `server/routes/ready.get.ts` and `server/utils/bff/readiness.ts`; `server/utils/bff/proxy.ts` now returns `ApiResponse<T> | Response`, and `server/api/[...slug].ts` follows.
  - `scripts/check-bff.mjs` grows from 25 to 38 assertions: group ① +2 (no-upstream `/ready`, no-store), group ⑤ +6 (ready state plus the three failure reasons), group ⑥ +5 (content-type, incremental arrival, all events, no envelope, no-store + no buffering).
  - Deployment: `readinessProbe` targets `/ready`, `livenessProbe` targets `/health`, and traffic must not be routed to an instance while `/ready` returns 503.
  - `.env.example` documents the two readiness variables.
- **Alternatives (rejected)**:
  - **Reuse `/health` for readiness**: mixing liveness and readiness restarts pods on upstream hiccups and widens the blast radius.
  - **Return an `ApiResponse` envelope from `/ready`**: probes and load balancers only read the status code; wrapping adds parsing and blurs the "a probe is not a business endpoint" boundary.
  - **Echo the upstream URL or upstream error text**: anyone who can reach `/ready` would learn internal topology details.
  - **Keep `response.text()` and slice manually**: decoding still happens after the whole payload arrives, so real-time behaviour is already lost.
  - **Use `proxyRequest` to pass SSE straight through**: that bypasses the header allowlist and explicit CORS, giving up gateway convergence.
- **Follow-ups**:
  - The probe is a single-shot check; it does not aggregate replicas or feed load-balancer draining.
  - SSE has no `Last-Event-ID` resume semantics and no explicit backpressure policy (slow clients rely on TCP backpressure).
  - The session / token model is still **ADR-0009** (reserved by the follow-up section of `NMCPS-ADR-0008`).
  - The repository has no k8s manifests yet, so probe wiring is not part of a deployment artifact.
