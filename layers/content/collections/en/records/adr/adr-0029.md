# ADR-0029: update-class semantics on the session channel (M1.2 freeze)

> **Layer**: Tier 5, the record layer — published text is append-only; corrections arrive as a new `##` section, never by rewriting a published conclusion.
> **Relationship to the existing baselines**: `NMCPS-DESIGN-008` (`layers/content/collections/cn/architecture/2.domain/simulation.md`) §4 records that "the update semantics of the unified model are not frozen", which is why the `Engine` protocol **deliberately has no** `update_node`; §8 lists "writes and updates still go through 1.x" as the status quo. This ADR fills exactly that gap: how the update class enters the session channel, how effect semantics are tiered, and what is deliberately left out.

## 1. Context (why freeze first instead of defining while coding)

- **Updates are the only class the session channel lacks**. The whitelist's 12 session entries cover read / create / delete / start-stop (the block at the end of `mininetRoutes.ts`); updates remain nine groups of 1.x per-type endpoints: `POST /node_position`, `PATCH /hosts/{id}`, `PATCH /routers/{id}`, `PUT /controllers/{id}`, `PUT /switches/{id}/openflow`, `PUT /links`, `PATCH /links/{src}/{dst}/state`, `POST /flows` (plus two `DELETE /flows`), `POST /associate_switch` (plus `DELETE /remove_association/{src}/{dst}`).
- **The same edit behaves four ways while the network is stopped** — the concrete defect this ADR removes (all read from `api.py`):
  - `PATCH /hosts/{id}`: `app.net.nameToNode` is empty when stopped, so it hits `404 Node … not found` first — even though the host is still in the ledger;
  - `PATCH /routers/{id}`: returns 200, but `_apply_router_configuration()` sees `is_started` false and returns early, so the change is **deferred** to the next start;
  - `PUT /links`: returns 200, while the exception from `link.intf1.config()` is swallowed by `debug()` — the ledger changed, the interface did not;
  - `POST /flows`, `PATCH /links/{}/state`: `400 network must be started …`.

  The page cannot tell whether an edit took effect, and the self-checks cannot cover the class with one assertion.
- **Per-type updates inside the session channel would clone five tables into 2.0**. The per-type models (`Host` / `Router` / `Switch` / `Controller` / `Nat`) are the 1.x compatibility view; the unified node projection (`engines/wired.py`'s `unified_nodes()`, `NMCPS-DESIGN-008` §4) is the only shape on the session side. Opening the update path with per-type field names would immediately create a second vocabulary — unified reads, per-type writes.
- **The switch order decides when to freeze**. The page switches one place at a time, and at that moment the write path must already exist on the session channel with stable semantics; implementing first and documenting later means the page ships behaviour on unfrozen semantics.

## 2. Decision (D1–D7)

| # | Decision | Notes |
| :--- | :--- | :--- |
| **D1** | **Updates go only through the unified node / link paths** | M1.2 adds two session endpoints: `PATCH /api/simulation/sessions/{session_id}/nodes/{node_id}` and `PATCH /api/simulation/sessions/{session_id}/links/{link_id}`. The body is a **partial update of the unified model**: nodes `{ x?, y?, attributes? }`, links `{ options? }`; per-type field names (`of_version` / `interface_ips` / `switch_type` …) are only accepted inside `attributes`, validated against a per-type allow-list. The 1.x `POST /node_position` semantics fold into the node PATCH (position is `x` / `y`), so that endpoint is not mirrored. |
| **D2** | **Only three effect classes: `layout` / `deferred` / `live`** | `layout` (`x` / `y`): ledger only, writable in any state, never restarts anything. `deferred` (host `ip` / default route, router `interface_ips` / `routes` / `proxy_arp` / `ip_forward`, link `options` `bw` / `delay` / `jitter` / `loss`, controller attributes): **write the ledger first**, apply immediately to the live node / interface while the session is `running`, and leave it to the next `start` while `created` / `stopped`. `live` (switch OpenFlow version): requires `running`, otherwise `409 engine_conflict` (`session is not running`) — it edits OVS bridge parameters and cannot be honoured while stopped. Every response carries an `applied` boolean so the page can tell "in effect" from "queued". |
| **D3** | **Immutable fields are rejected explicitly** | `id` / `type` / `mac` / `name` cannot change in M1.2 (renaming, retyping or re-MACing a node means rebuilding it, which is another action); any of them yields `400 engine_invalid_request` rather than a silent ignore — ignoring would make the page believe the edit succeeded. Unregistered `attributes` keys also get 400 instead of being written to the ledger verbatim. |
| **D4** | **The response is the projection, not a per-type model** | A successful update returns `{ "node": <unified node projection>, "applied": <bool> }` / `{ "link": <unified link projection>, "applied": <bool> }`, reusing the `NodeSpec.as_dict()` / `LinkSpec.as_dict()` shape shared with `unified_nodes()`; never `{"status": "ok"}`, never a per-type `model_dump()`, never an echo of the request. Errors keep the engine vocabulary: `engine_invalid_request` (400) / `engine_resource_not_found` (404) / `engine_conflict` (409) / `engine_unsupported` (501). |
| **D5** | **The `Engine` protocol gains `update_node` / `update_link`** | Two synchronous methods, `update_node(session_id, node_id, patch) -> (projection, applied)` and `update_link(session_id, link_id, patch) -> (projection, applied)`; the `wired` implementation **only maps and normalises errors**, still calling the existing `api.py` functions (`setIP` / `setDefaultRoute` / `_apply_router_configuration()` / `intf.config()`), never rewriting network construction (same line as `NMCPS-DESIGN-008` §3). `wireless` answers `501 engine_unsupported` until M3, with no fallback. |
| **D6** | **Permission bits stay as they are; no new bit** | Both PATCHes need only `lab:operate` (matching the 1.x update entries); an update is not destructive, so it gets no `lab:delete`, and "can change an IP" does not make it `lab:create`. The capability table (`LAB_PERMISSIONS`) is therefore unchanged. |
| **D7** | **Flows, stats and link state stay on 1.x (revisit in M1.3)** | `POST /flows` / `DELETE /flows*` are `ovs-ofctl` commands, `GET /stats/{node_id}` and `GET /links/stats/{src}/{dst}` are runtime readings, and `PATCH /links/{}/state` toggles whether a link is up right now rather than a model attribute — none of them is a unified-model object, and forcing them into `PATCH nodes` / `PATCH links` would mix "attributes" with "commands" on one path. M1.2 moves only the two classes the page actually edits (node and link attributes); flows and stats keep using 1.x, and moving them later needs an appended section justified by a real page need. |

## 3. Per-field semantics

Nodes (`attributes` validated against a per-type allow-list; unregistered keys get 400):

| Type | Field | Class | Notes |
| :--- | :--- | :--- | :--- |
| all | `x` / `y` | `layout` | Top-level fields; equivalent to the 1.x `POST /node_position`, touching only the ledger and canvas coordinates |
| `host` | `ip` | `deferred` | With a prefix length (`10.0.0.5/24`); `node.setIP()` runs immediately when running |
| `host` | `defaultRoute` | `deferred` | Same meaning as the 1.x `default_route`; `via <ip>` or a device name, an empty string deletes the default route |
| `router` | `ip` | `deferred` | Primary interface address |
| `router` | `interfaceIps` | `deferred` | `{ <intf>: <cidr> }`; the interface must be attached to the node, otherwise 400 |
| `router` | `routes` | `deferred` | Static route strings in `ip route` syntax |
| `router` | `proxyArp` / `ipForward` | `deferred` | Booleans; `ipForward` also drives `/proc/sys/net/ipv4/ip_forward` |
| `controller` | `ip` / `port` / `ryuApp` | `deferred` | Ledger only, the controller process is never restarted (same line as the 1.x `PUT /controllers/{id}`), see §5 |
| `switch` | `ofVersion` | `live` | `OpenFlow10`…`OpenFlow15`, or `null` to clear; OVS-family switches only, anything else is 400 |
| `nat` | — | — | Read-only: NAT has no 1.x update endpoint either, so M1.2 opens none |

Links (`options`):

| Field | Class | Notes |
| :--- | :--- | :--- |
| `bw` | `deferred` | Mbit cap written into `TCLink`; `intf.config()` runs immediately when running |
| `delay` / `jitter` | `deferred` | Milliseconds as a number or a `10ms` string, applied through tc netem |
| `loss` | `deferred` | Loss percentage |
| omitted | — | No `options` means "do not change"; an explicit `{}` clears the ledger attributes and does **not** remove the applied tc (same as 1.x, see §5) |

## 4. Deliverables and acceptance

| Item | Where | Acceptance |
| :--- | :--- | :--- |
| Upstream endpoints | Two session update routes in `api.py` (node PATCH, link PATCH; position folds into the node PATCH); `sessions.py` forwards them | `pnpm lab:check` route list + the `pnpm contracts:gen` snapshot |
| Engine | `Engine.update_node` / `update_link` as abstract methods in `engines/base.py`; `engines/wired.py` maps them onto the 1.x apply functions | `pnpm check:engines`: dryrun walks "add node → move → change attributes → read the projection back"; `applied` follows `is_started` |
| BFF | Two entries in `mininetRoutes.ts` (`lab:operate`), with the whitelist counts updated | `pnpm check:lab-bff` ⓪ / ① counts and the read/write isolation case in the same ⑰ group |
| Page | Drag persistence and the node / link detail saves all call the session PATCH; the page no longer calls the 1.x update endpoints | `pnpm check:ui` 11.14 and the drag case assert the session path in the upstream hit log |
| Real host | Root backend on the 90 box | Changing a host IP → `GET /nodes` reads the new value with `applied: true`; changing an IP while stopped → `applied: false`, and the new value appears after `start`; changing a link `bw` → the `rate` in `tc class show` matches the request (asserted only as root, `⏭` otherwise) |

## 5. Known limits (not defects)

- **No version / ETag**: concurrent updates are last-write-wins; protecting against two simultaneous writes still relies on the BFF's in-flight 409 (`NMCPS-DESIGN-008` §5) and ledger reconciliation, with no optimistic locking on the model — multi-user concurrency on a single-instance host is outside this stage.
- **`deferred` does not mean "visible while stopped"**: an IP changed while stopped only takes effect at the next `start`; `applied: false` is the machine-readable form of that fact, and the page must not render it as "in effect".
- **An explicit `options: {}` does not remove tc**: the 1.x `PUT /links` also only clears the ledger for empty `options` without `tc qdisc del`, and M1.2 keeps that line; removing the shaping means deleting the link and adding it again (`DELETE /sessions/{id}/links/{link_id}` + `POST`).
- **Controller attributes do not restart the controller**: it is a process, so a ledger change does not restart it with the new port / app; that is the existing 1.x semantics, and M1.2 documents it without adding a "restart controller" endpoint.
- **Wireless is unavailable**: `ap` / `station` updates answer 501 until M3, rather than pretending by writing the ledger and waiting for M3.

## 6. Migration order and "no dual write"

1. **Upstream first**: the two `Engine` methods + the `wired` mapping + two session routes + `sessions.py` forwarding, all runnable under `dryrun` (semantics verifiable without root).
2. **Then the BFF**: two whitelist entries (`lab:operate`) + updated counts + self-check cases; the session PATCHes are callable at this point, but the page has not switched.
3. **The page last**: switch one place at a time (drag → node detail → link detail), deleting the matching 1.x call with each switch; **one entry point per action**, never two requests for the same edit.
4. **The 1.x update endpoints stay**: they remain the "default session" equivalent for pages that have not switched and for the real-host self-checks; deleting them needs another decision after the page has fully switched.
5. Completion criterion: in `check:ui` the upstream hit log for drag and detail saves contains only `/api/simulation/sessions/**`, with zero hits for the 1.x `node_position` / `PATCH hosts` / `PATCH routers` / `PUT links`.

## 7. Explicitly out of scope

- **Batch updates**: one object per request, no array `PATCH /nodes`.
- **Rename / retype / re-MAC**: see D3, those rebuild the node.
- **Flows, stats, link state**: see D7, they stay on 1.x and are revisited in M1.3.
- **Automatic restart**: an update never triggers `stop` + `start`; rebuilding the network is an explicit page action (restart is the existing device-rail action — one entry point per action).
- **Per-type pass-through**: `attributes` is validated against a per-type allow-list, never "write whatever key arrives into the ledger".
