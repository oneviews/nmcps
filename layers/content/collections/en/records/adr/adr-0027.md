# ADR-0027: engine-face positioning and the not-carried list

> **Layer**: Tier 5, the record layer — published text is append-only; corrections arrive as a new `##` section, never by rewriting a published conclusion.
> **Relationship to the existing baselines**: `NMCPS-DESIGN-008` (`layers/content/collections/cn/architecture/2.domain/simulation.md`) owns sessions / engines / the unified projection / phase boundaries, and `NMCPS-ARCH-007` (`layers/content/collections/cn/architecture/1.architecture/lab-deployment-architecture.md`) owns the listening surface / privileges / credentials / restart semantics. Both assume "the engine face is this repository's stack", but neither settles **which capabilities enter the engine face, which never enter it, and how the old channel retires**. This ADR fills that gap and turns the tiering inside `docs/ai/simulation-parity.md` (an engineering plan, not a governed document) into a citable ruling.

## 1. Background (why this must be written down)

- **The reference deployment is a fact on the ground**: the `_reference/netsim` backend (`app/`, 36,961 lines, 131 endpoints) runs on host 90 as **root `uvicorn :8001`** (`_reference/netsim/BASELINE.md`). It and this repo's `services/mininet-api` (3,138 lines) are two code bases with two resource models (session-based vs one global singleton, unified node vs five tables — see the last table in parity §1).
- **"Retire `:8001`" currently lives in the plan, not in the code**: `server/api/sim/[...slug].ts` forwards through `SIMULATOR_ROUTES` in `shared/constants/simulatorRoutes.ts` (**23 entries, 18 of them writes**) to :8001, `GET /api/sim/channel` reports `writeEnabled`, and the write surface is switched on separately with `NUXT_SIMULATOR_ALLOW_WRITE` (default `false`). The production topology monitor page (`layers/topology/app/pages/topology/monitor.vue` + `useTopologyMonitor.ts`) still reads `runtime-inventory` / `stats` / `lldp/neighbors` from it and sends node / link actions through it.
- **The consequence of leaving it undecided is predictable**: as long as the channel exists and the whitelist can grow, "the reference has it, so this repo should too" gets re-opened in every phase; and one tenant-triggered `allowWrite: true` hands the 18 write endpoints of :8001 to the browser face.

## 2. Decision (D1–D7)

| ID | Decision | Rationale |
| :--- | :--- | :--- |
| **D1** | **The only engine face is this repo's `services/mininet-api`; the reference retires to read-only** | `:8001` is no longer deployed and is no longer a source of truth or of contracts; `_reference/netsim` is only consulted for behaviour and for its trap notes (and is bound by D7). There is exactly one front door: BFF prefix `/api/mininet/**` and WS `/mininet-ws/*` (`NMCPS-ADR-0022` D11); `/api/sim/**` is not kept as a long-term second channel (retirement path in §4). |
| **D2** | **One unified node model: the engine face only knows `NodeSpec{type, ...}`** | `type` is one of `host` / `router` / `switch` / `controller` / `nat` / `ap` / `station` (`NODE_TYPES` in `engines/base.py`, which already cites this clause). The five tables (`/hosts` `/routers` `/switches` `/controllers` `/nats`) are a **compatibility read-only view** and do not enter the engine; the unified projection exists once, in `unified_nodes()` in `engines/wired.py`, and `GET /api/mininet/nodes` has the same shape as the session-side `/sessions/{id}/nodes`. The tables and the projection are not two sources of truth: the tables are projected from the same network, so a node may never exist in a table and be missing from the unified view. |
| **D3** | **The session is the resource root; no implicit-session double path** | `/api/simulation/sessions/**` (BFF side `/api/mininet/sessions/**`) is the 2.0 resource root; the 1.x `/api/mininet/**` routes are the "default session" (`NMCPS-DESIGN-008` M1.1). S-B in parity §4.1 (keep the singleton and add a one-id implicit session, keeping both paths) is **rejected**: two parallel paths split the OpenAPI generated by `contracts:gen` and give permissions and ledger ownership two entrances. |
| **D4** | **The engine registry never falls back; `dryrun` stays** | `get_engine()` raises `EngineNotFound` (404 at the route layer) when a name was never registered, and never falls back to "any engine that happens to work" — a fallback turns "asked for wireless, got wired" into a silently wrong topology. `dryrun` is the only engine that can validate API semantics on a root-less CI (`check:engines` / `check:simulation` depend on it) and may not be deleted for being "unused in production"; before M3, `wired` answers 501 when asked to create `ap` / `station`, it does not substitute a wired node. |
| **D5** | **Capability bits do not grow with the reference** | The reference's "internal service, no auth" shape is **not inherited**. The only permission surface is the six `lab:*` bits (`read` / `create` / `operate` / `delete` / `terminal` / `sniffer`, `layers/scenario/shared/constants/mininetRoutes.ts`); `terminal` / `sniffer` are never derived from read or write (`NMCPS-ADR-0021` D3). If the SNMP face ever exposes writes (onboard / rotate / revoke), it gets its **own** `lab:snmp`, never `lab:operate` — "the reference has 131 endpoints" is not a reason to grow the permission surface. |
| **D6** | **One instance per host; the tenant→instance registry fails closed** | `app.net` and the `mac80211_hwsim` radios are global resources, so a host runs exactly one simulation instance; multi-tenancy is a "one tenant, one instance" mapping whose only source of truth is `NUXT_MININET_INSTANCES`, and a missing entry answers `503 tenant_runtime_unavailable` with **no** "fall back to a default instance" path (`NMCPS-ARCH-007` §5). |
| **D7** | **Porting gate: no copied code and no copied MIB text** | Until the redistribution licence for the reference code and its 21 MIBs is confirmed, nothing is copied — not code, not MIB text; this repo writes by **behaviour** (so M1 is not blocked by the licence, only "copy the MIB definitions" is). The `.bak-*` hot-fix leftovers (5 in `engine.py`, 2 in `runtime_config.py`, 2 in `snmp_agent.py`…) are bug leads only and are **never requirements**. |

## 3. The not-carried list (R1–R8)

R1–R7 map one-to-one, in order, onto `SIMULATOR_EXCLUDED_PREFIXES` in `shared/constants/simulatorRoutes.ts` (the existing guard of the 1.0 channel, seven entries); R8 is a channel-level retirement, not an endpoint. The last column states both "why" and "where 2.0 lands".

| ID | Reference side | Disposition | Criterion / where 2.0 lands |
| :--- | :--- | :--- | :--- |
| **R1** | `/api/network/nodes/{id}/execute` (POST) | **Permanently excluded** | 2.0 only has an **interactive PTY** (`/mininet-ws/terminal` + `lab:terminal`, one keystroke at a time, no local echo) and no "run one command per call" REST face. Attaching an arbitrary-command endpoint to a node hands the host's root over HTTP to anyone who holds the bit; the audit and approval posture of the terminal face does not cover scripted batch runs either. |
| **R2** | `/api/browser/*` | **Permanently excluded** | Headless-browser scraping is an operator-script capability, not a product one; inside the BFF it becomes an outbound fetch **a tenant can trigger**, with the target chosen by the request, which collides head-on with the outbound-surface rules in `NMCPS-ARCH-007`. |
| **R3** | `/api/integrity/*` (including `watch/*`) | **Permanently excluded** | Topology / config integrity sweeps are operations tooling and the first 2.0 release does not need them (P2 in parity §2.5). Sweep from an external read-only client instead of growing a second state inside the engine process. |
| **R4** | `/api/devices/*` (including `devices/clear`) | **Never enters the engine** | The device library is management-plane data (the asset domain); the engine only knows `NodeSpec`. Putting it into the engine welds "build a network" to "maintain assets": deleting one device would then have to consider a running network. |
| **R5** | `/api/test/*` (`mtr` / `traceroute` / `netcat` / `lldp` probes) | **No separate channel** | `ping` / `iperf` are already carried by `/api/mininet/pingall` and `/api/mininet/iperf` (the latter a subprocess with its own timeout, `NMCPS-ADR-0026` §5); the remaining probes have no consumer, and `netcat`-class tools carry the same risk as R1. |
| **R6** | `/api/snmp/onboard` (v2c / v3 onboarding, `rotate` / `revoke`, `export`) | **Rebuilt in another shape (M2)** | The :8001 "hand out credentials" shape is **not** reproduced as a forwarding channel; 2.0 rebuilds it on the in-process agent (same source as the ledger) and requires its **own** `lab:snmp` bit (D5). Until then the prefix stays blocked by `SIMULATOR_EXCLUDED_PREFIXES`. |
| **R7** | `/api/nms/vmagent` (target management, `snmp-exporter-reset`) | **Permanently excluded** | The external monitoring stack (VictoriaMetrics agent / exporter) has its own deployment and credentials and is not a product capability; a BFF that pushes targets on its behalf lets a tenant edit the host's monitoring stack indirectly. |
| **R8** | `/api/sim/**` (the gateway to :8001) plus any `:8001` compatibility alias | **Retired and deleted** | Same posture as `NMCPS-ADR-0022` D11 took for `/api/lab/**`: **no alias, no double write**. Deletion is gated on every migration step in §4 landing; until then the channel is "being retired", not "open for additions". |

> The remaining P2 items — `network/scan-subnets`, `DELETE /metrics/{sim_id}`, `protocol/compare`, `gateway/*` — are handled by their parity §2 tier and do not take an R number. They are absent from `SIMULATOR_EXCLUDED_PREFIXES` because the 1.0 pages never called them (the whitelist only lists what pages actually call), not because they are safe.

## 4. R8 blast radius and migration order

The chain as it exists today (all inside this repository, nothing inferred):

| File | Role | After migration |
| :--- | :--- | :--- |
| `server/api/sim/[...slug].ts` | per-endpoint whitelist forwarding (404 on miss, 405 on verb mismatch, 503 unconfigured, 405 writes disabled) | deleted |
| `server/api/sim/channel.get.ts` | answers `configured` / `writeEnabled` / `timeoutMs`, never touches the upstream | replaced by `GET /api/mininet/channel` (`capabilities` + `endpointCount`) |
| `server/api/sim/index.ts` | 400 `bff_path_missing` for the bare path | deleted |
| `server/utils/bff/simConfig.ts`, `server/utils/bff/simulator.ts` | `runtimeConfig.simulator` reading and egress | deleted (`NUXT_SIMULATOR_*` retires with them) |
| `shared/constants/simulatorRoutes.ts`, `shared/types/simulator.ts` | the whitelist itself and the upstream shapes | deleted |
| `layers/topology/app/composables/useTopologyMonitor.ts`, `layers/topology/app/pages/topology/monitor.vue` | the page consumer (reads plus node / link actions) | moves to `/api/mininet/**` |
| `app/utils/graph/simulatorOverlay.ts`, `app/utils/graph/topologyNeighbors.ts` | runtime alignment (matching :8001 nodes onto the :8888 topology by "management IP → name") | rewritten with the page; the :8001 shape notes are evidence for the matching algorithm, not a channel dependency |
| `scripts/fixtures/simulator-openapi.json`, `check-bff` ⑨-6 | the "`SIMULATOR_ROUTES` ⊆ openapi paths" guard | retires with the whitelist |

Order (strictly in sequence; never delete before migrating):

1. **Reads**: `runtime-inventory` moves to `GET /api/mininet/nodes` + `/links` (ready since M1.1); `stats` moves to a per-node `/stats/{id}` aggregate; `lldp/neighbors` gets **no equivalent endpoint** — adjacency is derived from `/links` instead (see the §7 addendum, ruling of 2026-11-25).
2. **Writes**: node / link actions move to the matching `/api/mininet/**` endpoints (`lab:operate`), with no "the reference is handier" side door left open. Link `up` / `down` / `toggle` is already served by `PATCH /api/mininet/links/{src_id}/{dst_id}/state` (M1.2, 2026-11-25); the page has no node-level action left, so the migration does not re-add one.
3. **Capability bits**: the page's `writeEnabled` test moves from `/api/sim/channel` to `capabilities` on `GET /api/mininet/channel` (`NMCPS-ADR-0022` D3).
4. **Delete**: the "deleted" rows above go in one pass, together with the data-flow diagram in `docs/ai/repo-map.md` and the self-check counts. **Docs before code**: `/api/sim/**` is the second egress channel registered in `NMCPS-ARCH-002` §6 (Tier 1, normative), and every `SIMULATOR_ROUTES` entry traces to a data-source table in `NMCPS-DESIGN-001` / `007` — so both must be amended first (this ADR lives in the tier-5 record layer and only settles "it retires" and the order; it does not override a normative baseline). Otherwise the code is gone while the baseline still says the channel exists.

Discipline while the migration is in flight: **no new** `SIMULATOR_ROUTES` entries, `NUXT_SIMULATOR_ALLOW_WRITE` stays off (its `false` default is the machine form of this rule), and new page code never imports `/api/sim` or `shared/types/simulator.ts`.

## 5. Consequences and what we do not do

- **Not doing**: ① keeping a `:8001` compatibility entrance (reverse proxy or `/api/sim` alias included); ② migrating by "copying the reference endpoints" (the structural differences are in the last table of parity §1: sessions / unified node / engine abstraction / capability bits / single instance); ③ growing the capability bits or adding equivalent actions because the reference has more endpoints (D5); ④ duplicating the five tables inside the engine (D2).
- **Cost**: until the migration lands the topology monitor page still depends on :8001, and `check-bff` ⑨-6 still pins "whitelist ⊆ simulated-upstream openapi". R8 counts as done only when both are gone. In the meantime the write surface of `/api/sim/**` is held closed by `allowWrite`, not by "nobody would use it".
- **Division of labour**: DESIGN-008 owns "sessions / engines / projection / phases"; ARCH-007 owns "listening surface / privileges / credentials / restart"; this ADR owns "which capabilities enter the engine face, which never do, and how the old channel retires". None of the three restates another's detail.

## 7. Addendum (2026-11-25, v0.1.2): no LLDP face, adjacency comes from `/links`

§4 step 1 used to read "the LLDP face switches once M1 adds `/lldp/*`", which made "build an LLDP endpoint family" the last prerequisite for R8. This section changes that: **no `/api/lldp/*` is built and no `lldpd` is added**; the page derives adjacency from `GET /api/mininet/links`. Only the prerequisite and the landing spot change — D1–D7 and R1–R7 stand, and R5's "no separate channel" now **extends** to `/api/lldp/**`.

### 7.1 Three checks (all reproducible inside this repository)

1. **The reference was never measuring LLDP**: the `native` branch of `_reference/netsim/backend/app/engines/mininet_wifi/lldp_agent.py` is documented as "build LLDP-MIB data from the real topology (**no extra daemon needed**)" and simply assembles `lldpRem*` fields from the ledger links (`_build_neighbor_entry()`). In other words `:8001`'s `neighbors[]` has always been "topology adjacency wearing an LLDP field shell"; no LLDP frame was ever received. The "measured as-is" notes in `shared/types/simulator.ts` record the shape of that **synthesis**, not a protocol fact.
2. **That synthesis has known defects**: `_reference/netsim/docs/已知问题-AP侧LLDP假边.md` documents fake AP-side edges (synthetic adjacency disagreeing with the real wireless association), and `docs/backlog/2026-09-21-lldp-ghost-404.md` documents "unknown node returns 200 with an empty array" (it should be 404). Both are inherent to the synthetic path rather than implementation slips.
3. **Real LLDP costs more than it yields here**: the host has no `lldpd` installed (`which lldpd` is empty), so real collection means one daemon per node namespace; and Mininet switches are OVS running in the root netns with layer-2 forwarding only — LLDP's reserved multicast (`01:80:C2:00:00:0E`) is neither trapped nor forwarded by default, so host-to-host LLDP never reaches the far end, and a switch identity has nowhere to come from (one OVS process serves every port, so there is no "chassis id of switch X"). It delivers no fact beyond the ledger and only adds a channel that can lie.

### 7.2 Ruling

| Item | Decision |
| :--- | :--- |
| `/api/lldp/summary`, `/api/lldp/neighbors/{node_id}` | **Not implemented.** The BFF whitelist (`mininetRoutes.ts`) registers no `/lldp/*` row, so `check:lab-bff` ⓪ stays at "22 reads + 37 writes = 59". |
| `lldpd` / `lldpcli` | **Not taken as a dependency** (neither the system package nor the per-node daemon). |
| Page adjacency (the "LLDP neighbours" card on `topology/monitor.vue`) | When the read path switches, it becomes `GET /api/mininet/links` + the pure function **`topologyNeighborsOf()`** (`app/utils/graph/topologyNodeFacts.ts`, already live, already deriving neighbours with link status from canvas links); no new endpoint, no new backend state. |
| Field gap | `ttl` / `discovered_at` / `sys_name` / `chassis_id` / `mib_oids` have **no substitute** (they exist only inside real LLDP TLVs). The card must not invent them, and must not replace `discovered_at` with the local clock; what it can show is `neighbor_id` / name / both interfaces / link status (`up` / `down` / `unknown`, the semantics M1.2 already provides). The card's title and copy get renamed accordingly ("topology adjacency"); it must stop calling itself LLDP. |

### 7.3 Why the other two options were rejected

- **A self-built synthetic agent**: it would port the defect from §7.1 item 2 verbatim and contradict the stance M1.2 already set — a reading that was **never taken** may only be `unknown`, while synthetic adjacency would confidently answer `up` with `ttl: 120`. The existing "no upstream normalisation, no invented data" position (`NMCPS-ADR-0026` D4, the notes in `shared/types/simulator.ts`) does not allow it.
- **`apt lldpd` with a per-node daemon**: see §7.1 item 3 — no extra fact, while a new system dependency and per-node process lifecycle (start / stop / node delete / rebuild) would drag in the M3 wireless face for the same "few edges the ledger already knows".

### 7.4 Effect on R8

- "Switches once LLDP lands" in §4 step 1 is void; all three read items (nodes / links / adjacency) are now ready.
- The page switch (§4 steps 1–3) has no engine-face prerequisite left and can proceed in order; the completion test is unchanged (`grep -rn "/api/sim"` finds nothing, `check:lab-bff` no longer has ⑨-6, `nuxt.config.ts` no longer has a `simulator` block).
- The two `/api/lldp/*` rows stay in `SIMULATOR_ROUTES` until the page switch lands — they are the "current state of the 1.0 channel" right now, not a 2.0 to-do; they retire with ⑨-6 once the page has moved.
