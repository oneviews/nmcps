# ADR-0014: Name the Forced Password Page change-password, Not reset-password

- **Context**:
  - **The industry splits the two flows cleanly**: `reset password` means the **anonymous** "I forgot my password" flow that re-sets it via an email or SMS token (Auth0 `password-reset`, Firebase `sendPasswordResetEmail`, Django `reset/<uid>/<token>/`, Keycloak `reset-credentials`, Azure AD SSPR). `change password` / `update password` means an **authenticated** change that requires the old password (Django `PasswordChangeView` at `/password_change/`, Azure AD `ChangePassword`, AWS IAM `ChangePassword`, the OWASP Cheat Sheet's "Change Password"). A forced change at first login belongs to the second family: Keycloak required action `UPDATE_PASSWORD`, AD `ChangePasswordAtLogon`, Linux `chage -d 0`.
  - **Upstream draws the same line**: in the interface table of `_reference/DESIGN.md`, `ResetPassword` is "administrator resets the password" (`POST /auth/user/{id}/action/reset-password`) and `ChangePassword` is "user changes their own password" (`POST /auth/user/action/change-password`). Our page is the self-service change but borrowed the `reset` word.
  - **The repository already had one consistent word**: `useAuth().changePassword(newPassword, oldPassword)`, the BFF route `POST /api/auth/password`, and the "password change" block on `/user/security`. Only this page said `reset-password`, together with 21 `auth.reset*` i18n keys. `NMCPS-ADR-0013` had just unified `sign-in` on `login` because "one action under two words means a word-based search always misses something"; this was the same split in the opposite direction, and it also broke the file-naming rule set there (page files are noun-like kebab-case; `sign-in` was rejected as a verb phrase, and `reset-password` has the same shape).
- **Decision**:
  1. **Page and route become `change-password`**: `app/pages/auth/change-password.vue` serving `/auth/change-password`. No `reset-password` alias redirect: the page lives inside the `/auth/**` allowlist with no external references, so an alias would only keep two words alive (the same argument ADR-0013 used for `sign-in`).
  2. **Rename the i18n keys, not the copy**: the 21 `auth.reset*` keys become `auth.changePassword*` (`changePasswordTitle`, `changePasswordCurrentLabel`, `changePasswordNewTooShort`, `changePasswordSameAsCurrent`, `changePasswordCurrentInvalid`, …) in both zh and en. The strings stay identical, so the `check:ui` copy assertions keep working.
  3. **`reset` is reserved for the forgot-password flow**: a future "forgot password" follows the industry naming of `/auth/forgot-password` (request) plus `/auth/reset-password?token=…` (token re-set). Both are anonymous, so they never collide with this page.
  4. **Records stay append-only**: the old path inside `NMCPS-ADR-0011` remains as written; this ADR is the current authority for the path.
- **Impact**:
  - Code: `app/pages/auth/change-password.vue` (renamed), `app/pages/auth/login.vue` (the `mustResetPassword` target and its comment), `i18n/locales/{cn,en}.json` (21 keys each).
  - Self-checks: `scripts/check-ui.mjs` — four path assertions plus the anonymous guard case now expect the new path; the number of cases is unchanged (61 self-built / 49 external).
  - Docs: `NMCPS-ARCH-003` §7.4 / §7.5 / §7.6 / §7.8 and `NMCPS-REC-001` REPO-04 move to the new path and gain one sentence on why it is not called `reset`.
  - No data migration: the route is only used inside the client-side allowlist; a stale bookmark lands on the login page and `mustResetPassword` sends the user straight back.
- **Alternatives rejected**:
  - **Keep `/auth/reset-password` and merely document "reset means forced reset here"**: the word still collides with the upstream design (`ResetPassword` is an administrator reset) and with industry usage, so whoever debugs this will look for a token/email endpoint that does not exist.
  - **`/auth/password` (pure resource style, the most literal fit for the noun rule)**: it matches the BFF route `POST /api/auth/password` by name but is a different entry point, which is the easiest thing to confuse in logs and during triage; the page is about changing a password, not about the credential resource itself.
  - **`/auth/password/change`**: more RESTful, but `app/pages/auth/password/change.vue` adds a directory level and buys hierarchy rather than searchability.
