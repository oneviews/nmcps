# ADR-0020: A read-only BFF channel for the Mininet lab backend

> **Layer**: Tier 5 record layer — the body is append-only after publication.
> **Relation to ADR-0019**: ADR-0019 made the simulator (8001) the second upstream. This ADR integrates the Mininet-GUI FastAPI backend (8000 by default). They are **different data sources** and do not share a whitelist, configuration or client.
> **Status**: phase A is implemented (read-only channel). Writes, terminal, sniffing and multi-user isolation remain closed and need separate decisions.

---

## 一、Verdicts at a glance

| # | Verdict | Detail |
| :--- | :--- | :--- |
| **D1** | The Mininet backend is the BFF's **third egress channel** | Own `runtimeConfig.mininet`, own `layers/scenario/server/utils/bff/mininet*.ts`, own `layers/scenario/server/api/lab/**`. It never reuses the primary gateway or the simulator channel. |
| **D2** | Only **GET queries** are open | The `method` type in `MININET_ROUTES` is literally `GET`; write endpoints are absent from the table, so there is no entry point and no runtime boolean to flip. |
| **D3** | An explicit per-endpoint whitelist | 17 query endpoints, template matching rather than prefix passthrough; unlisted paths 404, wrong verbs 405, traversal 400. |
| **D4** | No credentials on egress | Never reads `nmcps_at`, never converts it to `Bearer`, never forwards cookies; only `accept` / `user-agent` / `x-request-id`. |
| **D5** | Exports, WebSockets and all writes are **out of scope here** | Text / pcap downloads need their own content-type contract; terminal / logs / sniffing / monitor need ticket auth. |
| **D6** | Authentication and multi-user isolation remain **undecided** | This channel assumes Mininet listens only on loopback or a controlled network; the BFF introduces no new permission model. |

## 二、Channel shape

| Item | Value |
| :--- | :--- |
| Browser entry | `/api/lab/**` |
| Upstream | `${NUXT_MININET_BASE_URL}`, empty by default (disabled) |
| Config | `runtimeConfig.mininet.baseUrl` / `timeoutMs` |
| Whitelist | `layers/scenario/shared/constants/mininetRoutes.ts` |
| Egress | `layers/scenario/server/utils/bff/mininet.ts` |
| Probe | `GET /api/lab/channel` (200 + capabilities, never echoes `baseUrl`) |
| Not configured | `/api/lab/**` → 503 `mininet_not_configured` |

**Why not reuse `proxyToUpstream()`**: the primary proxy turns the access-token cookie into a `Bearer` header and participates in single-flight refresh on 401. The Mininet backend has no authentication, so sending it a token has no benefit and widens the leak surface; its 401/403 responses must never refresh or terminate a session.

---

## 三、Read-only whitelist

| Group | BFF paths | Upstream paths |
| :--- | :--- | :--- |
| Probes | `/health`, `/version`, `/ryu/apps` | `/api/health`, `/api/version`, `/api/ryu/apps` |
| Inventory | `/hosts`, `/interfaces`, `/switches`, `/controllers`, `/nats`, `/routers`, `/links`, `/start` | `/api/mininet/*` |
| Runtime reads | `/addressing_plan`, `/stats/{node_id}`, `/flows/{switch_id}`, `/links/stats/{src_id}/{dst_id}` | `/api/mininet/*` |
| Sniffer reads | `/sniffer/state`, `/sniffer/history` | `/api/mininet/sniffer/*` |

**Explicitly excluded**:

- `export_json` / `export_script` / `sniffer/export`: text or pcap bytes, a download contract rather than a JSON envelope;
- every POST / PUT / PATCH / DELETE: `start`, `stop`, `reset`, `full_reset`, node / link mutation, flows, iperf, sniffer start / stop;
- all four WebSockets: `terminal/{node_id}`, `logs`, `sniffer`, `monitor`.

These exclusions are not a regex waiting to be widened: writes and terminal require permission bits, audit and multi-user isolation first (see §五).

---

## 四、Rejection semantics and guards

The channel shares one `ApiResponse` rejection vocabulary with the primary gateway and the simulator:

| Case | Status / message |
| :--- | :--- |
| `/api/lab` or `/api/lab/` | 400 `bff_path_missing` |
| `..` / `%2e%2e%2f` / a segment containing `/` | 400 `bff_path_invalid` |
| Unlisted path (including every write endpoint) | 404 `bff_resource_not_allowed` |
| Non-GET verb on a listed path | 405 `bff_method_not_allowed` |
| No `baseUrl` | 503 `mininet_not_configured` |
| Upstream unreachable / timed out | 502 `mininet_unreachable` / 504 `mininet_timeout` |

`pnpm check:lab-bff` carries 26 assertions covering whitelist ⊆ OpenAPI snapshot, read-only verbs, the unconfigured channel, whitelist, query forwarding, parameterised paths, traversal, zero upstream hits for writes, credential-free egress, preserved upstream errors and the channel capability payload. It consumes the build output, so `pnpm build:server` is a prerequisite.

---

## 五、Open decisions

1. **Single user or multi-user**: `app.net` is a process-wide topology, so only one network exists at a time. The BFF must not pretend it is isolated per session.
2. **BFF authentication**: this phase only prevents direct browser access to port 8000; deployment must keep it on loopback or a controlled network.
3. **Permission bits**: `lab:read`, `lab:operate`, `lab:terminal`, `lab:sniffer`.
4. **WebSocket auth**: the BFF issues a short-lived ticket that the reverse proxy verifies before forwarding.
5. **Audit**: every write, terminal session and sniffer start / stop must leave a trace.

Until those are settled, no write endpoint, terminal, sniffer control or `reset` may be added to the whitelist.
