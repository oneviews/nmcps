# ADR-0028: the minimal shape of the SNMP collection face (first M2 increment)

> **Layer**: Tier 5, the record layer — published text is append-only; corrections arrive as a new `##` section, never by rewriting a published conclusion.
> **Relationship to the existing baselines**: `NMCPS-DESIGN-008` (`layers/content/collections/cn/architecture/2.domain/simulation.md`) states the M2 acceptance as "an external `snmpwalk` reads consistent OIDs"; `NMCPS-ARCH-007` (`layers/content/collections/cn/architecture/1.architecture/lab-deployment-architecture.md`) leaves "SNMP `:161` versus the host `snmpd`" undecided; `NMCPS-ADR-0027` D5 / R6 says an SNMP write face needs its own `lab:snmp` and that `snmp/onboard` is not rebuilt as a forwarding channel. None of them says what the first increment looks like — this ADR fills that gap.

## 1. Context (why the reference cannot be copied)

- **The reference implementation depends on third-party system components**: `engines/mininet_wifi/snmp_agent.py` writes an `snmpd.conf` per node namespace, starts net-snmp's `snmpd`, and bridges enterprise OIDs through AgentX / `pass`; the wireless side ships 21 MIB texts. Neither premise holds here: redistribution is unlicensed (`NMCPS-ADR-0027` D7), and whether the host has net-snmp installed must not decide whether the simulated network is collectable.
- **Collection is an external behaviour, not a page behaviour**: the NMS polls simulated nodes with its own `snmpwalk` / exporter, so the face must answer standard OIDs. The acceptance stays `snmpwalk -v2c -c public <node> 1.3.6.1.2.1.1`; only the implementation stops being `snmpd`.
- **The port conflict is a host-face problem, not a node-face problem**: each Mininet node is its own netns, so binding `:161` **inside that namespace** never touches the host `snmpd`. Only a single root-namespace proxy would contend for the port, and that shape cannot work anyway — node IPs are not routed in the root namespace.

## 2. Decisions (D1–D7)

| ID | Decision | Detail |
| :--- | :--- | :--- |
| **D1** | **A self-written stdlib agent, one per node** | BER encoding, the MIB projection and the UDP server live in `services/mininet-api/mininet_gui_backend/snmp/` and use the Python standard library only. No `net-snmp` import, no generated `snmpd.conf`, no MIB text in the package: only the numeric OID arcs from RFC 1213 / 2863, resolved by the NMS's own MIBs. |
| **D2** | **The agent runs inside the node's own netns** | After a successful start, `nsenter -t <node.pid> -n --` puts the agent process into that node's network namespace and it binds `0.0.0.0:<port>`. Node IPs are reachable by construction; the host `snmpd` and the host port table are untouched. Without root or `nsenter` the node is reported `unavailable` — there is no fallback root-namespace proxy. |
| **D3** | **Read-only v2c, community from the environment** | Only GET / GETNEXT over `SNMPv2c` (version encoding 1); no SET, no v3 USM, no traps. Community is `LAB_SNMP_COMMUNITY` (default `public`), port is `LAB_SNMP_PORT` (default 161, inside the node netns); both are deployment configuration, not page input. The write face (onboard / rotate / revoke) needs the independent `lab:snmp` bit per `NMCPS-ADR-0027` D5 — **this increment exposes no SNMP write endpoint**. |
| **D4** | **Lifecycle follows network start/stop, off by default** | With `LAB_SNMP_ENABLED=1` the agents start after a successful `POST /api/mininet/start` and are reaped by `stop`, `reset`, `full_reset` and process exit. A collection failure **must not** fail the network start; a node that cannot be served is only visible in the state reading. Off by default because M2 is still experimental and 161 must be opened deliberately by the deployer. |
| **D5** | **Three MIB groups plus the enterprise type OID** | `SNMPv2-MIB` system (`1.3.6.1.2.1.1`, including `sysName` / `sysDescr` / `sysObjectID` / `sysUpTime` / `sysServices`), `IF-MIB` `ifTable` with the basic columns (including `ifName` / `ifAlias`), and the `IP-MIB` `ipAddrTable` (including `ipAdEntNetMask`). `sysObjectID` uses the same enterprise numbering as the reference, `1.3.6.1.4.1.99999.<type>` (1 switch / 2 ap / 3 router / 5 station / 7 host …), so NMSs that classify by `sysObjectID` still recognise node types. Counter columns (`ifInOctets` / `ifOutOctets`) are zero in this increment — see §4. |
| **D6** | **Adjacency comes from the ledger projection, not LLDP** | The LLDP face was retired in `NMCPS-ADR-0027` R8, so the agent serves no `lldpRemTable`. An NMS that needs topology uses `GET /api/mininet/snmp/topology` (same path behind the BFF, `lab:read`), which projects ledger nodes / links into a collectable target list (node IP, port, community, sysObjectID, interfaces) for its seed configuration. This is **semantically different** from the reference `POST /snmp/topology` (subnet scan + LLDP inference): that one discovers the host network, this one publishes the simulated one. |
| **D7** | **No credential orchestration or exporter wiring yet** | `snmp/onboard` (v2c/v3 onboarding, rotate / revoke / export), `nms/*` (vmagent, snmp-exporter-reset) and `GET /snmp/tools` are out of scope: they need `lab:snmp` plus the IAM `lab_snmp` role first, or belong to an external monitoring stack. The BFF whitelist grows by two read-only entries only. |

## 3. Deliverables and acceptance

| Item | Location | Acceptance |
| :--- | :--- | :--- |
| BER / PDU | `snmp/ber.py`: TLV codec, OID arcs, Integer / OctetString / TimeTicks / Counter32 / IpAddress, GET / GETNEXT parsing and response encoding | `pnpm check:snmp` (stdlib, no root): encode/decode round-trips plus assertions on responses to hand-built requests |
| MIB projection | `snmp/mib.py`: an ordered OID table built from the node profile, with `get()` / `getnext()` semantics (`noSuchObject` for a missing object, `endOfMibView` past the last) | same check: system / ifTable / ipAddrTable OIDs exist and `getnext` is monotonic |
| Node profile | `snmp/inventory.py`: node and interface facts (IP / MAC / prefix / MTU) read from `app.net`; no page state | same check: a stub node yields a complete profile; nodes without IP or pid are skipped |
| Agent | `snmp/agent.py`: `respond()` (pure) + `serve()` (UDP); v2c GET / GETNEXT only; a wrong community is dropped | same check: a server on `127.0.0.1:0` answers a loopback client with the system group; a wrong community gets no response; plus a **real subprocess** `python -m … snmp.agent --profile … --port … --community …` asserting that all three flags take effect, SIGTERM exits 0 and the port is bindable again afterwards |
| Runtime | `snmp/runtime.py`: `LAB_SNMP_ENABLED` / `LAB_SNMP_PORT` / `LAB_SNMP_COMMUNITY`, profiles under `.data/snmp/` (0600), process table, start/stop/status | same check: `start` is a no-op when disabled; state is three-valued (running / stopped / unavailable) |
| Upstream endpoints | `GET /api/mininet/snmp/state` (runtime + per-node status) and `GET /api/mininet/snmp/topology` (ledger projection) | `pnpm lab:check` route list + `pnpm check:lab-bff` counts / forwarding |
| Lifecycle hooks | started from `start_network()`; reaped by `stop_network()` / `full_reset_network()` and lifespan shutdown; failures only logged | `pnpm lab:check` source guard (group 4, "SNMP collection hooks"): all four hook points plus the `try/except` in `_start_snmp_collection()` are present |
| Real acceptance | On 90: root backend + `LAB_SNMP_ENABLED=1`, `snmpwalk -v2c -c public <h1-ip> 1.3.6.1.2.1.1` / `…1.3.6.1.2.1.2.2.1` | closed 2026-11-26 with net-snmp on the host — see §5 for the measured walks, the cross-node check and the stop/start reaping |

## 4. Explicitly out of scope for this increment

- **Real counters**: `ifInOctets` / `ifOutOctets` / error counters are zero; feeding real traffic needs periodic interface sampling or IPC with the backend (P1).
- **64-bit counters and `ifXTable`**: `ifHCInOctets` and friends need Counter64 and the same statistics source; they land with real counters.
- **Dynamic topology**: after adding / removing nodes or links at runtime the agent view refreshes only on the next `start` (`/snmp/topology` reads the live ledger, so the two differ briefly). No page exposes this; it is booked as "restart the network to refresh".
- **Credential orchestration**: `LAB_SNMP_COMMUNITY` is a single deployment value; per-node / per-tenant communities, v3 users and rotate / revoke wait for `lab:snmp` and the IAM `lab_snmp` role.
- **MIB files**: not shipped; the NMS brings standard MIBs. Shipping them later requires resolving redistribution first (`NMCPS-ADR-0027` D7).

## 5. Acceptance and known limits

- Machine side: `pnpm check:snmp` (stdlib, no root, no mininet; 28 assertions today) covers the codec / MIB / profile / loopback UDP / the **real subprocess entry** (the `--profile` / `--port` / `--community` flags of `python -m … snmp.agent` all take effect, SIGTERM exits 0, the port is reclaimable — a self-check of the command line `runtime.py` builds, not a netns acceptance); `pnpm lab:check` covers the upstream routes and the lifecycle hooks; `pnpm check:lab-bff` covers the whitelist counts and forwarding. In CI it is its own step, `SNMP agent self-check` (conclusion key `snmp`, regex `结果：N 通过 / 0 失败`, sample `scripts/fixtures/ci-logs/snmp.log`), no longer appended to the `lab-api` step's log — mixed in there, "which layer went red" was only answerable by reading the whole log.
- Real side (closed on 90, 2026-11-26): back up the ledger with `GET /api/mininet/export_json`, `mn -c`, restart the backend as root with `LAB_SNMP_ENABLED=1`, rebuild the same topology (3 switches / 4 hosts / 6 links) and `POST /start`; `GET /api/mininet/snmp/state` reported all four hosts `running`. With net-snmp installed on the host (`apt-get install snmp` → `/usr/bin/snmpwalk`) the measured results were:
  - `nsenter -t <h1 pid> -n snmpwalk -v2c -c public 127.0.0.1 1.3.6.1.2.1.1` → `sysName=h1`, `sysObjectID=1.3.6.1.4.1.99999.7`, `sysServices=72`;
  - `…1.3.6.1.2.1.2.2.1` → `ifDescr=h1-eth0`, `ifType=6`, `ifMtu=1500`, `ifPhysAddress=00 00 00 00 00 01` (matching the ledger MAC), admin/oper up;
  - `…1.3.6.1.2.1.4.20.1` → `ipAdEntAddr=10.0.0.1` with `ipAdEntNetMask=255.0.0.0`, the same value `addressing_plan` reports as `10.0.0.1/8` (the agent serves the node netns' real prefix, not an assumed ledger prefix);
  - walking from **h2's netns** against `10.0.0.1` returned the same system group, so the agent binds the node's real IP and is reachable across the simulated fabric, not just on loopback;
  - `-c private` got no response (timeout) and an unregistered OID answered `No Such Object`;
  - `POST /stop` left zero agent processes with `running=false`, and `POST /start` brought back four `running` entries (both directions of the lifecycle hooks exercised).
  All three assertions hold: `sysName` equals the ledger node id, and `ifDescr` / `ipAdEntAddr` agree with `GET /api/mininet/interfaces` / `addressing_plan`. Cleanup followed `09-local-sudo.md`: both `.data` and `services/mininet-api/.data` were chowned back to the current user, because the agent profiles are 0600 files written by root.
- Ports: binding 161 inside each node netns needs no host port mapping, and the host `snmpd` may keep the root namespace's 161. This closes the `NMCPS-ARCH-007` §7 "port conflict" item: there is no node-face conflict, and the only conflicting shape (a root-namespace proxy) is rejected by D2.
