# ADR-0018: Backend generation switch — upstream moves wholesale to the 8888 NMS unified gateway

> **Layer**: Tier 5 record layer — the body is append-only after release; detail is added in extra `##` sections.
> **Relation to the baselines**: this ADR records the decision and its evidence. The normative documents stay `NMCPS-ARCH-003` (`arch.iam`) and `NMCPS-DESIGN-005` (`domain.system`); on conflict the baselines win (both must be re-versioned with this switch, see §7).
> **Work order**: per-file diff drafts, commit slicing and acceptance commands live in `documents/3.operations/backend-generation-migration.md` (Tier 4, never a source of authority).

---

## 1. Decisions

| ID | Decision | Basis |
| :--- | :--- | :--- |
| **D1** | The single BFF upstream is `http://192.168.1.55:8888/api/v1` (NMS unified gateway). The old go-zero gateway instance is **retired**; no repository file, script, document or environment may reference the old port again | §2 evidence + owner instruction (2026-11-04) |
| **D2** | The outbound allow-list is rebuilt around the twelve service namespaces: `iam` / `asset` / `metric` / `topology` / `alarm` / `audit` / `system` / `task` / `transmission` / `dashboard` / `frequency` / `protocol` (plus `health`). The old `account` / `role` / `permission` / `abac` / `access` / `tenant` / `user` resources are retired | 131 OpenAPI paths / 13 tags |
| **D3** | Login becomes `POST /api/v1/iam/login` with `{ username, password }`, answering `data.{ access_token, refresh_token, expires_in, user_info }`. There is **no `whoami`**; identity comes from `user_info` (persisted by the BFF — a single source of truth for the session) | §2 rows 2 and 7 |
| **D4** | **Revokes** the "refresh rotates the session" premise of `NMCPS-ADR-0011`: the new `/iam/refresh` only returns `{ access_token, expires_in }` and the same `refresh_token` can be replayed (both measured refreshes succeeded). Kept: single-flight refresh after 401, dual-cookie model, desktop body tokens, CSRF checks | §2 row 8 |
| **D5** | Business errors travel on **HTTP 200 + `code ≠ 0`** (e.g. `10003` for a wrong password). Every consumer must gate on `isSuccessResponse()`; checking only `status` or the HTTP code is wrong | §2 row 3 |
| **D6** | Paging lives inside `data`: `data.{ list, page, page_size, total }`, and **empty lists may be `list: null`** (not `[]`). The BFF normalises to `[]` at the boundary | §2 rows 4 and 5 |
| **D7** | `GET /api/v1/asset/device` returns `snmp_auth_pass` / `snmp_priv_pass` in **plaintext**; the BFF must mask them (`***`) at the boundary and the UI only ever sees the mask | §2 row 6 |
| **D8** | Naming flips from camelCase to **snake_case** (`display_name` / `tenant_id` / `mfa_enabled` / `created_at`); the BFF does not camel-cast, so the frontend types are rewritten in snake_case | §2 row 4 |

## 2. Evidence (re-measured 2026-11-04, seed account `admin` / `Admin@123456`)

| # | Request | Observation | Consequence |
| :---: | :--- | :--- | :--- |
| 1 | `GET /api/v1/health` | `200 { code: 0, data: { status: "ok", version: "v1.0", services: { …12 up… } } }` | The readiness probe (`NUXT_BFF_READINESS_PATH=/health`) needs **no change** |
| 2 | `POST /api/v1/iam/login` | `200 { data: { access_token, expires_in: 86400, refresh_token, user_info: { id: "u_platform_admin", username: "admin", display_name: "平台管理员", email, phone, tenant_id: null } }, code: 0 }` | `user_info` exists; no `accountCode` / `accountLevel` / `sessionId` / `mfaRequired` / `mustResetPassword` |
| 3 | `POST /api/v1/iam/login` (wrong password) | `200 { code: 10003, message: "用户名或密码错误" }` | **Business errors are still HTTP 200** |
| 4 | `GET /api/v1/iam/users?page=1&page_size=2` | `200 { code: 0, data: { list: [{ id, tenant_id, department_id, username, email, display_name, status, mfa_enabled, created_at, updated_at }], page, page_size, total: 23 } }` | The account model is the IAM user; no `accountLevel` |
| 5 | `GET /api/v1/audit/operation-logs?page=1&page_size=1` | `200 { code: 0, data: { list: null, total: 0, page: 1, page_size: 1 } }` | **Empty lists come back as `null`** |
| 6 | `GET /api/v1/asset/device?page=1&page_size=1` | `data.list[0]` carries `snmp_auth_pass: "rYeg…"` and `snmp_priv_pass: "DrpC…"` | Plaintext credentials on the wire → masking is mandatory (D7) |
| 7 | `GET /api/v1/iam/whoami` | `404 page not found` | No `whoami` (D3) |
| 8 | `POST /api/v1/iam/refresh` (same `refresh_token`, twice) | Both `200 { data: { access_token, expires_in: 86400 } }`, **no** `refresh_token` in the response | No rotation, replayable (D4) |
| 9 | `GET /api/v1/iam/users` (no token) | `401 { code: 40101, message: "缺少认证凭证" }` | Unauthenticated requests take HTTP 401 + a numeric code (unlike business errors) |
| 10 | `POST /api/v1/iam/logout` | Needs `Authorization: Bearer` plus a body `{ user_id }`; success is `200 { code: 0 }` | Logout is **no longer an empty form-urlencoded body** |

The JWT claims (`exp / iat / sub: "admin" / tid: null / uid: "u_platform_admin"`) carry **no** `display_name`, `email` or roles, which is why D3 makes `user_info` the only viable identity source.

## 3. Envelope shape

```
success:        { code: 0, message: "success", data: T }
business error: HTTP 200 + { code: 10003, message: "用户名或密码错误" }   // no data
auth failure:   HTTP 401 + { code: 40101, message: "缺少认证凭证" }
paged:          data = { list: T[] | null, page, page_size, total }
```

Key order is unstable (`data` may come first) and fields are snake_case — the BFF passes them through and the frontend must not depend on key order. The existing BFF envelope `ApiResponse<T>` does not conflict with this, except that `code` now carries upstream business codes verbatim and `status` is derived from `code === 0`.

## 4. Field mapping (old → new)

### 4.1 Authentication (`shared/types/auth.ts`, full rewrite)

| Old (`/api/v1/auth/*`) | New (`/api/v1/iam/*`) | Note |
| :--- | :--- | :--- |
| `POST /auth/login` | `POST /iam/login` | path |
| `accountName` | `username` | renamed |
| `tenantCode` | **none** | the tenant is resolved from the account |
| `mfaCode` | **none** | no MFA endpoints (§6) |
| `data.accessToken` | `data.access_token` | naming |
| `data.refreshToken` | `data.refresh_token` | naming |
| `data.expiresIn` (variable) | `data.expires_in` (fixed 86400 = 24h) | TTL 30 min → 24 h |
| `data.sessionId` | **none** | session id is BFF-side or dropped |
| `data.accountCode` | `data.user_info.id` | `u_platform_admin` |
| `data.accountName` | `data.user_info.username` | |
| `data.displayName` (absent on the old login) | `data.user_info.display_name` | the new backend does return it |
| `data.tenantId: number` (0 for super admin) | `data.user_info.tenant_id: string \| null` | type and meaning both change |
| `data.accountLevel: 0/1/2/3/4` | **none** | the level model is gone (gap G1) |
| `data.mfaRequired` / `mustResetPassword` | **none** | forced reset loses its upstream signal (gap G2) |
| `GET /auth/whoami` | **none** | identity comes from `user_info` (D3) |
| `POST /auth/token/refresh { refreshToken }` | `POST /iam/refresh { refresh_token }` | response only carries `access_token` / `expires_in`; **no rotation** (same RT used twice, both 200, measured 2026-11-04) |
| `POST /auth/logout` (empty body, form) | `POST /iam/logout` (Bearer + `{ user_id }`) | the id comes from `user_info.id`; the upstream is **idempotent** (repeat call still `200 { code: 0 }`) |
| `POST /auth/password { newPassword, oldPassword?, firstReset? }` | `PUT /iam/password { old_password, new_password }` | measured: camelCase → `400 field "old_password" is not set`; wrong old password → **`200 + code 10003`** |
| `POST /auth/mfa/bind`, `/auth/mfa/confirm` | **none** | MFA UI must be removed or marked unimplemented |

Measured addendum (2026-11-04): `POST /iam/refresh` with a bad token answers **`HTTP 200 + code 10007`**
("invalid authentication token"), not 401 — the BFF must treat it as a dead session (`SESSION_INVALID_CODES`
includes `10007`), otherwise the "200 means success" legacy rule reads a failed refresh as success.

| Old | New | Note |

| `POST /account { accountName, password, accountLevel, tenantId }` | `POST /iam/users { username, password, email?, display_name?, tenant_id?, department_id? }` | required set still to be measured; `department_id` is new |
| `PUT /account/{accountCode}/status { status }` | `PUT /iam/users/{id} { status }` | primary key code → uuid |
| no delete endpoint (defect `UP-ACC-04`) | `DELETE /iam/users/{id}` (soft delete via `deleted_at`) | upstream gap **closed** |
| account list lacked tenant attribution (`UP-ACC-05`) | the list carries `tenant_id` / `department_id` | closed |
| `GET /tenant` | `GET /iam/tenants` | |
| `POST /account/role` write-only (`UP-POL-07`) | `POST /iam/subject-roles/AssignRole` / `RevokeRole` plus `GET /iam/subject-roles` | symmetric read/write, closed |

## 8. Risks

| ID | Risk | Impact | Mitigation |
| :---: | :--- | :--- | :--- |
| R1 | `proxy.normalizeUpstreamEnvelope` loses the "`status` derives from `code === 0`" rule (upstream 2xx envelopes carry no `status`) | an HTTP 200 + `code: 10003` reads as `success`, so a wrong password looks like a successful login | keep that derivation while touching the gateway or the upstream paths, and assert "200 + `code: 10003` must not be a success" in `check:bff` |
| R2 | `SESSION_INVALID_CODES` still `{401, 10201, 20205}` | the new unauthenticated code is `40101`, so a dead session is not detected or cleared | change the constant and assert (a refresh after logout must be treated as invalid) |
| R3 | `list: null` not normalised | list pages crash in `.map` | normalise in the BFF (`?? []`) and assert it |
| R4 | half-converted snake_case | types pass, runtime values are empty | ship types and pages in one commit; never mix across commits |
| R5 | no `accountLevel` shifts permission semantics | visibility escalation | the G1 rule needs a new ADR before `/system/user` changes |
| R6 | plaintext SNMP credentials reach the browser | credential leak | D7 masking ships with the `asset` endpoint |
| R7 | no export/verify/dry-run upstream | lost features | state "not provided upstream" explicitly instead of silently disabling |

## 9. Verification

```bash
# readiness
curl -s http://192.168.1.55:8888/api/v1/health

# login (a wrong password is still HTTP 200 + code 10003)
curl -s -X POST http://192.168.1.55:8888/api/v1/iam/login \
  -H 'content-type: application/json' \
  -d '{"username":"admin","password":"Admin@123456"}'

# paged list (watch data.list / data.total and the snake_case fields)
TOK=<access_token>
curl -s "http://192.168.1.55:8888/api/v1/iam/users?page=1&page_size=2" -H "authorization: Bearer $TOK"

# no rotation: the same refresh_token works twice
curl -s -X POST http://192.168.1.55:8888/api/v1/iam/refresh \
  -H 'content-type: application/json' -d '{"refresh_token":"<rt>"}'

# sensitive fields (must be masked at the BFF boundary)
curl -s "http://192.168.1.55:8888/api/v1/asset/device?page=1&page_size=1" -H "authorization: Bearer $TOK"
```
