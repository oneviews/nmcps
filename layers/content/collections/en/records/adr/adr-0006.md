# ADR-0006: Desktop Update Entry & Startup Silent Check

> **Tier**: Tier 5 record layer — body is immutable (append-only); changes require a new ADR with `supersededBy`.

- **Background**:
  1. `useUpdater()` (`app/composables/useUpdater.ts`) was only consumed by `SiteNavbar.vue`, whose `home` / `blank` layouts are unused in 2.0.0 (`/` redirects to `/dashboard/overview` under the `default` layout). The desktop app therefore had **no visible check-for-updates entry**.
  2. The update chain itself was verified end to end (`latest.json` platform mapping → GitHub release asset → signature check): a v1.7.1 build made from `main@5b921b0` (which carries `plugins.updater`) upgrades to 2.0.0 successfully. Without an entry, installed 2.0.0 clients cannot trigger any further upgrade.
- **Decision**:
  1. Add a check-for-updates button (`carbon:renew`) to the right-hand controls of `AppHeader.vue`, shown only when `isTauri()` is true; clicking it runs the existing `useUpdater().checkForUpdates()` (download and install when an update exists).
  2. Add a startup silent check in `app/layouts/default.vue`: `onMounted` calls `useUpdater().silentCheckForUpdates()`, which shows a persistent toast (`duration: 0`) only when a new version exists; the user clicks "Install now" to run `downloadAndInstall()`. No update or a failed check stays silent.
  3. Route all `useUpdater` copy through i18n (`updater.*`, cn / en in sync), removing the previously hardcoded Chinese strings that leaked into the English UI.
- **Impact**:
  - The next desktop build (≥ 2.0.1) ships both a manual entry and a startup prompt, restoring the trigger for 2.0.0 → 2.0.1 updates.
  - New i18n keys: `updater.desktopOnly` / `found` / `downloading` / `upToDate` / `failed` / `available.*`.
  - The already released 2.0.0 build still has no entry; those users must install 2.0.1 manually once. This ADR does not change published artifacts.
- **Open items**:
  - Tag `nmcps-v1.7.1` points at `2c71100` (no `plugins.updater`) while the published assets were built from `main@5b921b0`; rebuilding from the tag yields a non-updatable app and needs a separate reconciliation.
  - 2.0.0 macOS artifacts are unsigned, so upgrades need `xattr -c /Applications/nmcps.app`.
