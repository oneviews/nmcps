# ADR-0013: Unify the Sign-in Page Naming on login and Pre-fill Demo Seed Accounts

> **Tier**: Tier 5 record layer — the body is append-only; changes require a new ADR and a `supersededBy` entry.

- **Context**:
  - **One action, two words**: the auth page was `app/pages/auth/sign-in.vue` (route `/auth/sign-in`), yet the same action is called `login` everywhere else — the BFF endpoint `/api/auth/login`, the server route `server/api/auth/login.post.ts`, the composable `useAuth().login()`, and the body of `NMCPS-ARCH-003` §7. Searching for `login` misses the page itself; searching for `sign-in` only finds the UI side.
  - **The file naming rule was already noun-based**: every other page file is a noun in kebab-case (`overview` / `security` / `plan-generation` / `auto-transmit`), while `sign-in` is a verb phrase and breaks the "page = resource" semantics.
  - **A demo program must be loggable out of the box**: the form started empty, so every demo and screen recording needed the credentials typed by hand, and both identities had to be shown — the **super admin** and the **tenant admin** (`accountLevel` `0` / `1`).
- **Decision**:
  1. **Rename the page and route to `login`**: `app/pages/auth/login.vue` → `/auth/login`. No `sign-in` alias redirect: the allowlist is already `/auth/**`, the old path has no external referrers, and an alias would keep two vocabularies alive.
  2. **Unify the term in source**: the i18n key `auth.signIn` becomes `auth.login`; comments, scripts and documents all say `/auth/login`. The historical `NMCPS-ADR-0011` keeps its body untouched per the record-layer rule, while `NMCPS-ADR-0012` lands in the same uncommitted batch and has its path reference corrected here.
  3. **Single source for seed accounts**: new `shared/constants/demoAccounts.ts` exporting `DEMO_ACCOUNTS` (super admin / tenant admin); the page consumes it and never hard-codes credentials.
  4. **Pre-fill by default, switch in one click**: the initial state is the first seed account (super admin); the "demo identity" buttons refill `accountName` / `password` / `tenantCode` as a set, and the fields stay editable (a real MFA account is not locked out).
  5. **Demo-only boundary**: the prefill serves demos and recordings; before a real deployment the constants must be checked against the upstream IAM seed script, or the prefill removed.
- **Consequences**:
  - `/auth/sign-in` no longer exists; `app/middleware/auth.global.ts`, `app/components/App/AppHeader.vue`, the assertions in `scripts/check-ui.mjs` and `NMCPS-ARCH-003` §7.4 / §7.6 are updated with it.
  - `NMCPS-ARCH-003` gains §7.7 to pin down the demo-seed and prefill behaviour; the login flow itself is unchanged (still `POST /api/auth/login`, the guard still judges by `/api/auth/session`).
  - The login page goes from "empty form" to "prefilled + switchable", so `check:ui` must clear the fields before asserting the empty-submit validation.
- **Seed values verified (owner-specified + 2026-10-31 probe, closes the earlier open item)**: the login API is `POST http://192.168.1.55:10000/api/v1/auth/login`; the seed accounts are `admin / Admin@123456` (super admin) and `tenantadmin / Tenant@123456` (tenant admin), both returning `code: 0` in the probe. The seeds carry no tenant code — upstream resolves the tenant from the account, so an empty `tenantCode` logs in fine (`GET /api/v1/tenant` shows the built-in default tenant code `default`, used only when a tenant must be selected explicitly). The earlier constants (`tenant / Admin@123456 / demo`) were wrong on all three values (probe returned `20201 账号或口令错误`) and are corrected; passwords still live in `shared/constants/demoAccounts.ts` only.
- **Prerequisite for any login (surfaced by the same probe)**: the repository ships `.env.example` but no `.env`, so `NUXT_BFF_UPSTREAM_BASE` is empty and the BFF answers the auth routes with 503 — no seed account can log in. "Seed data cannot log in" is therefore an unconfigured upstream first, not a credential problem. A local `.env` has been filled in (ignored by `.gitignore`, never committed).
- **Rejected alternatives**:
  - **Keep `/auth/sign-in` and add an `/auth/login` alias**: two vocabularies survive, `grep` still misses one of them, and a redirect has to be maintained.
  - **Use `auth/index.vue` (`/auth`) instead of `login.vue`**: the URL loses its action semantics, and `/auth` would be allowed "by accident" through the `/auth/**` prefix without explaining itself.
  - **Put the seed accounts in `.env` / runtimeConfig**: a demo build would need deployment configuration, and the passwords would leak into build metadata; a constants file is reviewable and changed in one place.
  - **Only document the seeds, never prefill**: demos and recordings still need typing, so the "prefilled by default" requirement is not met.
