# ADR-0016: drop the root download landing page and move it under the system download centre

> **Tier**: Tier 5 records layer — the body is append-only; changes need a new ADR with `supersededBy`.

- **Context**:
  - **The landing page does not match the product**: this repository ships a business console that starts after sign-in, yet `/` was the template-era download page — visitors saw `Powered by` / `Download NMCPS` / `Star on GitHub` and still had to click "sign in" to get in. Installers are consumed by people who already run the system, not by anonymous visitors.
  - **It kept orphaned resources alive**: while `/` existed, `app/layouts/home.vue`, `useOS()`, the `downloads` block in `app/app.config.ts` (4 platforms, 13 installer names) and `pages.index.*` (10 keys per locale) all had to keep working, and `check:ui` spent assertions on the landing page.
  - **The `blank` layout and `SiteNavbar` were already unused**: `NMCPS-ADR-0006` recorded that `/` renders under the `default` layout and that the `home` / `blank` layouts have no page; `Site/LanguageSwitch.vue` was referenced only by `SiteNavbar`. Language switching, colour mode and "check for updates" all have proper entries in `AppHeader`.
  - **Requirement**: clear the `/` landing page so the site opens straight into sign-in, without losing the download entry — fold it into the system section as a first-class sub-page.
- **Decision**:
  1. **`/` is no longer a page**: `nuxt.config.ts` gains `routeRules: { "/": { redirect: "/auth/login" } }`, so a cold load is answered by Nitro with an HTTP `302` (measured `307`) to the sign-in page — no SPA boot, no white flash.
  2. **In-app jumps to `/` are handled too**: under the SPA, `vue-router` resolves `/` to `[...all].vue` (the 404 page), so `auth.global.ts` gains a root branch — authenticated goes to `/dashboard/overview`, anonymous to `/auth/login` (`replace: true`). Both paths are needed: HTTP for cold loads, the guard for in-app navigation and the desktop bundle.
  3. **The guard allowlist keeps only `/auth/**`**: the `PUBLIC_PATHS` constant is gone and `isPublicPath()` reduces to a prefix check, so the download centre needs a session like every other business page.
  4. **The download page moves to `layers/system/app/pages/system/download.vue`** (`/system/download`, `sort: 5`, `icon: carbon:download`, sidebar "System → Downloads"): it keeps the platform detection, primary-format button, other-formats dropdown and other-platform links, but now renders in the console shell (`LayoutTile` + `UCard`) without the landing-only hero (animated logo, `Powered by`, Nuxt / Nuxt UI / Tauri links, "Made by" footer). The nav entry and breadcrumb come from `useNavigation` off the route table; no hand-written menu entry.
  5. **Only the resources the download page really needs come back**: the `downloads` block in `app.config.ts` (4 platforms, 13 installers) plus a new `releaseUrl` ("All installers" points at the release page); `useOS()` moves to `layers/system/app/composables/useOS.ts` because this page is its only consumer. `app.author` / `nuxtSite` / `nuxtUiSite` / `tauriSite` do not come back (`app.repo` stays — the `/webview` probe and the footer button use it).
  6. **What is still orphaned gets deleted**: `app/pages/index.vue`, `app/layouts/home.vue`, `app/layouts/blank.vue`, `app/components/Site/Navbar.vue`, `app/components/Site/LanguageSwitch.vue`; `Site/ColorModeButton.vue` stays because `AppHeader` still uses it. The `pages.index.*` strings become `pages.system-download.*` (11 keys per locale).
  7. **The self-check follows**: the four landing assertions become two root-path ones (`/` answers 3xx with `location: /auth/login`; a browser visit lands on the sign-in page and renders the form), plus one guard case (an anonymous visit to `/system/download` bounces back with the redirect target) and three download-centre cases (sidebar entry, Linux detection pointing the primary button at the `.deb`, three other-platform links), moving the counts from 68 self-built / 51 external to 70 / 53.
- **Impact**:
  - Code: five files deleted; `layers/system/app/pages/system/download.vue` and `layers/system/app/composables/useOS.ts` added; `nuxt.config.ts` (`routeRules`), `app/middleware/auth.global.ts` (root branch plus a narrower allowlist), `app/app.config.ts` (`downloads`), `i18n/locales/{cn,en}.json`, `scripts/check-ui.mjs`.
  - Docs: `NMCPS-ARCH-003` §7.4 / §7.6 / §7.7 and its change log; `NMCPS-DESIGN-005` §2 functional scope gains the `download` sub-page; `NMCPS-GOV-003` registers this ADR. This ADR supersedes `NMCPS-ADR-0008` (download landing page restoration), marked `superseded` per the records-layer rules.
  - Behaviour: `/` no longer shows download buttons; the download entry lives under System → Downloads, reachable after sign-in, and still links straight to GitHub Releases (the console indexes the binaries, it does not proxy them).
- **Alternatives (rejected)**:
  - **Keep the `/` landing page and turn its button into "enter the console"**: still requires maintaining the `home` layout and `pages.index.*`, i.e. carrying the template leftovers.
  - **`navigateTo('/auth/login')` inside `index.vue`**: a client-side jump, so the first paint waits for JS to download and run and slow networks see a blank frame; `routeRules` is a real HTTP redirect.
  - **Serve downloads from a top-level `/download`**: anonymous visitors could download, but it needs another public route, its own layout and a nav slot; that contradicts "downloads belong to the system section" and grows a new exception in the guard allowlist.
  - **Only drop `/` from the guard allowlist without `routeRules`**: it works, but the entrance first boots the SPA and then both `[...all]` and the guard get a say, so the 404 page or the sign-in page may flash; the HTTP-level 302 is deterministic.
