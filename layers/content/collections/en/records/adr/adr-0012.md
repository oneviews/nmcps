# ADR-0012: Introduce the platform Layer for Tauri Capability Demos

> **Tier**: Tier 5 record layer — the body is append-only; changes require a new ADR and a `supersededBy` entry.

- **Context**: the root `app/pages` carried two different kinds of pages — the site shell (`index.vue` download landing page, `[...all].vue` 404, `auth/login.vue` sign-in) and six Tauri capability demos (`commands` / `file` / `notifications` / `os` / `store` / `webview`). The demos assume a desktop runtime (shell, filesystem, store, notifications, WebviewWindow) and only render `common.unavailableInBrowser` in a browser, so keeping both together blurred the "root layer only holds the shell" boundary and made placement of new pages ambiguous.
- **Decision**:
  - Add the `layers/platform` layer (`package.json` + `nuxt.config.ts` + `app/pages/`) and register `./layers/platform` at the end of `extends` in the root `nuxt.config.ts` (no route conflicts, so the order is irrelevant).
  - `git mv` the six demo pages into `layers/platform/app/pages/`; **file names are unchanged, hence route paths are unchanged** (`/commands`, `/file`, `/notifications`, `/os`, `/store`, `/webview`).
  - Everything derived from routes stays as is: `app/composables/pages.ts` groups navigation by `meta.category` (`system` / `storage` / `interface`), the i18n `pages.*` keys, and the `/os` link inside `webview.vue`.
  - The root `app/pages` keeps only the site shell (`index.vue`, `[...all].vue`, `auth/login.vue`); the demo pages remain covered by the global sign-in guard (`NMCPS-ARCH-003` §7.6).
- **Consequences**: the route table of the build output is unchanged; `eslint` / `vue-tsc` pick the new directory up automatically (the `.nuxt` configs are generated from `extends`); future platform capability demos belong in this layer.
- **Rejected alternatives**:
  - **Move them into `layers/user`**: the user layer is about accounts and preferences, so platform demos do not belong there and would blur its responsibility again.
  - **Serve them under `/platform/*`**: requires an extra parent page and nested outlet, and changes existing URLs, internal links and navigation highlighting; the only gain is a URL prefix, which is not worth it.
  - **Keep them in the root `app/pages`**: the root layer would keep mixing the shell with demos, which is exactly the problem being solved.
