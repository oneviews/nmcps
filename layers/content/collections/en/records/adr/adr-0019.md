# ADR-0019: Three pre-conditions for the six-layer migration

> **Layer**: Tier 5 record layer — the body is append-only after publication; detail is added in `##` sections.
> **Relation to the baseline docs**: this ADR answers *whether* and *within which boundary*, and deliberately carries **no field-level contract**. Field and page-shape authority stays with `NMCPS-DESIGN-001` (`domain.topology`), `NMCPS-DESIGN-002` (`domain.spectrum`), `NMCPS-DESIGN-003` (`domain.transmission`), `NMCPS-DESIGN-004` (`domain.device`), `NMCPS-DESIGN-006` (`domain.scenario`) and `NMCPS-DESIGN-007` (`domain.dashboard`); data-source authority is `NMCPS-ARCH-002` (`arch.datasource`); type authority is `NMCPS-CONTRACT-001` (`contract.shared-types`). The baselines win on conflict, and they must be version-bumped alongside this record (§七).
> **Relation to `NMCPS-ADR-0018`**: ADR-0018 fixed the 8888 unified gateway as the *single main upstream* and this generation's contract shape. This ADR adds **a second egress channel** (the simulator on 8001) on top of it, so it **extends** ADR-0018 D1 rather than revoking it — `bff.upstreamBase` remains the only upstream for business data, and the simulator carries the *simulation control plane* only.
> **Status**: all three verdicts were confirmed by the requester on 2026-11-05 (gates A and C authorised me to decide on technical merit; gate B was confirmed after the requester measured that `http://192.168.1.55:8001/docs` and `/openapi.json` both respond).

## 三、Gate A: graphics drawn in-house (D1 / D2 / D3)

### 3.1 Why no library

| Test | Reasoning |
| :--- | :--- |
| **Fixed shapes** | The six layers need four shapes: a layered/radial **topology**, a time-series **trend line**, a spectrum **waterfall/sweep**, and a **single-value card with gauge**. These are specific shapes, not general BI (no cross-chart linking, no drill-down, no metric orchestration, no multi-axis composition). |
| **Bundle and runtime** | 2.0 is a Tauri desktop plus browser app with `ssr: false`; `@antv/g6` and its extensions are heavyweight. Adding one conflicts with the "no new dependencies" rule and forces a fresh look at offline packaging and CSP. |
| **Code we can test** | Drawn-in-house code lives in the repo, so `check:ui` can assert on it and `typecheck` covers it. A black-box layout that drifts leaves only guesswork. |
| **Clean reuse boundary** | §2.3 shows the computation layer is separable from the renderer: 52,811 lines of pure TS move, and only 13,135 lines die because of an `import`. |

### 3.2 Four renderers (the only rendering entry points)

| Component | Location | Carrier | Pages | Notes |
| :--- | :--- | :--- | :--- | :--- |
| `TopologyCanvas` | `app/components/Graph/TopologyCanvas.vue` | SVG (≤ 400 nodes) plus an isometric projection for a 2.5D feel | topology monitor, device connector, scenario, dashboard mini-map | Layout is injected as a pure function (layered / radial / tree; force-directed degrades to a fixed grid). **No real 3D**: 1.0's `topology3dLayouts` contributes projection maths only |
| `TrendChart` | `app/components/Graph/TrendChart.vue` | SVG polyline with area fill | device/link metrics, alarm trends, spectrum occupancy | Threshold bands, range selection, cursor readout; above 2,000 points aggregate per pixel column and keep the extremes |
| `SpectrumWaterfall` | `app/components/Graph/SpectrumWaterfall.vue` | Canvas 2D (`ImageData`) | spectrum waterfall, live sweep | Dense per-pixel writes where SVG does not fit; DPR-aware, 30fps ceiling |
| `SparkStat` | `app/components/Graph/SparkStat.vue` | SVG | dashboard card badges | Single value, mini trend, status colour — replaces the scattered unovis mini charts in 1.0 |

A page **must not** create its own canvas or run its own `requestAnimationFrame`. A genuinely new shape means extending one of these four or writing another ADR.

### 3.3 Hard constraints

1. **One rendering entry**: pages pass data and a layout name, never drawing commands.
2. **Sampling and caps**: `TopologyCanvas` caps at 400 nodes and 1,200 edges, trims by weight and reports "N trimmed"; `TrendChart` aggregates per pixel column; `SpectrumWaterfall` writes at most 5 MB per frame.
3. **Size and DPR**: always driven by `ResizeObserver` with `useDevicePixelRatio`; never read `window.innerWidth` to decide layout (it violates the container-query convergence rule of `NMCPS-ARCH-006`).
4. **Restrained motion**: honour `prefers-reduced-motion`, drop path animation and breathing highlights, and never run a continuous `rAF` loop without cause (the waterfall repaints only when streamed data arrives).
5. **Three complete states**: empty (no nodes / no data), loading (`USkeleton`), error (`UAlert` plus retry). A blank canvas is not an empty state.
6. **Accessibility fallback**: topology and trend views must offer an equivalent list view navigable by keyboard; the graphic itself gets `role="img"` and an `aria-label`.

### 3.4 Reversal condition

If general BI requirements appear — linked metrics, drill-down, user-composed dashboards, or true 3D perspective — they are **out of scope for this verdict**: write another ADR to evaluate a charting library and keep the in-house components as a compatibility layer.

### 3.5 Risks and mitigations

| Risk | Mitigation |
| :--- | :--- |
| Interaction work (drag, zoom, hit testing) is under-estimated | P1 builds the interaction core on the topology monitor page first, then reuses it; the code lives in `app/composables/useGraphInteraction.ts` |
| Performance misses on large graphs | Caps, trimming and pixel aggregation; the measured data (36 nodes / 48 edges) is far below the caps |
| Visual mismatch with Nuxt UI | Colours and spacing come from `app.config.ts` and CSS variables, never hard-coded hex values |

## 四、Gate B: the simulator as a second upstream (D4 – D7)

### 4.1 Channel shape (where the code goes)

| Piece | Where | Requirement |
| :--- | :--- | :--- |
| Config | `nuxt.config.ts` → `runtimeConfig.simulator = { baseUrl: "", allowWrite: false, timeoutMs: 15000, readinessPath: "/api/health" }` | Every key overridable via `NUXT_SIMULATOR_*`; an empty `baseUrl` means **channel disabled**, pages degrade to read-only/not-connected rather than throwing |
| Config reader | `server/utils/bff/simConfig.ts` | Shaped like `getBffConfig()`: defaults in one place, trailing slash stripped, `allowWrite` strictly boolean |
| Egress | `server/utils/bff/simulator.ts` | **No `Authorization` injection**, no `nmcps_at` cookie read, no forwarding of caller headers (only `accept` / `content-type`); timeout and `AbortSignal`; responses normalised to `ApiResponse` |
| Route | `server/api/sim/[...slug].ts` → `resolveSimulatorTarget()` | **Template match** on `{param}`, never a prefix pass-through; a miss is 404 `bff_resource_not_allowed`, a wrong method is 405, and `.` / `..` / `/` / `\` / NUL segments are rejected exactly as `resolveGatewayTarget` does |
| Whitelist | `shared/constants/simulatorRoutes.ts` | One entry per `{ method, template, write }`; a `write: true` entry answers 405 while `allowWrite === false` |

**Why not reuse `server/api/[...slug].ts`**: `proxyToUpstream()` reads the token cookie, turns it into `Bearer` and takes part in the single-flight refresh on 401. Sending a Bearer token to an **unauthenticated simulator** leaks credentials (the same trade-off 1.0's `proxySimulator.ts` made by egressing on its own). The 401 semantics also differ: a simulator 401 must never refresh a token or end the session.

### 4.2 Whitelist draft (the usage each page actually needs, not blanket access)

| Layer | Reads (GET) | Writes (`write: true`) |
| :--- | :--- | :--- |
| Topology monitor | `GET /api/network/runtime-inventory` (returns `nodes[]` + `links[]` in one call, measured 36/48), `GET /api/network/stats`, `GET /api/lldp/summary`, `GET /api/lldp/neighbors/{node_id}`, `GET /api/network/runtime/preview` | `POST /api/network/links/{link_id}/{down,up,toggle,disable,power,reconfigure}`, `PATCH /api/network/links/{link_id}/{tc,radio}`, `POST /api/network/nodes/{node_id}/{start,stop,restart,power}`, `PATCH /api/network/nodes/{node_id}/{radio,ip}`, `POST /api/network/runtime/{nodes,links}`, `DELETE /api/network/runtime/{nodes,links}/{id}` |
| Device connector | `/api/devices`, `/api/devices/importable`, `/api/devices/{dev_id}`, `/api/configs`, `/api/configs/{name}`, `/api/configs/{name}/topology-preview`, `/api/network/snmp-accounts`, `/api/network/wireless-nodes` | `/api/devices/import`, `/api/configs/{name}` (create/update via `POST`), `/api/configs/{name}` (remove via `DELETE`), `/api/configs/{name}/snmp-v3` |
| Scenario | `/api/simulation/engines`, `/api/simulation/sessions`, `/api/simulation/sessions/{sim_id}/{status,topology,connectivity,diagnostics,build-plan,boot-progress}`, `/api/network/overrides/{scenario}`, `/api/metrics/summary/{sim_id}` | `/api/simulation/sessions` (create), `/api/simulation/sessions/{sim_id}/{start,stop,pause,resume,trigger,bgtraffic}`, `/api/simulation/sessions/{sim_id}` (`DELETE`, destroy) |

| Spectrum | `/api/network/wireless-nodes`, `/api/weaknet/presets`, `/api/weaknet/profiles`, `/api/weaknet/current` | `/api/weaknet/sessions/{sim_id}/{apply,clear}`, `PATCH /api/network/nodes/{node_id}/radio` |
| Dashboard | `/api/simulation/sessions` (read-only badge), `/api/metrics/summary/{sim_id}` | — |

> Rule: each layer registers **only the entries its pages actually call**. This differs from ADR-0018 D2's "register the whole namespace first" — that was path grouping inside one upstream, whereas this is **a capability grant across upstreams**, so the grant granularity must be the endpoint.

> **Corrected against the measured `openapi.json` on 2026-11-05** (the first draft was written from 1.0 memory and got four verbs wrong):
> ① `/api/network/runtime/nodes` and `/api/network/runtime/links` are **POST** (create at runtime) and their `{id}` children are **DELETE**; a full read goes through `GET /api/network/runtime-inventory` — listing them as the old table did returns 405.
> ② `tc` / `radio` / `ip` are **PATCH** (parameterised attribute changes), not POST; `power` is POST on both nodes and links.
> ③ `POST /api/configs` does not exist (`/api/configs` is GET only); create and update both go through `POST /api/configs/{name}`.
> ④ `POST /api/protocol/compare` is a write-semantics endpoint (it stores a comparison run), not a GET; `GET /api/simulation/sessions/{sim_id}` does not exist — status lives at `.../status`, and on that path GET is 404 while DELETE destroys the session.
> ⑤ Same-day re-check of the gateway side: `openapi.json` now reports **127 paths** (the 131 recorded in §2.1 has drifted with a minor upstream change); the six `/metric/{datapoint,definition,device,link,name}` endpoints are unchanged, and the `metric_ListDatapointResp` / `metric_Datapoint` schemas match `NMCPS-CONTRACT-002` §6.

### 4.3 Permanently excluded (never whitelisted; a separate ADR is required to add one)

| Endpoint | Why excluded |
| :--- | :--- |
| `POST /api/network/nodes/{node_id}/execute` | **Arbitrary command execution inside a node**, the same class as the `shell:allow-execute` capability `.clinerules` bans forever; opening it hands the host shell to the front end |
| `/api/browser/{sim_id}/{capture,proxies,start,stop}` | Headless-browser and proxy process control: both an arbitrary-URL fetch (SSRF surface) and a side channel out of the network |
| `/api/integrity/watch/{start,stop}` | Starts a background daemon on the simulator; the BFF must not become a long-running task launcher (see D8) |
| `/api/devices/clear` | Destroys the device ledger, and no page needs it |
| `/api/test/{ping,traceroute,mtr,iperf,lldp,netcat}` | Active network probing that could be used as an intranet scanner; if ever needed, a separate ADR plus a dedicated confirmation dialog |
| `/api/snmp/onboard/**` (`rotate` / `revoke` / `export` / `live`) | Credential rotation and credential export, more sensitive than a read-only ledger |
| `/api/nms/vmagent/reload`, `/api/nms/vmagent/targets/{scenario}` | Changes collection-side configuration — deployment plane, not display plane |

### 4.4 Risks of an unauthenticated upstream and the guard rails

The simulator measured **no auth header requirement**, so every guard rail has to sit in the BFF:

1. **Off by default**: with an empty `baseUrl` the channel does not exist and any `/api/sim/**` request answers 503 `simulator_not_configured` (the same contract as `/ready` with no upstream).
2. **Write switch**: `allowWrite` defaults to `false`, every write endpoint answers 405, and pages render read-only with a "simulation control disabled" note.
3. **No credentials**: the outbound header whitelist is `accept` / `content-type`; the `check:bff` fake upstream asserts that no `authorization` header ever arrives.
4. **Controlled origin**: browser CORS still follows the BFF's `allowedOrigins`, and Tauri never talks to 8001 directly (the desktop WebView only knows `bffBase`).
5. **Audit**: every `write: true` call logs one structured line (`sim write <method> <template> <status> <duration>`) with no request body.
6. **Separate readiness**: an unreachable simulator must **not** turn `/ready` red — it only degrades the pages that depend on it, so a hiccup in an optional upstream never escalates into a global outage.

### 4.5 Guard (`check:bff`, new group ⑨)

| Assertion | Description |
| :--- | :--- |
| ⑨-1 | Without `simulator.baseUrl`, `/api/sim/**` answers 503 in the `ApiResponse` envelope |
| ⑨-2 | Whitelisted paths reach the fake upstream; anything else is 404; a wrong method is 405 |
| ⑨-3 | Path traversal (`..`, `%2e%2e`, a segment containing `/`) is 400 |
| ⑨-4 | With `allowWrite: false` write endpoints are 405; with `true` they reach the fake upstream |
| ⑨-5 | The outbound request carries **no** `authorization` header and never reads `nmcps_at` |
| ⑨-6 | **Whitelist ⊆ the `paths` in `/openapi.json`**: the script reads `shared/constants/simulatorRoutes.ts`, normalises each template's `{param}` and compares against the snapshot `scripts/fixtures/simulator-openapi.json`; a stale snapshot (its `info.version` differs from the measurement) only warns, so an upstream upgrade never reddens CI |

⑨-6 is how the requester's `/openapi.json` measurement turns into governance value: in 1.0 the simulator proxy could only be maintained from memory, while now the whitelist is **mechanically checkable** — a missing entry, an upstream rename or a malformed template all surface, for the price of one `curl`.

## 五、Gate C: the BFF engine boundary (D8 / D9)

### 5.1 Four admission rules (all four or no code)

| # | Rule | Forbidden counterpart |
| :--- | :--- | :--- |
| C-1 | **Pure function, no in-process mutable state**: input → output, same input same output | `globalThis` singletons, module-level `Map`/`Set` ledgers, `setInterval` background refreshes |
| C-2 | **Either read-only derivation or a write back to the real upstream**: the BFF never holds a second ledger | Keeping a device/link/policy state that only the BFF believes in |
| C-3 | **Own namespace and own route**: implementation in `server/utils/engine/<domain>/*`, endpoints in `server/api/<domain>/…`, **never through** the `[...slug]` gateway | Putting an engine endpoint on the resource whitelist and mixing it into the business data channel |
| C-4 | **Registered triple**: `page → endpoint → engine file`, one row each in §5.2 of this ADR; a combination that is not in the table may not be implemented | "I'll just add an endpoint while I'm here" |

### 5.2 Per-domain verdicts

| Page / capability | 1.0 source | 2.0 destination | Where the state lives | Verdict |
| :--- | :--- | :--- | :--- | :--- |
| Spectrum frequency pool | `server/utils/rrm/*` (about 2,337 lines of deterministic maths: pool, channel plan, conflict detection) | `server/utils/engine/rrm/*` (pure functions) plus `server/api/spectrum/pool.get.ts` | **Not persisted**: AP input is read from 8888 `/frequency/wifi/aps`, candidates and conflicts are computed per request and dropped; "locked / protected" becomes client session state | ✅ algorithm moves, state does not |
| Spectrum recommendation / RRM | same source (`recommend` / `plan`) | same engine, different endpoints | same | ✅ algorithm moves |
| Spectrum view / waterfall / resolution | `layers/spectrum` hand-written Canvas/WebGL2 plus `spectrumDsp` (no external dependency) | client `SpectrumWaterfall` plus pure DSP helpers | client | ✅ straightforward carry-over (zero decision) |
| Mesh edge ledger | `server/utils/mesh/edge-store.ts` plus `server/api/mesh/edge/index.get.ts` | **none** (deliberately no equivalent) | read-only: `/topology/graph` plus `/metric/link` | ⚠️ degrades to read-only; 1.0's write CRUD does not move (it is a mock — porting it would mint a second ledger) |
| Route policy / rehearsal | `shared/route-engine` (pure TS, portable) plus `memory-policy-store` (Nitro memory) | `server/utils/engine/route/*` plus `server/api/route/plan.post.ts` | **compute without storing**: the client holds the policy and posts it with the request; deploy/rehearse buttons are marked "not implemented" | ✅ engine moves, store does not |
| Scenario netforge / topoWizard | `layers/scenario` client engines | stay in a client composable | client | ✅ never touches the BFF |
| Topology layout maths | `topologyLayout` / `topologyLayering` / `topologyRadialLayout` / `topologyTierTreeLayout` / `topologyEdgeStyle` | `app/utils/graph/*` (client pure functions) | client | ✅ straightforward carry-over |

> Handling of upstream gaps: 8888 has no `spectrum` / `rrm` / `mesh` / `route` / `simulation` namespace (the same finding as ADR-0018 §4.3 G9 / G10). This ADR requests no new upstream capability; it assembles pages from "existing data plus pure computation" inside the §5.2 boundary. **Any requirement for upstream persistence goes back to upstream as a project**, never into the BFF as a stopgap.

### 5.3 Anti-patterns (explicitly not carried over)

- `globalThis` singletons (1.0's state host for mesh and rrm).
- A Nitro memory store acting as the business database.
- BFF-side polling plus caching (the client should fetch on demand, or the upstream should stream over SSE).
- Implementing "policy rollout" in the BFF — with no upstream endpoint behind it, `deploy` answers 501 and the page says so.

### 5.4 Guards and tests

| Item | Requirement |
| :--- | :--- |
| Unit tests | every file under `server/utils/engine/**` has at least one input/output case, run with Node's built-in `node --test` (zero new dependencies; the project has no vitest and this ADR does not add a test framework) |
| Static guard | `check:bff` asserts that "business data still leaves through exactly one place, `proxyToUpstream`" and that engine endpoints never appear in `GATEWAY_RESOURCES` |
| Doc sync | adding or removing a §5.2 triple happens in the same change as an appended section of this ADR |

## 八、Rejected options

| Option | Why rejected | When it may be revisited |
| :--- | :--- | :--- |
| Adopt `@antv/g6` to reuse 1.0's renderer | Heavyweight dependency conflicting with "no new dependencies", and 1.0's renderer does not match 2.0's Nuxt UI / container-query model — porting it still needs major surgery | when general BI requirements appear (§3.4) |
| Let `proxyToUpstream` handle the simulator too | The Bearer token would go to an unauthenticated upstream, and mixing 401 semantics would trigger spurious refreshes and logouts | never (a separate channel is the only safe shape) |
| Whitelist the simulator "by namespace" | That upstream contains command execution, headless browsers and credential rotation; prefix pass-through means fully open | never |
| Host the mesh / rrm mutable ledger in the BFF | It mints a second ledger that contradicts 8888 as the single source of truth; it is lost on restart and forks across instances | once the upstream exposes the corresponding persistent service, switch to reading and writing it |
| Port 1.0's `memory-policy-store` for route persistence | Same as above, and in 1.0 it was a mock anyway | once an upstream `/route` namespace lands |
| Migrate all six layers in one go | No intermediate validation point, all risk lands at the end, and any of the three unverified gates could force rework | not applicable |
