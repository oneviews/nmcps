# ADR-0025: the webshell's rendering boundary (no terminal emulator for now)

> **Layer**: Tier 5, the record layer — published text is append-only; corrections arrive as a new `##` section, never by rewriting a published conclusion.
> **Relationship to ADR-0022**: `NMCPS-ADR-0022` (`layers/content/collections/cn/records/adr/adr-0022.md`) W8 only answered "the webshell must accept per-keystroke input"; it never answered "how faithful must the rendering be". That gap comes back as repeated defect reports ("`top` shows garbage", "no colours"), so the boundary is written down as a decision.

## 1. Context (today, measured)

After W8 the two halves of the webshell are not symmetric:

- **The input half is a real terminal.** The panel translates `keydown` into PTY bytes (`\r`, `0x7f`, `\t`, CSI for arrows / Home / End / Delete, `Ctrl+letter` as `0x01–0x1A`), batches characters into one frame every 8ms and routes IME input through a hidden textarea's `input` event; the echo comes from the PTY, never locally.
- **The rendering half is still a cleaned text window.** `labTerminalTextOf()` strips ANSI / OSC sequences, keeps the last segment after `\r` and deletes characters on backspace, then the whole transcript goes into a `<pre>`. That is what keeps a real PTY's colour codes from filling the screen with `^[[1;32m`.

On 2026-11-17 the input side was re-measured against a real `bash --norc -i` on a PTY, feeding the exact byte sequences the component sends: 6/6 hold — backspace deletes one character, `\r` really executes, `0x03` interrupts a running `sleep`, `\t` completes `ech` → `echo `, `\x1b[D` moves the cursor so the next character lands mid-line, and `0x0c` clears the screen leaving the prompt. **The gap is rendering, not keystrokes.** What works today: line-oriented commands, `ls` / `cat` / `tail -f`, completion, `Ctrl-C` / `Ctrl-D` / `Ctrl-L`, history recall via the arrow keys (the tail of the redraw stays readable). What does not: full-screen TUIs such as `vi` / `top` / `htop` (cursor addressing and line clearing are not replayed, so the UI and the transcript overwrite each other), colours and bold, column alignment for wide (CJK) characters, and window resizing (no `SIGWINCH`, `COLUMNS` stays at its default).

## 2. Decision

| # | Decision | Rationale |
| :--- | :--- | :--- |
| **D1** | **No terminal-emulator dependency for now** (xterm.js / hterm / equivalents) | Project rules forbid depending on something unused, and it would drag a rendering layer, font metrics and a worker / WebGL path into the shared `layers/scenario`, touching CSP and first-paint budget. The benefit (full-screen TUIs) is unconfirmed; the cost is immediate. |
| **D2** | Rendering has exactly one path: `labTerminalTextOf()` plus `<pre>` | It stays a pure function so `check:lab-ws` / `check:ui` can assert "not one ESC survives". No second, half-parsing branch is allowed in the page. |
| **D3** | The boundary is documented, not discovered by bumping into it | The two columns above (works / does not work) are the product promise; the panel hint only says "click the terminal to start typing" and never promises full-screen programs. |
| **D4** | No hand-rolled CSI cursor addressing on top of the textarea | That is rewriting a terminal emulator, with more risk and work than adopting a mature one; a half-implementation is harder to explain than today's state. Either a text window or a real emulator — no middle state. |
| **D5** | Re-open triggers (any one, as a new ADR rather than an appended section) | ① the requester explicitly needs `vi` / `top`-class interaction; ② three or more defects about colours / cursor / wide characters; ③ upstream gains an operation that requires real terminal semantics (an interactive setup wizard, `dialog` / `whiptail`). Scope to evaluate then: `xterm.js` with `@xterm/addon-fit` (size reporting), CSP allowances, bundle budget, the `check:ui` assertion path, and what remains of `labTerminalTextOf()` (offline replay still needs it). |
| **D6** | The server keeps its semantics | PTY bytes pass through `labWsRelay` unchanged; rendering is the front end's business. No server-side HTML / Markdown rendering (it breaks "verbatim" and widens the injection surface) and no byte-stream trimming (a trimmed stream cannot be restored). |

## 3. Consequences

- Short term: the webshell is enough for configuration work (edit a file, read logs, start and stop services, follow a `tail -f`) and not enough for interactive full-screen programs — a public fact, not a defect.
- The fake upstream (`scripts/lib/bff-harness.mjs`) already answers in real-PTY shape (byte-by-byte echo, `echo:<line>` only on a newline, `^C` on `0x03`), so those assertions cover the transport rather than the rendering; the real input side is guarded by `pnpm check:lab-terminal` (a real `bash` on a PTY, POSIX only).
- Adding no dependency means no new version / licence / packaging surface, and no knock-on work in `pnpm check:platform` or the capabilities files.

## 4. Acceptance

- `pnpm check:lab-terminal` 6/6: a real `bash --norc -i` on a PTY replayed with the exact bytes the component sends (backspace / Enter / `0x03` / `\t` / CSI cursor / `0x0c`). Non-POSIX platforms skip with a stated reason instead of pretending to pass.
- `pnpm check:ui` 11.8 keeps its 12 cases (they assert the bytes the panel emits and the text the upstream returns, independent of how rendering is implemented).
- `pnpm check:lab-bff` ⑬ is unchanged (the BFF only relays bytes).
- On a real device (root + Mininet), by hand: `POST /start`, open the h1 session, confirm `ls` / `tail -f` work and `vi` does not — a fact inside this decision, not a defect to fix.
